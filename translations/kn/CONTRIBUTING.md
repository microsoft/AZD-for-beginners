# AZD For Beginners ಗೆ ಕೊಡುಗೆ ನೀಡುವುದು

AZD For Beginners ಕೋರ್ಸಿಗೆ ಕೊಡುಗೆ ನೀಡಲು ತಮಗೆ ಧನ್ಯವಾದಗಳು! ಈ ಡಾಕ್ಯುಮೆಂಟ್ ಕೊಡುಗೆಯ ನೀಡುವವರಿಗಾಗಿ ಮಾರ್ಗಸೂಚಿ ಮತ್ತು ಮಾಹಿತಿ ಒದಗಿಸುತ್ತದೆ.

## ಕೊಡುಗೆ ನೀಡುವ ವಿಧಾನ

### ಸಮಸ್ಯೆಗಳನ್ನು ವರದಿ ಮಾಡುವುದು

ನೀವು ದೋಷಗಳು, ತಪ್ಪುಗಳು ಅಥವಾ ಸುಧಾರಣೆಗಳ ಸಲಹೆಗಳನ್ನು ಕಂಡುಬಂದರೆ:

1. **ಯಿಜಜಮಾನ ಸಮಸ್ಯೆಗಳ ಪರಿಶೀಲನೆ**: ನಕಲು ತಡೆಯಲು [ಹಿಂದಿನ ಸಮಸ್ಯೆಗಳನ್ನು](https://github.com/microsoft/azd-for-beginners/issues) ಹುಡುಕಿ
2. **ಹೊಸ ಸಮಸ್ಯೆ ಸೃಷ್ಟಿ**: مناسبی ಸಮಸ್ಯೆ ಟೆಂಪ್ಲೇಟ್ ಬಳಸಿ
3. **ವಿವರಗಳನ್ನು ಒದಗಿಸಿ**: ಪುನರುತ್ಪಾದನೆಗೆ ಬೇಕಾದ ಹಂತಗಳು, ನಿರೀಕ್ಷಿತ ವರ್ತನೆ ಮತ್ತು ಅಗತ್ಯವಿದ್ದರೆ ಸ್ಕ್ರೀನ್‌ಶಾಟ್ ಗಳನ್ನು ಸೇರಿಸಿ

### ಬದಲಾವಣೆಗಳನ್ನು ಪ್ರಸ್ತಾವಿಸುವುದು

1. **ಸ್ಥಳಕೊಳ್ಳಿಕೆ ಫೋರ್ಕ್ ಮಾಡಿ**: ಯೋಜನೆಯ ನಿಮ್ಮ ಸ್ವಂತ ಫೋರ್ಕ್ ಸೃಷ್ಟಿಸಿ
2. **ಬ್ರಾಂಚ್ ಸೃಷ್ಟಿಸಿ**: ನಿಮ್ಮ ಬದಲಾವಣೆಗಳಿಗೆ ಫೀಚರ್ ಬ್ರಾಂಚ್ ಸೃಷ್ಟಿಸಿ
3. **ಬದಲಾವಣೆಗಳನ್ನು ಮಾಡಿ**: ನಮ್ಮ ಕೋಡಿಂಗ್ ಮತ್ತು ಡಾಕ್ಯುಮೆಂಟೇಷನ್ ಮಾನದಂಡಗಳನ್ನು ಅನುಸರಿಸಿ
4. **ನಿಮ್ಮ ಬದಲಾವಣೆಗಳನ್ನು ಪರೀಕ್ಷಿಸಿ**: ಎಲ್ಲಾ ಲಿಂಕ್‌ಗಳು ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿರುವುದನ್ನು ಮತ್ತು ವಿಷಯ ಸರಿಯಾದ ರೀತಿಯಲ್ಲಿ ಪ್ರದರ್ಶಿಸುತ್ತಿರುವುದನ್ನು ದೃಢೀಕರಿಸಿ
5. **ಪಲ್ಲ್ ರಿಕ್ವೆಸ್ಟ್ ಸಲ್ಲಿಸಿ**: ನಿಮ್ಮ ಬದಲಾವಣೆಗಳ ಸ್ಪಷ್ಟ ವಿವರಣೆಯನ್ನು ಒದಗಿಸಿ

### ಕೊಡುಗೆಗಳ ಪ್ರಕಾರಗಳು

ನಾವು ಕೆಳಗಿನ ರೀತಿಯ ಕೊಡುಗೆಗಳನ್ನು ಸ್ವಾಗತಿಸುವೆವು:

#### ವಿಷಯ ಸುಧಾರಣೆಗಳು
- ಟೈಪೋಗಳು, ವ್ಯಾಕರಣ, ಮತ್ತು ಫಾರ್ಮ್ಯಾಟಿಂಗ್ ಸಮಸ್ಯೆಗಳನ್ನು ಸರಿಪಡಿಸಿ
- ಇಂದ್ರಿಯವಾಗಿ ಸ್ವಚ್ಛವಾಗಿಸುವುದಕ್ಕಾಗಿ ಇತರ ಡಾಕ್ಯುಮೆಂಟ್ ಗಳ ಸ್ಪಷ್ಟತೆ ಹೆಚ್ಚಿಸಿ
- ಹಳೆಯ ಮಾಹಿತಿಯನ್ನು ನವೀಕರಿಸಿ
- ಕಳೆದು ಹೋದ ವಿವರಣೆಗಳ ಅಥವಾ ಸಂದರ್ಭವನ್ನು ಸೇರಿಸಿ

#### ಹೊಸ ಉದಾಹರಣೆಗಳು
- ವಾಸ್ತವಿಕ ನಿಯೋಜನೆ ಸಂದರ್ಭಗಳನ್ನು ಸೇರಿಸಿ
- ಸಾಮಾನ್ಯ ಬಳಕೆಗಾಗಿ ಹೊಸ AZD ಟೆಂಪ್ಲೇಟುಗಳನ್ನು ರಚಿಸಿ
- ಹೆಚ್ಚುವರಿ ಕೋಡ್ ಮಾದರಿಗಳನ್ನು ಮತ್ತು ಅಭ್ಯಾಸಗಳನ್ನು ಒದಗಿಸಿ

#### ಅನುವಾದ ಬೆಂಬಲ
- ಇಬ್ರುತಿರುವ ಅನುವಾದಗಳನ್ನು ನಿರ್ವಹಿಸಲು ಸಹಾಯ ಮಾಡಿ
- ಅನುವಾದ ಗುಣಮಟ್ಟವನ್ನು ಸುಧಾರಿಸಿ
- ಹೊಸ ವಿಷಯಗಳಿಗೆ ಅನುವಾದಗಳನ್ನು ಸೇರಿಸಿ

#### ದೋಷ ವರದಿಗಳು
- ಭಂಗವಾಗಿರುವ ಲಿಂಕ್‌ಗಳು ಅಥವಾ ತಪ್ಪಾದ ಕೋಡ್ ಉದಾಹರಣೆಗಳನ್ನು ವರದಿ ಮಾಡಿ
- ಡಾಕ್ಯುಮೆಂಟೇಷನ್ ವೈಷಮ್ಯಗಳನ್ನು ಗುರುತಿಸಿ
- ಪ್ರವೇಶಸಾಧ್ಯತಾ ಸಮಸ್ಯೆಗಳನ್ನು ಗುರುತಿಸಿ

## ಕೊಡುಗೆ ಮಾರ್ಗಸೂಚಿ

### ಡಾಕ್ಯುಮೆಂಟೇಷನ್ ಮಾನದಂಡಗಳು

- ಸ್ಪಷ್ಟ, ಆರಂಭಿಕರಿಗೆ ಅನುಕೂಲಕರ ಭಾಷೆಯನ್ನು ಬಳಸಿ
- ಕಲಿಕೆ ಗುರಿಗಳು ಮತ್ತು ಫಲಿತಾಂಶಗಳನ್ನು ಸೇರಿಸಿ
- ನಿರೀಕ್ಷಿತ ಫಲಿತಾಂಶಗಳೊಂದಿಗೆ ಹಂತ-ಹಂತದ ಸೂಚನೆಗಳನ್ನು ಒದಗಿಸಿ
- ಸಂಬಂಧಿತ ವಿಷಯಗಳಿಗೆ ನಾವಿಗೇಷನ್ ಲಿಂಕ್‌ಗಳನ್ನು ಸೇರಿಸಿ
- ಸತತವಾಗಿ ಫಾರ್ಮ್ಯಾಟಿಂಗ್ ಮತ್ತು ಮಾರ್ಕ್ಡೌನ್ ಶೈಲಿಯನ್ನು ಬಳಸಿ

### ಕೋಡ್ ಉದಾಹರಣೆಗಳು

- ಎಲ್ಲಾ ಕೋಡ್ ಉದಾಹರಣೆಗಳು ಪರೀಕ್ಷಿಸಲ್ಪಟ್ಟಿವೆ ಮತ್ತು ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿರುವುದನ್ನು ಖಚಿತಪಡಿಸಿ
- ಪ್ರಮುಖ ಕನ್ಸೆಪ್ಟ್‌ಗಳನ್ನು ವಿವರಿಸುವ ಕಾಮೆಂಟ್‌ಗಳನ್ನು ಸೇರಿಸಿ
- Azure ಮತ್ತು AZD ಉತ್ತಮ ಪ್ರಥಮಗಳಲ್ಲಿ ಅನುಸರಿಸಿ
- ಅಗತ್ಯವಿದ್ದಾಗ ನಿರೀಕ್ಷಿತ ಫಲಿತಾಂಶವನ್ನು ಒದಗಿಸಿ

### ಇಂಗ್ಲಿಷ್ ಡಾಕ್ಯುಮೆಂಟ್ ಪರಿಶೀಲಿಸಿ

ರೆಪೊರಿಟರಿ ಮೂಲದಿಂದ, ಇರುವ ಡೆವಲಪ್ಮೆಂಟ್ ಅಗತ್ಯಗಳನ್ನು ಸ್ಥಾಪಿಸಿ ಮತ್ತು ಕಳುಹಿಸಿ:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

ಆಫ್‌ಲೈನ್ ಲಿಂಕ್ ಚೆಕರ್ ಇಂಗ್ಲಿಷ್ ಮಾರ್ಕ್‌ಡೌನ್/HTML ಪಥಗಳು, ಶೀರ್ಷಿಕೆಗಳು, ಸ್ಪಷ್ಟ ಆಂಕರ್‌ಗಳು ಮತ್ತು ಖಾಲಿ ಲಿಂಕ್ ಪ್ಲೇಸ್‌ಹೋಲ್ಡರ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದು ಉತ್ಪಾದಿತ `translations/` ಮತ್ತು `translated_images/` ಹಾಗೂ ಆ ಡೈರಕ್ಟರಿಗಳಲ್ಲಿ ಲಿಂಕ್‌ಗಳನ್ನು ವಿಸರ್ಜಿಸುತ್ತದೆ. ಇದು ಹೊರಗಿನ ವೆಬ್‌ಸೈಟ್‌ಗಳನ್ನು ಪಡೆಯುವುದಿಲ್ಲ ಅಥವಾ Azure ನಿಯೋಜನೆಗಳನ್ನು ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ. ತೊಂದರೆಗಳನ್ನು ಮತ್ತು ಹೊರಗಿನ URL ಇನ್‌ವೆಂಟರಿ ವಾಸ್ತವಕ್ಕೆ ಪರಿಗಣಿಸಬೇಕಾದಾಗ `--json <report-path>` ಬಳಸಿ. ತಾಂತ್ರಿಕ ಸೂಚನೆಗಳನ್ನು ಬದಲಾಯಿಸಿದಾಗ ಪ್ರಸ್ತುತ ಅಪ್‌ಸ್ಟ್ರೀಂ ಕಮಾಂಡೆಗಳು ಮತ್ತು ಮಾದರಿ ಪೂರ್ವಾಪೇಕ್ಷಣಗಳನ್ನು ಪರಿಶೀಲಿಸಿ; ಪರೀಕ್ಷಿಸಲ್ಪಟ್ಟ ಅಪ್ಲಿಕೆಶನ್‌ಗಳನ್ನು ವಿನ್ಯಾಸದ ಬ್ಲೂಪ್ರಿಂಟ್‌ಗಳಿಂದ ವಿಭಜಿಸಿ.
