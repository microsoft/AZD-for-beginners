## ಕಾರ್ಯಾಗಾರ ಅವಲೋಕನ

ಈ ಕೈಗಾರಿಕೆಯ ಪ್ರಯೋಗಶಾಲೆ ಅಭಿವೃದ್ಧಿಪಡಕರು ಈಗಿನ AI ಟೆಂಪ್ಲೇಟ್ನಿಂದ ಪ್ರಾರಂಭಿಸಿ ಅದನ್ನು Azure Developer CLI (AZD) ಬಳಸಿ ನಿಯೋಜಿಸುವ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಮಾರ್ಗದರ್ಶಿಸುತ್ತದೆ. ನೀವು Microsoft Foundry ಸೇವೆಗಳ ಬಳಕೆದ ಮೂಲಕ ಉತ್ಪಾದನಾ AI ನಿಯೋಜನೆಗಳಿಗೆ ಅಗತ್ಯವಾದ ಮಾದರಿಗಳನ್ನು ಕಲಿಯುತ್ತೀರಿ.

> ** ಬಿಡುಗಡೆ ಪರಿಶೀಲನೆ (2026-11-04):** AZD ಆದೇಶ ಮಾರ್ಗಸೂಚಿ ಮತ್ತು ಮಾದರಿ ಸಂರಚನೆ ಹೆಸರುಗಳು `azd` `1.37.2` ಬಿಡುಗಡೆ ಮತ್ತು ಸಂಬಂದಿತ ಮಾದರಿಯ ಸೇದ್ಯ ಸಂರಚನೆಯ ವಿರುದ್ಧ ಪರಿಶೀಲಿಸಲ್ಪಟ್ಟವು. ಇದು ದಸ್ತಾವೇಜು ಪರಿಶೀಲನೆ, ನೇರ ನಿಯೋಜನೆ ಮಾನ್ಯತೆ ಅಲ್ಲ. RAG ಪ್ರಯೋಗಶಾಲೆಗೆ ಏಜೆಂಟ್ ವಿಸ್ತರಣೆ ಅಗತ್ಯವಿಲ್ಲ; ಏಜೆಂಟ್ ಮೌಲ್ಯಮಾಪನಗಳಿಗೆ, ಪ್ರತ್ಯೇಕ `azure.ai.evaluations` ವಿಸ್ತರಣೆ ಮತ್ತು [ಪ್ರಸ್ತುತ ಮೌಲ್ಯಮಾಪನ ಕಾರ್ಯವಿಧಾನ](../chapter-08-production/production-ai-practices.md#evaluation-migration-and-quality-checks) ಬಳಸಿ, ಹಳೆಯ ಏಜೆಂಟ್ ಮೌಲ್ಯಮಾಪನ ಆದೇಶಗಳನ್ನು ಬಳಕೆ ಮಾಡಬೇಡಿ.

ಈ ಕಮಾಂಡ್ ಬ್ಲಾಕ್‌ಗಳು ಬಾಷ್ ಸಿಂಟ್ಯಾಕ್ಸ್ ಅನ್ನು ಬಳಸುತ್ತವೆ (ಲೈನ್ ಕಂಟಿನ್ಯುಯೇಷನ್ಗಳನ್ನು ಸೇರಿಸಿಕೊಂಡು ಮತ್ತು `grep`). ವಿಂಡೋಸ್‌ನಲ್ಲಿ, Git Bash/WSL ಅನ್ನು ಬಳಸಿರಿ ಅಥವಾ ಅವುಗಳನ್ನು PowerShell ಗೆ ಅನುವಾದಿಸಿ. [ನಮೂನೆಯ ಸ್ಥಳೀಯ ಪರಿಸರ ಸೆಟಪ್](https://github.com/Azure-Samples/azure-search-openai-demo#local-environment) ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾದ ಭಾಷಾ, ಪ್ಯಾಕೇಜ್-ಮ್ಯಾನೇಜರ್ ಮತ್ತು ಕಂಟೈನರ್ ಉಪಕರಣಗಳನ್ನು ಕೂಡ ಸ್ಥಾಪಿಸಿ.

## ಘಟಕ 1: AI ಅಪ್ಲಿಕೇಶನ್ಗಳಿಗಾಗಿ AZD ಶ್ರಿಫ್ಟ್ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು

### AI AZD ಟೆಂಪ್ಲೇಟಿನ ಶರೀರ ರಚನೆ

AI-ಸಿದ್ಧ AZD ಟೆಂಪ್ಲೇಟ್‌ನಲ್ಲಿ ಪ್ರಮುಖ ಫೈಲ್‌ಗಳನ್ನು ಅನ್ವೇಷಿಸಿ:

```
azure-search-openai-demo/
├── azure.yaml              # AZD configuration
├── infra/                   # Infrastructure as Code
│   ├── main.bicep          # Main infrastructure template
│   ├── main.parameters.json # Environment parameters
│   ├── core/               # Shared infrastructure modules
│   └── app/                # Application-specific infrastructure
├── app/                    # Backend, frontend, and optional ingestion functions
├── scripts/               # Deployment scripts
└── .azure/               # AZD environment files
```

ಪರಿಶೀಲಿಸಿದ ಉದಾಹರಣೆ ಬದಲಾಗಬಹುದು; `.azure/` ಪರಿಸರದ ಚಾಲನೆ ನಂತರ ಪ್ರತ್ಯಕ್ಷವಾಗುತ್ತದೆ, ಹೊಸ ಕ್ಲೋನ್‌ನಲ್ಲಿ ಇಲ್ಲವೇ ಇರಬೇಕಾಗಿಲ್ಲ. ಈ ಸಂರಚನೆಗೆ ಹೊಂದಿಸಲು ಕಳೆದುಹೋಯ್ದ ಡೈರೆಕ್ಟರಿಗಳನ್ನು ಸೃಷ್ಟಿಸುವುದಕ್ಕಿಂತ ನಿಜವಾದ ಒಪ್ಪಂದವನ್ನು ಪರಿಶೀಲಿಸಿ.

### **ಪ್ರಯೋಗಾಲಯ ಅಭ್ಯಾಸ 1.1: ಸಂರಚನೆ ಅನ್ವೇಷಿಸಿ**

1. **azure.yaml ಫೈಲ್ ಪರಿಶೀಲಿಸಿ:**
```bash
cat azure.yaml
```

**ಏನು ತೀಕ್ಷ್ಣವಾಗಿ ನೋಡಬೇಕು:**
- AI ಘಟಕಗಳ ಸೇವಾ ವ್ಯಾಖ್ಯಾನಗಳು
- ಪರಿಸರ ವ್ಯತ್ಯಾಸ ನಕ್ಷೆಗಳು
- ಹೋಸ್ಟ್ ಸಂರಚನೆಗಳು

2. **main.bicep ಮೂಲಸೌಕರ್ಯ ಪರಿಶೀಲಿಸಿ:**
```bash
cat infra/main.bicep
```

**ಎಚ್ಚರಿಸಬೇಕಾದ ಮುಖ್ಯ AI ಮಾದರಿಗಳು:**
- Microsoft Foundry Models ಸೇವೆ ಪೂರೈಕೆ
- ಅಝ್ಯೂರ್ AI ಶೋಧ ಸಮೀಕರಣ
- ಸುರಕ್ಷಿತ ಕೀ ನಿರ್ವಹಣೆ
- ನೆಟ್ವರ್ಕ್ ಸುರಕ್ಷತೆ ಸಂರಚನೆಗಳು

### **ಚರ್ಚೆ ಬಿಂದು:** ಈ ಮಾದರಿಗಳು AIಗೆ ಮಹತ್ವವಿರುವುದು ಏಕೆ

- **ಸೇವೆ ಅವಲಂಬನೆಗಳು**: AI ಅಪ್ಲಿಕೇಶನ್‌ಗಳಿಗೆ ಬಹು ಸೇವೆಗಳ ಸಂಯೋಜನೆ ಅಗತ್ಯ
- **ಸುರಕ್ಷತೆ**: API ಕيز್ ಮತ್ತು ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗಳಿಗೆ ಸುರಕ್ಷಿತ ನಿರ್ವಹಣೆ ಬೇಕಾಗಿದೆ
- **ಪ್ರಮಾಣವೃದ್ಧಿ**: AI ಕಾರ್ಯಭಾರಗಳಿಗೆ ವಿಶಿಷ್ಟ ಪ್ರಮಾಣವೃದ್ಧಿ ಅಗತ್ಯತೆಗಳಿವೆ
- **ಖರ್ಚು ನಿರ್ವಹಣೆ**: AI ಸೇವೆಗಳು ಸರಿಯಾಗಿ ಸಂರಚಿಸಲು ತುಂಬ ವೆಚ್ಚವಾಗಬಹುದು

## ಘಟಕ 2: ನಿಮ್ಮ ಮೊದಲ AI ಅಪ್ಲಿಕೇಶನ್ ಅಳವಡಿಕೆ

### ಹಂತ 2.1: ಪರಿಸರ ಪ್ರಾರಂಭಿಸಿ

1. **ಹೊಸ AZಡೀ೦ ಪರಿಸರ ಸೃಷ್ಟಿಸಿ:**
```bash
azd env new myai-workshop
```

2. **ಅಗತ್ಯ ಪರಿಮಾಣಗಳನ್ನು ಸೆಟ್ ಮಾಡಿ:**
```bash
# Set your preferred Azure region
azd env set AZURE_LOCATION eastus

# Optional: select a chat model supported by your region and quota
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
```

### ಹಂತ 2.2: ಮೂಲಸೌಕರ್ಯ ಮತ್ತು ಅಪ್ಲಿಕೇಶನ್ ಆಳವಡಿಕೆ

1. **AZD ಬಳಸಿ ಡಿಪ್ಲಾಯ್ ಮಾಡಿ:**
```bash
azd up
```

**`azd up` ಸಮಯದಲ್ಲಿ ಏನು ಸಂಭವಿಸುತ್ತದೆ:**
- ✅ Microsoft Foundry Models ಸೇವೆಯನ್ನು ಪೂರೈಸುತ್ತದೆ
- ✅ ಅಝ್ಯೂರ್ AI ಶೋಧ ಸೇವೆಯನ್ನು ಸೃಷ್ಟಿಸುತ್ತದೆ
- ✅ ಬ್ಯಾಕ್ಎಂಡ್ ಮತ್ತು ಜೊತೆಗಡೆ ಫ್ರಂಟ್ಎಂಡ್‌ಗಾಗಿ ಅಝ್ಯೂರ್ ಕಂಟೈನರ್ ಅಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನು ಸ್ಥಾಪಿಸುತ್ತದೆ (ಪ್ರಸ್ತುತ ಉದಾಹರಣೆಯ ಮಧ್ಯಸ್ಥ ಡಿಫಾಲ್ಟ್)
- ✅ ನೆಟ್ವರ್ಕಿಂಗ್ ಮತ್ತು ಸುರಕ್ಷತೆ ಸಂರಚನೆ ಮಾಡುತ್ತದೆ
- ✅ ಅಪ್ಲಿಕೇಶನ್ ಕೋಡ್ ಅನ್ನು ನಿಯೋಜಿಸುತ್ತದೆ
- ✅ಮಾನದಂಡ ಮತ್ತು ಲಾಗಿಂಗ್‌ಗಳನ್ನು ಸ್ಥಾಪಿಸುತ್ತದೆ

2. **ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್ ಪ್ರಗತಿಯನ್ನು ಗಮನಿಸಿ** ಮತ್ತು ಸೃಷ್ಟಿಸಲಾಗುತ್ತಿರೋ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಗಮನಿಸಿ.

### ಹಂತ 2.3: ನಿಮ್ಮ ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್ ಪರಿಶೀಲಿಸಿ

1. **ಡಿಪ್ಲಾಯ್ ಮಾಡಿದ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:**
```bash
azd show
```

2. **ಡಿಪ್ಲಾಯ್ ಮಾಡಿದ ಅಪ್ಲಿಕೇಶನ್ ತೆಗೆಯಿರಿ:**
```bash
azd show
```

`azd show` ಔಟ್‌ಪುಟ್‌ನಲ್ಲಿ ತೋರಿಸಿದ ವೆಬ್ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಪಡೆಯಿರಿ.

3. **AI ಕಾರ್ಯಕ್ಷಮತೆಯನ್ನು ಪರೀಕ್ಷಿಸಿ:**
   - ವೆಬ್ ಅಪ್ಲಿಕೇಶನ್‌ಗೆ ಸಂಪರ್ಕಿಸಿ
   - ಉದಾಹರಣಾ ಪ್ರಶ್ನೆಗಳನ್ನು ಪ್ರಯತ್ನಿಸಿ
   - AI ಪ್ರತಿಕ್ರಿಯೆಗಳು ಕೆಲಸ ಮಾಡುತ್ತಿವೆ ಎಂದು ಪರಿಶೀಲಿಸಿ

### **ಪ್ರಯೋಗಾಲಯ ಅಭ್ಯಾಸ 2.1: ಸಮಸ್ಯೆಗಳ ಪರಿಹಾರ ಅಭ್ಯಾಸ**

**ದೃಶ್ಯಾವಳಿ**: ನಿಮ್ಮ ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್ ಯಶಸ್ವಿಗೊಂಡಿದೆ, ಆದರೆ AI ಪ್ರತಿಕ್ರಿಯಿಸದೆ ಇದೆ.

**ಪರಿಚಿತ ಸಮಸ್ಯೆಗಳು ಸರಿಯಾದುದೇ ಎಂದು ಪರಿಶೀಲಿಸಿ:**
1. **ಪರಿಚಯಮುಖತೆ**: ನಿರ್ವಹಿತ ಐಡೆಂಟಿಟಿ ಮತ್ತು ಪಾತ್ರ-ಆಸೈನ್‌ಮೆಂಟ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ; API ಕಿಗಳಿಗೆ ಮಾತ್ರ ನೀವು ಮನಸ್ಸು ಮಾಡಿದ್ದಲ್ಲಿ ಆಯ್ಕೆಮಾಡಿ
2. **ಮಾದರಿ ಲಭ್ಯತೆ**: ನಿಮ್ಮ ಪ್ರದೇಶ ಆ ಮಾದರಿಯನ್ನು ಬೆಂಬಲಿಸುವುದೇ ಎಂದು ಪರಿಶೀಲಿಸಿ
3. **ನೆಟ್ವರ್ಕ್ ಸಂಪರ್ಕತೆ**: ಸೇವೆಗಳು ಸಂವಹನ ಮಾಡಬಲ್ಲುದೇ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ
4. **RBAC ಅನುಮತಿಗಳು**: ಅಪ್ಲಿಕೇಶನ್ OpenAI ಗೆ ಪ್ರವೇಶ ಹೊಂದಬಹುದು ಎಂದು ಪರಿಶೀಲಿಸಿ

**ಡಿಬಗ್ಗಿಂಗ್ ಕಮಾಂಡ್‌ಗಳು:**
```bash
# Check environment variables
azd env get-values

# Open the selected environment's logging view
azd monitor --logs

# Check OpenAI deployment status
az cognitiveservices account deployment list --name YOUR_OPENAI_NAME --resource-group YOUR_RG
```

## ಘಟಕ 3: ನಿಮ್ಮ ಅಗತ್ಯಗಳಿಗೆ AI ಅಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನು ಕಸ್ಟಮೈಸ್ ಮಾಡುವುದು

### ಹಂತ 3.1: AI ಸಂರಚನೆಯನ್ನು ಬದಲಾಯಿಸಿ

1. **OpenAI ಮಾದರಿಯನ್ನು ನವೀಕರಿಸಿ:**
```bash
# Change to a different model (if available in your region)
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1

# Apply the model infrastructure change, then deploy the application
azd up
```

2. **ಹೆಚ್ಚಿನ AI ಸೇವೆಗಳನ್ನು ಸೇರಿಸಿ:**

Document Intelligence ಸೇರಿಸಲು `infra/main.bicep` ಅನ್ನು ಸಂಪಾದಿಸಿ:

ಕೆಳಗಿನವು ಒಂದು ಚಿತ್ತಾರ ಭಾಗವಾಗಿದ್ದು, ಸಂಪೂರ್ಣ ಟೆಂಪ್ಲೇಟು ಅಲ್ಲ. ಉದಾಹರಣೆಗೆ ಈಗಾಗಲೇ ಡಾಕ್ಯುಮೆಂಟ್-ಪ್ರೊಸೆಸಿಂಗ್ ಸೇವೆಗಳನ್ನು ಪೂರೈಸಬಹುದು: ನಕಲಿ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಸೇರಿಸುವ ಮುನ್ನ ಅದರ ಇತ್ತೀಚಿನ ಮೂಲಸೌಕರ್ಯವನ್ನು ಪರಿಶೀಲಿಸಿ. ಕಸ್ಟಮ್ ಸೇರಿಸುವಿಕೆಯು ಔಟ್‌ಪುಟ್‌ಗಳು, ಐಡೆಂಟಿಟಿಗಳು ಮತ್ತು ಅಪ್ಲಿಕೇಶನ್ ಸಂರಚನೆಯನ್ನು ಸಂಪರ್ಕಿಸುವದನ್ನು ಅಗತ್ಯವಿರುತ್ತದೆ.

```bicep
// Add to main.bicep
resource documentIntelligence 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: 'doc-intel-${uniqueString(resourceGroup().id)}'
  location: location
  kind: 'FormRecognizer'
  sku: {
    name: 'F0'  // Free tier for workshop
  }
  properties: {
    customSubDomainName: 'doc-intel-${uniqueString(resourceGroup().id)}'
```

### ಹಂತ 3.2: ಪರಿಸರವಿಷಯಕ್ಕಾಗಿ ವಿಶೇಷ ಸಂರಚನೆಗಳು

**ಉತ್ತಮ ಅಭ್ಯಾಸ**: ಅಭಿವೃದ್ಧಿ ಮತ್ತು ಉತ್ಪಾದನೆಗಾಗಿ ವಿಭಿನ್ನ ಸಂರಚನೆಗಳು.

1. **ಉತ್ಪಾದನಾ ಪರಿಸರ ನಿರ್ಮಿಸಿ:**
```bash
azd env new myai-production
```

2. **ಉತ್ಪಾದನಾ-ನಿರ್ದಿಷ್ಟ ಪರಿಮಾಣಗಳನ್ನು ಸೆಟ್ ಮಾಡಿ:**
```bash
# Use the sample's actual Search SKU parameter
azd env set AZURE_SEARCH_SERVICE_SKU standard

# Enable private endpoints using the sample's parameter
azd env set AZURE_USE_PRIVATE_ENDPOINT true
```

ಈ ಹೆಸರುಗಳು ನಮೂನೆಯ [main.parameters.json](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/infra/main.parameters.json) ಇಂದ ಬರುತ್ತವೆ. `azd env set` ಒಂದು ಮೌಲ್ಯವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಆದರೆ ಒಂದು ಅಲಂಕಾರಿಕ ವ್ಯತ್ಯಾಸವನ್ನು ಪ್ರಭಾವ ಒಳಗೊಳ್ಳುವುದಿಲ್ಲ: ಟೆಂಪ್ಲೇಟು ಅದನ್ನು ಬಳಸಬೇಕು. ಸಾರ್ವಜನಿಕ ಪ್ರವೇಶ ಅಸಮರ್ಥಗೊಳಿಸುವ ಮುನ್ನ ನಮೂನೆಯ [ನೆಟ್ವರ್ಕ್ ಐಸೊಲೆಷನ್ ಮಾರ್ಗದರ್ಶಿ](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/docs/deploy_private.md) ಅನ್ನು ಪರಿಶೀಲಿಸಿ ಮತ್ತು ಮೂಲಸೌಕರ್ಯ ಬದಲಾವಣೆಗಳಿಗೆ `azd up` ಬಳಸಿ. OpenAI SKU `S0` ಮಾತ್ರ ಮಾದರಿ ಥ್ರೂಪೂಟ್ ನಿರ್ಧರಿಸುವುದಿಲ್ಲ; ಮಾದರಿ ನಿಯೋಜನೆಯ ಪ್ರಕಾರ ಮತ್ತು ಸಾಮರ್ಥ್ಯವೂ ಮುಖ್ಯ.

### **ಪ್ರಯೋಗಾಲಯ ಅಭ್ಯಾಸ 3.1: ವೆಚ್ಚ ಅನುಕೂಲತೆ**

**ಚಾಲೆಂಜ್**: ಡೆವಲಪ್‌ಮೆಂಟ್‌ಗೆ ವೆಚ್ಚ-ಸಚೇತ ಟೆಂಪ್ಲೇಟನ್ನು ಸಂರಚಿಸಿ.

**ಕಾರ್ಯಗಳು:**
1. ಅಳಿಸಬಹುದಾದ ವರ್ಕ್‌ಶಾಪ್ ಪರಿಸರವನ್ನು ಆಯ್ಕೆ ಮಾಡಿ: `azd env select myai-workshop`.
2. ಪ್ರಸ್ತುತ ಶೋಧ SKU ಮತ್ತು ಮಾದರಿ ಸಾಮರ್ಥ್ಯವನ್ನು `infra/main.parameters.json` ಮತ್ತು ಆಯ್ಕೆದ ಪರಿಸರದಿಂದ ದಾಖಲಿಸಿ.
3. ಮಾದರಿ/ಪ್ರದೇಶ ಅನುದಾನವನ್ನು ಖಚಿತಪಡಿಸಿಕೊಂಡು ಕೆಳಗಿನ ಬೆಂಬಲಿತ ಇನ್‌ಪುಟ್‌ಗಳನ್ನು ಬಳಸಿ:
   ```bash
   azd env set AZURE_SEARCH_SERVICE_SKU basic
   azd env set AZURE_OPENAI_CHATGPT_DEPLOYMENT_CAPACITY 10
   azd up
   ```
4. ಸಾಕ್ಷಾತ್ ನಿರ್ವಹಣೆ ಕೇಂದ್ರದಲ್ಲಿ ಶೋಧ SKU ಮತ್ತು ನಿಯೋಜನೆ ಸಾಮರ್ಥ್ಯವನ್ನು ಪರಿಶೀಲಿಸಿ ಮತ್ತು ದರ каль್ಕುಲೇಟರ್ ಮೂಲಕ ವ್ಯತ್ಯಾಸವನ್ನು ಅಂದಾಜಿಸಿ. ಬಿಲಿಂಗ್ ಮಾಹಿತಿಗಳು వెంటనే ನವೀಕರಿಸುವುದಿಲ್ಲ ಎಂದು ನಿರೀಕ್ಷಿಸಬೇಡಿ.

**ಯಶಸ್ವಿ ಮಾಪಕಗಳು:** ಶೋಧ ಮೂಲಾಭಿವೃದ್ಧಿ ಬಳಸುತ್ತದೆ, ಚಾಟ್ ನಿಯೋಜನೆ ಬೇಡಿಕೆಯಾದ ಬೆಂಬಲಿತ ಸಾಮರ್ಥ್ಯವನ್ನು ಹೊಂದಿದೆ, ಮತ್ತು ಅಪ್ಲಿಕೇಶನ್ ಇನ್ನೂ ಉದಾಹರಣಾ ಪ್ರಶ್ನೆಗೆ ಉತ್ತರಿಸುತ್ತದೆ. ಸಾಮರ್ಥ್ಯ `10` ಒಂದು ದರ-ಮಿತಿಯ ಹಂಚಿಕೆ, ಟೋಕನ್ ಬೆಲೆ ರಿಯಾಯಿತಿ ಅಲ್ಲ. ಶೋಧ ತಳದ ಬದಲಾವಣೆಗಳು ನಿರ್ಬಂಧಿತಅಥವಾ ಮರುಸೃಷ್ಟಿಸುವ ಅಗತ್ಯವಿರಬಹುದು; ಉತ್ಪಾದನಾ ಸಂಪನ್ಮೂಲಗಳಲ್ಲಿ ಪ್ರಯೋಗ ಮಾಡಬೇಡಿ. F0 ಒಂದು ಸೇವಾ-ನಿರ್ಧಿಷ್ಟ SKU ಆಗಿದ್ದು ಅಝ್ಯೂರ್ OpenAI ಮಾದರಿ SKU ಅಲ್ಲ.

## ಘಟಕ 4: ಸುರಕ್ಷತೆ ಮತ್ತು ಉತ್ಪಾದನಾ ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು

### ಹಂತ 4.1: ಕ್ರೆಡೆನ್ಶಿಯಲ್ ನಿರ್ವಹಣೆಯನ್ನು ಸುರಕ್ಷಿತಗೊಳಿಸಿ

**ಪ್ರಸ್ತುತ ಚಾಲೆಂಜ್**: ಹಲವು AI ಅಪ್ಲಿಕೇಶನ್‌ಗಳು API ಕೀಲಿಗಳನ್ನು ಹಾರ್ಡ್‌ಕೋಡ್ ಮಾಡುತ್ತವೆ ಅಥವಾ ಅಸುರಕ್ಷಿತ ಸಂಗ್ರಹಣೆ ಬಳಸುತ್ತವೆ.

**AZD ಪರಿಹಾರ**: ನಿರ್ವಹಿತ ಐಡೆಂಟಿಟಿ + ಕೀ ವೈಲ್ಟ್ ಸಂಯೋಜನೆ.

1. **ನಿಮ್ಮ ಟೆಂಪ್ಲೇಟ್‌ನ ಸುರಕ್ಷತೆ ಸಂರಚನೆಯನ್ನು ಪರಿಶೀಲಿಸಿ:**
```bash
# Look for Key Vault and Managed Identity configuration
grep -r "keyVault\|managedIdentity" infra/
```

2. **ನಿರ್ವಹಿತ ಐಡೆಂಟಿಟಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ:**
```bash
# For the sample's default Container Apps host
az containerapp identity show --name YOUR_CONTAINER_APP_NAME --resource-group YOUR_RG
```

### ಹಂತ 4.2: ನೆಟ್ವರ್ಕ್ ಸುರಕ್ಷತೆ

1. **ನಿಜದ ಅಂತಿಮ ಬಿಂದುಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ** (ಹಿನ್ನೆಲೆ ಇತ್ತೀಚೆಗೆ ಸಂಯೋಜನೆಯಾದ ಹಾಗಿದ್ದರೆ).

ನಿಮ್ಮ ಸ್ವಂತ ಟೆಂಪ್ಲೇಟ್‌ಗೆ, ಈ ಚಿತ್ರಣ ಭಾಗವು OpenAI ಎಂಡ್‌ಪಾಯಿಂಟ್ ಸಂಪರ್ಕವನ್ನು ತೋರಿಸುತ್ತದೆ. ಇದಕ್ಕೆ VNet, ಖಾಸಗಿ DNS ಸಂರಚನೆ ಮತ್ತು ಅಪ್ಲಿಕೇಶನ್ ಸಂಪರ್ಕತೆಯೂ ಅಗತ್ಯ; ಅದನ್ನು ಇದೇ ರೀತಿಯಂತೆ ನಕಲಿಸಿ ಬಳಸದಿರಿ, ಇದು ಈಗಾಗಲೇ ಖಾಸಗಿ-ಎಂಡ್‌ಪಾಯಿಂಟ್ ಘಟಕಗಳನ್ನು ಹೊಂದಿದೆ:
```bicep
// Private endpoint for OpenAI
resource openAIPrivateEndpoint 'Microsoft.Network/privateEndpoints@2023-04-01' = {
  name: 'pe-openai-${uniqueString(resourceGroup().id)}'
  location: location
  properties: {
    subnet: {
      id: vnet.properties.subnets[0].id
    }
    privateLinkServiceConnections: [
      {
        name: 'openai-connection'
        properties: {
          privateLinkServiceId: openAIAccount.id
          groupIds: ['account']
        }
      }
    ]
  }
}
```

### ಹಂತ 4.3: ಮಾರ್ಗದರ್ಶನ ಮತ್ತು ಗಮನಿಸುವಿಕೆ

1. **ಅಪ್ಲಿಕೇಶನ್ ಇನ್ಸೈಟ್ಸ್ ಸಂರಚಿಸಿ:**

```bash
# Check the configuration:
```

2. **ನಮೂನೆಯ ಅಪ್ಲಿಕೇಶನ್ ಇನ್ಸೈಟ್ಸ್ ಸಂಯೋಜನೆಯನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ:**
```bash
azd env set AZURE_USE_APPLICATION_INSIGHTS true
azd up
azd monitor --overview
```

ನಮೂನೆಯ ಉಪಕರಣವು ಟೆಲಿಮೆಟ್ರಿಯನ್ನು ಹೊರಡಿಸುತ್ತದೆ; ಒಂದು ಅಲಂಕಾರಿಕ `OPENAI_MONITOR_ENABLED` ಸೆಟ್ಟಿಂಗ್ AI ಮೆಟ್ರಿಕ್ಸ್ ಸಕ್ರಿಯಗೊಳಿಸುವುದಿಲ್ಲ. ಮಾದರಿ ಕರೆಗಳು, ವಿಳಂಬ, ವಿಫಲತೆಗಳು ಮತ್ತು ಟೋಕನ್ ಬಳಕೆಯನ್ನು ಪರಿಶೀಲಿಸಿ ಮತ್ತು ಸಂವೇದಿ ಪ್ರಾಂಪ್ಟ್‌ಗಳು ಅಥವಾ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ದಾಖಲಿಸುವುದನ್ನು ತಪ್ಪಿಸಿ.

### **ಪ್ರಯೋಗಾಲಯ ಅಭ್ಯಾಸ 4.1: ಸುರಕ್ಷತಾ ಪರಿಶೀಲನೆ**

**ಕಾರ್ಯ**: ನಿಮ್ಮ ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್‌ನ ಸುರಕ್ಷತೆ ಉತ್ತಮ ಅಭ್ಯಾಸಗಳನ್ನು ಪರಿಶೀಲಿಸಿ.

**ಪರಿಶೀಲನಾ ಪಟ್ಟಿಕೆ:**
- [ ] ಕೋಡ್ ಅಥವಾ ಸಂರಚನೆಯಲ್ಲಿ ಯಾವುದೇ ಹಾರ್ಡ್‌ಕೋಡ್ ಮಾಡಿದ ರಹಸ್ಯಗಳಿಲ್ಲ
- [ ] ಸೇವೆ-ತೊ-ಸೇವೆ ಪ್ರಮಾಣಿೀಕರಣಕ್ಕಾಗಿ ನಿರ್ವಹಿತ ಐಡೆಂಟಿಟಿ ಬಳಕೆಯಾಗಿದೆ
- [ ] ಕೀ ವೈಲ್ಟ್ ಸಂವೇದಿ ಸಂರಚನೆಯನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ
- [ ] ನೆಟ್ವರ್ಕ್ ಪ್ರವೇಶವು ಸೂಕ್ತವಾಗಿ ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ
- [ ] ಮಾರ್ಗದರ್ಶನ ಮತ್ತು ಲಾಗಿಂಗ್ ಸಕ್ರಿಯಗೊಂಡಿದೆ

## ಘಟಕ 5: ನಿಮ್ಮ ಸ್ವಂತ AI ಅಪ್ಲಿಕೇಶನ್ ಪರಿವರ್ತನೆ

### ಹಂತ 5.1: ಮೌಲ್ಯಮಾಪನ ವರ್ಕ್‌ಷೀಟ್

**ನಿಮ್ಮ ಅಪ್ಲಿಕೇಶನ್ನುವನ್ನು ಪರಿವರ್ತಿಸುವ ಮೊದಲು, ಈ ಪ್ರಶ್ನೆಗಳಿಗೆ ಉತ್ತರಿಸಿ:**

1. **ಅಪ್ಲಿಕೇಶನ್ ವಾಸ್ತುಶಿಲ್ಪ:**
   - ನಿಮ್ಮ ಅಪ್ಲಿಕೇಶನ್ ಯಾವ AI ಸೇವೆಗಳನ್ನು ಬಳಸುತ್ತದೆ?

### ಹಂತ 5.2: ನಿಮ್ಮ AZD ಟೆಂಪ್ಲೇಟ್ ಸೃಷ್ಟಿಸುವುದು

**ನಿಮ್ಮ ಅಪ್ಲಿಕೇಶನ್ ಪರಿವರ್ತಿಸಲು ಈ ಮಾದರಿಯನ್ನು ಅನುಸರಿಸಿ:**

** scaffolding ಮಾತ್ರ:** ಈ ವಿಭಾಗವು API/ವೆಬ್ ಅಪ್ಲಿಕೇಶನ್ ಮೂಲ, ಹೋಸ್ಟ್ ಮೂಲಸೌಕರ್ಯ, ಮಾದರಿ ನಿಯುತಿಗಳು, ಗುರುತು/ಪರಿಚಯ RBAC, ಅಥವಾ ಪೂರ್ಣಗೊಂಡ `main.parameters.json` ಅನ್ನು ನೀಡುತ್ತಿಲ್ಲ. ರಿಸೋರ್ಸ್-ಗ್ರೂಪ್-ಸ್ಕೋಪ್ಡ್ ಬೈಸೆಪ್ ಗಣಕೋಚ್ಛದ ಸಂಯೋಜನೆಯನ್ನು ತೋರಿಸುತ್ತದೆ; ಸಾಮಾನ್ಯ AZD ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್-ಸ್ಕೋಪ್ಡ್ ಪ್ರವೇಶ ಬಿಂದು ರಿಸೋರ್ಸ್ ಗುಂಪನ್ನು ರಚಿಸಿ ಅದನ್ನು ಆ ಸ್ಕೋಪ್ ನಲ್ಲಿ ಕರೆದಿಡಬೇಕು. ಕೇವಲ ಈ ಭಾಗಗಳನ್ನು ನಕಲಿಸಿದ ನಂತರ `azd up` ಸಂಪೂರ್ಣ ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ನಿಯೋಜಿಸುವುದಾಗಿ ನಿರೀಕ್ಷಿಸಬೇಡಿ. ಚಾಲನೆಯಲ್ಲಿರುವ ಬೇಸ್‌ಲೈನ್ ಗಾಗಿ, ಮೋಡ್ಯೂಲ್ 1 ರಿಂದ RAG ಟೆಂಪ್ಲೇಟನ್ನು ಬಳಸುತ್ತಾ ಇರಿಸಿ.

1. **ಮೂಲ ರಚನೆಯನ್ನು ರಚಿಸಿ:**
```bash
mkdir my-ai-app-azd
cd my-ai-app-azd

# Initialize AZD template
azd init --template minimal .
```

2. **azure.yaml ರಚಿಸಿ:**
```yaml
# Metadata
name: my-ai-app
metadata:
  template: my-ai-app-template@0.0.1-beta

# Services definition
services:
  api:
    project: ./api
    host: containerapp
  web:
    project: ./web
    host: staticwebapp
    
# Hooks for custom deployment logic  
hooks:
  predeploy:
    shell: sh
    run: echo "Preparing AI models..."
```

3. **ಮೂಲಸೌಕರ್ಯ ಟೆಂಪ್ಲೇಟುಗಳನ್ನು ರಚಿಸಿ:**

**infra/main.bicep** - ಮುಖ್ಯ ಟೆಂಪ್ಲೇಟು:
```bicep
@description('Primary location for all resources')
param location string = resourceGroup().location

@description('Name of the OpenAI service')
param openAIServiceName string = 'openai-${uniqueString(resourceGroup().id)}'

// Your AI services here
module openAI 'modules/openai.bicep' = {
  name: 'openai'
  params: {
    name: openAIServiceName
    location: location
  }
}
```

**infra/modules/openai.bicep** - OpenAI ಮೋಡ್ಯೂಲ್:
```bicep
@description('Name of the OpenAI service')
param name string

@description('Location for the OpenAI service')
param location string

resource openAIAccount 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: name
  location: location
  kind: 'OpenAI'
  sku: {
    name: 'S0'
  }
  properties: {
    customSubDomainName: name
    disableLocalAuth: true
  }
}

output endpoint string = openAIAccount.properties.endpoint
output name string = openAIAccount.name
```

**ಸವಾಲು**: ಡಾಕ್ಯುಮೆಂಟ್ ಪ್ರೊಸೆಸಿಂಗ್ AI ಅಪ್ಲಿಕೇಶನ್ ಗಾಗಿ AZD ಟೆಂಪ್ಲೇಟು ರಚಿಸಿ.

```bash
# Failed-request count on the Application Insights component (not a percentage)
```

### **ಪ್ರಯೋಗಾಲಯ ವ್ಯಾಯಾಮ 7.1: ಕಾರ್ಯಕ್ಷಮತೆಯ ಸುಧಾರಣೆ**

- 99.9% ಲಭ್ಯತೆ SLO ಮತ್ತು ಅಳೆಯುವ ವಿಂಡೋಸ್ಥಳವನ್ನು ನಿಗದಿಪಡಿಸು (ಚಿಕ್ಕ ಪ್ರಯೋಗಾಲಯವು ಮಾಸಿಕ ಅಪ್ಟೈಮ್ ಪ್ರದರ್ಶಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ)

**ಪ್ರಯತ್ನಿಸಲು ತಂತ್ರಗಳು:**
- ಪ್ರತಿಕ್ರಿಯಾ ಕ್ಯಾಶಿಂಗ್ ಜಾರಿಗೊಳಿಸು
- ಟೋಕನ್ ಸಾಮರ್ಥ್ಯಕ್ಕಾಗಿ ಪ್ರಾಂಪ್ಟ್‌ಗಳನ್ನು ಸುಧಾರಿಸು
- ಸೂಕ್ತ ಗಣನೆ SKUಗಳನ್ನು ಬಳಕೆಮಾಡು
- ಸರಿಯಾದ ಸ್ವಯಂಸ್ಕೇಲಿಂಗ್ ವ್ಯವಸ್ಥೆಯನ್ನು ಹೊಂದಿಸು

## ಅಂತಿಮ ಟಾಸ್ಕ್: ಪೂರ್ಣ-ಕೈಗಾರಿಕೆ ಜಾರಿಗೊಳಿಸುವಿಕೆ

### ಸವಾಲು ದೃಶ್ಯಪಟ

ಇದು **ಐಚ್ಛಿಕ ವಾಸ್ತುಶಿಲ್ಪ/ರೋಚಕತೆ ಸವಾಲು**, ಒದಗಿಸಲಾದ ಚಲಿಸುವ ವ್ಯಾಯಾಮ ಅಥವಾ ಉತ್ಪಾದನಾ ಪ್ರಮಾಣಪತ್ರವಾಗಿಲ್ಲ. AI-ಚಾಲಿತ ಗ್ರಾಹಕ ಸೇವೆ ಚಾಟ್‌ಬಾಟ್ ಅನ್ನು ಪ್ರಸ್ತಾಪಿಸಿ ಹಾಗೂ ಯಾವ ಅವಶ್ಯಕತೆಗಳಿಗೆ ಮುಂದಿನ ಜಾರಿಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಪುರಾವೆಗಳ ಅಗತ್ಯವಿದೆ ಎಂಬುದನ್ನು ದಾಖಲಿಸು:

**ಕಾರ್ಯಾಚರಣೆ ಅಗತ್ಯಗಳು:**
- ಗ್ರಾಹಕರ ಸಂವಹನಕ್ಕಾಗಿ ವೆಬ್ ಇಂಟರ್ಫೇಸ್
- Microsoft Foundry ಮಾದರಿಗಳಿಂದ ಪ್ರತ್ಯುತ್ತರಗಳ ಸಂಯೋಜನೆ
- Azure AI ಹುಡುಕಾಟ ಬಳಸಿ ದಸ್ತಾವೇಜು ಹುಡುಕಾಟ ಸಾಮರ್ಥ್ಯ
- বিদ্যমান ಗ್ರಾಹಕ ಡೇಟಾಬೇಸ್ ಸಹಿತ ಸಂಯೋಜನೆ
- ಬಹುಭಾಷಾ ಬೆಂಬಲ

**ಅಕಾರ್ಯಾಚರಣೆ ಅಗತ್ಯಗಳು:**
- 1000 ಒಂದೇ ವೇಳೆ ಬಳಕೆದಾರರನ್ನು ನಿರ್ವಹಿಸು
- 99.9% ಅಪ್ಟೈಮ್ SLA
- SOC 2 ಅನುಕೂಲತೆ
- $500/ತಿಂಗಳು ಒಳಗೆ ವೆಚ್ಚ
- ವಿವಿಧ ಪರಿಸರಗಳಿಗೆ ನಿಯೋಜನೆ (ಅಭಿವೃದ್ಧಿ, ಸ್ಟೇಜಿಂಗ್, ಉತ್ಪಾದನೆ)

ಇವು ಊಹಿಸಿದ ಭಾಗಧಾರಿಗಳ ನಿರ್ಬಂಧಗಳು, ಒಂದೇ ಸಮಯದಲ್ಲಿ ಖಚಿತಗೊಳ್ಳುವ ಫಲಿತಾಂಶಗಳಲ್ಲ. ವಿನಂತಿ ದರ, ಪ್ರಾಂಪ್ಟ್/ಔಟ್‌ಪುಟ್ ಗಾತ್ರಗಳು, ಮತ್ತು ಸೆಷನ್ ಅವಧಿಯನ್ನು ವ್ಯಯ ಅಂದಾಜಿಸುವ ಮೊದಲು ವ್ಯಾಖ್ಯಾನಿಸು; 1000 ಒಂದೇ ವೇಳೆ ಬಳಕೆದಾರರು ಕಾರ್ಯಭಾರ ಅಥವಾ $500 ಬಜೆಟ್ ಸಾಧ್ಯತೆ ನಡೆಸುವುದಿಲ್ಲ. SOC 2 ಸಂಸ್ಥೆಯ ಪರಿಶೀಲನಾ ಫಲಿತಾಂಶ, AZD ಟೆಂಪ್ಲೇಟಿಂದ ಸಕ್ರಿಯಗೊಳ್ಳುವ ಸ್ವಿಚ್ ಅಲ್ಲ. Lieber ತನಿಖೆಮಾಡಿ ಮತ್ತು ಸಾಧ್ಯವಿಲ್ಲದ ನಿರ್ಬಂಧಗಳನ್ನು ಪುರಾವೆಯೊಂದಿಗೆ ತಿದ್ದಿ.

### ಜಾರಿಗೆ ಹಾಕುವ ಹಂತಗಳು

1. **ವಾಸ್ತುಶಿಲ್ಪವನ್ನು ವಿನ್ಯಾಸಗೊಳಿಸು**
2. **AZD ಟೆಂಪ್ಲೇಟನ್ನು ರಚಿಸು**
3. **ಭದ್ರತಾ ಮಾರ್ಗಸೂಚಿಗಳನ್ನು ಜಾರಿಗೊಳಿಸು**
4. **ಮಾನಿಟರಿಂಗ್ ಮತ್ತು ಎಚ್ಚರಿಕೆಗಳನ್ನು ಹೊಂದಿಸು**
5. **ನಿಯೋಜನೆ ಪೈಪ್ಲೈನ್‌ಗಳನ್ನು ರಚಿಸು**
6. **ಉತ್ತರದ ಆವೃತ್ತಿಯನ್ನು ದಾಖಲು ಮಾಡು**

### ಮೌಲ್ಯಮಾಪನ ಮಾನದಂಡಗಳು

- ✅ **ಕಾರ್ಯಗತತೆ**: ಜಾರಿಗೊಳಿಸಲಾದ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಪ್ರದರ್ಶಿಸಲಾಗಿದೆ ಮತ್ತು ಉಳಿದಿರುವ ತುಮುಲ್‌ಗಳ ಬಗ್ಗೆ ಸ್ಪಷ್ಟವಾಗಿದೆ?
- ✅ **ಭದ್ರತೆ**: ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು ಜಾರಿಗೊಳಿಸಲ್ಪಟ್ಟವೆಯೇ?
- ✅ **ಸ್ಕೇಲೆಬಿಲಿಟಿ**: ಭಾರವನ್ನು ನಿಭಾಯಿಸಲು ಸಮರ್ಥವೇ?
- ✅ **ಅಳೆಯುವಿಕೆ**: ಕೋಡ್ ಮತ್ತು ಮೂಲಸೌಕರ್ಯ ಚರಿತ್ರೆಯಲ್ಲೇ ಸುಸಂಬಂಧಿತವಾಗಿದೆಯೇ?
- ✅ **ವೆಚ್ಚ**: ಬಜೆಟ್ ಒಳಗೆ ಇರುತ್ತದೆ?
