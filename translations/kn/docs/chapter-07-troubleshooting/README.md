# ಅಧ್ಯಾಯ 7: ಸಮಸ್ಯೆ ಪರಿಹಾರ ಮತ್ತು ದೋಷನಿರೋಧನ

**📚 ಕೋರ್ಸ್**: [ಆಜಡ್ ಕಡತಗಾರರಿಗೆ](../../README.md) | **⏱️ ಅವಧಿ**: 1-1.5 ಗಂಟೆಗಳು | **⭐ ಜಟಿಲತೆ**: ಮಧ್ಯಂತರ

## ಅವಲೋಕನ

ಈ ಅಧ್ಯಾಯವು ನೀವು Azure Developer CLI ಜೊತೆ ಕೆಲಸ ಮಾಡುವಾಗ ಉಂಟಾಗುವ ಸಾಮಾನ್ಯ ಸಮಸ್ಯೆಗಳನ್ನು ಪತ್ತೆ ಹಚ್ಚಿ ಪರಿಹರಿಸುಗೆ ಸಹಾಯ ಮಾಡುತ್ತದೆ. ನಿಯೋಜನೆ ವೈಫಲ್ಯಗಳಿಂದ AI-ನ ಉದ್ದೇಶಿತ ಸಮಸ್ಯೆಗಳವರೆಗೆ.

> ಬಿಡುಗಡೆಗೊಳ್ಳಲಾದ `azd 1.37.2` ರೆಫರೆನ್ಸ್ ವಿರುದ್ಧ ಪರಿಶೀಲಿಸಲಾದ கட்டளை ಮಾರ್ಗದರ್ಶನ. ಕ್ಲೌಡ್ ನಿಯೋಜನೆಗಳು ಕಾರ್ಯಗತಗೊಳ್ಳಿರಲಿಲ್ಲ. கட்டளைಗಳನ್ನು ಬಳಸುವುದಕ್ಕೆ ಮುಂಚೆ ಉದಾಹರಣೆಯ ಸಂಪನ್ಮೂಲ ಹೆಸರುಗಳು ಮತ್ತು ID ಗಳನ್ನು ಬದಲಾಯಿಸಿ.

## ಅಭ್ಯಾಸ ಗುರಿಗಳು

ಈ ಅಧ್ಯಾಯವನ್ನು ಪೂರೈಸುವ ಮೂಲಕ, ನೀವು:
- ಸಾಮಾನ್ಯ ಆಜಡ್ ನಿಯೋಜನೆ ವೈಫಲ್ಯಗಳನ್ನು ಪತ್ತೆ ಹಚ್ಚುವುದು
- ಪ್ರಾಮಾಣೀಕರಣ ಮತ್ತು ಅನುಮತಿ ಸಮಸ್ಯೆಗಳನ್ನು ದೋಷನಿರೋಧಿಸಲು
- AI ಸೇವೆ ಸಂಪರ್ಕ ಸಮಸ್ಯೆಗಳನ್ನು ಪರಿಹರಿಸಲು
- ಸಮಸ್ಯೆ ಪರಿಹಾರಕ್ಕಾಗಿ ಆಜುರ್ ಪೋರ್ಟ್‌ಲ್ ಮತ್ತು CLI ಉಪಯೋಗಿಸಲು

## 🚨 ತ್ವರಿತ ಪರಿಹಾರಗಳು

### ಪ್ರಾಮಾಣೀಕರಣ ಸಮಸ್ಯೆಗಳು
```bash
# Required for AZD workflows
azd auth login

# Optional if you are also using Azure CLI commands directly
az login

azd auth login --check-status
```

### ನಿಯೋಜನೆ ವೈಫಲ್ಯಗಳು
```bash
azd show
azd monitor --logs
az deployment sub list --query "[?properties.provisioningState!='Succeeded']"
```

### ಸಂಪನ್ಮೂಲ ಘರ್ಷಣೆಗಳು
ಇದ್ದು ಇರುವ ಸಂಪನ್ಮೂಲ ಮತ್ತು ನಿಯೋಜನೆ ದೋಷಗಳನ್ನು ಮೊದಲು ಪರಿಶೀಲಿಸಿ. ಹೆಸರಿನ ಘರ್ಷಣೆಯನ್ನು ಪರಿಹರಿಸಲು ಹಂಚಿಕೆಯ ಅಥವಾ ಉತ್ಪಾದನಾ ಪರಿಸರವನ್ನು ಅಳಿಸಬೇಡಿ. **ಹೊಸ ಉಪಯೋಗಿಸಬಹುದಾದ ಪರಿಸರ**ಗಾಗಿ ಏಕೈಕ ಹೆಸರನ್ನು ಬಳಸಿ:

```bash
azd env new different-name
azd up
```

### ಕೋಟಾ ಮೀರಿದೆ
```bash
az vm list-usage --location eastus --output table
# Check the affected service's own quotas, not just VM quotas.
# For a new environment only, choose a supported region with available quota.
```

`AZURE_LOCATION` ಬದಲಾವಣೆ ಆಗುವುದರಿಂದ ಈಗಿರುವ ಸಂಪನ್ಮೂಲಗಳು ಸ್ಥಳಾಂತರವಾಗುವುದಿಲ್ಲ ಮತ್ತು ಪುನರುತ್ಪಾದನೆಯಾದಾಗ ಸ್ಥಳದ ಘರ್ಷಣೆಗಳು ಉಂಟಾಗಬಹುದು.

## 📋 ದೋಷ ಕೋಡ್ ರೆಫರೆನ್ಸ್

| ದೋಷ | ಕಾರಣ | ಪರಿಹಾರ |
|-------|-------|----------|
| `AuthenticationError` | ಲಾಗಿನ್ ಆಗಿಲ್ಲ | `azd auth login` |
| `ResourceNotFound` | ಸಂಪನ್ಮೂಲ ಇಲ್ಲ | ಸಂಪನ್ಮೂಲ ಹೆಸರನ್ನು ಪರಿಶೀಲಿಸಿ |
| `QuotaExceeded` | ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಮಿತಿ ಮೀರಿ | ಕೋಟಾ ಹೆಚ್ಚಳವನ್ನು ವಿನಂತಿಸಿ |
| `InvalidTemplate` | ಬೈಸಿಪ್ ವ್ಯಾಕರಣ ದೋಷ | `az bicep build` |
| `Conflict` | ಸಂಪನ್ಮೂಲ ಅಸ್ತಿತ್ವವಿದೆ | ಹೊಸ ಹೆಸರನ್ನು ಬಳಸಿ ಅಥವಾ ಅಳಿಸಿ |
| `Forbidden` | ಸರಿಯಾದ ಅನುಮತಿಗಳು ಇಲ್ಲ | RBAC ಪಾತ್ರಗಳನ್ನು ಪರಿಶೀಲಿಸಿ |

## 🔄 ಮರುಹೊಂದಿಕೆ ಮತ್ತು ಪುನಃಪಡೆಯಿಕೆ

```bash
# Soft reset (keep resources, redeploy code)
azd deploy

# Hard reset (delete everything, start fresh)
azd down
azd up
```

ಕಠಿಣ ಮರುಹೊಂದಿಕೆ ಡೇಟಾವನ್ನು ಅಳಿಸುತ್ತದೆ ಮತ್ತು ಸಂತಾನದಸ್ಥಾನಗಳನ್ನು ಬದಲಾಯಿಸಬಹುದು. ಮೊದಲು ಬ್ಯಾಕಪ್ ಮಾಡಿ ಮತ್ತು ಪರಸ್ಪರ ಕ್ರಿಯಾಶೀಲ ಅಳಿಸುವ ತಿರುವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. `--force --purge` ಮಾರೂ ಉಪಯೋಗಿಸಬಹುದಾದ ಪರಿಸರಗಳಿಗಷ್ಟೇ ಯೋಗ್ಯವಾಗಿದೆ, ಅಸ್ಥಾಯಿಯಾಗಿ ಅಳಿಸುವ ಉದ್ದೇಶವಿದ್ದಾಗ.
