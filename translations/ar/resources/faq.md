## البدء

### س: ما هو Azure Developer CLI (azd)؟
**ج**: Azure Developer CLI (azd) هي أداة سطر أوامر تركز على المطور تسّرع الوقت اللازم لنقل تطبيقك من بيئة التطوير المحلية إلى Azure. توفر أفضل الممارسات من خلال القوالب وتساعد في دورة حياة النشر بأكملها.

### س: كيف يختلف azd عن Azure CLI؟
**ج**: 
- **Azure CLI**: أداة عامة لإدارة موارد Azure
- **azd**: أداة تركز على المطورين لسير عمل نشر التطبيقات
- لدى azd سير عمل خاص بالمصادقة والنشر؛ Azure CLI أداة منفصلة ومتممة
- يتضمن azd قوالب، إدارة بيئات، وأتمتة النشر

### س: هل أحتاج إلى تثبيت Azure CLI لاستخدام azd؟
**ج**: ليس لسير عمل AZD الرئيسي. قم بالمصادقة باستخدام `azd auth login`. ثبّت Azure CLI بشكل منفصل عندما يشغّل قالب معين أو تمرين أوامر `az` صراحة.

### س: ما هي لغات البرمجة التي يدعمها azd؟
**ج**: azd مستقل عن اللغة. يعمل مع:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- مواقع ثابتة
- تطبيقات محملة بالحاويات

### س: هل يمكنني استخدام azd مع مشاريع موجودة؟
**ج**: نعم! يمكنك إما:
1. استخدام `azd init` لإضافة تكوين azd إلى المشاريع الموجودة
2. تعديل المشاريع الموجودة لتتوافق مع هيكل قالب azd
3. إنشاء قوالب مخصصة استنادًا إلى هندستك القائمة

## المصادقة والوصول

### س: كيف أقوم بالمصادقة مع Azure باستخدام azd؟
**ج**: استخدم `azd auth login` الذي سيفتح نافذة متصفح للمصادقة على Azure. في سيناريوهات CI/CD، استخدم principals الخدمة أو الهويات المدارّة.

### س: هل يمكنني استخدام azd مع اشتراكات Azure متعددة؟
**ج**: نعم. استخدم `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` لتحديد الاشتراك المستخدم لكل بيئة.

### س: ما الأذونات التي أحتاجها للنشر باستخدام azd؟
**ج**: عادة تحتاج:
- دور **مساهم** على مجموعة الموارد أو الاشتراك
- دور **مسؤول وصول المستخدم** إذا كنت تنشر موارد تتطلب تعيين أدوار
- تختلف الأذونات المحددة حسب القالب والموارد التي يتم نشرها

### س: هل يمكنني استخدام azd في أنابيب CI/CD؟
**ج**: بالتأكيد! صُمم azd لدمج CI/CD. استخدم principals الخدمة للمصادقة واضبط متغيرات البيئة للتكوين.

### س: كيف أتعامل مع المصادقة في GitHub Actions؟
**ج**: يفضل اتحاد هوية عبء العمل (OIDC)، مُكوّن بـ `azd pipeline config`. يقوم سير العمل المُنشأ بتثبيت AZD ومصادقته مباشرة بهوية موحدة. خطوت `azure/login` بمفردها لا تنشئ تسجيل دخول AZD. خطوة تسجيل الدخول داخل وظيفة موجودة هي:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

قم بالتمهيد أو النشر بعد تسجيل الدخول، مع تكوين البيئة والاشتراك والموقع المرغوب لـ AZD. يجب أن تثق بيانات اعتماد الهوية الموحدة بالمستودع/المرجع أو بيئة GitHub، ويجب أن تسمح أدوار Azure بالعمليات المطلوبة.

## القوالب والمشاريع

### س: أين أجد قوالب azd؟
**ج**: 
- القوالب الرسمية والمجتمعية: [Awesome AZD](https://azure.github.io/awesome-azd/)
- القوالب المجتمعية: بحث GitHub عن "azd-template"
- استخدم `azd template list` لتصفح القوالب المتاحة

### س: كيف أنشئ قالبًا مخصصًا؟
**ج**: 
1. ابدأ من هيكل قالب موجود
2. عدل `azure.yaml` وملفات البنية التحتية، وكود التطبيق
3. اختبر جيدًا باستخدام `azd up`
4. انشره على GitHub مع الوسوم المناسبة

### س: هل يمكنني استخدام azd بدون قالب؟
**ج**: نعم، استخدم `azd init` في مشروع قائم لإنشاء ملفات التكوين اللازمة. ستحتاج لتكوين `azure.yaml` وملفات البنية التحتية يدويًا.

### س: ما الفرق بين القوالب الرسمية وقوالب المجتمع؟
**ج**: 
- **القوالب الرسمية**: صيانة من مايكروسوفت، تحديثات منتظمة، توثيق شامل
- **قوالب المجتمع**: أنشأها مطورون، قد تحتوي على حالات استخدام متخصصة، جودة وصيانة متفاوتة

### س: كيف أقوم بتحديث قالب في مشروعي؟
**ج**: لا يتم تحديث القوالب تلقائيًا. يمكنك:
1. المقارنة والدمج اليدوي للتغييرات من القالب الأصلي
2. البدء من جديد باستخدام `azd init` مع القالب المُحدّث
3. انتقاء وتحليل تحسينات محددة من القوالب المُحدّثة

## النشر والبنية التحتية

### س: ما خدمات Azure التي يمكن لـ azd نشرها؟
**ج**: azd يمكنه نشر أي خدمة Azure عبر قوالب Bicep/ARM، بما في ذلك:
- خدمات التطبيقات، تطبيقات الحاويات، الوظائف
- قواعد البيانات (SQL، PostgreSQL، Cosmos DB)
- التخزين، مفتاح الأمان، Application Insights
- الشبكات، الأمان، وموارد المراقبة

### س: هل يمكنني النشر إلى مناطق متعددة؟
**ج**: نعم، قم بتكوين مناطق متعددة في قوالب Bicep الخاصة بك وعيّن معلمة الموقع بشكل مناسب لكل بيئة.

### س: كيف أتعامل مع ترحيل مخطط قاعدة البيانات؟
**ج**: استخدم الخطافات النشرية في `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### س: هل يمكنني نشر البنية التحتية فقط بدون التطبيقات؟
**ج**: نعم، استخدم `azd provision` لنشر مكونات البنية التحتية فقط المحددة في القوالب الخاصة بك.

### س: كيف أنشر إلى موارد Azure قائمة؟
**ج**: نعم، عندما يدعم القالب ذلك. أشر إلى الموارد القائمة باستخدام إعلانات `existing` في Bicep أو معلمات الموارد القائمة الموثقة في القالب، واربط خدمات التطبيق بأهدافها المقصودة. هذا لا يستورد الملكية أو ينشئ أذونات مفقودة تلقائيًا. راجع القالب قبل النشر.

### س: هل يمكنني استخدام Terraform بدلاً من Bicep؟
**ج**: نعم. يدعم AZD كل من Terraform و Bicep. اختر قالبًا يعتمد على Terraform أو قم بتكوين `infra.provider: terraform` في `azure.yaml`، مع ملفات Terraform المناسبة وتكوين الحالة/الخلفية. انظر [سير عمل Terraform](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## التكوين والبيئات

### س: كيف أدير بيئات مختلفة (تطوير، اختبار، إنتاج)؟
**ج**: أنشئ بيئات منفصلة باستخدام `azd env new <environment-name>` وقم بتكوين إعدادات مختلفة لكل منها:
```bash
azd env new development
azd env new staging  
azd env new production
```

### س: أين يتم تخزين تكوينات البيئة؟
**ج**: في مجلد `.azure` ضمن دليل مشروعك. لكل بيئة مجلد خاص مع ملفات التكوين.

### س: كيف أعيّن تكوين خاص ببيئة؟
**ج**: استخدم `azd env set` لتكوين متغيرات البيئة:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### س: هل يمكنني مشاركة تكوينات البيئة بين أعضاء الفريق؟
**ج**: يحتوي مجلد `.azure` على معلومات حساسة ويجب ألا يُلتزم في نظام التحكم في الإصدار. عوضًا عن ذلك:
1. وثّق متغيرات البيئة المطلوبة
2. استخدم نصوص النشر لإعداد البيئات
3. استخدم Azure Key Vault للتكوين الحساس

### س: كيف أتجاوز إعدادات القالب الافتراضية؟
**ج**: عيّن متغيرات البيئة التي تتوافق مع معلمات القالب:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

فقط المتغيرات التي يستهلكها القالب تؤثر على النشر. `SKU_NAME` أعلاه مثال على مدخل مخصص، وليس إعداد AZD عالميًا.

## استكشاف الأخطاء وإصلاحها

### س: لماذا يفشل `azd up`؟
**ج**: الأسباب الشائعة:
1. **مشكلات المصادقة**: شغّل `azd auth login`
2. **أذونات غير كافية**: تحقق من تعيينات الدور في Azure الخاصة بك
3. **تعارضات تسمية الموارد**: راجع المورد المتعارض ومدخلات التسمية في القالب؛ أنشئ بيئة منفصلة باستخدام `azd env new` عندما تكون العزلة مطلوبة
4. **مشكلات الحصة/السعة**: تحقق من التوافر الإقليمي
5. **أخطاء القالب**: تحقق من صحة قوالب Bicep

### س: كيف أصحح إخفاقات النشر؟
**ج**: 
1. استخدم `azd deploy --debug` لإخراج مفصل
2. تحقق من سجل النشر في بوابة Azure
3. راجع سجل النشاط في بوابة Azure
4. استخدم `azd show` لعرض حالة البيئة الحالية

### س: لماذا لا تعمل متغيرات البيئة الخاصة بي؟
**ج**: تحقق من:
1. تطابق أسماء المتغيرات مع معلمات القالب تمامًا
2. تقديم القيم بشكل صحيح إذا احتوت على فراغات
3. تم اختيار البيئة: `azd env select <environment>`
4. تعيين المتغيرات في البيئة الصحيحة

### س: كيف أنظف عمليات النشر الفاشلة؟
**ج**: 
```bash
azd down
```
راجع البيئة المختارة وتأكيد الحذف أولاً. هذا يحذف موارد Azure المقدمة، وليس تكوين البيئة المحلي `.azure`. `--purge` يطلب أيضًا الحذف الدائم للموارد المحذوفة ناعمًا المدعومة وقد يتم حظره بواسطة حماية الاحتفاظ/التطهير؛ هذه ليست خطوة استعادة روتينية.

### س: لماذا لا يمكن الوصول إلى تطبيقي بعد النشر؟
**ج**: تحقق من:
1. اكتمال النشر بنجاح
2. تشغيل التطبيق (تحقق من السجلات في بوابة Azure)
3. السماح بحركة المرور في مجموعات الأمان الشبكية
4. تكوين DNS/النطاقات المخصصة بشكل صحيح

## التكلفة والفوترة

### س: كم ستكلف نشرات azd؟
**ج**: تعتمد التكاليف على:
- خدمات Azure التي تم نشرها
- مستويات الخدمة/رموز المنتج المختارة
- الفروقات السعرية الإقليمية
- أنماط الاستخدام

استخدم [حاسبة أسعار Azure](https://azure.microsoft.com/pricing/calculator/) للتقديرات.

### س: كيف أتحكم في التكاليف في نشرات azd؟
**ج**: 
1. استخدم مستويات أدنى للبيئات التطويرية
2. إعداد ميزانيات وتنبيهات Azure
3. استخدم `azd down` لإزالة الموارد عندما لا تكون مطلوبة
4. اختر المناطق المناسبة (تختلف التكاليف حسب الموقع)
5. استخدم أدوات إدارة تكلفة Azure

### س: هل توجد خيارات مجانية لقوالب azd؟
**ج**: بعض الخدمات لها رموز SKU مجانية أو منح شهرية، حسب الأهلية، وخطة الاستضافة، والمنطقة، وحدود الاشتراك. هذه لا تجعل القالب بأكمله مجانيًا: قواعد البيانات، البحث، الشبكات، السجل، التليمتري، واستدلال النماذج قد تفرض رسومًا مستقلة. تحقق من [قائمة خدمات Azure المجانية](https://azure.microsoft.com/free/) والأسعار الحالية لكل مورد قبل النشر.

### س: كيف أقدر التكاليف قبل النشر؟
**ج**: 
1. راجع `main.bicep` للقالب لمعرفة الموارد التي يُنشئها
2. استخدم حاسبة أسعار Azure مع رموز SKU محددة
3. انشر أولًا إلى بيئة تطوير لمراقبة التكاليف الفعلية
4. استخدم إدارة تكلفة Azure لتحليل تفصيلي للتكاليف

## أفضل الممارسات

### س: ما هي أفضل ممارسات هيكل مشروع azd؟
**ج**: 
1. احتفظ بكود التطبيق منفصلًا عن البنية التحتية
2. استخدم أسماء خدمات واضحة في `azure.yaml`
3. نفذ معالجة أخطاء مناسبة في نصوص البناء
4. استخدم تكوين خاص بكل بيئة
5. تضمّن توثيقًا شاملاً

### س: كيف أنظم خدمات متعددة في azd؟
**ج**: استخدم الهيكل الموصى به:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### س: هل يجب عليّ الالتزام بمجلد `.azure` في نظام التحكم بالإصدار؟
**ج**: **لا!** يحتوي مجلد `.azure` على معلومات حساسة. أضفه إلى `.gitignore`:
```gitignore
.azure/
```

### س: كيف أتعامل مع الأسرار وتهيئة الإعدادات الحساسة؟
**ج**: 
1. استخدم Azure Key Vault للأسرار
2. ارجع إلى أسرار Key Vault في إعدادات التطبيق
3. لا تقم أبداً بارتكاب الأسرار في نظام التحكم في النسخ
4. استخدم الهويات المُدارة للمصادقة بين الخدمات

### س: ما هو النهج الموصى به لـ CI/CD مع azd؟
**ج**: 
1. استخدم بيئات منفصلة لكل مرحلة (تطوير/اختبار/إنتاج)
2. نفذ اختبارات مؤتمتة قبل النشر
3. استخدم حسابات الخدمة للمصادقة
4. خزّن الإعدادات الحساسة في أسرار/متغيرات خطوط الأنابيب
5. نفذ بوابات الموافقة لنشر الإنتاج

## مواضيع متقدمة

### س: هل يمكنني توسيع azd بوظائف مخصصة؟
**ج**: نعم، من خلال خطوط نشر في `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### س: كيف أدمج azd مع عمليات DevOps القائمة؟
**ج**: 
1. استخدم أوامر azd في سكريبتات خطوط الأنابيب الحالية
2. اعتمد قوالب azd موحدة عبر الفرق
3. دمج مع المراقبة والتنبيهات الحالية
4. استخدم مخرجات JSON الخاصة بـ azd لدمج الخطوط

### س: هل يمكنني استخدام azd مع Azure DevOps؟
**ج**: نعم، يعمل azd مع أي نظام CI/CD. أنشئ خطوط أنابيب Azure DevOps التي تستخدم أوامر azd.

### س: كيف أساهم في azd أو أنشئ قوالب مجتمعية؟
**ج**: 
1. **أداة azd**: ساهم في [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **القوالب**: اتبع [تعليمات مساهمة معرض Awesome AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **الوثائق**: ساهم في الوثائق في [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### س: ما هي خارطة الطريق لـ azd؟
**ج**: راجع [خارطة الطريق الرسمية](https://github.com/Azure/azure-dev/projects) للميزات والتحسينات المخططة.

### س: كيف أهاجر من أدوات نشر أخرى إلى azd؟
**ج**: 
1. حلل بنية النشر الحالية
2. أنشئ قوالب Bicep المعادلة
3. إعداد `azure.yaml` لمطابقة الخدمات الحالية
4. اختبر بشكل شامل في بيئة التطوير
5. هاجر البيئات تدريجياً
