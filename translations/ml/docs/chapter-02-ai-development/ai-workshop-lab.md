## മോഡ്യൂൾ 1: AI അപ്ലിക്കേഷനുകൾക്കുള്ള AZD ഘടന മനസ്സിലാക്കൽ

### AI AZD ടെംപ്ലേറ്റിന്റെ ഘടന

AI ഒരുക്കിയ AZD ടെംപ്ലേറ്റിലെ പ്രധാന ഫയലുകൾ പരിശോധിക്കുക:

```
azure-search-openai-demo/
├── azure.yaml              # AZD configuration
├── infra/                   # Infrastructure as Code
│   ├── main.bicep          # Main infrastructure template
│   ├── main.parameters.json # Environment parameters
│   ├── core/               # Shared infrastructure modules
│   └── app/                # Application-specific infrastructure
├── app/                    # Backend, frontend, and optional ingestion functions
├── scripts/               # Deployment scripts
└── .azure/               # AZD environment files
```

ചെക്ക്ഔട്ട് ചെയ്ത സാമ്പിൾ മാറാം; `.azure/` പരിസ്ഥിതി ആദ്യം തുടങ്ങുമ്പോൾ കാണാം, ശുദ്ധമായ ക്ലോൺ ല്‍ മാത്രമല്ല. ഈ സ്കെമാറ്റിക്ക് അനുയോജ്യമായ പ്രവർത്തനങ്ങൾക്കായി അസ്ഥിതിക്കുള്ള ഡയറക്ടറികൾ നിർമ്മിക്കുന്നതിനു പകരം യഥാർത്ഥ ചെക്ക്ഔട്ട് പരിശോധിക്കുക.

### **ലാബ് വ്യായാമം 1.1: കോൺഫിഗറേഷൻ പരിശോധിക്കുക**

1. **azure.yaml ഫയൽ പരിശോധിക്കുക:**
```bash
cat azure.yaml
```

**പറയേണ്ടത്:**
- AI ഘടകങ്ങൾക്ക് സേവന നിർവചനങ്ങൾ
- പരിസ്ഥിതി വേരിയബിൾ മാപ്പിംഗുകൾ
- ഹോസ്റ്റ് കോൺഫിഗറേഷനുകൾ

2. **main.bicep ഇൻഫ്രാസ്ട്രക്ചർ അവലോകനം ചെയ്യുക:**
```bash
cat infra/main.bicep
```

**സൂക്ഷ്മമായി കാണേണ്ട AI പാറ്റർണുകൾ:**
- Microsoft Foundry Models സേവന പ്രോവിഷനിംഗ്
- അസ്യൂർ AI സേർച്ച് ഇന്റഗ്രേഷൻ
- സെക്യൂർ കീ മാനേജ്മെന്റ്
- നെറ്റ്വർക്ക് സെക്യൂരിറ്റി കോൺഫിഗറേഷൻ

### **ചർച്ചാ വിഷയം:** AI-ക്കുള്ള ഇവ പ്രസക്തമായ പാറ്റർണുകൾ

- **സേവന ആശ്രിതത്വങ്ങൾ**: AI അപ്ലിക്കേഷനുകൾ പല സേവനങ്ങളും ഏകോപിപ്പിച്ചുവേണ്ടതുള്ളത്
- **സുരക്ഷ**: API കീകളും എൻഡ്പോയിന്റുകളും സുരക്ഷിതമായി കൈകാര്യം ചെയ്യണം
- **സ്കേലബിലിറ്റി**: AI പ്രവൃത്തി ഭാരം പ്രത്യേക സ്കേലിംഗ് ആവശ്യങ്ങൾ ഉണ്ട്
- **ചെലവ് നിയന്ത്രണം**: ശരിയായി ക്രമീകരിക്കാതിരുന്നാൽ AI സേവനങ്ങൾ ചെലവേറിയതാകാം

## മോഡ്യൂൾ 2: നിങ്ങളുടെ ആദ്യ AI അപ്ലിക്കേഷൻ ഡിപ്ലോയ്മെന്റ്

### പടി 2.1: പരിസ്ഥിതി ആരംഭിക്കൽ

1. **പുതിയ AZD പരിസ്ഥിതി സൃഷ്ടിക്കുക:**
```bash
azd env new myai-workshop
```

2. **ആവശ്യമായ പാരാമീറ്ററുകൾ സജ്ജീകരിക്കുക:**
```bash
# Set your preferred Azure region
azd env set AZURE_LOCATION eastus

# Optional: select a chat model supported by your region and quota
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
```

### പടി 2.2: ഇൻഫ്രാസ്ട്രക്ടർ ഉം ആപ്ലിക്കേഷൻ ഉം ഡിപ്ലോയ് ചെയ്യുക

1. **AZD ഉപയോഗിച്ച് ഡിപ്ലോയ് ചെയ്യുക:**
```bash
azd up
```

**`azd up` പ്രവർത്തനസമയം സംഭവിക്കുന്നത്:**
- ✅ Microsoft Foundry Models സേവനം പ്രോവിഷൻ ചെയ്യും
- ✅ അസ്യൂർ AI സേർച്ച് സേവനം സൃഷ്ടിക്കും
- ✅ ബാക്ക്‌എൻഡിനും ബുണ്ടി ഫ്രണ്ട്എൻഡിനും അസ്യൂർ കോൺടൈനർ ആപ്പുകൾ സജ്ജീകരിക്കും (ഇപ്പോഴത്തെ സാമ്പിൾ ഡീഫോൾട്ട്)
- ✅ നെറ്റ്വർക്ക് സെക്യൂരിറ്റി ക്രമീകരണങ്ങൾ ചെയ്യും
- ✅ ആപ്ലിക്കേഷൻ കോഡ് ഡിപ്ലോയ് ചെയ്യും
- ✅ നിരീക്ഷണവും ലോഗിംഗും സജ്ജീകരിക്കും

2. **ഡിപ്ലോയ്മെന്റ് പുരോഗതി കാണുകയും സൃഷ്ടിക്കപ്പെടുന്ന റിസോഴ്‌സുകൾ ശ്രദ്ധിക്കുകയും ചെയ്യുക.**

### പടി 2.3: നിങ്ങളുടെ ഡിപ്ലോയ്‌മെന്റ് സ്ഥിരീകരിക്കുക

1. **ഡിപ്ലോയ് ചെയ്ത റിസോഴ്‌സുകൾ പരിശോധിക്കുക:**
```bash
azd show
```

2. **ഡിപ്ലോയ് ചെയ്ത അപ്ലിക്കേഷൻ തുറക്കുക:**
```bash
azd show
```

`azd show` ഔട്ട്‌പുട്ടിൽ കാണുന്ന വെബ് എൻഡ്‌പോയിന്റ് തുറക്കുക.

3. **AI പ്രവർത്തനം പരീക്ഷിക്കുക:**
   - വെബ് അപ്ലിക്കേഷനിലേക്ക് പോകുക
   - പ്രയോഗത്തിൽ സാമ്പിൾ സംവാദങ്ങൾ പരീക്ഷിക്കുക
   - AI പ്രതികരണങ്ങൾ ശരിയാണോയെന്ന് പരിശോധിക്കുക

### **ലാബ് വ്യായാമം 2.1: പ്രശ്നപരിഹാര പരിശീലനം**

**സംഭവം**: ഡിപ്ലോയ്മെന്റ് വിജയിച്ചാലും AI പ്രതികരിക്കുന്നില്ല.

**ഏറ്റവും പൊതുവായി പരിശോധിക്കേണ്ട കാര്യങ്ങൾ:**
1. **പ്രാമാണീകരണം**: മാനേജ് ചെയ്ത ഐഡന്റിറ്റി, റോളുകൾ പരിശോധിക്കുക; കീ അടിസ്ഥാന പ്രാമാണീകരണം സജ്ജമാക്കിയെങ്കിൽ മാത്രമേ API കീകൾ പരിശോധിക്കേണ്ടതുള്ളൂ
2. **മോഡൽ ലഭ്യത**: നിങ്ങളുടെ പ്രദേശം മോഡൽ പിന്തുണയ്ക്കുന്നുണ്ടോയെന്ന് പരിശോധിക്കുക
3. **നെറ്റ്‌വർക്ക് ബന്ധം**: സേവനങ്ങൾ തമ്മിൽ ബന്ധപ്പെടുന്നു എന്ന് ഉറപ്പാക്കുക
4. **RBAC അനുവാദങ്ങൾ**: അപ്ലിക്കേഷൻ OpenAI ആക്സസ് ചെയ്യാനായി നിലനിർത്തുക

**ഡീബഗ്ഗിംഗ് കമാൻഡുകൾ:**
```bash
# Check environment variables
azd env get-values

# Open the selected environment's logging view
azd monitor --logs

# Check OpenAI deployment status
az cognitiveservices account deployment list --name YOUR_OPENAI_NAME --resource-group YOUR_RG
```

## മോഡ്യൂൾ 3: നിങ്ങളുടെ ആവശ്യങ്ങൾക്ക് AI അപ്ലിക്കേഷനുകൾ ഇഷ്ടാനുസൃതമാക്കൽ

### പടി 3.1: AI കോൺഫിഗറേഷൻ മാറ്റങ്ങൾ

1. **OpenAI മോഡൽ അപ്ഡേറ്റ് ചെയ്യുക:**

```bash
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1

# Apply the model infrastructure change, then deploy the application
azd up
```

2. **കൂടുതൽ AI സേവനങ്ങൾ ചേർക്കുക:**

ഡോക്യുമെന്റ് ഇന്റലിജൻസ് ചേർക്കാൻ `infra/main.bicep` എഡിറ്റ് ചെയ്യുക:

താഴെ കാണിക്കുന്ന കൊഡ് ഒരു ഉദാഹരണ ഭാഗമാണ്, പൂർണ്ണ ടെംപ്ലേറ്റ് അല്ല. സാമ്പിൾ ഇപ്പോഴും ഡോക്യുമെന്റ് പ്രോസസ് ചെയ്യുന്ന സേവനങ്ങൾ പ്രോവിഷൻ ചെയ്തേക്കാം: പ്രാധാന്യം കൊടുക്കുന്നുള്ള ഇൻഫ്രാസ്ട്രക്ചർ പരിശോധിച്ച് ഡ്യൂപ്ലിക്കേറ്റ് റിസോഴ്‌സുകൾ ചേർക്കരുത്. ഇഷ്ടാനുസൃത ചേർക്കലുകൾ ഔട്ട്‌പുട്ട്, ഐഡന്റിറ്റികൾ, ആപ്ലിക്കേഷൻ കോൺഫിഗറേഷൻ എന്നിവർ വയറിംഗ് ആവശ്യമാണ്.

```bicep
  }

    customSubDomainName: 'doc-intel-${uniqueString(resourceGroup().id)}'
```

### പടി 3.2: പരിസ്ഥിതി-നിര്ദ്ദിഷ്ട കോൺഫിഗറേഷനുകൾ

**ഉത്തമ പത്തതി**: വികസനത്തിനും പ്രൊഡക്ഷനിനും വ്യത്യസ്ത കോൺഫിഗറേഷനുകൾ.

1. **പ്രൊഡക്ഷൻ പരിസ്ഥിതി സൃഷ്ടിക്കുക:**
```bash
azd env new myai-production
```

2. **പ്രൊഡക്ഷൻ-നിർദ്ദിഷ്ട പാരാമീറ്ററുകൾ സജ്ജമാക്കുക:**
```bash
# Use the sample's actual Search SKU parameter
azd env set AZURE_SEARCH_SERVICE_SKU standard

# Enable private endpoints using the sample's parameter
azd env set AZURE_USE_PRIVATE_ENDPOINT true
```

ഈ പേരുകൾ സാമ്പിളിന്റെ [main.parameters.json](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/infra/main.parameters.json) ലിൽ നിന്നാണ്. `azd env set` മൂല്യം സൂക്ഷിക്കുന്നു, പക്ഷേ ആകസ്മികമായി ഒരു വ്യത്യസ്ത വേരിയബിൾ സജീവമാക്കുന്നില്ല: ടെംപ്ലേറ്റ് അതു ഉപയോഗിക്കണം. പബ്ലിക് ആക്സസ് ഡിസേബിൾ ചെയ്യുന്നതിന് മുൻപ് സാമ്പിളിന്റെ [നെറ്റ്‌വർക്ക് ഐസൊലേഷൻ ഗൈഡ്](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/docs/deploy_private.md) പരിശോധിക്കുക, അനന്തര തിരുത്തലുകൾക്ക് `azd up` ഉപയോഗിക്കുക. OpenAI SKU `S0` മാത്രം മോഡൽ ത്രൂപുട്ട് നിശ്ചയിക്കുന്നില്ല; മോഡൽ ഡिप്ലോയ്‌മെന്റ് തരംയും ശേഷിയും കൂടി ബാധകമാണ്.

### **ലാബ് വ്യായാമം 3.1: ചെലവ് കാര്യക്ഷമത**

**ചലഞ്ച്**: ടംപ്ലേറ്റ് ചെലവ് വിഷമം കൂടാതെ വികസനത്തിനായി ക്രമീകരിക്കുക.

**ടാസ്കുകൾ:**
1. ഡിസ്പോസബിൾ വർക്‌ഷോപ്പ് പരിസ്ഥിതി തിരഞ്ഞെടുക്കുക: `azd env select myai-workshop`.
2. നിലവിലെ Search SKU, മോഡൽ ശേഷി `infra/main.parameters.json` ലും തെരഞ്ഞെടുക്കപ്പെട്ട പരിസ്ഥിതിയിലും രേഖപ്പെടുത്തുക.
3. മോഡൽ/പ്രദേശം ക്വോട്ട സ്ഥിരീകരിച്ചതിനു ശേഷം പിന്തുണയുള്ള ഇൻപുട്ടുകൾ താഴെ ഉപയോഗിക്കുക:
   ```bash
   azd env set AZURE_SEARCH_SERVICE_SKU basic
   azd env set AZURE_OPENAI_CHATGPT_DEPLOYMENT_CAPACITY 10
   azd up
   ```
4. പോർട്ടലിൽ Search SKU, ഡിപ്ലോയ്‌മെന്റ് ശേഷി പരിശോധിക്കുകയും വില കണക്കുകൂട്ടിയുമായി താരതമ്യം ചെയ്യുകയും ചെയ്യുക. ബില്ലിംഗ് ഡാറ്റ ഉടനടി അപ്ഡേറ്റ് ആയിരിക്കുമെന്ന് പ്രതീക്ഷിക്കരുത്.

**വിജയ критерികൾ:** Search ബേസിക് ടയർ ആണ് ഉപയോഗിക്കുന്നത്, ചാറ്റ് ഡിപ്ലോയ്മെന്റിന് ആവശ്യമായ സപ്പോർട്ടഡ് ശേഷി ഉണ്ട്, ആപ്പ് സാമ്പിൾ ചോദ്യത്തിന് മറുപടി നൽകുന്നു. ശേഷി `10` നിരക്ക് സീമितാടിസ്ഥാനത്തിലാണ്, ടോക്കൺ വിലക്കുറയൽ അല്ല. Search ടയർ മാറ്റങ്ങൾ നിയന്ത്രിക്കപ്പെട്ടേക്കാം അല്ലെങ്കിൽ പുനഃസൃഷ്ടി ആവശ്യമായേക്കാം; പ്രൊഡക്ഷൻ റിസോഴ്‌സുകളിൽ പരീക്ഷണം നടത്തരുത്. F0 സെർവീസ്-സ്പെസിഫിക് ആണ്, അസ്യൂർ OpenAI മോഡൽ SKU ആകയില്ല.

## മോഡ്യൂൾ 4: സുരക്ഷയും പ്രൊഡക്ഷൻ ഉത്തമ പത്തതികളും

### പടി 4.1: സുരക്ഷിത ക്രെഡൻഷ്യൽ മാനേജ്മെന്റ്

**ഇപ്പോൾ നിലവിളി**: പല AI അപ്ലിക്കേഷനുകളും API കീകൾ ഹാർഡ്‌കോഡ് ചെയ്‌തോ അണിശ്രദ്ധയുള്ള സംഭരണവും ഉപയോഗിക്കുന്നു.

**AZD പരിഹാരം**: മാനേജ് ചെയ്ത ഐഡന്റിറ്റി + കീ വാൾട്ട് ഇന്റഗ്രേഷൻ.

1. **ടെംപ്ലേറ്റിലെ സുരക്ഷാ കോൺഫിഗറേഷൻ അവലോകനം ചെയ്യുക:**

```bash
# Look for Key Vault and Managed Identity configuration
```

2. **Managed Identity പ്രവർത്തിക്കുന്നുവെന്ന് പരിശോധിക്കുക:**

```bash
# For the sample's default Container Apps host

```

### പടി 4.2: നെറ്റ്‌വർക്ക് സുരക്ഷ

1. **പ്രൈവറ്റ് എൻഡ്‌പോയിന്റുകൾ സജീവമാക്കുക** സാമ്പിളിന്റെ പിന്തുണയുള്ള നെറ്റ്‌വർക്ക് കോൺഫിഗറേഷൻ ഉപയോഗിച്ച് (മുൻകൂട്ടി ക്രമീകരിക്കപ്പെട്ടവയല്ലെങ്കിൽ).

നിങ്ങളുടെ സ്വന്തം ടെംപ്ലേറ്റിനായി, ഇത് OpenAI എൻഡ്‌പോയിന്റ് ബന്ധം കാണിക്കുന്ന ഒരു ഉദാഹരണ ഭാഗമാണ്. കൂടാതെ VNet, പ്രൈവറ്റ് DNS കോൺഫിഗറേഷൻ, ആപ്ലിക്കേഷൻ കണക്ടിവിറ്റി ആവശ്യമാണ്; ഇത് മാറ്റവുമില്ലാതെ സാമ്പിളിൽ പ്ലാസ്റ്റ് ചെയ്യരുത്, കാരണം ഇതിനകം പ്രൈവറ്റ് എൻഡ്‌പോയിന്റ് മൊഡ്യൂളുകൾ ഉണ്ട്:
```bicep
// Private endpoint for OpenAI
resource openAIPrivateEndpoint 'Microsoft.Network/privateEndpoints@2023-04-01' = {
  name: 'pe-openai-${uniqueString(resourceGroup().id)}'
  location: location
  properties: {
    subnet: {
      id: vnet.properties.subnets[0].id
    }
    privateLinkServiceConnections: [
      {
        name: 'openai-connection'
        properties: {
          privateLinkServiceId: openAIAccount.id
          groupIds: ['account']
        }
      }
    ]
  }
}
```

1. **ആപ്ലിക്കേഷൻ ഇൻസൈറ്റ്സ് കോൺഫിഗർ ചെയ്യുക:**

### പടി 5.1: വിലയിരുത്തൽ വർക്ക്‌ഷീറ്റ്

**നിങ്ങളുടെ അപ്ലിക്കേഷൻ പരിവർത്തനം ചെയ്യുന്നതിന് മുമ്പ്**, താഴെ ചേർന്ന ചോദ്യങ്ങൾ മറുപടി നൽകുക:

1. **അപ്ലിക്കേഷൻ ആർക്കിടെക്ചർ:**
   - നിങ്ങളുടെ അപ്ലിക്കേഷൻ ഏത് AI സേവനങ്ങൾ ഉപയോഗിക്കുന്നു?
   - ഏത് കംപ്യൂട്ട് റിസോഴ്‌സുകൾ ആവശ്യമുണ്ട്?
   - ഡേറ്റാബേസ് ആവശ്യമാണ്?
   - സേവനങ്ങൾക്കിടയിൽ ആശ്രിതത്വങ്ങൾ എന്തൊക്കെയാണ്?

2. **സുരക്ഷാ ആവശ്യകതകൾ:**
   - നിങ്ങളുടെ അപ്ലിക്കേഷൻ കൈകാര്യം ചെയ്യുന്ന സെൻസിറ്റീവ് ഡാറ്റ എന്തൊക്കെയാണ്?
   - നിങ്ങൾക്ക് ഉള്ള ബൃഹതാനുസൃത പരിധി ആവശ്യകതകൾ എന്തൊക്കെയാണ്?
   - സ്വകാര്യ നെറ്റ്‌വർക്ക് ആണോ നിങ്ങൾക്ക് ആവശ്യം?

3. **സ്കേലിംഗിനുള്ള ആവശ്യങ്ങൾ:**
   - നിങ്ങളുടെ പ്രതീക്ഷിച്ച ലോഡ് എന്താണ്?
   - ഓട്ടോ-സ്കേലിംഗ് ആവശ്യമുണ്ടോ?
   - പ്രദേശിക ആവശ്യകതകൾ ഉള്ളവയോ?

### പടി 5.2: നിങ്ങളുടെ AZD ടെംപ്ലേറ്റ് സൃഷ്ടിക്കുക

**നിങ്ങളുടെ അപ്ലിക്കേഷൻ പരിവർത്തനം ചെയ്യാൻ ഈ മാതൃക പിന്തുടരുക:**

**മാത്രം സ്കാഫോൾഡ്:** ഈ സെക്ഷൻ API/വെബ് അപ്ലിക്കേഷൻ സോഴ്സ്, ഹോസ്റ്റ് ഇൻഫ്രാസ്ട്രക്ചർ, മോഡൽ ഡിപ്ലോയ്മെന്റുകൾ, ഐഡന്റിറ്റി/ആർബിഎസി അല്ലെങ്കിൽ ഒരു പൂർത്തിയാക്കിയ `main.parameters.json` നൽകിയിട്ടില്ല. റിസോഴ്‌സ്-ഗ്രൂപ്പ്-സ്കോപ്പഡ് ബൈസിപ്പാണ് മോഡ്യൂൾ നിർമാണം കാണിക്കുന്നതായത്; ഒരു സാധാരണ AZD സബ്സ്ക്രിപ്ഷൻ-സ്കോപ്പഡ് എൻട്രി പോയിന്റ് ഒരു റിസോഴ്‌സ് ഗ്രൂപ്പ് സൃഷ്ടിച്ച് അതിനെ ആ സ്കോപ്പിൽ വിളിക്കണം. ഈ ഭാഗങ്ങൾ മാത്രം പകർത്തിയാൽ `azd up` ഒരു സമ്പൂർണ്ണ ആപ്പ് വിന്യസിക്കുമെന്ന് പ്രതീക്ഷിക്കേണ്ട. റണ്ണബിൾ ബേസ്ലൈൻക്കായി, മോഡ്യൂൾ 1 ൽ നിന്നും RAG ടെംപ്ലേറ്റ് തുടര്‍ന്നും ഉപയോഗിക്കുക.

1. **അടിസ്ഥാന ഘടന സൃഷ്ടിക്കുക:**
```bash
mkdir my-ai-app-azd
cd my-ai-app-azd

# Initialize AZD template
azd init --template minimal .
```

2. **azure.yaml സൃഷ്ടിക്കുക:**
```yaml
# Metadata
name: my-ai-app
metadata:
  template: my-ai-app-template@0.0.1-beta

# Services definition
services:
  api:
    project: ./api
    host: containerapp
  web:
    project: ./web
    host: staticwebapp
    
# Hooks for custom deployment logic  
hooks:
  predeploy:
    shell: sh
    run: echo "Preparing AI models..."
```

3. **ഇൻഫ്രാസ്ട്രക്ചർ ടെംപ്ലേറ്റുകൾ സൃഷ്ടിക്കുക:**

**infra/main.bicep** - പ്രധാന ടെംപ്ലേറ്റ്:
```bicep
@description('Primary location for all resources')
param location string = resourceGroup().location

@description('Name of the OpenAI service')
param openAIServiceName string = 'openai-${uniqueString(resourceGroup().id)}'

// Your AI services here
module openAI 'modules/openai.bicep' = {
  name: 'openai'
  params: {
    name: openAIServiceName
    location: location
  }
}
```

**infra/modules/openai.bicep** - OpenAI മോഡ്യൂൾ:
```bicep
@description('Name of the OpenAI service')
param name string

@description('Location for the OpenAI service')
param location string

resource openAIAccount 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: name
  location: location
  kind: 'OpenAI'
  sku: {
    name: 'S0'
  }
  properties: {
    customSubDomainName: name
    disableLocalAuth: true
  }
}

output endpoint string = openAIAccount.properties.endpoint
output name string = openAIAccount.name
```

### **ലാബ് വ്യായാമം 5.1: ടെംപ്ലേറ്റ് സൃഷ്ടി വെല്ലുവിളി**

**വെല്ലുവിളി**: ഒരു ഒാപ്പർ‌മെന്റ് പ്രോസസ്സിങ് AI ആപ്പിനുള്ള AZD ടെംപ്ലേറ്റ് സൃഷ്ടിക്കുക.

**അവശ്യങ്ങൾ:**

- പ്രോസസ്സിങ് ലാജിക്കിന് ഫംഗ്ഷൻ ആപ്പ്

## മോഡ്യൂൾ 6: സാധാരണ പ്രശ്നങ്ങളുടെ പരിഹാരം

### സാധാരണ ഡിപ്ലോയ്മെന്റ് പ്രശ്നങ്ങൾ

#### പ്രശ്നം 1: OpenAI സർവീസ് ക്വോട്ട തുറന്നു.
**ലക്ഷണങ്ങൾ:** ക്വോട്ട പരാധി കൊണ്ട് ഡിപ്ലോയ്മെന്റ് പരാജയം
**പരിഹാരങ്ങൾ:**
```bash
# Check current quotas
az cognitiveservices usage list --location eastus

# Request quota increase, OR try a new disposable environment in another region.
# Azure resources cannot be relocated merely by changing AZURE_LOCATION.
azd env new myai-quota-test
azd env set AZURE_LOCATION westus2
azd up
```

#### പ്രശ്നം 2: മൂഡൽ ആ മേഖലയിൽ ലഭ്യമല്ല
**ലക്ഷണങ്ങൾ:** AI പ്രതികരണങ്ങൾ പരാജയപ്പെടുന്നു അല്ലെങ്കിൽ മോഡൽ ഡിപ്ലോയ്മെന്റ് പിശകുകൾ
**പരിഹാരങ്ങൾ:**
```bash
# Check model availability by region
az cognitiveservices model list --location eastus

# Update to available model
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
azd up
```

#### പ്രശ്നം 3: അനുമതി പ്രശ്നങ്ങൾ
**ലക്ഷണങ്ങൾ:** AI സർവീസുകൾ വിളിക്കുമ്പോൾ 403 വിലക്ക് പിശകുകൾ
**പരിഹാരങ്ങൾ:**
```bash
# Check role assignments
az role assignment list --scope /subscriptions/YOUR_SUB/resourceGroups/YOUR_RG

# Add missing roles
az role assignment create \
  --assignee YOUR_PRINCIPAL_ID \
  --role "Cognitive Services OpenAI User" \
  --scope /subscriptions/YOUR_SUB/resourceGroups/YOUR_RG
```

#### പ്രശ്നം 4: മന്ദഗതിയിലുള്ള AI പ്രതികരണങ്ങൾ
**പരിശോധനാ ഘട്ടങ്ങൾ:**

2. ആസറിലാണ് OpenAI സർവീസ് മീറ്റ്രിക്‌സുകൾ പരിശോധിക്കുക
3. നെറ്റ്‌വർക്ക് ബന്ധവും വിരുദ്ധതയും സ്ഥിരീകരിക്കുക

**പരിഹാരങ്ങൾ:**
- സാധാരണ ചോദ്യങ്ങൾക്കായി കാഷിംഗ് നടപ്പാക്കുക
- നിങ്ങളുടെ ഉപയോഗത്തിന് അനുയോജ്യമായ OpenAI മോഡൽ ഉപയോഗിക്കുക
- മോഡൽ RPM/TPM പരിധികൾ പരിശോധിച്ചതിനു ശേഷം ആപ്ലിക്കേഷൻ പ്രതലങ്ങൾ കൂടി വർധിപ്പിക്കുക; ആസർ OpenAI വിന്യസനങ്ങൾ പൊതുവായ ഡേറ്റാബേസ്-സ്റ്റൈൽ "റീഡ് റെപ്ലിക്ക" നിർദ്ദേശം വെളിപ്പെടുത്തുന്നില്ല

## മഡ്‌ളി 7: നിരീക്ഷണവും മെച്ചപ്പെടുത്തലും

### ഘട്ടം 7.1: സമഗ്രമായ നിരീക്ഷണം സജ്ജീകരിക്കുക

1. **സൗകര്യപ്രദമായ ഡാഷ്‌ബോർഡുകൾ സൃഷ്ടിക്കുക:**

Azure പോർട്ടലിലേയ്ക്ക് പോകുക, താഴെപ്പറയുന്നവ ഉൾപ്പെടുന്നതായ ഒരു ഡാഷ്ബോർഡ് സൃഷ്ടിക്കുക:
- OpenAI അഭ്യർത്ഥന എണ്ണവും വൈകിയും
- ആപ്ലിക്കേഷൻ പിശക് നിരക്കുകൾ
- റിസോഴ്സ് ഉപയോഗം
- ചെലവ് ട്രാക്കിംഗ്

2. **അലർട്ടുകൾ സജ്ജീകരിക്കുക:**
```bash
# Failed-request count on the Application Insights component (not a percentage)
az monitor metrics alert create \
  --name "AI-App-Failed-Requests" \
  --resource-group YOUR_RG \
  --scopes YOUR_APPLICATION_INSIGHTS_RESOURCE_ID \
  --condition "count requests/failed > 10" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --description "More than 10 failed requests in five minutes"
```

ഘടകം അഭ്യർത്ഥന ടെലിമെട്രി ജారీ ചെയ്യുന്നതാണ് എന്ന് സ്ഥിരീകരിക്കുക, അറിയിപ്പുകൾ ആവശ്യമായാൽ ഒരു ആക്ഷൻ ഗ്രൂപ്പ് ചേർക്കുക. ഈ മീറിക് ഒരു എണ്ണം ആണ്, പരാജയ ശതമാനം അല്ല; നിരക്ക് അലർട്ട് അനുസരിച്ച് യോഗ്യമായ ചോദ്യവും തുടര്‍ച്ചയും വേണം.

### ഘട്ടം 7.2: ചെലവ് മെച്ചപ്പെടുത്തൽ

1. **നിലവിലെ ചെലവുകൾ വിശകലനം ചെയ്യുക:**
```bash
# Set a recent reporting window supported by your billing account.
az consumption usage list --start-date YYYY-MM-DD --end-date YYYY-MM-DD
```

തീയതി പ്ലേസ്‌ഹോൾഡറുകൾ മാറ്റുക. കൺസംപ്ഷൻ API പിന്തുണ ബില്ലിംഗ് കരാറിന് വിധേയമാണ്; ഉപയോഗ വിവരങ്ങൾ ലഭ്യമല്ലെങ്കിൽ പോർട്ടലിലെ ചെലവ് മാനേജ്മെന്റ് ഉപയോഗിക്കുക. ചെലവുകൾ വൈകിയുള്ളവയാണ്, തത്സമയം പരിശോധിക്കേണ്ട തരം അല്ല.

2. **ചെലവ് നിയന്ത്രണങ്ങൾ നടപ്പിലാക്കുക:**
- ബജറ്റ് അലർട്ടുകൾ സജ്ജീകരിക്കുക
- ഓട്ടോ സ്കെയിലിംഗ് നയങ്ങൾ ഉപയോഗിക്കുക
- അഭ്യർത്ഥന കാഷിംഗ് നടപ്പിലാക്കുക
- OpenAI ടോക്കൺ ഉപയോഗം നിരീക്ഷിക്കുക

### **ലാബ് അഭ്യാസം 7.1: പ്രകടന മെച്ചപ്പെടുത്തൽ**

**ടാസ്‌ക്ക്**: നിങ്ങളുടെ AI ആപ്ലിക്കേഷൻ പ്രകടനവും ചെലവും തരുമാറ്റി മെച്ചപ്പെടുത്തുക.

** മെച്ചപ്പെടുത്തേണ്ട മെട്രിക്കുകൾ:**
- ശരാശരി മറുപടി സമയം 20% കുറയ്ക്കുക
- മാസവാറി ചെലവ് 15% കുറഞ്ഞുകൂട്ടുക
- 99.9% ലഭ്യത SLO നിർവചിക്കുക, അളവിൽ തടസ്സം (ഗണനാമാസം ഇല്ലാത്ത ശുശ്രൂഷാ ലാബിൽ പ്രദർശിപ്പിക്കാൻ കഴിയില്ല)

**ശ്രമിക്കാനുള്ള തന്ത്രങ്ങൾ:**
- മറുപടി കാഷിംഗ് നടപ്പിലാക്കുക
- ടോക്കൺ കാര്യക്ഷമതക്കായി പ്രൊംപ്റ്റുകൾ മെച്ചപ്പെടുത്തുക
- അനുയോജ്യമായ കംപ്യൂട്ട് SKUs ഉപയോഗിക്കുക
- ശരിയായ ഓട്ടോ സ്കെയിലിംഗ് സജ്ജീകരണം

## അന്തിമ പ്രതിസന്ധി: അവസാനത്തേത് നടപ്പാക്കൽ

### സവാലിൻ സാന്റാരിയോ

ഇത് **ഐച്ഛികമായ ആർക്കിടെക്ചർ/ഡിസൈൻ സവാലാണ്**, റണ്ണബിള്‍ എക്സർസൈസ് അല്ല അല്ലെങ്കിൽ പ്രൊഡക്ഷൻ സർട്ടിഫിക്കേഷൻ. AI-സമർപ്പിത ഉപഭോക്തൃ സേവന ചാറ്റ്ബോട്ട് നിർദേശിച്ച് ഏത് ആവശ്യങ്ങൾ കൂടുതൽ നടപ്പാക്കാൻ വേണ്ടതും തെളിവുകളും രേഖപ്പെടുത്തുക:

**പ്രവർത്തന ആവശ്യങ്ങൾ:**
- ഉപഭോക്തൃ ഇടപാടുകൾക്കായുള്ള വെബ് ഇന്റർഫെയ്സ്
- പ്രതികരണങ്ങൾക്ക് Microsoft Foundry Models ഇंटीഗ്രേഷൻ
- Azure AI Search ഉപയോഗിച്ച് ഡോക്യുമെന്റ് തിരയുന്ന സവിശേഷത
- നിലവിലുള്ള ഉപഭോക്തൃ ഡേറ്റാബേസുമായി സംയോജനം
- ബഹുമുഖ ഭാഷ പിന്തുണ

**പ്രവർത്തനാതീത ആവശ്യങ്ങൾ:**
- 1000 സമകാലീന ഉപയോക്താക്കളെ കൈകാര്യം ചെയ്യുക
- 99.9% അപ്പടൗട്ട് SLA
- SOC 2 അനുസരണ
- $500/മാസം നഷ്ടംക്കടുത്ത് ചെലവ്
- പല പരിസരങ്ങളിലേക്കും വിന്യസിക്കുക (ഡെവ്, സ്ഥിതിഗതികൾ, പ്രൊഡക്ഷൻ)

ഇവ സിദ്ധാന്തപരമായ ഓഹരി ദാരകരുടെ നിയന്ത്രണങ്ങളാണ്, ഒരേ സമയം ഉറപ്പ് നൽകുന്ന ഫലങ്ങൾ അല്ല. അഭ്യർത്ഥന നിരക്ക്, പ്രോംപ്റ്റ്/ഔട്ട്പുട്ട് വലിപ്പങ്ങൾ, സെഷൻ ദൈർഘ്യം നിർവചിച്ച് ചെലവ് കണക്കുകൂട്ടുക; 1000 സമകാലീന ഉപയോക്താവ് ജോലി ബൂലം ലക്ഷ്യമാക്കുകയോ $500 ബജറ്റ് സാധ്യമാണെന്നു തെളിയിക്കുകയോ ചെയ്യില്ല. SOC 2 ഒരു സംഘടനാ ഓഡിറ്റ് ഫലം ആണ്, AZD ടെംപ്ലേറ്റ് കൊണ്ട് ഉടൻ സ്വിച്ച് ചേരുന്ന കാര്യം അല്ല. വരെ തരംതിരിക്കുകയും അസാധ്യമായ നിയന്ത്രണങ്ങൾക്ക് തെളിവുകൂടി ഒഴിവാക്കുകയും ചെയ്യുക.

### നടപ്പാക്കൽ ഘട്ടങ്ങൾ

1. **ആർക്കിടെക്ചർ രൂപകൽപന**
2. **AZD ടെംപ്ലേറ്റ് സൃഷ്ടിക്കുക**
3. **സുരക്ഷാ ഉപഗ്രാഹങ്ങൾ നടപ്പിലാക്കുക**
4. **നിരീക്ഷണവും അലർട്ടിംഗും സജ്ജീകരിക്കുക**
5. **വിന്യാസ പൈപ്പ്ലൈനുകൾ സൃഷ്ടിക്കുക**
6. **പരിഹാരം രേഖപ്പെടുത്തുക**

### മൂല്യനിർണ്ണയ മാനദണ്ഡങ്ങൾ

- ✅ **പ്രവൃത്തി സാദ്ധ്യത**: നടപ്പിലാക്കിയ കഴിവുകൾ തെളിയിച്ചിട്ടുണ്ടോ? ശേഷിച്ചിട്ടുള്ള വിജയ ഭേദഗതികൾ വ്യക്തമാകുന്നുണ്ടോ?
- ✅ **സുരക്ഷ**: മികച്ച പ്രാക്ടീസുകൾ നടപ്പിലാക്കിയിട്ടുണ്ടോ?
- ✅ **സ്കാലബിലിറ്റി**: താൾ ചുമതല കൈകാര്യം ചെയ്യാൻ കഴിയുമോ?
- ✅ **പരിപാലനക്ഷമത**: കോഡ്, ഇൻഫ്രാസ്ട്രക്ചർ നല്ല രീതിയിൽ ക്രമീകരിച്ചിട്ടുണ്ടോ?
- ✅ **ചെലവ്**: ബജറ്റിനകത്ത് തുടരുന്നു എങ്കിൽ?
