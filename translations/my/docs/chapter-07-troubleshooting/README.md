## အနှစ်ချုပ်

ဤအခန်းသည် Azure Developer CLI နှင့် အလုပ်လုပ်စဉ်တွင်တွေ့ကြုံရသော ပုံမှန်ပြသနာများကို ရှာဖွေပြီး ဖြေရှင်းရာတွင် ကူညီပေးသည်။ တပ်ဆင်မှု မအောင်မြင်ခြင်းမှ AI ဆိုင်ရာပြသနာများအထိ။

> အမိန့်လမ်းညွှန်ချက်ကို ထုတ်ပြန်ထားသော `azd 1.37.2` ကိုးကားချက်နှင့် ဆိုင်ရာ စစ်ဆေးထားသည်။ မိုးကောင်းကင်တပ်ဆင်မှုများ မပြုလုပ်ရသေးပါ။ ဥပမာအရင်းအမြစ်အမည်များနှင့် ID များကို အစားထိုးပြီးနောက် အမိန့်များကို အသုံးပြုပါ။

## သင်ယူရမည့် ရည်ရွယ်ချက်များ

ဤအခန်းကို ပြီးမြောက်စွာ သင်ယူပြီးနောက်၊ သင်သည်-
- ပုံမှန် AZD တပ်ဆင်မှု မအောင်မြင်မှုများကို ခွဲခြမ်းစိတ်ဖြာနိုင်မည်
- ကိုယ်တိုင် စစ်ဆေးခြင်းနှင့် ခွင့်ပြုချက်ပြဿနာများကို အမှားရှာဖွေမည်
- AI ဝန်ဆောင်မှု ဆက်သွယ်မှု ပြဿနာများကို ဖြေရှင်းမည်
- ပြဿနာများကို ဖြေရှင်းရာတွင် Azure Portal နှင့် CLI ကို အသုံးပြုမည်

## 🚨 အမြန်ပြုပြင်ချက်များ

### အတည်ပြုချက်ပြဿနာများ
```bash
# Required for AZD workflows
azd auth login

# Optional if you are also using Azure CLI commands directly
az login

azd auth login --check-status
```

### တပ်ဆင်မှု မအောင်မြင်မှုများ
```bash
azd show
azd monitor --logs
az deployment sub list --query "[?properties.provisioningState!='Succeeded']"
```

### အရင်းအမြစ် ကွဲပြားမှုများ
ရှိပြီးသား အရင်းအမြစ်နှင့် တပ်ဆင်မှု မှားယွင်းမှုများကို ပထမဦးဆုံး စစ်ဆေးပါ။ အမည်အလွဲကို ဖြေရှင်းရန် မျှဝေသော သို့မဟုတ် ထုတ်လုပ်မှုပတ်ဝန်းကျင်ကို ဖျက်မလုပ်ပါနှင့်။ **အသစ်ဖြတ်တောက်ပစ်နိုင်သော ပတ်ဝန်းကျင်** တစ်ခုအတွက် သီးခြားအမည် အသုံးပြုပါ:

```bash
azd env new different-name
azd up
```

### ခွင့်ပြုမှု ထပ်မံကျော်လွန်ခြင်း
```bash
az vm list-usage --location eastus --output table
# Check the affected service's own quotas, not just VM quotas.
# For a new environment only, choose a supported region with available quota.
```

`AZURE_LOCATION` ကိုပြောင်းလဲခြင်းသည် ရှိပြီးသား အရင်းအမြစ်များကို ဉာဏ်ကြီးသယ်ယူခြင်း မဟုတ်ပါ၍ ပြန်တပ်ဆင်မှုတွင် တည်နေရာ ထပ်မံပြဿနာဖြစ်စေနိုင်သည်။

## 📋 အမှားကုဒ် ကိုးကားချက်

| အမှား | ဖြစ်ပေါ်ရခြင်း | ဖြေရှင်းမှု |
|-------|-------|----------|
| `AuthenticationError` | စနစ်ဝင်မထားခြင်း | `azd auth login` |
| `ResourceNotFound` | အရင်းအမြစ်လွတ်လပ်ခြင်း | အရင်းအမြစ်အမည်များကို စစ်ဆေးပါ |
| `QuotaExceeded` | စံချိန်များကျော်လွန်ခြင်း | ခွင့်ပြုမည့် အတိုင်းအတာတောင်းဆိုပါ |
| `InvalidTemplate` | Bicep သတ်မှတ်ချက် အမှား | `az bicep build` |
| `Conflict` | အရင်းအမြစ် ရှိပြီးသား | အသစ်အမည် သို့မဟုတ် ဖျက်ပါ |
| `Forbidden` | ခွင့်ပြုချက် မလုံလောက်ခြင်း | RBAC အခန်းကဏ္ဍများကို စစ်ဆေးပါ |

## 🔄 ပြန်လည်သတ်မှတ်ခြင်းနှင့် ပြန်လည်ရယူခြင်း

```bash
# Soft reset (keep resources, redeploy code)
azd deploy

# Hard reset (delete everything, start fresh)
azd down
azd up
```

ခွန်အားပြန်လည်သတ်မှတ်ခြင်းသည် ဒေတာများကို ဖျက်သိမ်းပြီး တည်နေရာများကို ပြောင်းလဲနိုင်သည်။ မတိုင်မီ မိမိဒေတာကောက်ယူပြီး ဖျက်ပစ်ရန် အကိုက်အခဲပြုမည့် ပုံစံကို ကြည့်ရှုပါ။ `--force --purge` သည် ပြန်လည်မရနိုင်သော ဖျက်ပစ်မှု ရည်ရွယ်ချက်ဖြင့် ဖြတ်တောက်နိုင်သော ပတ်ဝန်းကျင်များတွင်သာ သင့်တော်သည်။
