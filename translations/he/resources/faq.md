## מבוא

שאלות נפוצות מקיפות אלו מספקות תשובות לשאלות הנפוצות ביותר לגבי Azure Developer CLI (azd) ופריסות Azure. מצא פתרונות מהירים לבעיות נפוצות, הבן שיטות עבודה מומלצות, וקבל הבהרות על מושגי azd וזרימות עבודה.

## מטרות הלמידה

בסקירת שאלות נפוצות אלה, תוכל:
- למצוא תשובות מהירות לשאלות ובעיות נפוצות ב-Azure Developer CLI
- להבין מושגים מרכזיים וטרמינולוגיה דרך פורמט שאלות ותשובות מעשי
- לקבל פתרונות פתרון תקלות לבעיות ותסריטי שגיאה תכופים
- ללמוד שיטות עבודה מומלצות דרך שאלות נפוצות על אופטימיזציה
- לגלות תכונות ויכולות מתקדמות דרך שאלות ברמת מומחים
- להפנות ביעילות להנחיות בנוגע לעלות, אבטחה ואסטרטגיית פריסה

## תוצאות למידה

בהתייחסות שוטפת לשאלות נפוצות אלו, תוכל:
- לפתור בעיות נפוצות ב-Azure Developer CLI באופן עצמאי באמצעות הפתרונות המסופקים
- לקבל החלטות מושכלות לגבי אסטרטגיות ותצורות פריסה
- להבין את הקשר בין azd לכלים ושירותי Azure אחרים
- ליישם שיטות עבודה מומלצות המבוססות על ניסיון הקהילה והמלצות מומחים
- לפתור בעיות אימות, פריסה ותצורה ביעילות
- לאופטימיזציה של עלויות וביצועים באמצעות תובנות והמלצות מהשאלות הנפוצות

## התחלה

### ש: מהו Azure Developer CLI (azd)?
**ת**: Azure Developer CLI (azd) הוא כלי שורת פקודה ממוקד מפתח המאיץ את הזמן שלוקח לך להעביר את היישום מהסביבת פיתוח מקומית ל-Azure. הוא מספק שיטות עבודה מומלצות דרך תבניות ועוזר לאורך כל מחזור חיי הפריסה.

### ש: כיצד azd שונה מ-Azure CLI?
**ת**: 
- **Azure CLI**: כלי כללי לניהול משאבי Azure
- **azd**: כלי ממוקד מפתח לזרימות עבודה של פריסת אפליקציות
- לאzd יש תהליך אימות ופריסה משלו; Azure CLI הוא כלי נפרד ומשלים
- azd כולל תבניות, ניהול סביבות ואוטומציה של פריסה

### ש: האם אני צריך להתקין Azure CLI כדי להשתמש ב-azd?
**ת**: לא עבור זרימת העבודה המרכזית של AZD. בצע אימות עם `azd auth login`. התקן Azure CLI בנפרד כאשר תבנית או תרגיל מפעילים במפורש פקודות `az`.

### ש: באילו שפות תכנות azd תומך?
**ת**: azd הוא ניטרלי לשפה. הוא עובד עם:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- אתרי אינטרנט סטטיים
- יישומים במכולות

### ש: האם אפשר להשתמש ב-azd עם פרויקטים קיימים?
**ת**: כן! ניתן:
1. להשתמש ב-`azd init` להוספת תצורת azd לפרויקטים קיימים
2. להתאים פרויקטים קיימים למבנה התבנית של azd
3. ליצור תבניות מותאמות אישית המבוססות על הארכיטקטורה הקיימת שלך

### ש: מה השתנה עם זמינות כללית של ההרחבה Foundry?
**ת**: חבילת `microsoft.foundry` הגיעה לגרסת 1.0 וזמינה כללית ב-5 בנובמבר 2026. מ-AZD 1.37.0 ומעלה, השתמש ב-`azd ext install microsoft.foundry` כדי להתקין שבעה הרחבות מרכזיות עבור סוכנים, חיבורים, מבקר, פרויקטים, שגרות, כישורים וארגז כלים. זו אינה מרחב פקודות חדש, וההרכיבים שלה מתעדכנים בנפרד. הערכות, מערכי נתונים, כיוונון עדין ודגמים מותאמים מותקנים בנפרד; תכונות תצוגה מוקדמת אופציונליות אינן נהפכות לזמינות כללית רק בגלל שזו זמינה כללית.

ההדרכה של [hosted-agent](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) משתמשת ב-Python 3.13+ וב-uv העדכנית. `azd ai agent run` פותח את Agent Inspector באופן מקומי, אך הקריאות למודל עדיין משתמשות ב-Azure וגוררות חיובים. מצב קוד `azd deploy` מעלה מקור לבנייה מרוחקת ללא צורך בבנייה מקומית במכולה.

### ש: האם `azd down` מסיר סוכן מאוחסן מפרויקט Foundry קיים?
**ת**: לא עבור מסלול הפרויקט הממוחזר המתואר במדריך ההתחלה של hosted-agent: הוא משאיר את הפרויקט, הסוכן המאוחסן, ומשאבים אחרים במקומם. הסר משאבים לא רצויים בנפרד מבלי למחוק משאבים משותפים. אם הסביבה יצרה פרויקט Foundry חדש, `azd down` מוחק את קבוצת המשאבים שלו ואת כל מה שבתוכה. עיין ב-[הנחיות ניקוי](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#7-clean-up-deliberately) והנחיות למחיקה לפני האישור.

## אימות וגישה

### ש: כיצד מאמתים עם Azure באמצעות azd?
**ת**: השתמש ב-`azd auth login` שיפתח חלון דפדפן לאימות Azure. לתרחישי CI/CD, השתמש ב-service principals או identities מנוהלים.

### ש: האם אפשר להשתמש ב-azd עם מספר מנויים ב-Azure?
**ת**: כן. השתמש ב-`azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` כדי לציין איזה מנוי להשתמש עבור כל סביבה.

### ש: אילו הרשאות דרושות לפריסה עם azd?
**ת**: בדרך כלל נדרש:
- תפקיד **Contributor** בקבוצת המשאבים או במנוי
- תפקיד **User Access Administrator** אם מבצעים פריסת משאבים שדורשים הקצאת תפקידים
- הרשאות ספציפיות משתנות בהתאם לתבנית ולמשאבים המפורסים

### ש: האם אפשר להשתמש ב-azd בצינורות CI/CD?
**ת**: בהחלט! azd מתוכנן לשילוב עם CI/CD. השתמש ב-service principals לאימות והגדר משתני סביבה להגדרות.

### ש: כיצד מטפלים באימות ב-GitHub Actions?
**ת**: העדף פדרציית זהויות עבודה (OIDC), המוגדרת עם `azd pipeline config`. זרימת העבודה שנוצרה מתקינה את AZD ומאמתת את AZD ישירות עם זהות מאוחדת. שלב `azure/login` בלבד אינו מבצע התחברות ל-AZD. שלב התחברות בתוך משימה קיימת הוא:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

בצע פריסה לאחר ההתחברות, עם הסביבה, המנוי והמיקום של AZD שהוגדרו. האימות המאוחד חייב לסמוך על מאגר/סניף זרימת העבודה או סביבה של GitHub, ותפקידי Azure שלו חייבים לאפשר את הפעולות המתבקשות.

## תבניות ופרויקטים

### ש: היכן ניתן למצוא תבניות azd?
**ת**: 
- תבניות רשמיות וקהילתיות: [Awesome AZD](https://azure.github.io/awesome-azd/)
- תבניות קהילתיות: חיפוש GitHub ל-"azd-template"
- השתמש ב-`azd template list` כדי לעיין בתבניות הזמינות

### ש: כיצד ליצור תבנית מותאמת אישית?
**ת**: 
1. התחלת ממבנה תבנית קיים
2. שינוי `azure.yaml`, קבצי תשתית וקוד היישום
3. בדיקה יסודית עם `azd up`
4. פרסום ל-GitHub עם תגיות מתאימות

### ש: האם אפשר להשתמש ב-azd בלי תבנית?
**ת**: כן, השתמש ב-`azd init` בפרויקט קיים ליצירת קבצי התצורה הנחוצים. תצטרך להגדיר ידנית את `azure.yaml` וקבצי התשתית.

### ש: מה ההבדל בין תבניות רשמיות לתבניות קהילתיות?
**ת**: 
- **תבניות רשמיות**: מתוחזקות על ידי מייקרוסופט, מתעדכנות בקביעות, עם תיעוד מקיף
- **תבניות קהילתיות**: נוצרות על ידי מפתחים, יכולות להיות בְּעֵינַיִם מיוחדות, איכות ותחזוקה משתנות

### ש: כיצד לעדכן תבנית בפרויקט שלי?
**ת**: תבניות אינן מתעדכנות אוטומטית. באפשרותך:
1. להשוות ולמזג שינויים מהתבנית המקורית באופן ידני
2. להתחיל מחדש עם `azd init` תוך שימוש בתבנית המעודכנת
3. לבחור שיפורים ספציפיים מתבניות מעודכנות

## פריסה ותשתית

### ש: אילו שירותי Azure azd יכול לפרוס?
**ת**: azd יכול לפרוס כל שירות Azure דרך תבניות Bicep/ARM, כולל:
- שירותי אפליקציה, יישומי מכולות, פונקציות
- מסדי נתונים (SQL, PostgreSQL, Cosmos DB)
- אחסון, Key Vault, Application Insights
- משאבי רשת, אבטחה וניטור

### ש: האם אפשר לפרוס לאזורים מרובים?
**ת**: כן, הגדר אזורים מרובים בתבניות Bicep שלך והגדר את פרמטר המיקום בהתאם לכל סביבה.

### ש: כיצד מתמודדים עם מיגרציות סכמות מסד נתונים?
**ת**: השתמש ב-hooks פריסה ב-`azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### ש: האם אפשר לפרוס רק תשתית ללא יישומים?
**ת**: כן, השתמש ב-`azd provision` כדי לפרוס רק את רכיבי התשתית המוגדרים בתבניות.

### ש: כיצד לפרוס למשאבי Azure קיימים?
**ת**: כן, כאשר התבנית תומכת בכך. הפנה למשאבים קיימים עם הצהרות `existing` של Bicep או לפרמטרים המתועדים של משאבים קיימים בתבנית, ומפה שירותי יישום ליעדים המתוכננים שלהם. זה אינו מייבא בעלות ואינו יוצר הרשאות חסרות באופן אוטומטי. עיין בתבנית לפני הפריסה.

### ש: האם אפשר להשתמש ב-Terraform במקום Bicep?
**ת**: כן. AZD תומך גם ב-Terraform וגם ב-Bicep. בחר תבנית מבוססת Terraform או הגדר `infra.provider: terraform` ב-`azure.yaml`, עם קבצי Terraform מתאימים ותחום/הגדרות backend. ראה את [זרימת העבודה של Terraform](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## תצורה וסביבות

### ש: כיצד מנהלים סביבות שונות (פיתוח, סטייגינג, פרוד)?
**ת**: צור סביבות נפרדות עם `azd env new <environment-name>` והגדר הגדרות שונות לכל אחת:
```bash
azd env new development
azd env new staging  
azd env new production
```

### ש: איפה נשמרות הגדרות הסביבה?
**ת**: בתיקיית `.azure` בתוך ספריית הפרויקט שלך. לכל סביבה יש תיקייה נפרדת עם קבצי תצורה.

### ש: כיצד מגדירים תצורת סביבה ספציפית?
**ת**: השתמש ב-`azd env set` להגדרת משתני סביבה:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### ש: האם אפשר לשתף הגדרות סביבה בין חברי צוות?
**ת**: תיקיית `.azure` מכילה מידע רגיש ואינה צריכה להיות מחויבת לניהול גרסאות. במקום זאת:
1. תעד משתני סביבה נדרשים
2. השתמש בסקריפטים לפריסה כדי להגדיר סביבות
3. השתמש ב-Azure Key Vault להגדרות רגישות

### ש: כיצד משנים ברירות מחדל של תבנית?
**ת**: הגדר משתני סביבה התואמים לפרמטרי התבנית:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

משתנים שאינם בשימוש על ידי התבנית אינם משפיעים על הפריסה. `SKU_NAME` למעלה הוא דוגמה לקלט מותאם אישית, לא הגדרת AZD אוניברסלית.

## פתרון תקלות

### ש: מדוע `azd up` נכשל?
**ת**: סיבות נפוצות:
1. **בעיות אימות**: הרץ `azd auth login`
2. **הרשאות חסרות**: בדוק את הקצאות התפקידים שלך ב-Azure
3. **התנגשויות בשמות משאבים**: עיין במשאב המתנגש ובקלטי השמות של התבנית; צור סביבה נפרדת עם `azd env new` כשנדרשת הפרדה
4. **בעיות מכסת קיבולת**: בדוק זמינות אזורית
5. **שגיאות בתבנית**: אמת תבניות Bicep

### ש: כיצד לאבחן כישלונות פריסה?
**ת**: 
1. השתמש ב-`azd deploy --debug` לפלט מפורט
2. בדוק היסטוריית פריסות בפורטל Azure
3. עיין ביומן הפעילות בפורטל Azure
4. השתמש ב-`azd show` כדי להציג את מצב הסביבה הנוכחי

### ש: מדוע משתני הסביבה שלי לא עובדים?
**ת**: בדוק:
1. שמות המשתנים תואמים במדויק לפרמטרי התבנית
2. ערכים מובאים במרכאות כראוי אם הם מכילים רווחים
3. הסביבה נבחרה: `azd env select <environment>`
4. משתנים מוגדרים בסביבה הנכונה

### ש: כיצד לנקות פריסות שנכשלו?
**ת**: 
```bash
azd down
```
 עיין בסביבה שנבחרה ובאישור המחיקה תחילה. זה מוחק משאבי Azure שסופקו, לא את תצורת הסביבה המקומית `.azure`. `--purge` מבקש בנוסף מחיקה תמידית של משאבים נמחקים רכים הנתמכים ועלול להיחסם על ידי הגנה על שמירת נתונים/ניקוי; אינו שלב שיקום שגרתי.

### ש: מדוע היישום שלי אינו נגיש לאחר פריסה?
**ת**: בדוק:
1. הפריסה הושלמה בהצלחה
2. היישום פועל (בדוק לוגים בפורטל Azure)
3. קבוצות האבטחה ברשת מאפשרות תעבורה
4. DNS/דומיינים מותאמים מוגדרים כראוי

## עלות וחשבוניות

### ש: כמה יעלו פריסות azd?
**ת**: העלויות תלויות ב:
- שירותי Azure שפורסמו
- דרגות שירות/SKU שנבחרו
- הבדלים במחירי אזורים
- דפוסי שימוש

השתמש ב-[מחשב המחירים של Azure](https://azure.microsoft.com/pricing/calculator/) להערכות.

### ש: כיצד לשלוט בעלויות בפריסות azd?
**ת**: 
1. השתמש ב-SKU בדרגה נמוכה יותר לסביבות פיתוח
2. הגדר תקציבים והתראות ב-Azure
3. השתמש ב-`azd down` להסרת משאבים כשאינם נדרשים
4. בחר אזורים מתאימים (העלויות משתנות לפי מיקום)
5. השתמש בכלי Azure Cost Management

### ש: האם יש אפשרויות שכבת חינם לתבניות azd?
**ת**: ישנם שירותים עם גרסאות חינמיות או מענקים חודשיים, בכפוף לזכאות, תכנית אירוח, אזור ומגבלות מנוי. אלה לא הופכות תבנית שלמה לחינמית: מסדי נתונים, חיפוש, רשת, רישום, טלמטריה, ואינפרנס של מודלים עשויים לגרום לחיובים נפרדים. בדוק את [רשימת השירותים החינמיים של Azure](https://azure.microsoft.com/free/) ואת התמחור הנוכחי לכל משאב לפני פריסה.

### ש: איך אני מעריך עלויות לפני פריסה?
**ת**: 
1. סקור את `main.bicep` של התבנית כדי לראות אילו משאבים נוצרים
2. השתמש במחשבון התמחור של Azure עם גרסאות ספציפיות
3. פרוס תחילה לסביבת פיתוח כדי לנטר עלויות אמיתיות
4. השתמש בניהול עלויות Azure לניתוח מפורט של העלויות

## שיטות מומלצות

### ש: מהם השיטות המומלצות למבנה פרויקט azd?
**ת**: 
1. שמור את קוד היישום נפרד מתשתית
2. השתמש בשמות שירות משמעותיים ב-`azure.yaml`
3. יישם טיפול שגיאות נכון בסקריפטים של בנייה
4. השתמש בקונפיגורציה ייחודית לסביבה
5. כלל תיעוד מקיף

### ש: איך לארגן שירותים מרובים ב-azd?
**ת**: השתמש במבנה המומלץ:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### ש: האם עליי להתחייב לתיקיית `.azure` בבקרת גרסאות?
**ת**: **לא!** תיקיית `.azure` כוללת מידע רגיש. הוסף אותה ל-`.gitignore`:
```gitignore
.azure/
```

### ש: איך לטפל בסודות וקונפיגורציה רגישים?
**ת**: 
1. השתמש ב-Azure Key Vault לסודות
2. הפנה לסודות Key Vault בקונפיגורציית היישום
3. לעולם אל תתחייב סודות לבקרת גרסאות
4. השתמש בזיהויים מנוהלים לאימות שירות לשירות

### ש: מה הגישה המומלצת ל-CI/CD עם azd?
**ת**: 
1. השתמש בסביבות נפרדות לכל שלב (פיתוח/בדיקות/ייצור)
2. יישם בדיקות אוטומטיות לפני פריסה
3. השתמש ב-Service Principals לאימות
4. אחסן קונפיגורציה רגיש בקונפיגורציית סקריפטים/סודיים
5. יישם שערי אישור לפריסות בייצור

## נושאים מתקדמים

### ש: האם אפשר להרחיב את azd עם פונקציונליות מותאמת?
**ת**: כן, באמצעות deployment hooks ב-`azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### ש: איך להשתלב עם תהליכי DevOps קיימים באמצעות azd?
**ת**: 
1. השתמש בפקודות azd בסקריפטים קיימים של צינור
2. תקן תבניות azd בין צוותים
3. שלב עם ניטור והתרעה קיימים
4. השתמש בפלט JSON של azd לאינטגרציה עם הצינור

### ש: האם אפשר להשתמש ב-azd עם Azure DevOps?
**ת**: כן, azd עובד עם כל מערכת CI/CD. צור צינורות Azure DevOps שמשתמשים בפקודות azd.

### ש: איך לתרום ל-azd או ליצור תבניות קהילה?
**ת**: 
1. **כלי azd**: תרום ל-[Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **תבניות**: עקוב אחרי [הוראות לתרומת גלריית Awesome AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **תיעוד**: תרום למסמכים ב-[MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### ש: מה מפת הדרך של azd?
**ת**: בדוק את [מפת הדרך הרשמית](https://github.com/Azure/azure-dev/projects) עבור תכונות ושיפורים מתוכננים.

### ש: איך להמיר מכלים אחרים לפריסת azd?
**ת**: 
1. נתח את ארכיטקטורת הפריסה הנוכחית
2. צור תבניות Bicep מקבילות
3. קבע תצורת `azure.yaml` להתאמה לשירותים הקיימים
4. בדוק היטב בסביבת פיתוח
5. העבר סביבות בהדרגה
