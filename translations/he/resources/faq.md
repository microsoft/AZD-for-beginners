## התחלה מהירה

### ש: מה זה Azure Developer CLI (azd)?
**ת**: Azure Developer CLI (azd) הוא כלי שורת פקודה הממוקד במפתחים, שמזרז את הזמן שלוקח לך להוציא את האפליקציה שלך מסביבת הפיתוח המקומית אל Azure. הוא מספק שיטות עבודה מומלצות דרך תבניות ועוזר בכל מחזור החיים של הפריסה.

### ש: איך azd שונה מ-Azure CLI?
**ת**: 
- **Azure CLI**: כלי כללי לניהול משאבי Azure
- **azd**: כלי ממוקד מפתחים לזרימות עבודה של פריסת יישומים
- ל-azd יש תהליך אימות ופריסה משלו; Azure CLI הוא כלי נפרד ומשלים
- azd כולל תבניות, ניהול סביבות ואוטומציה של פריסה

### ש: האם יש צורך להתקין Azure CLI כדי להשתמש ב-azd?
**ת**: לא לשלבי העבודה המרכזיים של AZD. תוכל לאמת עם `azd auth login`. התקנת Azure CLI מבוצעת בנפרד כאשר תבנית תלויה או תרגיל מריץ במפורש את פקודות `az`.

### ש: באילו שפות תכנות azd תומך?
**ת**: azd אינה תלויה בשפה. היא פועלת עם:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- אתרי אינטרנט סטטיים
- אפליקציות ממונעות בקונטיינרים

### ש: האם אפשר להשתמש ב-azd עם פרויקטים קיימים?
**ת**: בהחלט! אפשר:
1. להשתמש ב-`azd init` כדי להוסיף הגדרת azd לפרויקטים קיימים
2. להתאים את מבנה הפרויקטים הקיימים לתבנית azd
3. ליצור תבניות מותאמות אישית בהתבסס על הארכיטקטורה הקיימת

## אימות וגישה

### ש: איך מאמתים עם Azure בעזרת azd?
**ת**: השתמש ב-`azd auth login` שיפתח דפדפן לאימות Azure. עבור תרחישי CI/CD, השתמש ב-service principals או זהויות מנוהלות.

### ש: האם אפשר להשתמש ב-azd עם מספר מנויים של Azure?
**ת**: כן. השתמש ב-`azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` כדי לציין איזה מנוי להשתמש עבור כל סביבה.

### ש: אילו הרשאות דרושות לי לפריסה עם azd?
**ת**: בדרך כלל דרושות:
- תפקיד **Contributor** בקבוצת המשאבים או במנוי
- תפקיד **User Access Administrator** אם מפרסים משאבים שדורשים הקצאות תפקידים
- הרשאות ספציפיות משתנות בהתאם לתבנית ולמשאבים בפריסה

### ש: האם אפשר להשתמש ב-azd בצינורות CI/CD?
**ת**: בהחלט! azd מיועד לאינטגרציה עם CI/CD. השתמש ב-service principals לאימות והגדר משתני סביבה עבור ההגדרות.

### ש: איך מטפלים באימות ב-GitHub Actions?
**ת**: מומלץ להשתמש בפדרציית זהות משימות (OIDC), המוגדרת עם `azd pipeline config`. תהליך העבודה שנוצר מתקין את AZD ומאמת ישירות את AZD עם זהות מפודרת. שלב `azure/login` לבדו אינו מקים כניסה ל-AZD. שלב כניסה בתוך משימה קיימת הוא:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

הפרוס או בצע פריסה לאחר הכניסה, עם סביבת AZD, מנוי ומיקום המוגדרים כראוי. תעודת האימות של הזהות חייבת לסמוך על מאגר/ריפו/הגדרת סביבה של תהליך העבודה, ותפקידי Azure שלה חייבים לאפשר את הפעולות המבוקשות.

## תבניות ופרויקטים

### ש: איפה אפשר למצוא תבניות של azd?
**ת**: 
- תבניות רשמיות וקהילתיות: [Awesome AZD](https://azure.github.io/awesome-azd/)
- תבניות קהילתיות: חיפוש ב-GitHub עבור "azd-template"
- השתמש ב-`azd template list` לגלישה בתבניות זמינות

### ש: איך יוצרים תבנית מותאמת אישית?
**ת**: 
1. התחל במבנה תבנית קיים
2. ערוך את `azure.yaml`, קבצי תשתית, וקוד האפליקציה
3. בדוק בקפידה עם `azd up`
4. פרסם ב-GitHub עם תגיות מתאימות

### ש: האם אפשר להשתמש ב-azd בלי תבנית?
**ת**: כן, השתמש ב-`azd init` בפרויקט קיים כדי ליצור את קבצי ההגדרות הנדרשים. תצטרך להגדיר ידנית את `azure.yaml` וקבצי התשתית.

### ש: מה ההבדל בין תבניות רשמיות לקהילתיות?
**ת**: 
- **תבניות רשמיות**: מנוהלות על ידי מיקרוסופט, מתעדכנות באופן שגרתי, توثيق מקיף
- **תבניות קהילתיות**: נוצרו על ידי מפתחים, כוללות מקרים מיוחדים ושימושים מגוונים, איכות ותחזוקה משתנים

### ש: איך מעדכנים תבנית בפרויקט שלי?
**ת**: תבניות לא מתעדכנות אוטומטית. ניתן:
1. להשוות ולמזג שינויים ידנית מהתבנית המקורית
2. להתחיל מחדש עם `azd init` תוך שימוש בתבנית המעודכנת
3. לבחור שיפורים ספציפיים מהתבניות המעודכנות

## פריסה ותשתית

### ש: אילו שירותי Azure azd יכול לפרוס?
**ת**: azd יכול לפרוס כל שירות Azure דרך תבניות Bicep/ARM, כולל:
- שירותי אפליקציה, אפליקציות קונטיינרים, פונקציות
- מסדי נתונים (SQL, PostgreSQL, Cosmos DB)
- אחסון, Key Vault, Application Insights
- רשתות, אבטחה ומשאבי ניטור

### ש: האם אפשר לפרוס לאזורים מרובים?
**ת**: כן, הגדר אזורים מרובים בתבניות Bicep שלך והגדר את פרמטר המיקום בהתאם לכל סביבה.

### ש: איך מתמודדים עם מיגרציות סכמות במסד הנתונים?
**ת**: השתמש ב-hooks לפריסה ב-`azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### ש: האם אפשר לפרוס רק תשתית בלי אפליקציות?
**ת**: כן, השתמש ב-`azd provision` לפריסת מרכיבי התשתית בלבד כפי שהוגדרו בתבניות.

### ש: איך לפרוס למשאבי Azure קיימים?
**ת**: כן, כאשר התבנית תומכת בכך. התייחס למשאבים קיימים באמצעות הצהרות `existing` של Bicep או פרמטרים המתועדים בתבנית עבור משאבים קיימים, ומפה שירותי אפליקציה ליעדים המיועדים להם. זה אינו מייבא בעלות או יוצר הרשאות חסרות אוטומטית. יש לסקור את התבנית לפני הפריסה.

### ש: האם אפשר להשתמש ב-Terraform במקום Bicep?
**ת**: כן. AZD תומך ב-Terraform בנוסף ל-Bicep. בחר תבנית מבוססת Terraform או הגדר `infra.provider: terraform` בתוך `azure.yaml`, עם קבצי Terraform והגדרות מצב/backend מתאימות. ראה את [זרימת העבודה של Terraform](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## הגדרות וסביבות

### ש: איך מנהלים סביבות שונות (dev, staging, prod)?
**ת**: צור סביבות נפרדות עם `azd env new <environment-name>` והגדר משתנים שונים לכל אחת:
```bash
azd env new development
azd env new staging  
azd env new production
```

### ש: איפה נשמרות הגדרות הסביבה?
**ת**: בתיקיית `.azure` בתוך ספריית הפרויקט שלך. לכל סביבה יש תיקייה נפרדת עם קבצי הגדרות.

### ש: איך להגדיר תצורת סביבה ספציפית?
**ת**: השתמש ב-`azd env set` להגדרת משתני סביבה:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### ש: האם אפשר לשתף הגדרות סביבה בין חברי צוות?
**ת**: תיקיית `.azure` מכילה מידע רגיש ואין להכניסה לניהול גרסאות. במקום זאת:
1. תעד את משתני הסביבה הנדרשים
2. השתמש בסקריפטים לפריסה ליצירת הסביבות
3. השתמש ב-Azure Key Vault עבור תצורות רגישות

### ש: איך לעקוף הגדרות ברירת מחדל בתבנית?
**ת**: הגדר משתני סביבה התואמים לפרמטרים בתבנית:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

רק משתנים שנצרכים על ידי התבנית ישפיעו על הפריסה. `SKU_NAME` לעיל הוא דוגמה לקלט מותאם אישית, לא הגדרה כללית של AZD.

## פתרון תקלות

### ש: למה `azd up` נכשל?
**ת**: סיבות נפוצות:
1. **בעיות אימות**: הרץ `azd auth login`
2. **הרשאות לא מספיקות**: בדוק את הקצאות התפקידים שלך ב-Azure
3. **קונפליקטים בשם המשאב**: עיין בשם המשאב המתנגש וקלטי השם בתבנית; צור סביבה נפרדת עם `azd env new` כאשר נדרשת בידוד
4. **בעיות מכסה/קיבולת**: בדוק זמינות אזורית
5. **שגיאות בתבנית**: אמת תבניות Bicep

### ש: איך לא לבחון כשיש כישלונות בפריסה?
**ת**: 
1. השתמש ב-`azd deploy --debug` לפלט מפורט
2. בדוק היסטוריית פריסה בפורטל Azure
3. עיין ביומן הפעילות בפורטל Azure
4. השתמש ב-`azd show` להצגת מצב הסביבה הנוכחי

### ש: למה משתני הסביבה שלי לא עובדים?
**ת**: בדוק:
1. שמות המשתנים תואמים בדיוק לפרמטרי התבנית
2. הערכים מוקפים במירכאות אם הם כוללים רווחים
3. הסביבה הנכונה נבחרה: `azd env select <environment>`
4. המשתנים מוגדרים בסביבה הנכונה

### ש: איך לנקות פריסות שנכשלו?
**ת**: 
```bash
azd down
```
 עיין בסביבה שנבחרה ובאישור המחיקה תחילה. זה מוחק משאבי Azure שסופקו, לא את קובצי הגדרת הסביבה המקומיים `.azure`. `--purge` מבצע בקשה למחיקה קבועה של משאבים שנמחקו רכה ותלויים בהגנות שמירת זיכרון/ניקוי; איננו שלב שגרתי לשחזור.

### ש: למה האפליקציה שלי לא נגישה אחרי פריסה?
**ת**: בדוק:
1. הפריסה הושלמה בהצלחה
2. האפליקציה פועלת (בדוק יומנים בפורטל Azure)
3. קבוצות אבטחת הרשת מאפשרות תנועה
4. DNS/דומיינים מותאמים מוגדרים נכון

## עלויות וחשבוניות

### ש: כמה יעלו פריסות azd?
**ת**: העלויות תלויות ב:
- שירותי Azure שנפרסו
- שכבות שירות/SKU שנבחרו
- הבדלים במחירים אזוריים
- דפוסי שימוש

השתמש במחשבון המחירים של [Azure Pricing Calculator](https://azure.microsoft.com/pricing/calculator/) לאומדנים.

### ש: איך לשלוט בעלויות בפריסות azd?
**ת**: 
1. השתמש ב-SKU ברמה נמוכה יותר בסביבות פיתוח
2. הגדר תקציבים והתראות ב-Azure
3. השתמש ב-`azd down` להסרת משאבים כשלא דרושים
4. בחר אזורים מתאימים (העלויות משתנות לפי מיקום)
5. השתמש בכלי ניהול עלויות של Azure

### ש: האם יש אפשרויות שכבת חינם לתבניות azd?
**ת**: לכמה שירותים קיימים SKU חינמיים או מענקים חודשיים, בכפוף לזכאות, תכנית אירוח, אזור ומגבלות מנוי. אלו אינם משחררים תבנית שלמה: מסדי נתונים, חיפוש, רשת, רישום, טלמטריה והסקת מודל יכולים להביא לחיובים בנפרד. בדוק את [רשימת השירותים החינמיים של Azure](https://azure.microsoft.com/free/) ואת המחירים המעדכנים לפני כל פריסה.

### ש: איך להעריך עלויות לפני פריסה?
**ת**: 
1. סקור את `main.bicep` של התבנית כדי לראות אילו משאבים נוצרים
2. השתמש במחשבון מחירים של Azure עם SKU ספציפיים
3. פרוס תחילה לסביבת פיתוח לניטור עלויות אמתיות
4. השתמש בניהול עלויות של Azure לניתוח מפורט

## שיטות עבודה מומלצות

### ש: מהן שיטות העבודה המומלצות למבנה פרויקט azd?
**ת**: 
1. שמור את קוד האפליקציה נפרד מהתשתית
2. השתמש בשמות שירות משמעותיים בתוך `azure.yaml`
3. יישם טיפול שגיאות תקין בסקריפטים לבנייה
4. השתמש בהגדרות סביבתיות ספציפיות
5. הכנס תיעוד מקיף

### ש: איך לארגן שירותים מרובים ב-azd?
**ת**: השתמש במבנה המوصה:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### ש: האם כדאי להוסיף את תיקיית `.azure` לניהול גרסאות?
**ת**: **לא!** תיקיית `.azure` מכילה מידע רגיש. הוסף אותה ל-`.gitignore`:
```gitignore
.azure/
```

### שאלה: איך אני מטפל בסודות ובהגדרות רגישות?
**תשובה**: 
1. השתמש ב-Azure Key Vault עבור סודות
2. התייחס לסודות מ-Key Vault בהגדרות האפליקציה
3. אל תבצע מעולם commit לסודות במערכת ניהול גרסאות
4. השתמש בזיהויים מנוהלים לאימות בין שירותים

### שאלה: מה הגישה המומלצת ל-CI/CD עם azd?
**תשובה**: 
1. השתמש בסביבות נפרדות לכל שלב (פיתוח/ביניים/ייצור)
2. בצע בדיקות אוטומטיות לפני פריסה
3. השתמש ב-service principals לאימות
4. אחסן הגדרות רגישות בסודות/משתנים של הפייפליין
5. יישם שערי אישור לפריסות ייצור

## נושאים מתקדמים

### שאלה: האם אני יכול להרחיב את azd עם פונקציונליות מותאמת?
**תשובה**: כן, דרך ווים לפריסה ב-`azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### שאלה: איך אני משלב את azd בתהליכי DevOps קיימים?
**תשובה**: 
1. השתמש בפקודות azd בסקריפטים קיימים של הפייפליין
2. תקן תבניות azd אחידות בין הצוותים
3. שלב עם ניטור והתראות קיימים
4. השתמש ביציאת JSON של azd לאינטגרציה בפייפליין

### שאלה: האם אפשר להשתמש ב-azd עם Azure DevOps?
**תשובה**: כן, azd עובד עם כל מערכת CI/CD. צור פייפליינים ב-Azure DevOps שמשתמשים בפקודות azd.

### שאלה: איך אני תורם ל-azd או יוצר תבניות לקהילה?
**תשובה**: 
1. **כלי azd**: תרום ל-[Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **תבניות**: עקוב אחרי [הוראות תרומה לגלריית Awesome AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **תיעוד**: תרום לתיעוד ב-[MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### שאלה: מהן הדרך העתידית ל-azd?
**תשובה**: בדוק את [מפת הדרך הרשמית](https://github.com/Azure/azure-dev/projects) לתכונות מתוכננות ושיפורים.

### שאלה: איך אני מיגר מ כלי פריסה אחרים ל-azd?
**תשובה**: 
1. נתח את ארכיטקטורת הפריסה הנוכחית
2. צור תבניות Bicep שקולות
3. הכן את `azure.yaml` להתאים לשירותים הנוכחיים
4. בדוק לעומק בסביבת פיתוח
5. הגר בצורה הדרגתית את הסביבות
