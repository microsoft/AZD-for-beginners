## परिचय

यह व्यापक FAQ Azure Developer CLI (azd) और Azure तैनाती से संबंधित सबसे सामान्य प्रश्नों के उत्तर प्रदान करता है। सामान्य समस्याओं के त्वरित समाधान खोजें, सर्वोत्तम प्रथाओं को समझें, और azd अवधारणाओं और कार्यप्रवाहों पर स्पष्टीकरण प्राप्त करें।

## सीखने के लक्ष्य

इस FAQ की समीक्षा करके, आप:
- सामान्य Azure Developer CLI प्रश्नों और मुद्दों के त्वरित उत्तर पाएंगे
- व्यावहारिक प्रश्नोत्तर प्रारूप के माध्यम से मुख्य अवधारणाओं और शब्दावली को समझेंगे

- अनुकूलन से संबंधित सामान्यतः पूछे जाने वाले प्रश्नों के माध्यम से सर्वोत्तम प्रथाएं सीखें
- विशेषज्ञ स्तर के प्रश्नों के माध्यम से उन्नत सुविधाओं और क्षमताओं की जानकारी प्राप्त करें
- लागत, सुरक्षा, और तैनाती रणनीति मार्गदर्शन को प्रभावी रूप से संदर्भित करें

## शुरुआत

### प्रश्न: Azure Developer CLI (azd) क्या है?
**उत्तर**: Azure Developer CLI (azd) एक डेवलपर-केंद्रित कमांड-लाइन टूल है जो आपको आपकी एप्लिकेशन को स्थानीय विकास परिवेश से Azure पर पहुँचाने का समय कम करता है। यह टेम्प्लेट्स के माध्यम से सर्वोत्तम प्रथाएं प्रदान करता है और पूरे तैनाती जीवनचक्र में मदद करता है।

### प्रश्न: azd और Azure CLI में क्या अंतर है?
**उत्तर**: 
- **Azure CLI**: Azure संसाधनों का प्रबंधन करने के लिए सामान्य-उद्देश्य उपकरण
- **azd**: एप्लिकेशन तैनाती कार्यप्रवाहों के लिए डेवलपर-केंद्रित उपकरण
- azd के अपने प्रमाणीकरण और तैनाती कार्यप्रवाह हैं; Azure CLI अलग, पूरक उपकरण है
- azd में टेम्प्लेट, पर्यावरण प्रबंधन, और तैनाती स्वचालन शामिल हैं

### प्रश्न: क्या मुझे azd उपयोग करने के लिए Azure CLI स्थापित करना आवश्यक है?
**उत्तर**: मुख्य AZD कार्यप्रवाह के लिए आवश्यक नहीं। प्रमाणीकरण के लिए `azd auth login` का उपयोग करें। जब कोई टेम्प्लेट होक या व्यायाम स्पष्ट रूप से `az` आदेश चलाए, तब Azure CLI अलग से इंस्टॉल करें।

### प्रश्न: azd कौन-कौन सी प्रोग्रामिंग भाषाओं का समर्थन करता है?
**उत्तर**: azd भाषा-आधारित नहीं है। यह निम्नलिखित के साथ काम करता है:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- स्थैतिक वेबसाइटें
- कंटेनर आधारित एप्लिकेशन

### प्रश्न: क्या मैं azd को मौजूदा परियोजनाओं के साथ उपयोग कर सकता हूँ?
**उत्तर**: हाँ! आप या तो:
1. मौजूदा परियोजनाओं में azd कॉन्फ़िगरेशन जोड़ने के लिए `azd init` का उपयोग करें
2. मौजूदा परियोजनाओं को azd टेम्प्लेट संरचना के अनुसार अनुकूलित करें
3. अपनी मौजूदा वास्तुकला के आधार पर कस्टम टेम्प्लेट बनाएं

## प्रमाणीकरण और पहुंच

### प्रश्न: मैं azd के साथ Azure में कैसे प्रमाणित करूं?
**उत्तर**: `azd auth login` का उपयोग करें जो Azure प्रमाणीकरण के लिए एक ब्राउज़र विंडो खोलेगा। CI/CD परिदृश्यों के लिए, सेवा प्रधानों या प्रबंधित पहचानों का उपयोग करें।

### प्रश्न: क्या मैं azd को एक से अधिक Azure सबस्क्रिप्शन के साथ उपयोग कर सकता हूँ?
**उत्तर**: हाँ। प्रत्येक वातावरण के लिए इस्तेमाल किए जाने वाले सबस्क्रिप्शन को निर्दिष्ट करने के लिए `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` का उपयोग करें।

### प्रश्न: मुझे azd के साथ तैनाती के लिए कौन-कौन से अनुमतियाँ चाहिए?
**उत्तर**: आमतौर पर आपको चाहिए:
- संसाधन समूह या सबस्क्रिप्शन पर **सहयोगी (Contributor)** भूमिका
- यदि संसाधनों को भूमिका असाइनमेंट की आवश्यकता हो तो **यूजर एक्सेस एडमिनिस्ट्रेटर**
- विशिष्ट अनुमतियाँ टेम्प्लेट और तैनात संसाधनों के अनुसार भिन्न होती हैं

### प्रश्न: क्या मैं azd को CI/CD पाइपलाइनों में उपयोग कर सकता हूँ?
**उत्तर**: बिल्कुल! azd CI/CD एकीकरण के लिए डिज़ाइन किया गया है। प्रमाणीकरण के लिए सेवा प्रिंसिपल का उपयोग करें और कॉन्फ़िगरेशन के लिए पर्यावरण चर सेट करें।

### प्रश्न: मैं GitHub Actions में प्रमाणीकरण कैसे करता हूँ?
**उत्तर**: वर्कलोड आइडेंटिटी फेडरेशन (OIDC) को प्राथमिकता दें, जिसे `azd pipeline config` के साथ कॉन्फ़िगर किया गया है। उत्पन्न वर्कफ़्लो AZD स्थापित करता है और AZD को सीधे एक फेडरेटेड आइडेंटिटी के साथ प्रमाणीकरण करता है। केवल एक `azure/login` चरण AZD लॉगिन स्थापित नहीं करता। एक मौजूदा जॉब में लॉगिन चरण इस प्रकार है:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

लॉगिन के बाद प्रावधान या तैनाती करें, इच्छित AZD पर्यावरण, सबस्क्रिप्शन, और स्थान के साथ कॉन्फ़िगर किया गया। आइडेंटिटी का फेडरेटेड क्रेडेंशियल वर्कफ़्लो के रिपॉजिटरी/रेफ या GitHub वातावरण पर भरोसा करना चाहिए, और उसके Azure भूमिकाएं अनुरोधित संचालन की अनुमति देना चाहिए।

## टेम्प्लेट और प्रोजेक्ट

### प्रश्न: मैं azd टेम्प्लेट कहाँ पा सकता हूँ?
**उत्तर**: 
- आधिकारिक और सामुदायिक टेम्प्लेट: [Awesome AZD](https://azure.github.io/awesome-azd/)
- सामुदायिक टेम्प्लेट: GitHub पर "azd-template" खोजें
- उपलब्ध टेम्प्लेट ब्राउज़ करने के लिए `azd template list` का उपयोग करें

### प्रश्न: मैं कस्टम टेम्प्लेट कैसे बनाऊं?
**उत्तर**: 
1. मौजूदा टेम्प्लेट संरचना के साथ शुरू करें
2. `azure.yaml`, अवसंरचना फ़ाइलें, और एप्लिकेशन कोड संशोधित करें
3. `azd up` के साथ पूरी तरह से परीक्षण करें
4. उपयुक्त टैग के साथ GitHub पर प्रकाशित करें

### प्रश्न: क्या मैं टेम्प्लेट के बिना azd का उपयोग कर सकता हूँ?
**उत्तर**: हाँ, एक मौजूदा प्रोजेक्ट में आवश्यक कॉन्फ़िगरेशन फ़ाइलें बनाने के लिए `azd init` का उपयोग करें। आपको मैन्युअल रूप से `azure.yaml` और अवसंरचना फ़ाइलों को कॉन्फ़िगर करना होगा।

### प्रश्न: आधिकारिक और सामुदायिक टेम्प्लेट में क्या अंतर है?
**उत्तर**: 
- **आधिकारिक टेम्प्लेट**: माइक्रोसॉफ्ट द्वारा बनाए और नियमित रूप से अपडेट किए जाते हैं, व्यापक दस्तावेजीकरण के साथ
- **सामुदायिक टेम्प्लेट**: डेवलपर्स द्वारा बनाए गए, हो सकते हैं विशेष उपयोग के मामले हों, गुणवत्ता और रखरखाव में विभिन्नता हो सकती है

### प्रश्न: मैं अपने प्रोजेक्ट में टेम्प्लेट कैसे अपडेट करूं?
**उत्तर**: टेम्प्लेट अपने आप अपडेट नहीं होते। आप:
1. मैन्युअल रूप से स्रोत टेम्प्लेट से परिवर्तनों की तुलना कर मर्ज करें
2. अपडेटेड टेम्प्लेट का उपयोग करके नए सिरे से `azd init` शुरू करें
3. अपडेट किए गए टेम्प्लेट से विशिष्ट सुधार चुनें (चेरी-पिक)

## तैनाती और अवसंरचना

### प्रश्न: azd कौन सी Azure सेवाओं को तैनात कर सकता है?
**उत्तर**: azd Bicep/ARM टेम्प्लेट्स के माध्यम से किसी भी Azure सेवा को तैनात कर सकता है, जिसमें शामिल हैं:
- ऐप सर्विसेज, कंटेनर ऐप्स, फंक्शन्स
- डेटाबेस (SQL, PostgreSQL, Cosmos DB)
- स्टोरेज, की वॉल्ट, एप्लिकेशन इनसाइट्स
- नेटवर्किंग, सुरक्षा, और मॉनिटरिंग संसाधन

### प्रश्न: क्या मैं कई क्षेत्रों में तैनाती कर सकता हूँ?
**उत्तर**: हाँ, अपनी Bicep टेम्प्लेट्स में कई क्षेत्र कॉन्फ़िगर करें और प्रत्येक वातावरण के लिए स्थान पैरामीटर उपयुक्त रूप से सेट करें।

### प्रश्न: मैं डेटाबेस स्कीमा माइग्रेशन कैसे संभालूं?
**उत्तर**: `azure.yaml` में तैनाती हुक्स का उपयोग करें:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### प्रश्न: क्या मैं केवल अवसंरचना तैनात कर सकता हूँ बिना एप्लिकेशन के?
**उत्तर**: हाँ, अपने टेम्प्लेट्स में परिभाषित केवल अवसंरचना घटकों को तैनात करने के लिए `azd provision` का उपयोग करें।

### प्रश्न: मैं मौजूदा Azure संसाधनों पर तैनाती कैसे करूं?
**उत्तर**: हाँ, जब टेम्प्लेट इसका समर्थन करता है। Bicep के `existing` घोषणाओं या टेम्प्लेट के प्रलेखित मौजूदा- संसाधन पैरामीटर के साथ मौजूदा संसाधनों का संदर्भ लें, और एप्लिकेशन सेवाओं को उनके इच्छित लक्ष्यों से मैप करें। यह स्वामित्व को आयात नहीं करता और न ही स्वचालित रूप से अनुपस्थित अनुमतियाँ बनाता है। तैनाती से पहले टेम्प्लेट की समीक्षा करें।

### प्रश्न: क्या मैं Bicep के बजाय Terraform का उपयोग कर सकता हूँ?
**उत्तर**: हाँ। AZD Terraform के साथ-साथ Bicep का समर्थन करता है। Terraform-आधारित टेम्प्लेट चुनें या `infra.provider: terraform` को `azure.yaml` में उपयुक्त Terraform फ़ाइलों और स्टेट/बैकएंड कॉन्फ़िगरेशन के साथ कॉन्फ़िगर करें। देखें [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd)।

## कॉन्फ़िगरेशन और वातावरण

### प्रश्न: मैं विभिन्न वातावरणों (dev, staging, prod) का प्रबंधन कैसे करूं?
**उत्तर**: `azd env new <environment-name>` के साथ अलग-अलग वातावरण बनाएं और प्रत्येक के लिए विभिन्न सेटिंग्स कॉन्फ़िगर करें:
```bash
azd env new development
azd env new staging  
azd env new production
```

### प्रश्न: वातावरण कॉन्फ़िगरेशन कहाँ संग्रहीत होते हैं?
**उत्तर**: आपकी परियोजना निर्देशिका में `.azure` फ़ोल्डर में। प्रत्येक वातावरण की अपनी अलग- अलग कॉन्फ़िगरेशन फ़ाइलों के साथ फ़ोल्डर होती है।

### प्रश्न: मैं वातावरण-विशिष्ट कॉन्फ़िगरेशन कैसे सेट करूं?
**उत्तर**: वातावरण चरों को कॉन्फ़िगर करने के लिए `azd env set` का उपयोग करें:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### प्रश्न: क्या मैं टीम सदस्यों के बीच वातावरण कॉन्फ़िगरेशन साझा कर सकता हूँ?
**उत्तर**: `.azure` फ़ोल्डर संवेदनशील जानकारी रखता है और इसे संस्करण नियंत्रण में कमिट नहीं किया जाना चाहिए। इसके बजाय:
1. आवश्यक वातावरण चर दस्तावेज़ करें
2. वातावरण सेटअप के लिए तैनाती स्क्रिप्ट का उपयोग करें
3. संवेदनशील कॉन्फ़िगरेशन के लिए Azure Key Vault का उपयोग करें

### प्रश्न: मैं टेम्प्लेट डिफ़ॉल्ट्स को कैसे ओवरराइड करूं?
**उत्तर**: टेम्प्लेट पैरामीटर के अनुरूप पर्यावरण चर सेट करें:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

केवल टेम्प्लेट द्वारा उपयोग किए जाने वाले चर तैनाती को प्रभावित करते हैं। ऊपर `SKU_NAME` एक उदाहरण कस्टम इनपुट है, कोई सार्वभौमिक AZD सेटिंग नहीं।

## समस्या निवारण

### प्रश्न: क्यों `azd up` असफल हो रहा है?
**उत्तर**: सामान्य कारण:
1. **प्रमाणीकरण समस्याएँ**: `azd auth login` चलाएं
2. **पर्याप्त अनुमतियाँ नहीं**: अपने Azure भूमिका असाइनमेंट जांचें
3. **संसाधन नामकरण टकराव**: टकराने वाले संसाधन और टेम्प्लेट के नामकरण इनपुट की समीक्षा करें; आवश्यकता होने पर अलग वातावरण बनाने के लिए `azd env new` का उपयोग करें
4. **कोटा/क्षमता समस्याएँ**: क्षेत्रीय उपलब्धता जांचें
5. **टेम्प्लेट त्रुटियां**: Bicep टेम्प्लेट्स का सत्यापन करें

### प्रश्न: मैं तैनाती विफलताओं का डिबग कैसे करूं?
**उत्तर**: 
1. विस्तृत आउटपुट के लिए `azd deploy --debug` का उपयोग करें
2. Azure पोर्टल में तैनाती इतिहास जांचें
3. Azure पोर्टल में गतिविधि लॉग देखें
4. वर्तमान वातावरण स्थिति प्रदर्शित करने के लिए `azd show` का उपयोग करें

### प्रश्न: मेरे पर्यावरण चर काम क्यों नहीं कर रहे हैं?
**उत्तर**: जांचें:
1. चर नाम टेम्प्लेट पैरामीटर से बिल्कुल मेल खाते हों
2. यदि मानों में स्पेस हों तो वे ठीक से उद्धृत हों
3. सही वातावरण चुना गया हो: `azd env select <environment>`
4. चर सही वातावरण में सेट हों

### प्रश्न: मैं विफल तैनाती को कैसे साफ़ करूं?
**उत्तर**: 
```bash
azd down
```
सबसे पहले चयनित वातावरण और हटाने की पुष्टि की समीक्षा करें। यह प्रदान किए गए Azure संसाधनों को हटा देता है, स्थानीय `.azure` वातावरण कॉन्फ़िगरेशन को नहीं। `--purge` अतिरिक्त रूप से समर्थित सॉफ्ट-डिलीटेड संसाधनों के स्थायी हटाने का अनुरोध करता है और इसे प्रतिधारण/पर्ज सुरक्षा द्वारा ब्लॉक किया जा सकता है; यह नियमित पुनर्प्राप्ति चरण नहीं है।

### प्रश्न: तैनाती के बाद मेरा एप्लिकेशन क्यों सुलभ नहीं है?
**उत्तर**: जांचें:
1. तैनाती सफलतापूर्वक पूरी हुई हो
2. एप्लिकेशन चल रहा हो (Azure पोर्टल में लॉग जांचें)
3. नेटवर्क सुरक्षा समूह ट्रैफ़िक की अनुमति दें
4. DNS/कस्टम डोमेन सही से कॉन्फ़िगर हों

## लागत और बिलिंग

### प्रश्न: azd तैनाती की लागत कितनी होगी?
**उत्तर**: लागत निर्भर करती है:
- तैनात Azure सेवाओं पर
- चुने गए सेवा स्तर/SKU पर
- क्षेत्रीय मूल्य भिन्नताओं पर
- उपयोग पैटर्न पर

अनुमान के लिए [Azure मूल्य निर्धारण कैलकुलेटर](https://azure.microsoft.com/pricing/calculator/) का उपयोग करें।

### प्रश्न: मैं azd तैनाती में लागत कैसे नियंत्रित करूं?
**उत्तर**: 
1. विकास वातावरण के लिए निम्न-स्तर के SKU का उपयोग करें
2. Azure बजट और अलर्ट सेट करें
3. जब आवश्यकता न हो तो संसाधनों को हटाने के लिए `azd down` का उपयोग करें
4. उपयुक्त क्षेत्र चुनें (खर्च स्थान के अनुसार भिन्न होते हैं)
5. Azure लागत प्रबंधन उपकरणों का उपयोग करें

### प्रश्न: क्या azd टेम्प्लेट्स के लिए फ्री टियर विकल्प हैं?
**उत्तर**: कुछ सेवाओं के पास फ्री SKU या मासिक ग्रांट होते हैं, पात्रता, होस्टिंग योजना, क्षेत्र, और सबस्क्रिप्शन सीमाओं के अधीन। ये पूरे टेम्प्लेट को मुफ्त नहीं बनाते: डेटाबेस, सर्च, नेटवर्किंग, रजिस्ट्री, टेलीमेट्री, और मॉडल इन्फरेंस स्वतंत्र रूप से शुल्क लगा सकते हैं। तैनाती से पहले [Azure फ्री सेवाओं की सूची](https://azure.microsoft.com/free/) और प्रत्येक संसाधन की वर्तमान कीमत जांचें।

### प्रश्न: मैं तैनाती से पहले लागत का अनुमान कैसे लगाऊं?
**उत्तर**: 
1. टेम्प्लेट के `main.bicep` की समीक्षा करें कि क्या संसाधन बनाए जाते हैं
2. विशिष्ट SKU के साथ Azure मूल्य निर्धारण कैलकुलेटर का उपयोग करें
3. वास्तविक लागतों की निगरानी के लिए पहले विकास वातावरण में तैनाती करें
4. विस्तृत लागत विश्लेषण के लिए Azure लागत प्रबंधन का उपयोग करें

## सर्वोत्तम प्रथाएं

### प्रश्न: azd प्रोजेक्ट संरचना के लिए सर्वोत्तम प्रथाएं क्या हैं?
**उत्तर**: 
1. एप्लिकेशन कोड को अवसंरचना से अलग रखें
2. `azure.yaml` में सार्थक सेवा नामों का उपयोग करें
3. बिल्ड स्क्रिप्ट में उचित त्रुटि हैंडलिंग लागू करें
4. वातावरण-विशिष्ट कॉन्फ़िगरेशन का उपयोग करें
5. व्यापक दस्तावेज़ीकरण शामिल करें

### प्रश्न: मैं azd में कई सेवाओं का संगठन कैसे करूं?
**उत्तर**: अनुशंसित संरचना का उपयोग करें:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### प्रश्न: क्या मैं `.azure` फ़ोल्डर को संस्करण नियंत्रण में कमिट करूं?
**उत्तर**: **नहीं!** `.azure` फ़ोल्डर संवेदनशील जानकारी रखता है। इसे `.gitignore` में जोड़ें:
```gitignore
.azure/
```

### प्रश्न: मैं सीक्रेट्स और संवेदनशील कॉन्फ़िगरेशन को कैसे संभालूं?
**उत्तर**: 
1. सीक्रेट्स के लिए Azure Key Vault का उपयोग करें
2. एप्लिकेशन कॉन्फ़िगरेशन में Key Vault सीक्रेट्स का संदर्भ दें
3. कभी भी सीक्रेट्स को वर्शन कंट्रोल में कमिट न करें
4. सेवा-से-सेवा प्रमाणीकरण के लिए प्रबंधित पहचान (managed identities) का उपयोग करें

### प्रश्न: azd के साथ CI/CD के लिए अनुशंसित तरीका क्या है?
**उत्तर**: 
1. प्रत्येक चरण (dev/staging/prod) के लिए अलग-अलग वातावरण का उपयोग करें
2. परिनियोजन से पहले स्वचालित परीक्षण लागू करें
3. प्रमाणीकरण के लिए सेवा अधिकारी (service principals) का उपयोग करें
4. संवेदनशील कॉन्फ़िगरेशन पाइपलाइन सीक्रेट्स/वेरिएबल्स में संग्रहित करें
5. उत्पादन परिनियोजन के लिए अनुमोदन गेट लागू करें

## उन्नत विषय

### प्रश्न: क्या मैं azd को कस्टम कार्यक्षमता के साथ बढ़ा सकता हूँ?
**उत्तर**: हाँ, `azure.yaml` में परिनियोजन हुक्स के माध्यम से:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### प्रश्न: मैं azd को मौजूदा DevOps प्रक्रियाओं के साथ कैसे एकीकृत करूं?
**उत्तर**: 
1. मौजूदा पाइपलाइन स्क्रिप्ट्स में azd कमांड्स का उपयोग करें
2. टीमों के बीच azd टेम्प्लेट्स को मानकीकृत करें
3. मौजूदा निगरानी और अलर्टिंग के साथ एकीकृत करें
4. पाइपलाइन एकीकरण के लिए azd के JSON आउटपुट का उपयोग करें

### प्रश्न: क्या मैं azd को Azure DevOps के साथ उपयोग कर सकता हूँ?
**उत्तर**: हाँ, azd किसी भी CI/CD प्रणाली के साथ काम करता है। azd कमांड्स का उपयोग करने वाली Azure DevOps पाइपलाइन्स बनाएं।

### प्रश्न: मैं azd में योगदान कैसे करूं या समुदाय टेम्प्लेट्स कैसे बनाऊं?
**उत्तर**: 
1. **azd टूल**: में योगदान करें [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **टेम्पलेट्स**: अनुसरण करें [Awesome AZD गैलरी योगदान निर्देश](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **डॉक्यूमेंटेशन**: में योगदान करें डॉक्स पर [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### प्रश्न: azd के लिए रोडमैप क्या है?
**उत्तर**: जांचें [आधिकारिक रोडमैप](https://github.com/Azure/azure-dev/projects) नियोजित सुविधाओं और सुधारों के लिए।

### प्रश्न: मैं अन्य डिप्लॉयमेंट टूल्स से azd में कैसे माइग्रेट करूं?
**उत्तर**: 
1. वर्तमान डिप्लॉयमेंट आर्किटेक्चर का विश्लेषण करें
2. समतुल्य बाइसप टेम्पलेट बनाएं
3. कॉन्फ़िगर करें `azure.yaml` वर्तमान सेवाओं से मेल खाने के लिए
4. विकास पर्यावरण में पूरी तरह से परीक्षण करें
5. धीरे-धीरे वातावरण माइग्रेट करें
