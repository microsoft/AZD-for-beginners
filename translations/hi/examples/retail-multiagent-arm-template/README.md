# रिटेल मल्टी-एजेंट अवसंरचना ढांचा

**उन्नत वास्तुकला उदाहरण — कार्यशील मल्टी-एजेंट एप्लिकेशन नहीं।**

[कोर्स होम](../../README.md) ·
[अध्याय 5](../../docs/chapter-05-multi-agent/README.md) ·
[आर्किटेक्चर ब्लूप्रिंट](../retail-scenario.md)

## यह क्या तैनात करता है

इस निर्देशिका में एक ARM टेम्पलेट, पैरामीटर, और एक Bash तैनाती स्क्रिप्ट शामिल है।
कोई **`azure.yaml` या रिटेल एप्लिकेशन स्रोत** नहीं है।

| संसाधन | प्रावधान के बाद वास्तविक स्थिति |
|---|---|
| प्राथमिक Azure OpenAI खाता | `gpt-4.1-chat` तैनाती `gpt-4.1` संस्करण `2025-04-14`, `GlobalStandard` का उपयोग करके |
| द्वितीयक OpenAI खाता (वैकल्पिक) | `gpt-4.1-mini-inventory`, मॉडल `gpt-4.1-mini` संस्करण `2025-04-14`, `GlobalStandard` |
| एम्बेडिंग्स खाता (वैकल्पिक) | `text-embedding-ada-002` संस्करण `2`, `Standard`; कोई अनुक्रमण पाइपलाइन नहीं |
| ग्रेडर OpenAI खाता | `gpt-4.1-grader`, मॉडल `gpt-4.1` संस्करण `2025-04-14`, `GlobalStandard`; कोई मूल्यांकनकर्ता नहीं |
| AI खोज | खाली सेवा; कोई इंडेक्स या दस्तावेज़ नहीं |
| भंडारण | खाली `documents` और `uploads` ब्लॉब कंटेनर |
| Cosmos DB | सर्वरलेस खाता, `chathistory` डेटाबेस, `conversations` कंटेनर `/userId` द्वारा विभाजित, 30-दिन आइटम TTL |
| कंटेनर ऐप्स | राउटर और फ्रंटेंड दोनों `mcr.microsoft.com/azuredocs/containerapps-helloworld:latest` पर पोर्ट 80 पर चलते हैं |
| की वॉल्ट (वैकल्पिक) | खाली RBAC-सक्षम वॉल्ट; **कोई सीक्रेट्स या भूमिका असाइनमेंट नहीं** |
| एप्लिकेशन इंसाइट्स / लॉग एनालिटिक्स (वैकल्पिक) | संसाधन और पर्यावरण लॉग संग्रह; कोई कस्टम ऐप इंस्ट्रुमेंटेशन, अलर्ट या डैशबोर्ड नहीं |
| दस्तावेज़ खुफिया | S0 खाता; कोई दस्तावेज़ प्रोसेसिंग वर्कफ़्लो नहीं |

लेगेसी Bing Search v7 को 11 अगस्त, 2025 को रिटायर किया गया था और **प्रावधानित नहीं** किया गया है।
कोई प्रतिस्थापन वेब-ग्राउंडिंग इंटीग्रेशन लागू नहीं है।

**शामिल नहीं है:** ग्राहक/इन्वेंटरी एजेंट्स, राउटर `/chat` API, फ्रंटेंड चैट UI,
खोज स्कीमा या इन्गेस्टन स्क्रिप्ट्स, Azure कंटेनर रजिस्ट्री, प्राइवेट एंडपॉइंट्स,
प्रबंधित पहचान, RBAC असाइनमेंट्स, स्वचालित फेलओवर, फ्रंट डोर, रेड-टीम
स्कैनर, मूल्यांकन CLI, प्रमाणीकरण, या CI/CD।

एक ARM सफलता संदेश केवल संसाधन प्रावधान की पुष्टि करता है। यह प्रमाणित नहीं करता
एप्लिकेशन की कार्यक्षमता, सुरक्षा, उपलब्धता, या उत्पादन तत्परता।

## पूर्वापेक्षाएँ और लागतें

- Bash (Git Bash/WSL ऑन Windows) और
  [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)।
- एक सब्सक्रिप्शन जिसमें सूचीबद्ध सभी संसाधन बनाने की अनुमति हो।
- **प्रत्येक मॉडल/संस्करण/SKU प्रत्येक चयनित क्षेत्र में** उपलब्धता की जांच करें और
  अपने सब्सक्रिप्शन के लिए कोटा। डिफ़ॉल्ट उदाहरण हैं, गारंटी नहीं।
  परामर्श करें [मॉडल उपलब्धता](https://learn.microsoft.com/azure/ai-services/openai/concepts/models)।
- एक समर्पित संसाधन समूह चुनें जिसे आप परीक्षण के बाद हटा सकते हैं।

```bash
az version
az login
az account show --query "{subscription:id,name:name}" -o table
az cognitiveservices usage list --location eastus2 -o table
```

डिफ़ॉल्ट स्थान: प्राथमिक `eastus2`, द्वितीयक `westus2`, एम्बेडिंग्स `francecentral`;
ग्रेडर डिफ़ॉल्ट रूप से प्राथमिक क्षेत्र के लिए होता है जब तक कि `graderLocation` न दिया गया हो।
`--no-multi-region` द्वितीयक और एम्बेडिंग खाते को छोड़ देता है; यह
ग्रेडर खाता।

खोज तब भी शुल्क लिया जाता है जब खाली होते हुए भी प्रविधानित किया जाता है। कंटेनर न्यूनतम प्रतिकृतियाँ,
स्टोरेज redundancy, Cosmos DB अनुरोध/स्टोरेज, मॉडल टोकन, दस्तावेज़ इंटेलिजेंस
कॉल्स, और लॉग इनजेशन/स्टोरेज में शुल्क जोड़ सकते हैं। कोई **निश्चित या मान्य मासिक कुल** नहीं है।
सटीक SKU का अनुमान लगाएँ
[Azure मूल्य निर्धारण कैलकुलेटर](https://azure.microsoft.com/pricing/calculator/) में और
तैनाती से पहले बजट निर्धारित करें।

### तैनाती मोड

ये सेटिंग्स संसाधन आकार हैं, **प्रोडक्शन या SLA प्रमाणपत्र नहीं**:

| मोड | चैट / मिनी / एम्बेडिंग / ग्रेडर क्षमता इकाइयाँ | राउटर प्रतिकृतियाँ | फ्रंटेंड प्रतिकृतियाँ | खोज स्तर | स्टोरेज |
|---|---|---|---|---|---|
| न्यूनतम | 10 / 10 / 20 / 5 | 0–3 | 1–2 | बेसिक, 1 प्रतिकृति | Standard_LRS |
| मानक | 20 / 15 / 30 / 15 | 1–3 | 1–2 | मानक, 1 प्रतिकृति | Standard_ZRS |
| प्रीमियम | 40 / 30 / 60 / 30 | 1–10 | 1–5 | standard2, 2 प्रतिकृतियाँ | Standard_GRS |

मॉडल क्षमता इकाइयाँ मॉडल/SKU-विशिष्ट हैं; इन्हें एक सार्वभौमिक TPM
गारंटी के रूप में जोड़ें नहीं। प्रीमियम ज़ोन-रेडंडेंट कंटेनर ऐप्स सक्षम नहीं करता: इसके लिए
अतिरिक्त नेटवर्क डिज़ाइन की आवश्यकता होती है। बेसिक खोज वेक्टर सर्च का समर्थन करता है,
सेवा सीमाओं के अधीन; यह स्वाभाविक रूप से वेक्टर से असंगत नहीं है।

## 🚀 त्वरित तैनाती

पहले `azuredeploy.json` और `azuredeploy.parameters.json` की समीक्षा करें। नीचे दिए गए कमांड्स
**बिल योग्य Azure संसाधन बनाते हैं**; ये ऑफ़लाइन जांच नहीं हैं।

रिपॉज़िटरी रूट से:

```bash
cd examples/retail-multiagent-arm-template
bash deploy.sh --help
bash deploy.sh -g retail-learning-rg -m minimal --no-multi-region
```

स्क्रिप्ट अपनी डायरेक्टरी के सापेक्ष पथों का उपयोग करती है, लॉगिन/टूल्स/आर्गुमेंट्स की जांच करती है,
संसाधन समूह बनाती है यदि अनुपस्थित हो, तैनाती को मान्य करती है, प्रविधानित करती है, और
गैर-गोपनीय आउटपुट दिखाती है। कोई `jq`, डेटा पॉप्युलेशन, गुप्त पुनःप्राप्ति, या
पोस्ट-तैनाती एप्लिकेशन सेटअप आवश्यक या किया नहीं जाता।

स्क्रिप्ट के डिफ़ॉल्ट कमांड-लाइन मान पैरामीटर फ़ाइल के अनुरूप मानों को ओवरराइड करते हैं।
सेकेंडरी/टेर्शियरी क्षेत्रों जैसे सेटिंग के लिए पैरामीटर फ़ाइल संपादित करें;
यदि आपको मनमाने पैरामीटर ओवरराइड की आवश्यकता है तो डायरेक्ट CLI तैनाती का उपयोग करें:

```bash
az group create --name retail-learning-rg --location eastus2
az deployment group create \
  --resource-group retail-learning-rg \
  --name retail-learning \
  --template-file azuredeploy.json \
  --parameters azuredeploy.parameters.json \
  --parameters projectName=retail environmentName=dev \
    deploymentMode=minimal enableMultiRegion=false
```

प्रविधान में 15–45 मिनट या अधिक लग सकते हैं, और क्षेत्रीय कोटा या
मॉडल जीवनचक्र प्रतिबंधों पर विफल हो सकता है। अंधाधुंध पुनः प्रयास न करें: पहले विफल ऑपरेशन पढ़ें।

## विन्यास विकल्प

| पैरामीटर | टेम्पलेट में डिफ़ॉल्ट | अर्थ |
|---|---|---|
| `projectName` | आवश्यक (`retail` पैरामीटर फ़ाइल में) | 3–10 लोअरकेस अक्षर/संख्या |
| `location` | संसाधन समूह स्थान | प्राथमिक क्षेत्र (`eastus2` पैरामीटर फ़ाइल में) |
| `secondaryLocation` | `westus2` | मिनी मॉडल खाता क्षेत्र |
| `tertiaryLocation` | `francecentral` | एम्बेडिंग्स खाता क्षेत्र |
| `graderLocation` | प्राथमिक क्षेत्र | स्वतंत्र ग्रेडर खाता क्षेत्र |
| `environmentName` | `dev` | `dev`, `staging`, या `prod`; केवल नाम, कोई हार्डनिंग टॉगल नहीं |
| `deploymentMode` | `standard` | SKU/क्षमता चयन |
| `enableMultiRegion` | `true` | द्वितीयक और एम्बेडिंग खाते जोड़ें |
| `enableMonitoring` | `true` | Insights/कार्यस्थान और पर्यावरण लॉग संग्रह जोड़ें |
| `enableSecurity` | `true` | केवल एक खाली RBAC-सक्षम वॉल्ट बनाएं |

भ्रामक `openAiApiVersion` पैरामीटर हटा दिया गया: एक डेटा-प्लेन API संस्करण
ARM संसाधन संस्करणों या मॉडल संस्करणों को नियंत्रित नहीं करता है। मॉडल नाम/संस्करण जोड़े
`variables.modelDeployments` में होते हैं; उन्हें तैनाती SKU के साथ जांचें।

## प्रोवीजनिंग सत्यापित करें

स्क्रिप्ट के आउटपुट या `az deployment group list` से तैनाती नाम का उपयोग करें।
ऊपर प्रत्यक्ष तैनाती के लिए:

```bash
RG=retail-learning-rg
DEPLOYMENT=retail-learning
az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.provisioningState -o tsv
az deployment operation group list -g "$RG" -n "$DEPLOYMENT" -o table
az resource list -g "$RG" -o table
```

अपेक्षित: तैनाती स्थिति `Succeeded`। असफलता के लिए, संचालन त्रुटि
विवरण देखें। केवल संसाधन-सूची आउटपुट एक विश्वसनीय प्रोवीजनिंग-स्थिति जांच नहीं है।

प्लेसहोल्डर **रूट** का परीक्षण करें, न कि गैर-मौजूद एजेंट एंडपॉइंट का:

```bash
ROUTER_URL=$(az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.outputs.routerUrl.value -o tsv)
curl --fail-with-body "$ROUTER_URL"
```

अपेक्षित: HTTP 200 hello-world पेज, **चैट प्रतिक्रिया नहीं**। एक HTTP त्रुटि सफल सत्यापन के रूप में नहीं गिनी जाती है।


वास्तविक प्राथमिक मॉडल अनुमान (बिल योग्य) का परीक्षण करने के लिए:

```bash
OPENAI_ENDPOINT=$(az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.outputs.openAiEndpointPrimary.value -o tsv)
OPENAI_NAME=$(az cognitiveservices account list -g "$RG" \
  --query "[?kind=='OpenAI' && contains(name, '-openai-primary-')].name | [0]" -o tsv)
OPENAI_KEY=$(az cognitiveservices account keys list -g "$RG" -n "$OPENAI_NAME" \
  --query key1 -o tsv)
curl --fail-with-body \
  "${OPENAI_ENDPOINT%/}/openai/deployments/gpt-4.1-chat/chat/completions?api-version=2024-10-21" \
  -H "Content-Type: application/json" -H "api-key: $OPENAI_KEY" \
  -d '{"messages":[{"role":"user","content":"Say hello"}],"max_tokens":20}'
unset OPENAI_KEY
```

अपेक्षित: JSON जिसमें `choices` और `usage` हो। डिप्लॉयमेंट का नाम
`gpt-4.1-chat` है, न कि अंतर्निहित मॉडल का नाम `gpt-4.1`।

## 🔧 डिप्लॉयमेंट के बाद: अगले कदम

यह एक **विकास बैकलॉग** है, पूर्ण अभ्यास नहीं:

1. प्रमाणित ग्राहक/इन्वेंटरी एजेंट और राउटर अनुबंध को लागू करें।
2. फ्रंटएंड को लागू करें और इसकी कॉन्फ़िगरेशन को सत्यापित करें।
3. एक खोज सूचकांक बनाएं और उसे आपके एम्बेडिंग मॉडल से मेल खाने वाले आयाम/प्रोफ़ाइल के साथ भरें,
   तथा दस्तावेज़ विफलताओं और अपडेट्स को संभालें।
4. एक रजिस्ट्री बनाएँ और इमेज-पुल पहचान/अनुमतियाँ कॉन्फ़िगर करें।
5. असली इमेज बनाएं और पुश करें। परीक्षण से पहले कंटेनर ऐप के इनग्रेश पोर्ट और प्रोब्स को
   उन इमेज के अनुरूप बदलें; यहाँ पोर्ट 80 प्लेसहोल्डर्स के लिए है।
6. सीक्रेट्स या प्रबंधित पहचान और सीमित डेटा-प्लेन रोल्स को कॉन्फ़िगर करें। काल्पनिक सीक्रेट नामों का
   संदर्भ न लें: यह टेम्पलेट कोई एप्लिकेशन सीक्रेट्स नहीं बनाता।
7. एप्लिकेशन को इंस्ट्रूमेंट करें, अलर्ट सेट करें, विफलता/पुनर्प्राप्ति का परीक्षण करें, और परिणामों का
   प्रतिनिधि ग्राउंड ट्रुथ और मानव समीक्षा के साथ मूल्यांकन करें।

डिजाइन सीमाओं के लिए [आध संरचना ब्लूप्रिंट](../retail-scenario.md) देखें।

## समस्या निवारण और सुरक्षा सीमाएं

- **मॉडल उपलब्ध नहीं:** मॉडल/संस्करण/SKU, क्षेत्र, और सदस्यता कोटा जाँचें;
  स्क्रिप्ट मॉडल कैटलॉग की प्रीफ़्लाइट नहीं करती है।
- **निगरानी अक्षम की गई:** पर्यावरण लॉग गंतव्य `none` है, एक
  अवैध खाली लॉग एनालिटिक्स विन्यास नहीं।
- **केवल प्लेसहोल्डर:** `/chat`, एजेंट मूल्यांकन, और फ़ाइल इनजेशन मौजूद नहीं हैं।
- **नेटवर्क/पहचान:** सार्वजनिक अंतिम बिंदु और स्थानीय प्रमाणीकरण सक्षम हैं।
  केवल Key Vault RBAC सक्षम करना भूमिका असाइनमेंट या पहचान नहीं बनाता है।
- **उत्पादन:** प्रमाणीकरण, सीमित पहचान, गुप्त प्रबंधन,
  जहां उपयुक्त हो, निजी नेटवर्किंग, उपलब्धता डिजाइन, और संचालन परीक्षण जोड़ें।
  केवल बहु-क्षेत्र मॉडल खाते विफलता डेटा प्रदान नहीं करते हैं।

## सफाई

यहां कोई AZD प्रोजेक्ट नहीं है; `azd down` सफाई कमांड नहीं है।
जांच करने के बाद कि समूह में केवल आपकी लर्निंग संसाधन हैं:

```bash
az group delete --name retail-learning-rg --yes
az group exists --name retail-learning-rg
```

हटाने के बाद उम्मीद की गई स्थिति: `false`। Key Vault और कॉग्निटिव सर्विसेज़
सॉफ्ट-डिलीट किए गए संसाधन नाम रख सकते हैं; परिमार्जन उपयुक्त अनुमतियाँ मांगता है।
देरी से उपयोग शुल्क के लिए लागत प्रबंधन जांचें।
