# Внесок у AZD For Beginners

Дякуємо за вашу зацікавленість у внеску до курсу AZD For Beginners! Цей документ містить рекомендації та інформацію для учасників.

## Як зробити внесок

### Повідомлення про проблеми

Якщо ви знайшли помилки, баги або маєте пропозиції щодо покращень:

1. **Перевірте існуючі проблеми**: Пошукайте серед [існуючих проблем](https://github.com/microsoft/azd-for-beginners/issues), щоб уникнути дублювання
2. **Створіть нову проблему**: Використайте відповідний шаблон проблеми
3. **Надайте деталі**: Включіть кроки для відтворення, очікувану поведінку та скріншоти, якщо потрібно

### Пропозиції щодо змін

1. **Зробіть форк репозиторію**: Створіть власний форк проєкту
2. **Створіть гілку**: Створіть feature-гілку для ваших змін
3. **Внесіть зміни**: Дотримуйтесь наших стандартів кодування та документації
4. **Протестуйте ваші зміни**: Перевірте, що всі посилання працюють і контент відображається правильно
5. **Надішліть Pull Request**: Надайте чіткий опис ваших змін

### Типи внеску

Ми вітаємо такі типи внеску:

#### Покращення контенту
- Виправлення орфографічних, граматичних та форматувальних помилок
- Покращення зрозумілості існуючої документації
- Оновлення застарілої інформації
- Додавання відсутніх пояснень або контексту

#### Нові приклади
- Додавання сценаріїв розгортання з реального життя
- Створення нових шаблонів AZD для поширених випадків використання
- Надання додаткових прикладів коду та вправ

#### Підтримка перекладу
- Допомога у підтримці існуючих перекладів
- Покращення якості перекладу
- Додавання перекладів для нового контенту

#### Повідомлення про помилки
- Повідомлення про неробочі посилання або неправильні приклади коду
- Виявлення розбіжностей у документації
- Позначення проблем з доступністю

## Керівництво для внеску

### Стандарти документації

- Використовуйте чітку, зрозумілу для початківців мову
- Включайте навчальні цілі та результати
- Надавайте покрокові інструкції з очікуваними результатами
- Додавайте навігаційні посилання на пов’язаний контент
- Використовуйте послідовне форматування та стиль markdown

### Приклади коду

- Переконайтесь, що всі приклади коду протестовані та працюють
- Включайте коментарі, які пояснюють ключові концепції
- Дотримуйтесь кращих практик Azure та AZD
- Надавайте очікуваний результат там, де це можливо

### Перевірка англійської документації

З кореня репозиторію встановіть існуючі вимоги для розробки та виконайте:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

Офлайн перевірка посилань перевіряє англійські шляхи Markdown/HTML, заголовки, явні анкори та порожні місця посилань. Вона виключає з перевірки згенеровані `translations/` і `translated_images/`, включно з посиланнями в ці каталоги. Не виконує запити до зовнішніх сайтів чи перевірку розгортань Azure. Використовуйте `--json <report-path>` для експорту помилок та інвентаризації зовнішніх URL для окремої мережевої перевірки. Перевіряйте поточні команди upstream та вимоги до прикладів при зміні технічних інструкцій; розрізняйте протестовані застосунки та проєктні плани.

### Повідомлення комітів
