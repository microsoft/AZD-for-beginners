## 5.1 Встановлення базової лінії

Використовуйте ініціалізований репозиторій [Get Started with AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) з попередніх модулів. Запишіть версію шаблону, версію AZD, обране середовище, розгортання моделі та робочі зразкові питання до внесення будь-яких змін.

Зразок реалізує чат-додаток, підтримуваний агентом. Він **не** стає системою з двома агентами роздрібної торгівлі просто через встановлення змінних середовища або збереження додаткових файлів інструкцій. Додаткові агенти, обробники інструментів, маршрутизація, авторизація та доступ до даних потребують коду додатку.

Перевірте інструкції та інструменти наразі розгорнутого агента у Foundry. Протестуйте одне фактичне питання, одне питання пошуку та одне питання, на яке зразкові дані не можуть відповісти. Перевірте посилання на джерела з фактичними документами, а не припускайте, що розгорнута відповідь є правильною.

## 5.2 Налаштування пошуку знань

Шаблон підтримує пошук на основі файлів та необов’язкову інтеграцію Azure AI Search. Дотримуйтеся [поточних інструкцій AI Search](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) для індексації та налаштування інструментів.

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

Увімкнення сервісу — це лише одна частина пошуку. Перед завантаженням власних даних:

1. Переконайтеся, що маєте дозвіл на використання документів і видаліть конфіденційну інформацію.
2. Оберіть підтримувану у вашому регіоні модель ембеддінгу і встановіть відповідну версію, тип розгортання та розмірність векторів.
3. Створіть або заповніть індекс за документованим процесом зразка.
4. Налаштуйте інструмент пошуку агента для використання цього індексу.
5. Перевірте пошук, посилання, авторизацію і поведінку, коли відсутній відповідний документ.

Не перемикайтесь з `text-embedding-3-small` на іншу модель ембеддінгу без перевірки розмірності та необхідності перебудови/реіндексації векторів. Назва на кшталт `retail-products` не є реалізованим каталогом або політикою контролю доступу.

## 5.3 Трасування та моніторинг

Дотримуйтеся [інструкцій з оглядності зразка](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring). Переконайтеся, що потрібний ресурс Application Insights і з’єднання вже існують; якщо змінюєте налаштування інфраструктури, використовуйте `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

Надішліть тестовий запит, а потім перегляньте журнали додатка Container App і вигляд трасування агента у Foundry. Перевірте затримку, виклики інструментів, помилки та кореляцію між запитом і трасою. Не припускайте, що телеметрія підключена тільки через успішне розгортання.

Залишайте `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` вимкненим, якщо ви явно не переглянули згоду, усунення, збереження та контроль доступу. Траси можуть містити конфіденційні аргументи інструментів або вміст документів навіть коли звичайні журнали виглядають безпечними.

## 5.4 Оцінка агента

Тепер точка входу для оцінювання зразка — [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py), а не директорія `evals/`. З кореня зразка використовуйте Python-середовище, яке відповідає його документованим вимогам:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

Перед запуском виконайте [умови оцінювання](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md). Тести завантажують конфігурацію з обраного `.azure/<environment>/.env`; підтвердіть, що обране потрібне середовище. Важливі вхідні дані включають:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, з форматом, необхідним поточним зразком (перевірена версія використовує `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, який використовується як розгортання моделі судді

Перегляньте тести, щоб зрозуміти вибір оцінювача, порогові значення, потрібні ролі та вартість моделей. Завершений запуск не є автоматичною успішною перевіркою якості; перевірте бали, неуспішні/з помилками випадки та пов’язані результати в Foundry.

### Окрема розширена оцінка AZD

Вищенаведений тест Python — це **робочий процес, специфічний для зразка**. Необов’язкове розширення `azure.ai.evaluations` — це інший робочий процес із власною конфігурацією `evals/azure.eval.yaml`. Воно встановлюється окремо, не входить у загальнодоступний пакет `microsoft.foundry` 1.0:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

Для повного налаштування розширення див. [робочі процеси оцінок та міграція](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md). З агентних розширень beta.22 не використовуйте видалені команди `azd ai agent eval`. Встановлення розширення оцінок не конвертує тести Python зразка й не створює автоматично конфігурацію оцінювання.

Для окремої **вправи з хостингом GA агента** використовуйте порожню папку поза зразком цього воркшопа та дотримуйтеся [покрокового керівництва Foundry локально до хмари](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga). Воно використовує AZD 1.37.0+, пакет `microsoft.foundry`, Python 3.13+ і поточний uv. Ви переглянете `azure.yaml`, протестуєте локально з Agent Inspector, розгорнете джерела для віддаленого збору Foundry, створите/переглянете набір даних і рубрику перед налаштуванням `azd ai eval init --name quality`. Не замінюйте тести цього зразка та не припускайте, що встановлення пакету змінює його модель хостингу.

## 5.5 Red teaming на базі ШІ та безперервна оцінка

Поточний зразок надає [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py). Виконайте умови та перегляньте ціль і вартість перед запуском:

```bash
pytest tests/test_red_teaming.py -s
```

Використовуйте авторизоване тестове розгортання і синтетичні дані. Перегляньте згенеровані атаки та результати; це сканування не гарантує, що додаток є безпечним або відповідає вимогам.

У [керівництві з спостережності](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) також описано безперервну оцінку, налаштовану під час запуску контейнера. Вона оцінює реальні взаємодії користувачів, а не згенерований тестовий трафік, і підтримка оцінювача залежить від регіону. Відсутність взаємодій означає відсутність записів оцінки. Перевірте встановлену версію зразка та конфігурацію оцінювача замість того, щоб припускати, що в кожному розгортанні використовуються однакові налаштування за замовчуванням.

Аутентифікація відокремлена від оцінки. Дотримуйтесь задокументованої в зразку налаштування ідентичності/доступу. Не існує задокументованого «підпору базової автентифікації» для захисту публічного кінцевого пункту.

## 5.6 Практичне завдання з дизайну: індивідуалізація роздрібної торгівлі

!!! warning "Практичне завдання, а не завершене розгортання"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

Напишіть короткий план, що охоплює:

| Область | Рішення та докази для збору |
|------|----------------------------------|
| Відповідальність агента | Почати з одного агента або обґрунтувати окремих Shopper і Loyalty агентів та логіку маршрутизації |
| Дані | Визначити синтетичний каталог/нагороди та відповідальних за оновлення |
| Інструменти | Спочатку реалізувати обробники тільки для читання; вказати авторизацію та валідацію для будь-яких записів |
| Моделі | Вибрати доступні комбінації моделей/версій/SKU та перевірити квоту; уникати розгортання невикористаних моделей |
| Отримання | Визначити індексацію, розміри вбудов, цитування та контроли доступу на рівні документів |
| Оцінка | Додати випадки з очікуваними відповідями, не підтримуваними питаннями, використанням інструментів та безпекою з явними порогами |
| Операції | Визначити телеметрію, бюджети затримок/помилок, обмеження вартості та відповідальність за очищення |

Збереження `custom-agents/shopper-agent-instructions.md` не змушує зразок його завантажувати. Знайдіть код застосунку, який створює/оновлює агента, підключіть там переглянуті інструкції та перевірте отриману версію агента перед тестуванням. Інструкції не можуть надавати доступ до даних чи інструментів, які ви не реалізували.

Впроваджуйте по одній зміні за раз, перевстановлюйте уражені компоненти та повторно запускайте базові питання та оцінки. Збережіть робочу версію для порівняння. Для натхнення архітектури див. [ретейл-блюпринт](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md), який також не є завершеним роздрібним застосунком.
