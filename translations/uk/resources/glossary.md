## Вступ

Цей всебічний глосарій надає визначення термінів, понять і абревіатур, що використовуються у Azure Developer CLI та в хмарній розробці Azure. Важливе довідкове джерело для розуміння технічної документації, усунення неполадок та ефективного спілкування про проєкти azd і сервіси Azure.

## Цілі навчання

Використовуючи цей глосарій, ви:
- Зрозумієте основні терміни та поняття Azure Developer CLI
- Оволодієте словником хмарної розробки Azure і технічними термінами
- Ефективно орієнтуватиметеся у термінах Infrastructure as Code і розгортання
- Зрозумієте назви служб Azure, їх абревіатури та призначення
- Отримаєте визначення термінів для усунення неполадок і налагодження
- Вивчите розвинуті концепції архітектури та розробки Azure

## Результати навчання

Регулярно звертаючись до цього глосарію, ви зможете:
- Ефективно спілкуватися, використовуючи правильну термінологію Azure Developer CLI
- Кращe розуміти технічну документацію та повідомлення про помилки
- Впевнено орієнтуватися у службах та поняттях Azure
- Усувати неполадки за допомогою відповідної технічної термінології
- Брати участь у командних дискусіях з точною технічною мовою
- Систематично розширювати знання з хмарної розробки Azure

## А

**ARM Template**  
Шаблон Azure Resource Manager. Формат Infrastructure as Code на основі JSON, який використовується для декларативного визначення та розгортання ресурсів Azure.

**App Service**  
Платформа Azure як послуга (PaaS) для розміщення вебдодатків, REST API та мобільних бекендів без керування інфраструктурою.

**Application Insights**  
Сервіс моніторингу продуктивності додатків Azure (APM), який надає глибокий аналіз продуктивності, доступності та використання додатків.

**Azure CLI**  
Інтерфейс командного рядка для керування ресурсами Azure. Доповнює AZD, але має окремий вхід; основна автентифікація AZD використовує `azd auth login`.

**Azure Developer CLI (azd)**  
Орієнтований на розробника інструмент командного рядка, який прискорює процес створення та розгортання додатків в Azure за допомогою шаблонів і Infrastructure as Code.

**azure.yaml**  
Основний файл конфігурації проєкту azd, який визначає служби, інфраструктуру та хуки розгортання.

**Azure Resource Manager (ARM)**  
Сервіс Azure для розгортання та керування, який забезпечує шар управління для створення, оновлення та видалення ресурсів.

## Б

**Bicep**  
Спеціалізована мова (DSL), розроблена Microsoft для розгортання ресурсів Azure. Забезпечує простіший синтаксис, ніж ARM шаблони, компілюючись у ARM.

**Build**  
Процес компіляції вихідного коду, встановлення залежностей і підготовки додатків до розгортання.

**Blue-Green Deployment**  
Стратегія розгортання, що використовує два ідентичних робочих середовища (синє і зелене) для мінімізації простою та ризиків.

## В

**Container Apps**  
Безсерверний контейнерний сервіс Azure, який дозволяє запускати контейнеризовані додатки без керування складною інфраструктурою.

**CI/CD**  
Безперервна інтеграція/Безперервне розгортання. Автоматизовані практики інтеграції змін коду та розгортання додатків.

**Cosmos DB**  
Глобально розподілений, багатомодельний сервіс баз даних Azure, який забезпечує комплексні SLA щодо пропускної здатності, затримки, доступності та узгодженості.

**Configuration**  
Налаштування та параметри, які контролюють поведінку додатка та опції розгортання.

## Д

**Deployment**  
Процес встановлення та конфігурування додатків та їх залежностей на цільовій інфраструктурі.

**Docker**  
Платформа для розробки, доставки та запуску додатків із використанням технології контейнеризації.

**Dockerfile**  
Текстовий файл, що містить інструкції для побудови образу Docker контейнера.

## Е

**Environment**  
Цільове середовище розгортання, яке представляє конкретний екземпляр вашого додатка (наприклад, розробка, тестування, продакшн).

**Environment Variables**  
Конфігураційні значення, збережені у вигляді пар "ключ-значення", до яких додатки можуть звертатись під час виконання.

**Endpoint**  
URL або мережеву адресу, за якою можна отримати доступ до додатка або сервісу.

## Ф

**Function App**  
Безсерверний обчислювальний сервіс Azure, що дозволяє запускати код, який реагує на події, без керування інфраструктурою.

## Г

**GitHub Actions**  
Платформа CI/CD, інтегрована з репозиторіями GitHub для автоматизації робочих процесів.

**Git**  
Розподілена система контролю версій, яка використовується для відстеження змін у вихідному коді.

## Х

**Hooks**  
Користувацькі скрипти або команди, що виконуються у певні моменти життєвого циклу розгортання (preprovision, postprovision, predeploy, postdeploy).

**Host**  
Тип сервісу Azure, на якому буде розгорнуто додаток (наприклад, appservice, containerapp, function).

## І

**Infrastructure as Code (IaC)**  
Практика визначення та управління інфраструктурою за допомогою коду замість ручних процедур.

**Init**  
Процес ініціалізації нового проєкту azd, зазвичай з шаблону.

## Й

**JSON**  
JavaScript Object Notation. Формат обміну даними, широко використовується для конфігураційних файлів і відповідей API.

**JWT**  
JSON Web Token. Стандарт для безпечної передачі інформації між сторонами у вигляді JSON-об'єкта.

## К

**Key Vault**  
Сервіс Azure для безпечного зберігання та керування секретами, ключами й сертифікатами.

**Kusto Query Language (KQL)**  
Мова запитів, яка використовується для аналізу даних в Azure Monitor, Application Insights та інших сервісах Azure.

## Л

**Load Balancer**  
Сервіс, що розподіляє вхідний мережевий трафік між кількома серверами або екземплярами.

**Log Analytics**  
Сервіс Azure для збору, аналізу та реагування на телеметричні дані з хмарних і локальних середовищ.

## М

**Managed Identity**  
Функція Azure, яка надає службам Azure автоматично керовану ідентичність для аутентифікації в інших службах Azure.

**Microservices**  
Архітектурний підхід, коли додатки будуються як набір невеликих незалежних сервісів.

**Monitor**  
Уніфіковане рішення Azure для моніторингу, що забезпечує спостереження за додатками та інфраструктурою.

## Н

**Node.js**  
Виконувальне середовище JavaScript, побудоване на движку V8 від Chrome для створення серверних додатків.

**npm**  
Менеджер пакетів для Node.js, який керує залежностями та пакетами.

## О

**Output**  
Значення, що повертаються в результаті розгортання інфраструктури, які можуть використовуватись додатками або іншими ресурсами.

## П

**Package**  
Процес підготовки коду додатка та залежностей для розгортання.

**Parameters**  
Вхідні значення, які передаються у шаблони інфраструктури для налаштування розгортань.

**PostgreSQL**  
Система реляційних баз даних з відкритим кодом, підтримується як керований сервіс в Azure.

**Provisioning**  
Процес створення та налаштування ресурсів Azure, визначених у шаблонах інфраструктури.

## Q

**Quota**  
Обмеження на кількість ресурсів, які можна створити в підписці Azure або в регіоні.

## Р

**Resource Group**  
Логічний контейнер для ресурсів Azure, які мають однаковий життєвий цикл, права доступу та політики.

**Resource Token**  
Унікальний рядок, який генерується azd, щоб гарантувати унікальність імен ресурсів під час розгортань.

**REST API**  
Архітектурний стиль для проєктування мережевих додатків із використанням HTTP-методів.

**Rollback**  
Процес повернення до попередньої версії додатка або конфігурації інфраструктури.

## С

**Service**  
Компонент вашого додатка, визначений у azure.yaml (наприклад, веб-фронтенд, API-бекенд, база даних).

**SKU**  
Одиниця збереження запасів. Представляє різні рівні сервісу або продуктивності для ресурсів Azure.

**SQL Database**  
Керований реляційний сервіс баз даних Azure на основі Microsoft SQL Server.

**Static Web Apps**  
Сервіс Azure для створення та розгортання повністю стекових вебдодатків з репозиторіїв вихідного коду.

**Storage Account**  
Сервіс Azure, що надає хмарне сховище для об’єктів даних, включно з блобами, файлами, чергами та таблицями.

**Subscription**  
Контейнер облікового запису Azure, що містить групи ресурсів і ресурси, із відповідним управлінням доступом і виставленням рахунків.

## Т

**Template**  
Попередньо створена структура проєкту, що містить код додатка, визначення інфраструктури та конфігурації для поширених випадків.

**Terraform**  
Інструмент Infrastructure as Code з відкритим кодом, який підтримує кілька хмарних провайдерів, включно з Azure.

**Traffic Manager**  
DNS-базований балансувальник навантаження Azure для розподілу трафіку між глобальними регіонами Azure.

## У

**URI**  
Уніфікований ідентифікатор ресурсу. Рядок, що ідентифікує конкретний ресурс.

**URL**  
Уніфікований локатор ресурсу. Тип URI, який вказує, де знаходиться ресурс і як його отримати.

## В

**Virtual Network (VNet)**  
Основний будівельний блок приватних мереж в Azure, що забезпечує ізоляцію та сегментацію.

**VS Code**  
Visual Studio Code. Популярний редактор коду з відмінною інтеграцією Azure та azd.

## Ш

**Webhook**  
HTTP-зворотній виклик, який тригериться певними подіями, зазвичай використовується в CI/CD конвеєрах.

**What-if**  
Функція Azure, яка показує, які зміни будуть внесені розгортанням, не виконуючи його фактично.

## Ї

**YAML**  
YAML Ain't Markup Language. Людинозрозумілий стандарт серіалізації даних, який використовується для конфігураційних файлів, таких як azure.yaml.

## З

**Zone**  
Фізично окремі локації в межах регіону Azure, що забезпечують резервування та високу доступність.

## Відповідності назв служб Azure

| Загальна назва | Офіційна назва служби Azure | Тип хоста azd |
|-------------|------------------------------|---------------|
| Вебдодаток | Azure App Service | `appservice` |
| API-додаток | Azure App Service | `appservice` |
| Контейнер-додаток | Azure Container Apps | `containerapp` |
| Функція | Azure Functions | `function` |
| Статичний сайт | Azure Static Web Apps | `staticwebapp` |
| База даних | Azure Database for PostgreSQL | Ресурс інфраструктури, не додаток `host` |
| NoSQL БД | Azure Cosmos DB | Ресурс інфраструктури, не додаток `host` |
| Сховище | Azure Storage Account | Ресурс інфраструктури, не вбудований додаток `host` |
| Кеш | Azure Managed Redis | Ресурс інфраструктури, не додаток `host` |
| Пошук | Azure AI Search | Ресурс інфраструктури, не додаток `host` |
| Повідомлення | Azure Service Bus | Ресурс інфраструктури, не додаток `host` |

`services.<name>.host` вибирає ціль розгортання додатка; це не скорочення для будь-якого типу ресурсу Azure. Бази даних, кеші, служби пошуку та черги зазвичай надаються через провайдера інфраструктури і підключаються до додатка через вихідні дані/конфігурацію.

## Контекстно-специфічні терміни

### Терміни розробки
- **Hot Reload**: Автоматичне оновлення додатків під час розробки без перезапуску
- **Build Pipeline**: Автоматизований процес побудови та тестування коду
- **Deployment Slot**: Тестове середовище в межах App Service
- **Environment Parity**: Підтримання схожості між середовищами розробки, тестування та виробництва

### Терміни безпеки
- **Managed Identity**: Функція Azure, що надає автоматичне управління обліковими даними
- **Key Vault**: Безпечне сховище для секретів, ключів і сертифікатів
- **RBAC**: Контроль доступу за ролями для ресурсів Azure
- **Network Security Group**: Віртуальний фаєрвол для контролю мережевого трафіку

### Терміни моніторингу
- **Telemetry**: Автоматизований збір вимірювань і даних
- **Application Performance Monitoring (APM)**: Моніторинг продуктивності програмного забезпечення
- **Log Analytics**: Сервіс для збору та аналізу даних журналів
- **Alert Rules**: Автоматичні сповіщення на основі метрик або умов

### Терміни розгортання
- **Blue-Green Deployment**: Стратегія розгортання без простоїв
- **Canary Deployment**: Поступове впровадження для підмножини користувачів
- **Rolling Update**: Послідовна заміна екземплярів додатка
- **Rollback**: Повернення до попередньої версії додатка
