прикладу. Необхідно перевірити наявність і квоти Azure у вашій підписці.

## Що фактично існує локально

Існує **чотири приклади застосунків** та **один каркас інфраструктури**:

| Приклад | Локальна реалізація | Навчальний фокус | Рівень |
|---|---|---|---|
| [Простий Flask API](../../../examples/container-app/simple-flask-api) | Flask CRUD API, Dockerfile, Bicep, `azure.yaml` | Розгортання контейнерів, перевірки, журнали | Початковий |
| [Мікросервіси з двома службами](../../../examples/container-app/microservices) | Node.js шлюз і сервіс продукту для читання на Python, Dockerfiles, Bicep, `azure.yaml` | Внутрішня HTTPS взаємодія, незалежне масштабування | Середній |
| [Додаток з базою даних](../../../examples/database-app) | Flask read API, Azure SQL, App Service, Bicep, `azure.yaml` | Підключення до SQL, ініціалізація, журнали | Середній |
| [Azure OpenAI чат](../../../examples/azure-openai-chat) | Локальний Python CLI, Azure OpenAI та Key Vault Bicep, тільки інфраструктура `azure.yaml` | Налагодження моделі, історія чату, оцінки токенів | Середній |
| [Ритейл інфраструктура](../../../examples/retail-multiagent-arm-template) | ARM шаблон, параметри, скрипт розгортання Bash; **тільки контейнери hello-world** | Інфраструктура для майбутнього багатофункціонального застосунку | Розширений |

Сценарій [роздрібної торгівлі](retail-scenario.md) — це **архітектурний план**, а не
повна багатокористувацька реалізація. Код агента роздрібної торгівлі, чат-інтерфейс,
API маршрутизатора, конвеєр пошуку даних, CLI для оцінювання, автоматичне перемикання або
підвищення надійності для продакшену не включені. Вони повинні бути розроблені, побудовані та протестовані окремо.

Огляд [мікросервісів](microservices/README.md) веде до запускного
прикладу з двома сервісами; це не інший каталог для розгортання.

## Рекомендований шлях навчання

1. Розгорніть Flask API та перевірте `/health` та CRUD операції.
2. Розгорніть додаток бази даних і перевірте його п’ять доданих продуктів.
3. Розгорніть приклад з двома сервісами та перевірте запити від шлюзу до продуктів.
4. Підготуйте ресурси чату та запустіть інтерактивний CLI **локально**.
5. Вивчіть архітектурний план роздрібної торгівлі після завершення робочих прикладів.

Виділіть приблизно 30–60 хвилин на кожен приклад додатка, враховуючи 
передумови та перевірку. Реалізація роздрібної торгівлі — це окремий проект розробки, а не
30-хвилинний майстер-клас. Читання її архітектури займає близько 2–3 годин, а реалізація
та готовність до продакшену може зайняти значно більше часу, ніж ілюстративні
80–120 годин розробки, наведені в керівництві.

## Швидкий старт

З кореневої директорії репозиторію для першого контейнерного прикладу:

```bash
cd examples/container-app/simple-flask-api
azd auth login
azd env new flask-demo
azd up
API_URL=$(azd env get-value API_ENDPOINT)
curl --fail-with-body "${API_URL}/health"
```

Очікується: HTTP 200 і JSON, що містить `"status": "healthy"`.
Потрібно, щоб Docker був запущений для локальної збірки контейнера.

Для чату дотримуйтесь [README для чату](azure-openai-chat/README.md): використовуйте
`azd provision`, завантажте API-ключ з Key Vault у поточний шелл, встановіть
`src/requirements.txt` і запустіть `python src/chat.py`. Хостингового сервісу чату немає.

Для роздрібної торгівлі використовуйте [керівництво ARM](retail-multiagent-arm-template/README.md).
У ньому немає `azure.yaml` і його **не** розгортають або видаляють за допомогою `azd up`/`azd down`.

## Витрати та обмеження

- Всі розгортання створюють оплачувані ресурси Azure. Масштабування до нуля застосовується
  лише до обчислювальних ресурсів додатка; воно не усуває витрати на реєстр, базу даних, сховище, пошук чи логи.
- Точні ціни залежать від регіону, валюти, трафіку, моделі/SKU та збереження даних.
  Використовуйте [калькулятор цін Azure](https://azure.microsoft.com/pricing/calculator/)
  перед розгортанням і налаштуйте бюджет в Azure Cost Management.
- Дані Flask CRUD зберігаються в пам’яті, обмежені одним робочим процесом і максимум однією реплікою за
  замовчуванням. Вони зникають при перезапуску або масштабуванні до нуля. Це не надійне сховище.
- Мікросервіс продукту надає лише GET кінцеві точки. Сервіс замовлень, користувачів, база даних,
  Service Bus, реалізації на C# чи Go не включені.
- Ресурси Application Insights не інструментують автоматично кожен додаток.
  Зверніться до кожного прикладу для перевірки фактично згенерованої телеметрії.
- У прикладів немає аутентифікації додатка. Додайте ідентичність, авторизацію,
  постійне сховище, мережевий контроль, тести та операційні процедури перед продакшеном.

## Структура репозиторію

```text
examples/
├── azure-openai-chat/               # Local CLI + model infrastructure
├── container-app/
│   ├── simple-flask-api/            # Single Flask API
│   └── microservices/               # Gateway + read-only product service
├── database-app/                    # Flask + Azure SQL on App Service
├── microservices/README.md          # Navigation to the canonical example
├── retail-multiagent-arm-template/  # Infrastructure scaffold only
└── retail-scenario.md               # Architecture blueprint
```

Цей індекс не гарантує наявність спільного `configurations/`, `scripts/` або каталогу з тестами.
Фактичні файли та ідеї опціональних розширень наведені в кожному керівництві.

## Очищення

Для чотирьох прикладів AZD виконайте це **з вибраної директорії прикладу**:

```bash
azd down
```

Перевірте запит на підтвердження видалення. Для роздрібної торгівлі видаляйте лише спеціальну групу ресурсів,
яку ви створили, за інструкціями в її ARM керівництві. Перевірте Azure Cost Management
після очищення; дані про виставлення рахунків можуть надійти пізніше.

Явно позначайте матеріали лише з архітектурою та неповні фрагменти.
