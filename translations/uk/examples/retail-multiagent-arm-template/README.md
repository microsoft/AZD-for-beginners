## Що розгортається

Ця директорія містить ARM шаблон, параметри та скрипт розгортання Bash.
Джерело **немає `azure.yaml` або роздрібного застосунку**.

| Ресурс | Фактичний стан після розгортання |
|---|---|
| Первинний обліковий запис Azure OpenAI | Розгортання `gpt-4.1-chat` за допомогою версії `gpt-4.1` `2025-04-14`, `GlobalStandard` |
| Вторинний обліковий запис OpenAI (необов’язково) | `gpt-4.1-mini-inventory`, модель `gpt-4.1-mini` версія `2025-04-14`, `GlobalStandard` |
| Обліковий запис для ембедингів (необов’язково) | Версія `text-embedding-ada-002` `2`, `Standard`; без індексаційного конвеєра |
| Обліковий запис OpenAI для грейдера | `gpt-4.1-grader`, модель `gpt-4.1` версія `2025-04-14`, `GlobalStandard`; без оцінювача |
| AI Search | Порожній сервіс; без індексу або документів |
| Сховище | Порожні контейнери блобів `documents` і `uploads` |
| Cosmos DB | Безсерверний обліковий запис, база даних `chathistory`, контейнер `conversations` з розділенням за `/userId`, TTL елементів 30 днів |
| Container Apps | Маршрутизатор і фронтенд обидва запускаються на `mcr.microsoft.com/azuredocs/containerapps-helloworld:latest` на порті 80 |
| Key Vault (необов’язково) | Порожній сховище з увімкненим RBAC; **без секретів або призначень ролей** |
| Application Insights / Log Analytics (необов’язково) | Збір логів ресурсів та середовища; без кастомної інструментації додатку, сповіщень чи панелей моніторингу |
| Document Intelligence | Обліковий запис S0; без робочого процесу обробки документів |

Стару версію Bing Search v7 виведено з експлуатації 11 серпня 2025 року і вона **не надається**.
Немає реалізованої заміни для інтеграції з веб-джерелами.

**Не включено:** агенти клієнтів/інвентаризації, API маршрутизатора `/chat`, UI чату фронтенда,
схема пошуку або скрипти завантаження, Azure Container Registry, приватні кінцеві точки,
керовані ідентичності, призначення ролей RBAC, автоматичне відновлення, Front Door, сканер червоної команди,
CLI для оцінки, автентифікація або CI/CD.

Повідомлення про успішне розгортання ARM підтверджує лише створення ресурсів. Воно не підтверджує
функціональність застосунку, безпеку, доступність чи готовність до продуктивної експлуатації.

## Вимоги та витрати

- Bash (Git Bash/WSL на Windows) і
  [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli).
- Передплата з дозволами на створення усіх перелічених ресурсів.
- Перевірте доступність **кожної моделі/версії/SKU в кожному вибраному регіоні** та
  квоти для вашої підписки. Значення за замовчуванням є прикладами, а не гарантіями.
  Консультуйтеся з [доступністю моделей](https://learn.microsoft.com/azure/ai-services/openai/concepts/models).
- Оберіть спеціальну групу ресурсів, яку можна видалити після тестування.

```bash
az version
az login
az account show --query "{subscription:id,name:name}" -o table
az cognitiveservices usage list --location eastus2 -o table
```

Типові локації: первинна `eastus2`, вторинна `westus2`, ембединг `francecentral`;
грейдер за замовчуванням працює у первинному регіоні, якщо не надано `graderLocation`.
`--no-multi-region` пропускає вторинні та ембединг облікові записи; він не пропускає
обліковий запис грейдера.

Пошук сплачується поки розгорнутий, навіть якщо порожній. Мінімальна кількість реплік контейнера,
надлишковість сховища, запити/зберігання Cosmos DB, токени моделей, виклики Document Intelligence
та прийом/зберігання логів можуть додавати витрати. Немає **фіксованої або перевіреної
щомісячної суми**. Оцініть точні SKU у
[калькуляторі цін Azure](https://azure.microsoft.com/pricing/calculator/) і
налаштуйте бюджет перед розгортанням.

### Режими розгортання

Ці налаштування є розмірами ресурсів, **не сертифікатами продукційності або SLA**:

| Режим | Кількість одиниць для чату / міні / ембединг / грейдера | Репліки маршрутизатора | Репліки фронтенду | Рівень пошуку | Сховище |
|---|---|---|---|---|---|
| мінімальний | 10 / 10 / 20 / 5 | 0–3 | 1–2 | базовий, 1 репліка | Standard_LRS |
| стандартний | 20 / 15 / 30 / 15 | 1–3 | 1–2 | стандартний, 1 репліка | Standard_ZRS |
| преміальний | 40 / 30 / 60 / 30 | 1–10 | 1–5 | standard2, 2 репліки | Standard_GRS |

Кількість одиниць потужності моделі залежить від моделі/SKU; не складайте їх як універсальну гарантію TPM.
Преміальний режим не активує зонально надлишкові Container Apps: для цього потрібен
додатковий мережевий дизайн. Basic Search підтримує векторний пошук, з урахуванням
лімітів сервісу; він за замовчуванням сумісний з векторами.

## 🚀 Швидке розгортання

Спершу перегляньте `azuredeploy.json` і `azuredeploy.parameters.json`. Наведені нижче команди
**створюють платні ресурси Azure**; це не офлайн-перевірки.

З кореня репозиторію:

```bash
cd examples/retail-multiagent-arm-template
bash deploy.sh --help
bash deploy.sh -g retail-learning-rg -m minimal --no-multi-region
```

Скрипт використовує шляхи відносно власної директорії, перевіряє вхід у систему/інструменти/аргументи,
створює групу ресурсів, якщо її немає, валідить розгортання, провадить і
показує не секретні виводи. Не виконується жодне `jq`, наповнення даними, отримання секретів або
налаштування застосунку після розгортання.

Значення за замовчуванням командного рядка скрипта переважають відповідні значення у
файлі параметрів. Редагуйте файл параметрів для налаштувань, таких як вторинні/третинні
регіони; використовуйте пряме розгортання через CLI, якщо потрібні довільні перевизначення параметрів:

```bash
az group create --name retail-learning-rg --location eastus2
az deployment group create \
  --resource-group retail-learning-rg \
  --name retail-learning \
  --template-file azuredeploy.json \
  --parameters azuredeploy.parameters.json \
  --parameters projectName=retail environmentName=dev \
    deploymentMode=minimal enableMultiRegion=false
```

Підготовка може тривати 15–45 хвилин або довше, і може завершитися невдачею через регіональні ліміти або обмеження життєвого циклу моделі.
Не повторюйте спроби сліпо: спочатку прочитайте помилку операції.

## Параметри конфігурації

| Параметр | За замовчуванням у шаблоні | Значення |
|---|---|---|
| `projectName` | Обов’язково (`retail` у файлі параметрів) | 3–10 маленьких літер/цифр |
| `location` | Розташування групи ресурсів | Основний регіон (`eastus2` у файлі параметрів) |
| `secondaryLocation` | `westus2` | Регіон облікового запису Mini model |
| `tertiaryLocation` | `francecentral` | Регіон облікового запису embeddings |
| `graderLocation` | Основний регіон | Регіон облікового запису незалежного оцінювача |
| `environmentName` | `dev` | `dev`, `staging` або `prod`; лише назва, а не перемикач жорсткості |
| `deploymentMode` | `standard` | Вибір SKU/ємності |
| `enableMultiRegion` | `true` | Додати другорядні та embeddings облікові записи |
| `enableMonitoring` | `true` | Додати Insights/робочий простір та збір журналів середовища |
| `enableSecurity` | `true` | Створити лише порожній сховище з увімкненим RBAC |

Оманливий параметр `openAiApiVersion` було видалено: версія API рівня даних
не контролює версії ресурсів ARM або моделей. Пари назва/версія моделі
містяться у `variables.modelDeployments`; перевіряйте їх разом із SKU розгортання.

## Перевірка підготовки

Використовуйте назву розгортання з виводу скрипта або `az deployment group list`.
Для прямого розгортання вище:

```bash
RG=retail-learning-rg
DEPLOYMENT=retail-learning
az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.provisioningState -o tsv
az deployment operation group list -g "$RG" -n "$DEPLOYMENT" -o table
az resource list -g "$RG" -o table
```

Очікуваний стан розгортання `Succeeded`. У разі невдачі перевірте деталі помилки операції.
Вивід списку ресурсів сам по собі не є надійною перевіркою стану підготовки.

Тестуйте заповнювач **root**, а не неіснуючу кінцеву точку агента:

```bash
ROUTER_URL=$(az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.outputs.routerUrl.value -o tsv)
curl --fail-with-body "$ROUTER_URL"
```

Очікується HTTP 200 сторінка hello-world, **не відповідь чату**. HTTP помилка
не вважається успішною перевіркою.

Щоб протестувати фактичне передбачення основної моделі (платне):

```bash
OPENAI_ENDPOINT=$(az deployment group show -g "$RG" -n "$DEPLOYMENT" \
  --query properties.outputs.openAiEndpointPrimary.value -o tsv)
OPENAI_NAME=$(az cognitiveservices account list -g "$RG" \
  --query "[?kind=='OpenAI' && contains(name, '-openai-primary-')].name | [0]" -o tsv)
OPENAI_KEY=$(az cognitiveservices account keys list -g "$RG" -n "$OPENAI_NAME" \
  --query key1 -o tsv)
curl --fail-with-body \
  "${OPENAI_ENDPOINT%/}/openai/deployments/gpt-4.1-chat/chat/completions?api-version=2024-10-21" \
  -H "Content-Type: application/json" -H "api-key: $OPENAI_KEY" \
  -d '{"messages":[{"role":"user","content":"Say hello"}],"max_tokens":20}'
unset OPENAI_KEY
```

Очікується JSON із `choices` та `usage`. Назва розгортання
`gpt-4.1-chat`, а не назва основної моделі `gpt-4.1`.

## 🔧 Після розгортання: наступні кроки

Це **перелік завдань для розробки**, а не завершене вправляння:

1. Реалізувати аутентифікованих клієнтських/інвентарних агентів та контракт маршрутизатора.
2. Реалізувати фронтенд і перевірити його конфігурацію.
3. Створити та заповнити пошуковий індекс з розміром/профілем, що відповідає вашій
   моделі ембеддінгу, та обробляти відмови та оновлення документів.
4. Створити реєстр і налаштувати ідентифікацію/дозволи для завантаження образів.
5. Створити та завантажити реальні образи. Змінити порти та перевірки входу Container App, щоб
   відповідати цим образам перед тестуванням; порт 80 тут належить заповнювачам.
6. Налаштувати секрети або керовані ідентичності та обмежені ролі рівня даних. Не
   посилатися на уявні назви секретів: цей шаблон не створює секрети додатку.
7. Інструментувати додатки, налаштувати оповіщення, тестувати відмови/відновлення та оцінювати
   результати за допомогою представницької коректної інформації та людського огляду.

Дивіться [архітектурний план](../retail-scenario.md) для меж дизайну.

## Усунення несправностей і межі безпеки

- **Модель недоступна:** перевірте модель/версію/SKU, регіон і квоту підписки;
  скрипт не виконує попередню перевірку каталогів моделей.
- **Моніторинг вимкнено:** місце призначення журналу середовища `none`, а не
  недійсна порожня конфігурація Log Analytics.
- **Тільки заповнювачі:** `/chat`, оцінка агента та завантаження файлів відсутні.
- **Мережа/ідентичність:** публічні кінцеві точки та локальна аутентифікація увімкнені.
  Просто увімкнення RBAC Key Vault не створює призначення ролей або ідентичностей.
- **Виробництво:** додайте аутентифікацію, обмежені ідентичності, керування секретами,
  приватну мережу за потреби, проектування доступності та операційні тести.
  Багаторегіональні облікові записи моделей самі по собі не забезпечують відмовостійкість.

## Очищення

Тут немає проєкту AZD; `azd down` не є командою очищення.
Після перевірки, що група містить лише ваші навчальні ресурси:

```bash
az group delete --name retail-learning-rg --yes
az group exists --name retail-learning-rg
```

Очікувано після завершення видалення: `false`. Ключове сховище та ресурси Cognitive Services,
які м’яко видалені, можуть зберігати назви; повне очищення вимагає відповідних дозволів.
Перевірте Cost Management на предмет затриманих нарахувань використання.
