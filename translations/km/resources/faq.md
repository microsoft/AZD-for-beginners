- យោងដល់ការណែនាំអំពីចំណាយ សុវត្ថិភាព និងយុទ្ធសាស្រ្តការតែងតាំងយ៉ាងមានប្រសិទ្ធភាព

## ការចាប់ផ្តើម

### ស: Azure Developer CLI (azd) ជាអ្វី?
**ចំលើយ**: Azure Developer CLI (azd) គឺជាឧបករណ៍បញ្ជា​កម្រិតបន្ទាត់ផ្តោតលើអ្នកអភិវឌ្ឍន៍ ដែលពន្លឿនពេលវេលាដែលអ្នកចាំបាច់ប្រើដើម្បីយកកម្មវិធីរបស់អ្នកពីបរិយាកាសអភិវឌ្ឍន៍តំបន់មូលដ្ឋានទៅកាន់ Azure។ វាប្រគល់អនុវត្តបែបល្អៗតាមរចនាសម្ព័ន្ធពុម្ព និងជួយគ្រប់គ្រងជីវិតរ​​នៃដំណើរការ​តែងតាំងទាំងមូល។

### ស: តើ azd ខុសពី Azure CLI របៀបណា?
**ចំលើយ**: 
- **Azure CLI**: ឧបករណ៍ប្រើប្រាស់ទូទៅសម្រាប់គ្រប់គ្រងធនធាន Azure
- **azd**: ឧបករណ៍ផ្តោតលើអ្នកអភិវឌ្ឍន៍សម្រាប់ដំណើរការតែងតាំងកម្មវិធី
- azd មានដំណើរការសោតន្ទិសិទ្ធិ និងតែងតាំងផ្ទាល់ខ្លួន; Azure CLI គឺជាឧបករណ៍បំបែកទាំងពីរប្រភេទ
- azd រួមបញ្ចូលពុម្ព, ការគ្រប់គ្រងបរិយាកាស និងស្វ័យប្រវត្តិដំណើរការតែងតាំង

### ស: ខ្ញុំត្រូវតែដំឡើង Azure CLI ដើម្បីប្រើ azd មែនទេ?
**ចំលើយ**: មិនបាច់សម្រាប់ដំណើរការ AZD គឺមូលដ្ឋានទេ។ សូម Authenticate ជាមួយ `azd auth login`។ ដំឡើង Azure CLI ផ្សេង ឲ្យបានតែពេលពុម្ពខ្លះ ឬកាស្វែងយល់មានការប្រើប្រាស់ `az` ទៅបញ្ជា។

### ស: តើភាសាកម្មវិធីណាខ្លះដែល azd គាំទ្រ?
**ចំលើយ**: azd មិនចំណាត់ថ្នាក់ភាសា។ វាធ្វើការ​ជាមួយ:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- គេហទំព័រស្ថិតិ
- កម្មវិធីត្រូវបានបំពាក់ក្នុងកុងតឺន័រ

### ស: តើខ្ញុំអាចប្រើ azd ជាមួយគម្រោងមានស្រាប់បានទេ?
**ចំលើយ**: បាទ/ចាស! អ្នកអាច:
1. ប្រើ `azd init` ដើម្បីបន្ថែមការកំណត់រចនាសម្ព័ន្ធ azd ទៅគម្រោងមានស្រាប់
2. បំលែងគម្រោងមានស្រាប់ឲ្យត្រូវនឹងរចនាសម្ព័ន្ធពុម្ព azd
3. បង្កើតពុម្ពផ្ទាល់ខ្លួនបណ្តាលពីស្ថាបត្យកម្មមានស្រាប់របស់អ្នក

## សោតន្តិសិទ្ធិ និង ការចូលប្រើ

### ស: តើខ្ញុំAuthenticateជាមួយAzureដោយហើយ azdយ៉ាងដូចម្តេច?
**ចំលើយ**៖ ប្រើ `azd auth login` ដែលនឹងបើកផ្ទាំងកម្មវិធីរុករកសម្រាប់ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ Azure។ សម្រាប់ស្ថានភាព CI/CD ប្រើភាពជាមួយសេវាកម្មបុគ្គលិកឬអត្តសញ្ញាណដែលគ្រប់គ្រង។

### សំណួរ៖ តើខ្ញុំអាចប្រើ azd ជាមួយការចុះឈ្មោះ Azure ច្រើនបានទេ?
**ចំលើយ**៖ បាទ/ចាស។ ប្រើ `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` ដើម្បីបញ្ជាក់ថាតើត្រូវប្រើការចុះឈ្មោះណាសម្រាប់បរិស្ថាននីមួយៗ។

### សំណួរ៖ តើខ្ញុំត្រូវការអាជ្ញាបណ្ណអ្វីខ្លះដើម្បីដាក់បញ្ចាំងជាមួយ azd?
**ចំលើយ**៖ ជាទូទៅ អ្នកត្រូវការ៖
- តួនាទី **Contributor** លើក្រុមធនធាន ឬការចុះឈ្មោះ
- តួនាទី **User Access Administrator** ប្រសិនបើដាក់បញ្ចាំងធនធានដែលត្រូវការភ្ជាប់តួនាទី
- អាជ្ញាបណ្ណពិសេសនានាផ្លាស់ប្តូរតាមប៉ាតតំណាង និងធនធានដែលត្រូវដាក់បញ្ចាំង

### សំណួរ៖ តើខ្ញុំអាចប្រើ azd ក្នុងបម្រ៉ុង CI/CD បានទេ?
**ចំលើយ**៖ បានជាក់លាក់! azd ត្រូវបានរចនាសម្រាប់ការរួមបញ្ចូលភាព CI/CD។ ប្រើបុគ្គលិកសេវាកម្មសម្រាប់ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ហើយកំណត់អថេរបរិស្ថានសម្រាប់ការកំណត់រចនា។

### សំណួរ៖ តើខ្ញុំគ្រប់គ្រងការផ្ទៀងផ្ទាត់អត្តសញ្ញាណនៅក្នុង GitHub Actions ដូចម្ដេច?
**ចំលើយ**៖ ចូលចិត្តសមាសភាគអត្តសញ្ញាណ (OIDC) ដែលបានកំណត់ជាមួយ `azd pipeline config`។ ការបង្កើតដំណើរការនេះតំឡើង AZD និងផ្ទៀងផ្ទាត់ AZD ជាប់ដោយផ្ទាល់ជាមួយអត្តសញ្ញាណសមាសភាគ។ ជំហាន `azure/login` ផ្ទាល់មួយមិនបង្កើតការចូលឈ្មោះ AZD នោះទេ។ ជំហានចូលក្នុងការងារមាននៅរួចគឺ៖
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

បង្កើតឬដាក់បញ្ចាំងបន្ទាប់ពីចូលឈ្មោះ ដោយមានបរិស្ថាន AZD, ការចុះឈ្មោះ, និងទីតាំងដែលបានកំណត់។ លិខិតអត្តសញ្ញាណដែលភ្ជាប់គ្នាត្រូវតែទុកចិត្តនៅក្នុងឃ្លាំង​/ ref របស់ដំណើរការ ឬបរិស្ថាន GitHub ហើយតួអង្គ Azure របស់វាត្រូវតែអនុញ្ញាតឲ្យអនុវត្តន៍ការងារតាមដែលបានស្នើ។

## តំណាង & គម្រោង

### សំណួរ៖ តើខ្ញុំអាចស្វែងរកតំណាង azd នៅឯណា?
**ចំលើយ**៖ 
- តំណាងផ្លូវការ និងសហគមន៍៖ [Awesome AZD](https://azure.github.io/awesome-azd/)
- តំណាងសហគមន៍៖ ស្វែងរកនៅ GitHub ជាមួយពាក្យ "azd-template"
- ប្រើ `azd template list` ដើម្បីរុករកតំណាងដែលមាន

### សំណួរ៖ តើខ្ញុំរចនាតំណាងផ្ទាល់ខ្លួនបានយ៉ាងដូចម្ដេច?
**ចំលើយ**៖ 
1. ចាប់ផ្តើមជាមួយរចនាសម្ព័ន្ធតំណាងដែលមាន
2. បំលែង `azure.yaml`, ឯកសាររចនាសម្ព័ន្ធ និងកូដកម្មវិធី
3. ធ្វើតេស្តយ៉ាងល្អជាមួយ `azd up`
4. បោះពុម្ពផ្សាយទៅ GitHub ជាមួយស្លាកដូចគ្នា

### សំណួរ៖ តើខ្ញុំអាចប្រើ azd ដោយគ្មានតំណាងបានទេ?
**ចំលើយ**៖ បាន។ ប្រើ `azd init` ក្នុងគម្រោងដែលមានស្រាប់ដើម្បីបង្កើតឯកសារកំណត់រចនាសម្ព័ន្ធចាំបាច់។ អ្នកត្រូវតែចុះតម្រូវ `azure.yaml` និងឯកសាររចនាសម្ព័ន្ធដោយដៃ។

### សំណួរ៖ តើភាពខុសគ្នានៅចន្លោះតំណាងផ្លូវការនិងតំណាងសហគមន៍មានអ្វីខ្លះ?
**ចំលើយ**៖ 
- **តំណាងផ្លូវការ**៖ គ្រប់គ្រងដោយ Microsoft, មានការអាប់ដេតជាប្រចាំ, មានឯកសារពេញលេញ
- **តំណាងសហគមន៍**៖ បង្កើតដោយអ្នកអភិវឌ្ឍន៍, អាចមានករណីប្រើវិជ្ជាជីវៈជាក់លាក់, គុណភាព និងការថែទាំមិនស្មើគ្នា

### សំណួរ៖ តើខ្ញុំធ្វើឲ្យតំណាងក្នុងគម្រោងរបស់ខ្ញុំបានអាប់ដេតយ៉ាងដូចម្ដេច?
**ចំលើយ**៖ តំណាងមិនអាប់ដេតដោយស្វ័យប្រវត្តិទេ។ អ្នកអាច៖
1. ប្រៀបធៀប និងរួមបញ្ចូលការផ្លាស់ប្ដូរពីតំណាងដើមដោយដៃ
2. ចាប់ផ្តើមបង្កើតថ្មីជាមួយ `azd init` ដោយប្រើតំណាងដែលបានអាប់ដេត
3. ជ្រើសយកការកែលម្អពិសេសពីតំណាងដែលបានអាប់ដេត

## ការដាក់បញ្ចាំង និងរចនាសម្ព័ន្ធ

### សំណួរ៖ តើសេវាកម្ម Azure អ្វីខ្លះដែល azd អាចដាក់បញ្ចាំងបាន?
**ចំលើយ**៖ azd អាចដាក់បញ្ចាំងសេវាកម្ម Azure ណាមួយតាមរយៈតំណាង Bicep/ARM រួមមាន៖
- សេវាកម្មកម្មវិធី, កម្មវិធីផ្ទុកកុងតឺន័រ, មុខងារ
- មូលដ្ឋានទិន្នន័យ (SQL, PostgreSQL, Cosmos DB)
- ការផ្ទុកទិន្នន័យ, មូលដ្ឋាន Key Vault, ការស៊ើបអង្កេតកម្មវិធី
- បណ្ដាញ, សុវត្ថិភាព និងធនធានតាមដាន

### សំណួរ៖ តើខ្ញុំអាចដាក់បញ្ចាំងទៅតំបន់ច្រើនបានទេ?
**A**: បាទ/ចាស កំណត់តំបន់ច្រើនក្នុងពណ៌ Bicep របស់អ្នក ហើយកំណត់ប៉ារ៉ាម៉ែត្រទីតាំងឲ្យសមរម្យសម្រាប់បរិបទនិមួយៗ។

### សំណួរ៖ តើខ្ញុំគ្រប់គ្រងការផ្លាស់ប្តូររចនាសម្ព័ន្ធទិន្នន័យយ៉ាងដូចម្តេច?
**A**: ប្រើ deployment hooks ក្នុង `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### សំណួរ៖ តើខ្ញុំអាចដាក់បណ្ដេញតែហេដ្ឋារចនាសម្ព័ន្ធដោយគ្មានកម្មវិធីបានទេ?
**A**: បាទ/ចាស ប្រើ `azd provision` ដើម្បីដាក់បណ្ដេញតែធាតុខាងហេដ្ឋារចនាសម្ព័ន្ធដែលបានកំណត់ក្នុងពណ៌របស់អ្នក។

### សំណួរ៖ តើខ្ញុំដាក់បណ្ដេញទៅធនធាន Azure ដែលមានស្រាប់យ៉ាងដូចម្តេច?
**A**: បាទ/ចាស នៅពេលដែលពណ៌គាំទ្រ។ អ្នកអាចយោងធនធានដែលមានស្រាប់ដោយការប្រើប្រាស់ប្រកាស `existing` របស់ Bicep ឬប៉ារ៉ាម៉ែត្រ existing-resource ដែលបានឯកសាររបស់ពណ៌ ហើយផ្គូផ្គងសេវាកម្មកម្មវិធីទៅគោលដៅដែលគិតទុក។ វាមិននាំចូលកម្មសិទ្ធិ ឬបង្កើតសិទ្ធិខ្វះស្វ័យប្រវត្តិឡើយ។ សូមពិនិត្យពណ៌មុនពេលដាក់បណ្ដេញ។

### សំណួរ៖ តើខ្ញុំអាចប្រើ Terraform ជំនួស Bicep ទេ?
**A**: បាទ/ចាស AZD គាំទ្រ Terraform និង Bicep។ ជ្រើសពណ៌មូលដ្ឋាន Terraform ឬកំណត់ `infra.provider: terraform` នៅក្នុង `azure.yaml` ជាមួយឯកសារ Terraform និងការកំណត់ state/backend ដែលសមរម្យ។ ចូលមើល [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd)។

## ការកំណត់ & បរិបទ

### សំណួរ៖ តើខ្ញុំគ្រប់គ្រងបរិបទខុសៗគ្នា (dev, staging, prod) យ៉ាងដូចម្តេច?
**A**: បង្កើតបរិបទផ្សេងៗដោយប្រើ `azd env new <environment-name>` ហើយកំណត់ការកំណត់ផ្សេងៗសម្រាប់នីមួយៗ៖
```bash
azd env new development
azd env new staging  
azd env new production
```

### សំណួរ៖ តើការកំណត់បរិបទត្រូវបានរក្សាទុកនៅណា?
**A**: នៅក្នុងថត `.azure` នៅក្នុងថតគម្រោងរបស់អ្នក។ បរិបទនីមួយៗមានថតផ្ទាល់ខ្លួនជាមួយឯកសារកំណត់។

### សំណួរ៖ តើខ្ញុំកំណត់ការកំណត់លក្ខណៈបរិបទយ៉ាងដូចម្តេច?
**A**: ប្រើ `azd env set` ដើម្បីកំណត់តម្លៃបរិបទ៖
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### សំណួរ៖ តើខ្ញុំអាចចែករំលែកការកំណត់បរិបទទៅក្រុមការងារបានទេ?
**A**: ថត `.azure` មានព័ត៌មានលំអិតជ្ងីជ្រុល ហើយមិនគួរបញ្ជូលទៅក្នុង version control ទេ។ ជំនួស:
1. ចំណាំបញ្ញត្តិបរិបទត្រូវការ
2. ប្រើស្គ្រីបដាក់បណ្ដេញដើម្បីបង្កើតបរិបទ
3. ប្រើ Azure Key Vault សម្រាប់ការកំណត់លំអិតជ្ងីជ្រុល

### សំណួរ៖ តើខ្ញុំអាចលៃតម្រូវលំនាំដើមនៃពណ៌បានទេ?
**A**: កំណត់បរិបទដែលផ្គូផ្គងនឹងប៉ារ៉ាម៉ែត្រpពណ៌៖
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

មានតែបរិបទដែលត្រូវបានប្រើដោយពណ៌ប៉ុណ្ណោះដែលមានឥទ្ធិពលលើការដាក់បណ្ដេញ។ `SKU_NAME` ខាងលើគឺជាឧទាហរណ៍នៃការបញ្ចូលផ្ទាល់ខ្លួន មិនមែនជាការកំណត់ AZD សកលទេ។

## ការដោះស្រាយបញ្ហា

### សំណួរ៖ ហេតុអ្វីបានជា `azd up` បរាជ័យ?
**A**: មូលហេតុលំហួង៖
1. **បញ្ហាស្នាក់នៅ**: ដំណើរការ `azd auth login`
2. **សិទ្ធិមិនគ្រប់គ្រាន់**: ពិនិត្យតួនាទីរបស់អ្នកនៅ Azure
3. **ជំងឺស្មុគស្មាញនៃឈ្មោះធនធាន**: ពិនិត្យធនធានសម្មុចផ្ទាំង និងការបញ្ចូលឈ្មោះក្នុងពណ៌; បង្កើតបរិបទថ្មីជាមួយ `azd env new` នៅពេលដែលត្រូវការផ្ដាច់ផ្ដើមតែម្តង
4. **បញ្ហាគណនេយ្យ/សមត្ថភាព**: ពិនិត្យការចូលប្រើតំបន់
5. **កំហុសពណ៌**: ពិនិត្យមើលពណ៌ Bicep

### សំណួរ៖ តើខ្ញុំធ្វើដូចម្តេចដើម្បីវាយតម្លៃបញ្ហា deployment?
**A**: 
1. ប្រើ `azd deploy --debug` សម្រាប់ការបង្ហាញលម្អិត
2. ពិនិត្យប្រវត្តិ deployment នៅច្រក Azure
3. ពិនិត្យកំណត់ហេតុសកម្មភាពក្នុងច្រក Azure
4. ប្រើ `azd show` ដើម្បីបង្ហាញស្ថានភាពបច្ចុប្បន្នរបស់បរិបទ

### សំណួរ៖ ហេតុអ្វីបានជាបរិបទរបស់ខ្ញុំមិនដំណើរការទេ?
**A**: ពិនិត្យ៖
1. ឈ្មោះបរិបទត្រូវតែស្ថិតនៅតាមប៉ារ៉ាម៉ែត្រពណ៌ដោយផ្ទាល់
2. តម្លៃត្រូវបានដាក់ក្នុងសំដីសម្រាប់ករណីមានចន្លោះ
3. បរិស្ថានត្រូវបានជ្រើសរើស៖ `azd env select <environment>`

### សំណួរ៖ ហេតុអ្វីបានជាកម្មវិធីរបស់ខ្ញុំមិនអាចចូលដំណើរការបន្ទាប់ពីការតំឡើង?

4. DNS/ដែនផ្ទាល់ខ្លួនត្រូវបានកំណត់ត្រឹមត្រូវ
