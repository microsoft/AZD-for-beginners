## ការចាប់ផ្តើម

### ស: Azure Developer CLI (azd) ជាអ្វី?
**ក**: Azure Developer CLI (azd) គឺជាឧបករណ៍បញ្ជាការសម្រាប់អ្នកអភិវឌ្ឍន៍ដែលមានគោលបំណងបង្កើនល្បឿនចាប់ពីបរិយាកាសអភិវឌ្ឍតំបន់មូលដ្ឋានរបស់អ្នកទៅកាន់ Azure។ វាប្រើប្រាស់ការអនុវត្តល្អបំផុតតាមរយៈគំរូ និងជួយទាំងស្រុងការជួសជុលបញ្ហាក្នុងរយៈពេលជីវិតការតម្លើង។

### ស: តើ azd ផ្សេងពី Azure CLI យ៉ាងដូចម្តេច?
**ក**: 
- **Azure CLI**: ឧបករណ៍គោលបំណងទូទៅសម្រាប់គ្រប់គ្រងធនធាន Azure
- **azd**: ឧបករណ៍ផ្ដោតលើអ្នកអភិវឌ្ឍន៍សម្រាប់នីតិវិធីការតម្លើងកម្មវិធី
- azd មាននីតិវិធីផ្ទៀងផ្ទាត់ និងការតម្លើងផ្ទាល់ខ្លួន; Azure CLI គឺជាឧបករណ៍ផ្សេងទៀតដែលបន្ថែមគ្នា
- azd រួមបញ្ចូលគំរូ ការ​គ្រប់គ្រង​បរិស្ថាន និងស្វ័យ​ប្រវត្តិកម្ម​ការ​តម្លើង

### ស: តើខ្ញុំត្រូវតែដំឡើង Azure CLI មុនពេលប្រើ azd ទេ?
**A**: មិនសំរាប់ហ្វ្លូការងារចម្បង AZD ទេ។ ចូលគណនីជាមួយ `azd auth login`។ តំឡើង Azure CLI ដាច់ដោយឡែកនៅពេលមានកូនសោទំព័រគំរូ ឬហាត់ការណ៍ដែលបញ្ជាក់ច្បាស់ថា ប្រតិបត្តិការបញ្ជា `az`។

### Q: តើយ៉ាងដូចម្តេចភាសាកម្មវិធីដែល azd គាំទ្រ?
**A**: azd មិនចាប់ផ្តើមលើភាសា មិនផ្អែកលើភាសា។  វាធ្វើការជាមួយ៖
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- គេហទំព័របង្ហាញត្រឹមតែ
- កម្មវិធីដែលថតជាកុងតឺន័រ

### Q: តើខ្ញុំអាចប្រើ azd ជាមួយគម្រោងមានរួចហើយបានទេ?
**A**: បាន! អ្នកអាច:
1. ប្រើ `azd init` ដើម្បីបន្ថែម ការកំណត់រចនាសម្ព័ន្ធ azd ទៅគម្រោងមានរួចហើយ
2. កែប្រែគម្រោងមានរួច ហើយឲ្យស្របតាមរចនាសម្ព័ន្ធគំរូ azd
3. បង្កើតគំរូផ្ទាល់ខ្លួន ពីស្ថាបត្យកម្មមានរួចហើយរបស់អ្នក

### Q: មានអ្វីបានផ្លាស់ប្តូរជាមួយការ​ផ្តល់ជូនទូទៅនៃផ្នែកបន្ថែម Foundry?
**A**: កញ្ចប់ `microsoft.foundry` ទៅ Version 1.0 ហើយបានបើកការផ្គត់ផ្គង់ទូទៅ នៅថ្ងៃទី 5 ខែវិច្ឆិកា ឆ្នាំ 2026។ ជាមួយ AZD 1.37.0+ ប្រើ `azd ext install microsoft.foundry` ដើម្បីដំឡើងបន្ថែមមូលដ្ឋានប្រាំពីរសម្រាប់ភ្នាក់ងារ, ការតភ្ជាប់, អ្នកត្រួតពិនិត្យ, គម្រោង, របៀប, ជំនាញ និងប្រអប់ឧបករណ៍។ វាមិនមែនជាតំបន់បញ្ជាថ្មីទេ និងថេររបស់វាត្រូវបានកំណត់ជាច្បាស់ដោយឯករាជ្យ។ ការវាយតម្លៃ, សំណុំទិន្នន័យ, ការតំឡើងត្រាទំនើប និងម៉ូដែលផ្ទាល់ខ្លួន ត្រូវបានដំឡើងដោយឡែក; លក្ខខណ្ឌទស្សនិកជនដែលជាជម្រើសមិនមានស្ថានភាព GA ដោយសារតែកញ្ចប់ GA ទេ។

ការបង្ហាញ [hosted-agent walkthrough](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) ប្រើ Python 3.13+ និង uv បច្ចុប្បន្ន។ `azd ai agent run` បើក Agent Inspector នៅក្នុងតំបន់ផ្ទាល់ខ្លួន ប៉ុន្តែការហៅម៉ូដែលទាន់ប្រើ Azure ហើយកើតមានការចំណាយ។ របៀប code-mode ប្រើ `azd deploy` ផ្ទុកកូដប្រភពសម្រាប់បង្កើតឆ្ងាយដោយមិនចាំបាច់បង្កើត container នៅក្នុងតំបន់ផ្ទាល់ខ្លួន។

### Q: តើ `azd down` ដកភ្នាក់ងារច្រកចេញពីគម្រោង Foundry មានរួចទេ?
**A**: មិនសម្រាប់ផ្លូវគម្រោងដែលប្រើឡើងវិញដែលបានពិពណ៌នានៅក្នុង hosted-agent quickstart ទេ៖ វាបន្តទុកគម្រោង ភ្នាក់ងារ និងធនធានផ្សេងទៀតនៅកន្លែង។ ត្រូវដកធនធានដែលមិនចាំបាច់ដោយឡែកដោយមិនលុបធនធានរួម។ ប្រសិនបើបរិយាកាសបានបង្កើតគម្រោង Foundry ថ្មីមួយ ប្រើ `azd down` ដើម្បីលុបក្រុមធនធានរបស់វា និងរបស់ទាំងអស់នៅក្នុងវា។ សូមពិនិត្យ [ការណែនាំសម្អាត](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#7-clean-up-deliberately) និងការផ្តល់ការបញ្ជាក់ទៅមុនពេលបញ្ជាក់។

### Q: តើខ្ញុំត្រូវផ្សារភ្ជាប់ជាមួយ Azure ដោយប្រើ azd ដូចម្តេច?
**A**: ប្រើ `azd auth login` ដែលនឹងបើកផ្ទាំង browser សម្រាប់ការផ្ទៀងផ្ទាត់ Azure។ សម្រាប់សកម្មភាព CI/CD, ប្រើ service principals ឬ managed identities។

### Q: តើខ្ញុំអាចប្រើ azd ជាមួយការជាវ Azure ច្រើនបានទេ?
**A**: បាន។ ប្រើ `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` ដើម្បីបញ្ជាក់ច្បាស់ថាត្រូវប្រើជាវណាមួយសម្រាប់បរិយាកាសនីមួយៗ។

### Q: តើខ្ញុំត្រូវការសិទ្ធិអ្វីខ្លះដើម្បីបំពាក់ជាមួយ azd?
**A**: ជាធម្មតាអ្នកត្រូវការ៖
- តួនាទី **Contributor** លើក្រុមធនធាន ឬការជាវ
- តួនាទី **User Access Administrator** ប្រសិនបើបំពាក់ធនធានដែលតម្រូវសិទ្ធិតួនាទី
- សិទ្ធិពិសេសផ្សេងៗគ្នាតាមគំរូ និងធនធានដែលបានបំពាក់

### Q: តើខ្ញុំអាចប្រើ azd នៅក្នុងបំពង់ CI/CD បានទេ?
**A**: ច្បាស់ហើយ! azd ត្រូវបានរចនាសម្រាប់រួមបញ្ចូលជាមួយ CI/CD។ ប្រើ service principals សម្រាប់ការផ្ទៀងផ្ទាត់ និងកំណត់ environment variables សម្រាប់ការកំណត់រចនាសម្ព័ន្ធ។

### Q: តើខ្ញុំគ្រប់គ្រង authentication ក្នុង GitHub Actions ដូចម្តេច?
**A**: ចូលចិត្តការចងភ្ជាប់អត្តសញ្ញាណរ៉ូម (OIDC) ដែលបានកំណត់ជាមួយ `azd pipeline config`។ ការងារដែលបង្កើតឡើង ទាញយក និងផ្ទៀងផ្ទាត់ AZD ដោយផ្ទាល់ជាមួយអត្តសញ្ញាណរ៉ូមដែលចងភ្ជាប់។ ជំហាន `azure/login` ប៉ុណ្ណោះ មិនបង្កើតការចូលគណនី AZD ទេ។ ជំហានចូលក្នុងការងារដែលមានរួចគឺ៖
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

ធ្វើកំណត់ការផ្គត់ផ្គង់ឬបំពាក់ បន្ទាប់ពីចូលគណនី ជាមួយបរិយាកាស AZD កំណត់ subscription និងទីតាំងត្រឹមត្រូវ។ លិខិតប្រតិទ្ធជាតិដែលចងភ្ជាប់ត្រូវចាប់ផ្តើមទុកចិត្តដល់repository/ref ឬបរិយាកាស GitHub ហើយតួនាទី Azure របស់វាត្រូវអះអាងអោយធ្វើការប្រតិបត្តិការត្រូវបានទទួលយក។

## គំរូ និងគម្រោង

### Q: តើខ្ញុំអាចរកគំរូ azd នៅឯណា?
**A**: 
- គំរូផ្លូវការនិងសហគមន៍៖ [Awesome AZD](https://azure.github.io/awesome-azd/)
- គំរូសហគមន៍៖ ស្វែងរក GitHub សម្រាប់ "azd-template"
- ប្រើ `azd template list` ដើម្បីរកមើលគំរូដែលមាន

### Q: តើយ៉ាងដូចម្តេចបង្កើតគំរូផ្ទាល់ខ្លួន?
**A**: 
1. ចាប់ផ្តើមពីរចនាសម្ព័ន្ធគំរូដែលមានរួចហើយ
2. បម្លែង `azure.yaml`, ឯកសារចុះសម្រួល និងកូដកម្មវិធី
3. សាកល្បងយ៉ាងម៉ត់ចត់ជាមួយ `azd up`
4. បោះពុម្ពផ្សាយទៅ GitHub ជាមួយស្លេកដែលសមរម្យ

### Q: តើខ្ញុំអាចប្រើ azd ដោយគ្មានគំរូបានទេ?
**A**: បាទ, ប្រើ `azd init` ក្នុងគម្រោងមានរួច ដើម្បីបង្កើតឯកសារកំណត់រចនាសម្ព័ន្ធដែលត្រូវការ។ អ្នកត្រូវការកំណត់រចនាសម្ព័ន្ធ `azure.yaml` និងឯកសារចុះសម្រួលដោយដៃ។

### Q: តើមានភាពខុសគ្នារវាងគំរូផ្លូវការ និងគំរូសហគមន៍យ៉ាងដូចម្តេច?
**A**: 
- **គំរូផ្លូវការ**៖ ត្រូវបានថែរក្សាដោយ Microsoft, ថ្មីៗជាទៀងទាត់, មានឯកសារពេញលេញ
- **គំរូសហគមន៍**៖ បង្កើតដោយអ្នកអភិវឌ្ឍន៍, អាចមានករណីប្រើប្រាស់ពិសេស, គុណភាពនិងការថែទាំមានភាពខុសគ្នា

### Q: តើខ្ញុំធ្វើដូចម្តេចដើម្បីធ្វើបច្ចុប្បន្នភាពគំរូក្នុងគម្រោងខ្ញុំ?
**A**: គំរូមិនបានធ្វើបច្ចុប្បន្នភាពដោយស្វ័យប្រវត្តិនោះទេ។ អ្នកអាច៖
1. ប្រៀបធៀបដោយដៃ និងបញ្ចូលបម្រែបម្រួលពីគំរូដើម
2. ចាប់ផ្តើមពីបន្ទាប់ដោយ `azd init` ជាមួយគំរូដែលបានធ្វើបច្ចុប្បន្នភាព
3. ជ្រើសយកកំណែប្រសើរពិសេសពីគំរូដែលបានធ្វើបច្ចុប្បន្នភាព

## ការបំពាក់ និងរចនាសម្ព័ន្ធ

### Q: តើសេវាកម្ម Azure អ្វីខ្លះដែល azd អាចបំពាក់បាន?
**A**: azd អាចបំពាក់សេវាកម្ម Azure ណាមួយតាមរយៈគំរូ Bicep/ARM ដូចជា៖
- សេវាកម្មកម្មវិធី, Container Apps, Functions
- មូលដ្ឋានទិន្នន័យ (SQL, PostgreSQL, Cosmos DB)
- ផ្ទុកទិន្នន័យ, Key Vault, Application Insights
- ធនធានបណ្តាញ, សុវត្ថិភាព និងមេរោគភាព

### Q: តើខ្ញុំអាចបំពាក់ទៅតំបន់ជាច្រើនបានទេ?
**A**: បាន, កំណត់តំបន់ជាច្រើនក្នុងគំរូ Bicep របស់អ្នក និងកំណត់ប៉ារ៉ាម៉ែត្រទីតាំងឲ្យត្រឹមត្រូវសម្រាប់បរិយាកាសនីមួយៗ។

### Q: តើខ្ញុំគ្រប់គ្រងការផ្លាស់ប្តូររចនាសម្ព័ន្ធមូលដ្ឋានទិន្នន័យយ៉ាងដូចម្តេច?
**A**: ប្រើ deployment hooks ក្នុង `azure.yaml`៖
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### Q: តើខ្ញុំអាចបំពាក់តែរចនាសម្ព័ន្ធប៉ុណ្ណោះដោយគ្មានកម្មវិធីបានទេ?
**A**: បាន, ប្រើ `azd provision` ដើម្បីបំពាក់តែឯកត្តុនៃរចនាសម្ព័ន្ធ ដែលបានកំណត់ក្នុងគំរូរបស់អ្នក។

### Q: តើខ្ញុំអាចបំពាក់ទៅធនធាន Azure មានរួចហើយបានទេ?
**A**: បាន, នៅពេលដែលគំរូគាំទ្រ។ ធ្វើយោងទៅធនធានមានរួចជាមួយសេចក្តីប្រកាស `existing` របស់ Bicep ឬប៉ារ៉ាម៉ែត្រទ្រង់ទ្រាយធនធានមានរួចក្នុងគំរូ ហើយផ្គូផ្គងសេវាកម្មកម្មវិធីទៅគោលដៅដែលចង់បាន។ វាមិននាំមុខអំណាចជាម្ចាស់រួចហើយឬបង្កើតការអនុញ្ញាតបាត់បង់ដោយស្វ័យប្រវត្តិទេ។ សូមពិនិត្យគំរូមុនពេលបំពាក់។

### Q: តើខ្ញុំអាចប្រើ Terraform ជំនួស Bicep បានទេ?
**A**: បាន។ AZD គាំទ្រការប្រើ Terraform និង Bicep ផងដែរ។ ជ្រើសរើសគំរូអាស្រ័យលើ Terraform ឬកំណត់ `infra.provider: terraform` ក្នុង `azure.yaml` ជាមួយឯកសារ Terraform និងការកំណត់រដ្ឋ/backend ដែលសមរម្យ។ មើលការប្រតិបត្តិការប្រើប្រាស់ [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd)។

## ការកំណត់រចនាសម្ព័ន្ធ និងបរិយាកាស

### Q: តើខ្ញុំគ្រប់គ្រងបរិយាកាសផ្សេងៗ (វឌ្ឍនៈ, staging, ផលិត) ដូចម្តេច?
**A**: បង្កើតបរិយាកាសជាប្រភេទដោយប្រើ `azd env new <environment-name>` និងកំណត់កំណត់តម្លៃខុសគ្នាសម្រាប់នីមួយៗ៖
```bash
azd env new development
azd env new staging  
azd env new production
```

### Q: កន្លែងណាដែលរក្សាកំណត់រចនាសម្ព័ន្ធបរិយាកាស?
**A**: នៅថត `.azure` នៅក្នុងថតគម្រោងរបស់អ្នក។ បរិយាកាសនីមួយៗមានថតផ្ទាល់ខ្លួនដែលមានឯកសារកំណត់រចនាសម្ព័ន្ធ។

### Q: តើខ្ញុំកំណត់រចនាសម្ព័ន្ធជាក់លាក់សម្រាប់បរិយាកាសដូចម្តេច?
**A**: ប្រើ `azd env set` ដើម្បីកំណត់ environment variables៖
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### Q: តើខ្ញុំអាចចែករំលែកកំណត់រចនាសម្ព័ន្ធបរិយាកាសពីមនុស្សជាក្រុមបានទេ?
**A**: ថត `.azure` មានព័ត៌មាន حساسة ហើយមិនគួរត្រូវបានធ្វើ commit ទៅ version control ទេ។ នៅទីនេះ៖
1. បញ្ជាក់ឯកសារប្រភេទ environment variables ត្រូវការ
2. ប្រើស្គ្រីបតំឡើងដើម្បីបង្កើតបរិយាកាស
3. ប្រើ Azure Key Vault សម្រាប់កំណត់រចនាសម្ព័ន្ធគួរអោយអ្នក

### Q: តើខ្ញុំធ្វើដូចម្តេចដើម្បីលាបដើមតម្លៃនៅក្នុងគំរូ?
**A**: កំណត់ environment variables ដែលផ្គួរផ្គងជាមួយប៉ារ៉ាម៉ែត្រគំរូ៖
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

តែប្រែប្រួលដែលត្រូវបានប្រើដោយគំរូប៉ុណ្ណោះដែលប៉ះពាល់ដល់ការបំពាក់។ `SKU_NAME` ខាងលើគឺជាតំរូវការ custom មួយ មិនមែនជាការកំណត់ AZD ទូទៅទេ។

### Q: ហេតុអ្វីបានជា `azd up` បរាជ័យ?

1. **បញ្ហាការផ្ទៀងផ្ទាត់**: ប្រតិបត្តិ `azd auth login`
2. **សិទ្ធិនិម្មិតមិនគ្រប់គ្រាន់**: ពិនិត្យតួនាទី Azure របស់អ្នក
3. **ការប្រកួតប្រជែងឈ្មោះធនធាន**: ពិនិត្យធនធានប្រកួតប្រជែង និងបញ្ចូលឈ្មោះនៅក្នុងគំរូ; បង្កើតបរិយាកាសបំបែកដោយប្រើ `azd env new` ប្រសិនបើត្រូវការការផ្ទេរ
4. **បញ្ហាគណនាអត្រាសេវាកម្ម/សមត្ថភាព**: ពិនិត្យមើលក្ដីអាចប្រើបានតំបន់
5. **កំហុសគំរូ**: ផ្ទៀងផ្ទាត់គំរូ Bicep

### Q: តើខ្ញុំធ្វើដូចម្តេចដើម្បីវាយតម្លៃកំហុសបំពាក់?
**A**: 
1. ប្រើ `azd deploy --debug` សម្រាប់បង្ហាញលម្អិត
2. ពិនិត្យប្រវត្តិការបំពាក់នៅ Azure portal
3. ពិនិត្យ Activity Log នៅក្នុង Azure portal
4. ប្រើ `azd show` ដើម្បីបង្ហាញស្ថានភាពបច្ចុប្បន្នបរិយាកាស

### Q: ហេតុអ្វីបានជាតម្លៃបរិយាកាសខ្ញុំមិនដំណើរការទេ?
**A**: ពិនិត្យ៖
1. ឈ្មោះអថេរយោងតាមប៉ារ៉ាម៉ែត្រគំរូបានត្រឹមត្រូវ
2. តម្លៃបានដាក់សញ្ញាសម្រង់ខ្លួន ប្រសិនបើមានសន្លឹកស
3. បរិយាកាសត្រូវបានជ្រើសរើស៖ `azd env select <environment>`
4. អថេរត្រូវបានកំណត់នៅបរិយាកាសត្រឹមត្រូវ

### Q: តើខ្ញុំធ្វើដូចម្តេចដើម្បីសម្អាតការបំពាក់បរាជ័យ?
**A**: 
```bash
azd down
```
 ពិនិត្យបរិយាកាសដែលបានជ្រើសរើស និងការបញ្ជាក់លុបមុន។ នេះលុបធនធាន Azure ដែលបានផ្គត់ផ្គង់ ប៉ុន្តែមិនលុបការកំណត់បរិយាកាស `.azure` នៅក្នុងតំបន់ផ្ទាល់ខ្លួនទេ។ `--purge` ក៏ស្នើសុំការលុបប្រាកដនៃធនធានដែលត្រូវបានលុបបែបsoft-delete ផង ដោយអាចត្រូវបានរារាំងដោយការពារការរក្សាទុក/សម្អាត; វាមិនមែនជជំហានស្ដារឡើងវិញប្រចាំថ្ងៃទេ។

### Q: ហេតុអ្វីបានជា កម្មវិធីខ្ញុំមិនអាចចូលប្រើបានបន្ទាប់ពីបំពាក់?
**A**: ពិនិត្យ៖
1. ការបំពាក់ទទួលបានជោគជ័យ
2. កម្មវិធីដំណើរការ (ពិនិត្យកំណត់ហេតុក្នុង Azure portal)
3. សហគមន៍សុវត្ថិភាពបណ្តាញអនុញ្ញាតចរាចរណ៍
4. DNS/ដែនផ្ទាល់ខ្លួនត្រូវបានកំណត់ត្រឹមត្រូវ

**ច**:

3. កំណត់រចនា `azure.yaml` ដើម្បីផ្គូផ្គងសេវាកម្មបច្ចុប្បន្ន
4. សាកល្បងយ៉ាងពេញលេញនៅបរិយាកាសអភិវឌ្ឍន៍
5. បម្លែងបរិយាកាសដោយជំហានៗ
