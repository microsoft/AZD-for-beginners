## អធិការណ៍

មគ្គុទេសក៍សិក្សាដ៏ទូលំទូលាយនេះផ្តល់ជូនគោលបំណងរៀនដែលមានរចនាសម្ព័ន្ធ គំនិតសំខាន់ៗ លំហាត់អនុវត្ត និងសម្ភារៈវាយតម្លៃ ដើម្បីជួយអ្នកឱ្យអាចយល់ដឹងល្អលើ Azure Developer CLI (azd)។ ប្រើមគ្គុទេសក៍នេះដើម្បីតាមដានកំណត់ត្រារបស់អ្នក និងធ្វើឱ្យប្រាកដថាអ្នកបានគ្របដណ្តប់ប្រធានបទធំបំផុតទាំងអស់។

## គោលបំណងរៀន

ដោយផុតធ្វើការសិក្សាតាមមគ្គុទេសក៍នេះ អ្នកនឹងអាច:
- អភិវឌ្ឍជំនាញគ្រប់គ្រងមូលដ្ឋាន និងជំនាញកម្រិតខ្ពស់នៃ Azure Developer CLI
- អភិវឌ្ឍជំនាញអនុវត្តន៍ក្នុងការចុះហត្ថបទ និងគ្រប់គ្រងកម្មវិធី Azure
- បង្កើតការជឿជាក់ក្នុងការដោះស្រាយបញ្ហានិងធ្វើឱ្យការចុះហត្ថបទមានប្រសិទ្ធភាព
- យល់ដឹងអំពីអនុវត្តន៍ចុះហត្ថបទដែលមានភាពល្អសម្រាប់ផលិតកម្ម និងការពិចារណាអំពីសុវត្ថិភាព

## លទ្ធផលការសិក្សា

បន្ទាប់ពីបញ្ចប់ក្នុងគ្រប់ផ្នែកនៃមគ្គុទេសក៍សិក្សានេះ អ្នកនឹងអាច:
- រចនា ចុះហត្ថបទ និងគ្រប់គ្រងស្ថាបត្យកម្មកម្មវិធីពេញលេញដោយប្រើ azd
- អនុវត្តយុទ្ធសាស្រ្តត្រួតពិនិត្យ សុវត្ថិភាព និងបង្កើនប្រសិទ្ធភាពថ្លៃដើម
- ដោះស្រាយបញ្ហាក្នុងការចុះហត្ថបទចម្រូងចម្រាសដោយខ្លួនឯង
- បង្កើតទំព័រគំរូផ្ទាល់ខ្លួន និងចូលរួមជាមួយសហគមន៍ azd

## រចនាសម្ព័ន្ធការសិក្សារប្រចាំ 8 ជំពូក

### ជំពូកទី 1: មូលដ្ឋាន និងចាប់ផ្តើមយ៉ាងរហ័ស (សប្ដាហ៍ទី 1)
**រយៈពេល**: 30-45 នាទី | **កម្រិតកម្រាស់**: ⭐

#### គោលបំណងរៀន
- យល់ដឹងពីគំនិតមូលដ្ឋាន និងពាក្យសម្រួលរបស់ Azure Developer CLI
- ដំឡើង និងកំណត់រចនាសម្ព័ន្ធ AZD បានជោគជ័យលើវេទិកាការអភិវឌ្ឍរបស់អ្នក
- ចុះហត្ថបទកម្មវិធីដំបូងរបស់អ្នកដោយប្រើគំរូដែលមានរួចហើយ
- រុករកផ្ទាំងបញ្ជារ AZD ដោយមានប្រសិទ្ធភាព

#### គំនិតសំខាន់ៗដែលត្រូវអនុវត្ត
- រចនាសម្ព័ន្ធ និងធាតុផ្សំគម្រោង AZD (azure.yaml, infra/, src/)
- ដំណើរការចុះហត្ថបទដោយផ្អែកលើគំរូ
- មូលដ្ឋានកំណត់រចនាសម្ព័ន្ធបរិស្ថាន
- ការគ្រប់គ្រងក្រុមធនធាន និងការជាវសេវា

#### លំហាត់អនុវត្ត
1. **បញ្ជាក់ការដំឡើង**: ដំឡើង AZD ហើយពិនិត្យតាម `azd version`
2. **ចុះហត្ថបទដំបូង**: ចុះហត្ថបទគំរូ todo-nodejs-mongo បានជោគជ័យ
3. **កំណត់បរិស្ថាន**: កំណត់អថេរបរិស្ថានដំបូងរបស់អ្នក
4. **ពិនិត្យធនធាន**: រុករកធនធានដែលបានចុះហត្ថបទនៅក្នុង Azure Portal

#### សំនួរវាយតម្លៃ
- តើធាតុផ្សំសំខាន់ៗនៃគម្រោង AZD មានអ្វីខ្លះ?
- តើអ្នកធ្វើដូចម្តេចដើម្បីចាប់ផ្តើមគម្រោងថ្មីពីគំរូមួយ?
- តើភាពខុសគ្នារវាង `azd up` និង `azd deploy` ជាអ្វី?
- តើអ្នកគ្រប់គ្រងបរិស្ថានច្រើនជាមួយ AZD ដូចម្តេច?

### ជំពូកទី 2: ការអភិវឌ្ឍ ដំបូង AI (សប្ដាហ៍ទី 2)
**រយៈពេល**: 4-5 ម៉ោង រួមមានវគ្គសិក្សាដៃ | **កម្រិតកម្រាស់**: ⭐⭐

#### គោលបំណងរៀន
- បញ្ចូលសេវាកម្ម Microsoft Foundry ជាមួយសកម្មភាព AZD
- ប្រើជាគម្រោង GA `microsoft.foundry` ជាមួយ AZD 1.37.0+ សម្រាប់ការអភិវឌ្ឍដោយភ្នាក់ងាររួមបម្រើ
- ចុះហត្ថបទ និងកំណត់រចនាសម្ព័ន្ធកម្មវិធីដែលបង្កើតដោយ AI
- យល់ដឹងពីគំរូអនុវត្ត RAG (Retrieval-Augmented Generation)
- គ្រប់គ្រងការចុះហត្ថបទនិងកំណត់ទំហំម៉ូដែល AI

#### គំនិតសំខាន់ៗដែលត្រូវអនុវត្ត
- ការបញ្ចូលសេវា Microsoft Foundry Models និងការគ្រប់គ្រង API
- ការកំណត់រចនាសម្ព័ន្ធ AI Search និងវ៉ិចទ័រជំរុញ
- វិធីសាស្រ្តចុះហត្ថបទម៉ូដែល និងផែនការកំណត់ទំហំ
- ការត្រួតពិនិត្យកម្មវិធី AI និងធ្វើឱ្យមានប្រសិទ្ធភាព
- ពិនិត្យភ្នាក់ងារព័ត៌មានក្នុងស្រុក ប្រៀបធៀបសញ្ញាពពក ការចុះហត្ថលេខាឯកសារប្រាក់កូដ និងខ្សែផ្សាយនៅក្នុងប្រព័ន្ធ version control

#### លំហាត់អនុវត្ត
1. **ចុះហត្ថបទ AI Chat**: ចុះហត្ថលេខាគំរូ azure-search-openai-demo
2. **អនុវត្ត RAG**: កំណត់រចនាសម្ព័ន្ធឯកសារបញ្ជាក់ និងការរកមើល
3. **កំណត់ម៉ូដែល**: បង្កើតម៉ូដែល AI ច្រើនជាមួយគោលបំណងខុសៗគ្នា
4. **ត្រួតពិនិត្យ AI**: អនុវត្ត Application Insights សម្រាប់បន្ទុក AI
5. **ភ្នាក់ងារជាវ GA**: តាមដាន [ការបញ្ជ្រាបភ្នាក់ងារជាវ](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga); ប្រៀបធៀបចម្លើយនៅក្នុងស្រុកនិងពពក ពិនិត្យលទ្ធផលវាយតម្លៃ ហើយបញ្ជាក់កាន់កាប់ការសំអាត

#### សំនួរវាយតម្លៃ
- តើអ្នកកំណត់រចនាសម្ព័ន្ធសេវា Microsoft Foundry Models ក្នុងគំរូ AZD ដូចម្តេច?
- តើធាតុសំខាន់ៗនៃស្ថាបត្យកម្ម RAG មានអ្វីខ្លះ?
- តើអ្នកគ្រប់គ្រងទំហំ និងកំណត់ត្រាម៉ូដែល AI ដូចម្តេច?
- តើគោលការណ៍ត្រួតពិនិត្យអ្វីខ្លះដែលមានសារៈសំខាន់សម្រាប់កម្មវិធី AI?
- តើបន្ថែមណាខ្លះរួមមានក្នុង `microsoft.foundry` ហើយហេតុអ្វីបានជាការវាយតម្លៃត្រូវបានដំឡើងបំបែក?
- ហេតុអ្វីបានជា ការតេស្តភ្នាក់ងារព័ត៌មានក្នុងស្រុកនៅតែបង់ថ្លៃម៉ូដែល Azure?
- តើ `azd down` ទុកឱ្យនៅពេលអ្នកប្រើគម្រោង Foundry មានរួចហើយបន្សំផ្តុំអ្វី?

### ជំពូកទី 3: ការកំណត់រចនាសម្ព័ន្ធ និងការផ្ទៀងផ្ទាត់ (សប្ដាហ៍ទី 3)
**រយៈពេល**: 45-60 នាទី | **កម្រិតកម្រាស់**: ⭐⭐

#### គោលបំណងរៀន
- អភិវឌ្ឍន៍យុទ្ធសាស្រ្តគ្រប់គ្រងនិងកំណត់រចនាសម្ព័ន្ធបរិស្ថាន
- អនុវត្តគំរូផ្ទៀងផ្ទាត់សុវត្ថិភាព និងអត្តសញ្ញាណគ្រប់គ្រង
- រៀបចំធនធានជាមួយនាមគុណត្រឹមត្រូវ
- កំណត់រចនាសម្ព័ន្ធចុះហត្ថបទនៅបរិស្ថានច្រើន (dev, staging, prod)

#### គំនិតសំខាន់ៗដែលត្រូវអនុវត្ត
- របៀបដំណើរការជាន់ខ្ពស់នៃបរិស្ថាន និងអាទិភាពកំណត់រចនាសម្ព័ន្ធ
- អត្តសញ្ញាណគ្រប់គ្រង និងការផ្ទៀងផ្ទាត់សេវាកម្ម principal
- ការបញ្ចូលគ្នានឹង Key Vault សម្រាប់គ្រប់គ្រងសម្ងាត់
- ការគ្រប់គ្រងប៉ារ៉ាម៉ែត្រៗប្លែកគ្នាតាមបរិស្ថាន

#### លំហាត់អនុវត្ត
1. **កំណត់បរិស្ថានច្រើន**: កំណត់នូវបរិស្ថាន dev, staging និង prod
2. **កំណត់សុវត្ថិភាព**: អនុវត្តការផ្ទៀងផ្ទាត់អត្តសញ្ញាណគ្រប់គ្រង
3. **គ្រប់គ្រងសម្ងាត់**: បញ្ចូល Azure Key Vault សម្រាប់ទិន្នន័យសំងាត់

### ជំពូកទី 5: ដំណោះស្រាយ AI ពហុភ្នាក់ងារ (សប្ដាហ៍ 6-7)

- ការត្រួតពិនិត្យផលិតកម្មសម្រាប់ប្រព័ន្ធពហុភ្នាក់ងារ

3. **បង្កើនទំហំស្ថាបត្យកម្ម**: អនុវត្តកំណត់ទម្ងន់ និងបន្ថែមទំហំដោយស្វ័យប្រវត្តិ

បង្កើតកម្មវិធីគ្រប់គ្រងភារកិច្ចពេញលេញរួមមាន:
- React frontend ចេញផ្សាយទៅ App Service
- Node.js API backend ជាមួយនឹងការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ
- មូលដ្ឋានទិន្នន័យ PostgreSQL ជាមួយការផ្លាស់ប្តូរ
- ការត្រួតពិនិត្យ Application Insights

**អ្វីដែលត្រូវបញ្ចប់**:
- កម្មវិធីពេញលេញជាមួយការផ្ទៀងផ្ទាត់អ្នកប្រើ
- គំរូនិងស្គ្រីបផ្លាស់ប្ដូរមូលដ្ឋានទិន្នន័យ
- ការត្រួតពិនិត្យនិងច្បាប់ជូនដំណឹង
- ការកំណត់ការចេញផ្សាយពហុបរិយាកាស

### គម្រោង 3៖ វេទិកាមីក្រូសេវាកម្មពាណិជ្ជកម្មអេឡិចត្រូនិច
**កម្រិតស្មុគស្មាញ**៖ កម្រិតខ្ពស់  
**រយៈពេល**៖ 4-6 សប្តាហ៍

រចនានិងអនុវត្តវេទិកាមីក្រូសេវាកម្មសម្រាប់ពាណិជ្ជកម្មអេឡិចត្រូនិច៖
- សេវាកម្ម API ច្រើន (catalog, orders, payments, users)
- បញ្ចូលបន្ទាត់សារ​ជាមួយ Service Bus
- Redis cache សម្រាប់បង្រួមប្រសិទ្ធភាព
- ការកំណត់ហេតុ និងមើលថែយ៉ាងទូលំទូលាយ

**ឧទាហរណ៍យោង**៖ មើល [Microservices Architecture](../../../examples/container-app/microservices) សម្រាប់គំរូសិក្សាសេវាកម្មពីរដុំ និងមគ្គុទេសក៍ចេញផ្សាយ។ ប្រព័ន្ធច្រកសារ, ផ្ទុកទិន្នន័យ, ផ្ទៀងផ្ទាត់អត្តសញ្ញាណ, ដំណើរការទូទាត់ និងការគ្រប់គ្រងផលិតកម្មគឺជាការងារផ្សេងៗ។

**អ្វីដែលត្រូវបញ្ចប់**:
- ស្ថาปัตยกรรมមីក្រូសេវាកម្មពេញលេញ
- លំនាំការប្រាស្រ័យទាក់ទងរវាងសេវាកម្ម
- ការប្រឡងប្រសិទ្ធភាព និងបង្រួមគុណភាព
- ការអនុវត្តសន្តិសុខរួចរាល់ចេញផ្សាយ

## ការវាយតម្លៃ និងវិញ្ញាបនបត្រ

### ការត្រួតពិនិត្យចំណេះដឹង

បញ្ចប់ការវាយតម្លៃទាំងនេះបន្ទាប់ពីរាល់ម៉ូឌុល៖

**ការវាយតម្លៃម៉ូឌុល 1**: គំនិតមូលដ្ឋាន និងការដំឡើង
- សំណួរជាច្រើនជម្រើសលើគំនិតគ្រឹះ
- ការងារដំឡើងនិងកំណត់រចនាសម្ព័ន្ធក្នុងការអនុវត្ត
- លំហាត់ចេញផ្សាយសាមញ្ញ

**ការវាយតម្លៃម៉ូឌុល 2**: កំណត់រចនាសម្ព័ន្ធ និងបរិយាកាស
- ស្ថានការណ៍គ្រប់គ្រងបរិយាកាស
- លំហាត់ដោះស្រាយបញ្ហាការកំណត់រចនាសម្ព័ន្ធ
- ការអនុវត្តសន្តិសុខ

**ការវាយតម្លៃម៉ូឌុល 3**: ចេញផ្សាយនិងផ្គត់ផ្គង់
- ការប្រឈមមុខការរចនាឧបករណ៍អគ្គិសនី
- ស្ថានការណ៍ចេញផ្សាយសេវាកម្មច្រើន
- លំហាត់បង្រួមប្រសិទ្ធភាព

**ការវាយតម្លៃម៉ូឌុល 4**: ការត្រួតពិនិត្យមុនចេញផ្សាយ
- ករណីសិក្សាការធ្វើផែនការសមត្ថភាព
- ស្ថានការណ៍បង្រួមតម្លៃ
- ការអនុវត្តបន្ទាត់ត្រួតពិនិត្យ

**ការវាយតម្លៃម៉ូឌុល 5**: ដោះស្រាយបញ្ហា និងកំណត់កំហុស
- លំហាត់រាយការណ៍ប្រសិទ្ធភាពបញ្ហា
- ការអនុវត្តមើលថែ
- ផលិតកម្មឆ្លើយតបហេតុការណ៍

**ការវាយតម្លៃម៉ូឌុល 6**: ប្រធានបទកម្រិតខ្ពស់
- ការរចនាបន្ទាត់ pipeline CI/CD
- ការអភិវឌ្ឍន៍គំរូផ្ទាល់ខ្លួន
- ស្ថាបត្យកម្មសហគ្រាស

រចនា និងអនុវត្តដំណោះស្រាយពេញលេញ ដែលបង្ហាញពីជំនាញគ្រប់គ្រងគំនិតទាំងអស់៖

**តម្រូវការ**:

- ការអនុវត្តសន្តិសុខ និងការអនុវត្តតាមស្ដង់ដារ

- ឯកសារសម្រេចរួចនិង runbooks

**រូបមន្តសម្រាប់ការវាយតម្លៃ**:
- គុណភាពការអនុវត្តបច្ចេកទេស
- ភាពពេញលេញនៃឯកសារ
- វិធានសន្តិសុខ និងការអនុវត្តល្អបំផុត
- បង្រួមប្រសិទ្ធភាព និងការគ្រប់គ្រងថ្លៃកាច់
- ការដោះស្រាយបញ្ហា និងភាពច្បាស់លាស់ក្នុងការត្រួតពិនិត្យ
