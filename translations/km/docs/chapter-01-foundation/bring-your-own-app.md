## គោលបំណងសិក្សា

នៅចុងមេរៀននេះ អ្នកនឹង:

- ដំណើរការ `azd init` ក្នុងកូដដែលមានរួច

- រាប់អានពេលដែលគួរឱ្យអោយ azd បង្កើតហេដ្ឋារចនាសម្ព័ន្ធ ថែមទាំងសរសេរទិន្នន័យដោយខ្លួនឯង

- ចាប់ផ្តើម azd ក្នុងគម្រោងដែលអ្នកមានរួច

| **ចាប់ពីកូដដែលមានរួច** | `azd init` (នៅក្នុងថតគម្រោងរបស់អ្នក) | អ្នកមានកម្មវិធីរួចហើយ ហើយចង់ដាក់អោយដំណើរការ |

## ជំហានទី 1៖ ដំណើរការ `azd init` ក្នុងគម្រោងរបស់អ្នក

បើកបន្ទប់បញ្ជា **នៅក្នុងថតគម្រោងដែលមានរួចរបស់អ្នក** ហើយដំណើរការ៖

```bash
cd my-existing-app
azd init
```

azd នឹងសួរថាតើអ្នកចង់ចាប់ផ្តើមយ៉ាងដូចម្តេច។ ជ្រើសរើស៖

```
? How do you want to initialize your app?
> Use code in the current directory
  Select a template
```

ជ្រើស "**Use code in the current directory.**" បន្ទាប់ពី azd ស្កេនថតរបស់អ្នក ស្វែងរកភាសា និងស៊ែតផ័រមវ័ររបស់អ្នក ហើយផ្តល់អង្គុយ។

### អ្វីដែល azd ស្កេនឃើញ

azd ស្វែងរកសញ្ញាកម្មវិធីដូចជា `package.json`, `requirements.txt`, `pom.xml`, `*.csproj`, ឬ `Dockerfile`។ ដំណើរការចាប់ពីកូដមិនមែនជាកម្មវិធីជ្រើសរើសម៉ាស៊ីនធម្មតាសម្រាប់គោលដៅដាក់អោយដំណើរការទាំងអស់ទេ។

| កម្មវិធីរបស់អ្នក | អង្គុយដែលស្កេនឃើញបានស្មាន |
|----------|----------------------|
| កម្មវិធី Node.js / Python / .NET ដែលគាំទ្រ | ជាធម្មតា Azure Container Apps; សូមពិនិត្យការបញ្ជាក់ដែលបានបង្កើត |
| កម្មវិធីមាន Container (`Dockerfile`) | Azure Container Apps |
| កម្មវិធី Function ឬគម្រោង Static Web Apps | ប្រើគំរូដែលផ្គូផ្គង ឬ បង្កើត `azure.yaml` និងហេដ្ឋារចនាសម្ព័ន្ធបើ from-code មិនគាំទ្រការរៀបចំរបស់អ្នក |

ធានាថាសេវាកម្មដែលបានស្កេន គឺត្រឹមត្រូវ ហើយ azd នឹងបង្កើតឯកសារដែលអ្នកត្រូវការ។

## ជំហានទី 2៖ យល់ពីអ្វីដែល azd បានបង្កើត

បន្ទាប់ពីដំណើរការ init សូមពិនិត្យ `azure.yaml` ។ ដំណើរការបង្កើតហេដ្ឋារចនាសម្ព័ន្ធអាចរក្សាហេដ្ឋារចនាសម្ព័ន្ធឲ្យមិនបង្ហាញចេញរហូតដល់អ្នកដំណើរការ `azd infra generate`; កុំសន្មតថា `infra/` មានរួចហើយ៖

```
my-existing-app/
├── azure.yaml          # ← NEW: tells azd what to deploy and where
├── infra/              # Materialized with azd infra generate when using implicit infrastructure
│   ├── main.bicep
│   └── main.parameters.json
├── src/ (your code)    # unchanged
└── ...                 # your existing files, untouched
```

### `azure.yaml` — ការបញ្ជាក់គម្រោង

នេះជាចំខ៉ារសំខាន់នៃគម្រោង azd មួយ។ ការបញ្ជាក់ **App Service ប្រាប់តាមគំរូ** ខាងក្រោមត្រូវការហេដ្ឋារចនាសម្ព័ន្ធ App Service ផ្ទៀងផ្ទាត់; នេះមិនមែនជាមូលហេតុក្នុងការផ្លាស់ប្ដូរអង្គុយ Container Apps ដែលបានបង្កើតដោយគ្មានការផ្លាស់ប្ដូរហេដ្ឋារចនាសម្ព័ន្ធទេ។

```yaml
# azure.yaml
name: my-existing-app
services:
  web:
    project: ./src           # path to your app code
    language: js             # js | python | dotnet | java
    host: appservice         # appservice | containerapp | function | staticwebapp
```

ចំនុចសំខាន់ក្នុង `services` គឺប្រភេទបញ្ចូលមួយមួយដាក់ផ្ទុកថតកូដរបស់អ្នកទៅអ្នកបម្រើ Azure។ ប្រសិនបើកម្មវិធីរបស់អ្នកមានទាំងផ្នែកខាងមុខនិង API អ្នកនឹងមានសេវា២។

### `infra/` — ឧបករណ៍ Azure របស់អ្នកជាគូដ

ថត `infra/` រក្សាទុកឯកសារ Bicep ដែលកំណត់ធនធាន Azure ដែលកម្មវិធីរបស់អ្នកត្រូវការ (App Service, ប្រព័ន្ធទិន្នន័យ, និងផ្សេងៗ)។ អ្នកមិនចាំបាច់សរសេរពួកវាដោយដៃទេ—azd បង្កើតចំណុចចាប់ផ្តើមដែលដំណើរការ។ អ្នក *អាច* កែប្រែពួកវានៅពេលក្រោយដើម្បីបន្ថែមធនធាន ឬបន្ថែមសុវត្ថិភាព (បានគ្របដណ្តប់ក្នុង [ជំពូក ៤](../chapter-04-infrastructure/README.md))។

> **ជំនួយ៖** ចង់មើល ឬកំណត់រចនាសម្ព័ន្ធដែលបានបង្កើតមុនដាក់អោយដំណើរការ? ដំណើរការ `azd infra generate` (អាចប្រើបានដូចគ្នាជា `azd infra synth`) ដើម្បីសរសេរ IaC ទៅឌីសខ័រដើម្បីអ្នកពិនិត្យ និងគ្រប់គ្រងជំនាន់វា។

## ជំហានទី 3៖ កំណត់រៀបចំតម្រូវការ

ប្រសិនបើកម្មវិធីរបស់អ្នកត្រូវការកំណត់ ឬអត្ថុកថា (ជួរសរសេរចូល, សោអាយធី), កុំបញ្ចូលវាចូលបណ្តុះបណ្តាល។ ប្រើតម្លៃបរិដ្ឋាន្វ:

```bash
# Create an environment
azd env new dev

# Set a non-secret value
azd env set API_VERSION 1.0.0
```

នេះផ្ទុកតម្លៃនៅក្នុងម៉ាស៊ីនភាគីតែប៉ុណ្ណោះ។ ដើម្បីប៉ះពាល់កម្មវិធី អ្នកត្រូវប្រើវាមួយក្នុងរបៀបធ្វើជាប៉ារ៉ាម៉ែត្រ​ហេដ្ឋារចនាសម្ព័ន្ធ ឬកំណត់សេវាដែលគាំទ្រ ឬ hook មួយ; ការកំណត់អថេរជាដំណាច់មិនធ្វើអោយការដំណើរការដោយខ្លួនឯងកំណត់ទាំងស្រុង។

សម្រាប់អត្ថុកថាពិតប្រាកដ ត្រូវផ្ទុកវានៅក្នុង Key Vault ហើយយោងពីហេដ្ឋារចនាសម្ព័ន្ធរបស់អ្នក—មើល [ជំពូក ៣៖ កំណត់រៀបចំនិងការផ្ទៀងផ្ទាត់](../chapter-03-configuration/authsecurity.md)។

## ជំហានទី 4៖ ដាក់អោយដំណើរការ

ឥឡូវប្រើដំណើរការដដែលដែលអ្នកស្គាល់រួច៖

```bash
# Authenticate (required for azd)
azd auth login

# Preview the resources that will be created
azd provision --preview

# Provision infrastructure and deploy your code
azd up
```

ពេលវាចប់ហើយ azd នឹងបង្ហាញ URL កម្មវិធីរបស់អ្នក។ សូមផ្ទៀងផ្ទាត់វា ដូចជា កម្មវិធី azd ផ្សេងៗទៀត៖

```bash
azd show           # show endpoints
azd monitor --logs # check logs if needed
```

## សង្ខេប

- `azd init` → **"Use code in the current directory"** បន្ថែម azd ទៅក្នុងកម្មវិធីដែលអ្នកមានរួច។
- `azure.yaml` ផ្គូផ្គងថតកូដរបស់អ្នកទៅបម្រើ Azure; `infra/` កំណត់ធនធានជាមូលដ្ឋាន Bicep។
- `azd infra generate` អនុញ្ញាតឱ្យអ្នកពិនិត្យ ឬកែប្រែហេដ្ឋារចនាសម្ព័ន្ធដែលបានបង្កើត។
- បន្ទាប់ពីចាប់ផ្តើមគម្រោង កម្មវិធីដែលមានរួចរបស់អ្នកប្រើដំណើរការ `azd up` / `azd down` ដូចជាកម្មវិធីផ្អែកលើគំរូ។
