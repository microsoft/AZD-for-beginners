## Введение

Этот обширный глоссарий предоставляет определения терминов, понятий и аббревиатур, используемых в Azure Developer CLI и разработке в облаке Azure. Важный справочник для понимания технической документации, устранения неполадок и эффективного общения о проектах azd и службах Azure.

## Цели обучения

Используя этот глоссарий, вы сможете:
- Понять основные термины и концепции Azure Developer CLI
- Освоить словарь и технические термины разработки в облаке Azure
- Эффективно пользоваться терминологией Infrastructure as Code и развертывания
- Понять наименования служб Azure, аббревиатуры и их назначение
- Иметь доступ к определениям терминов для устранения неполадок и отладки
- Изучить продвинутые концепции архитектуры и разработки в Azure

- Систематически расширять знания по разработке в Azure cloud

## А

**ARM Template**  
Шаблон Azure Resource Manager. Формат Infrastructure as Code на основе JSON для декларативного определения и развертывания ресурсов Azure.

**App Service**  
Платформа Azure как услуга (PaaS) для хостинга веб-приложений, REST API и мобильных бэкендов без управления инфраструктурой.

**Application Insights**  
Сервис мониторинга производительности приложений Azure (APM), предоставляющий глубокие сведения о производительности, доступности и использовании приложений.

**Azure CLI**  
Интерфейс командной строки для управления ресурсами Azure. Дополняет AZD, но требует отдельного входа; основная аутентификация AZD использует `azd auth login`.

**Azure Developer CLI (azd)**  
Ориентированный на разработчика инструмент командной строки, ускоряющий процесс создания и развертывания приложений в Azure с использованием шаблонов и Infrastructure as Code.

**azure.yaml**  
Основной конфигурационный файл проекта azd, в котором определяются службы, инфраструктура и хуки развертывания.

**Azure Resource Manager (ARM)**  
Сервис развертывания и управления Azure, предоставляющий уровень управления для создания, обновления и удаления ресурсов.

## Б

**Bicep**  
Язык предметной области (DSL), разработанный Microsoft для развертывания ресурсов Azure. Обеспечивает более простой синтаксис по сравнению с ARM-шаблонами при компиляции в ARM.

**Build**  
Процесс компиляции исходного кода, установки зависимостей и подготовки приложений к развертыванию.

**Blue-Green Deployment**  
Стратегия развертывания с использованием двух одинаковых производственных сред (синей и зелёной) для минимизации времени простоя и рисков.

## C

**Container Apps**  
Серверлесс-сервис контейнеров Azure, позволяющий запускать контейнеризированные приложения без управления сложной инфраструктурой.

**CI/CD**  
Непрерывная интеграция/непрерывное развертывание. Автоматизированные практики интеграции изменений кода и развертывания приложений.

**Cosmos DB**  
Глобально распределённый много-модельный сервис баз данных Azure, предоставляющий комплексные соглашения об уровне обслуживания (SLA) по пропускной способности, задержке, доступности и согласованности.

**Configuration**  
Настройки и параметры, управляющие поведением приложения и вариантами развертывания.

## D

**Deployment**  
Процесс установки и настройки приложений и их зависимостей на целевой инфраструктуре.

**Docker**  
Платформа для разработки, доставки и запуска приложений с использованием технологии контейнеризации.

**Dockerfile**  
Текстовый файл, содержащий инструкции для сборки образа Docker-контейнера.

## E

**Environment**  
Целевая среда развертывания, представляющая конкретный экземпляр вашего приложения (например, разработка, тестирование, продакшн).

**Environment Variables**  
Конфигурационные значения, хранящиеся в виде пар ключ-значение, доступные приложениям во время выполнения.

**Endpoint**  
URL или сетевой адрес, по которому можно получить доступ к приложению или службе.

## F

**Function App**  
Серверлесс-вычислительный сервис Azure, позволяющий запускать код, основанный на событиях, без управления инфраструктурой.

## G

**GitHub Actions**  
Платформа CI/CD, интегрированная с репозиториями GitHub для автоматизации рабочих процессов.

**Git**  
Распределённая система управления версиями для отслеживания изменений в исходном коде.

## H

**Hooks**  
Пользовательские скрипты или команды, выполняющиеся в определённые моменты жизненного цикла развертывания (preprovision, postprovision, predeploy, postdeploy).

**Host**  
Тип сервиса Azure, на который будет развернуто приложение (например, appservice, containerapp, function).

## I

**Infrastructure as Code (IaC)**  
Практика определения и управления инфраструктурой с помощью кода вместо ручных операций.

**Init**  
Процесс инициализации нового проекта azd, обычно на основе шаблона.

## J

**JSON**  
JavaScript Object Notation. Формат обмена данными, широко используемый для конфигурационных файлов и ответов API.

**JWT**  
JSON Web Token. Стандарт безопасной передачи информации между сторонами в виде JSON-объекта.

## K

**Key Vault**  
Сервис Azure для безопасного хранения и управления секретами, ключами и сертификатами.

**Kusto Query Language (KQL)**  
Язык запросов, используемый для анализа данных в Azure Monitor, Application Insights и других службах Azure.

## L

**Load Balancer**  
Сервис, распределяющий входящий сетевой трафик между несколькими серверами или экземплярами.

**Log Analytics**  
Сервис Azure для сбора, анализа и обработки телеметрических данных из облачных и локальных сред.

## M

**Managed Identity**  
Функция Azure, предоставляющая службам Azure автоматически управляемую учетную запись для аутентификации в других службах Azure.

**Microservices**  
Архитектурный подход, в котором приложения строятся как набор небольших независимых служб.

**Monitor**  
Единой решение Azure для мониторинга, обеспечивающее полнофункциональную наблюдаемость за приложениями и инфраструктурой.

## N

**Node.js**  
Среда выполнения JavaScript, построенная на движке V8 от Chrome, для создания серверных приложений.

**npm**  
Менеджер пакетов для Node.js, управляющий зависимостями и пакетами.

## O

**Output**  
Значения, возвращаемые после развертывания инфраструктуры, которые могут использоваться приложениями или другими ресурсами.

## P

**Package**  
Процесс подготовки кода приложения и зависимостей к развертыванию.

**Parameters**  
Входные значения, передаваемые в инфраструктурные шаблоны для настройки развертываний.

**PostgreSQL**  
Система реляционных баз данных с открытым исходным кодом, поддерживаемая как управляемая служба в Azure.

**Provisioning**  
Процесс создания и настройки ресурсов Azure, определённых в инфраструктурных шаблонах.

## Q

**Quota**  
Ограничения на количество ресурсов, которые можно создать в подписке Azure или регионе.

## R

**Resource Group**  
Логический контейнер для ресурсов Azure, которые имеют общий жизненный цикл, права доступа и политики.

**Resource Token**  
Уникальная строка, генерируемая azd для обеспечения уникальности имён ресурсов в разных развертываниях.

**REST API**  
Архитектурный стиль проектирования сетевых приложений с использованием HTTP-методов.

**Rollback**  
Процесс возврата к предыдущей версии приложения или конфигурации инфраструктуры.

## S

**Service**  
Компонент вашего приложения, определённый в azure.yaml (например, веб-интерфейс, API-бэкенд, база данных).

**SKU**  
Единица складского учёта (Stock Keeping Unit). Представляет разные уровни службы или производительности ресурсов Azure.

**SQL Database**  
Управляемый сервис реляционных баз данных Azure на базе Microsoft SQL Server.

**Static Web Apps**  
Сервис Azure для создания и развертывания полнофункциональных веб-приложений из репозиториев исходного кода.

**Storage Account**  
Сервис Azure, предоставляющий облачное хранилище для объектов данных, включая блобы, файлы, очереди и таблицы.

**Subscription**  
Контейнер учётной записи Azure, в котором находятся группы ресурсов и ресурсы, а также происходят биллинг и управление доступом.

## T

**Template**  
Предварительно созданная структура проекта, содержащая код приложения, определения инфраструктуры и конфигурацию для распространённых сценариев.

**Terraform**  
Инструмент Infrastructure as Code с открытым исходным кодом, поддерживающий несколько облачных провайдеров, включая Azure.

**Traffic Manager**  
DNS-балансировщик нагрузки Azure для распределения трафика между глобальными регионами Azure.

## U

**URI**  
Унифицированный идентификатор ресурса. Строка, идентифицирующая конкретный ресурс.

**URL**  
Унифицированный локатор ресурса. Тип URI, указывающий, где находится ресурс и как его получить.

## V

**Virtual Network (VNet)**  
Основной строительный блок приватных сетей в Azure, обеспечивающий изоляцию и сегментацию.

**VS Code**  
Visual Studio Code. Популярный редактор кода с отличной интеграцией Azure и azd.

## W

**Webhook**  
HTTP callback, вызываемый по определённым событиям, обычно используется в CI/CD конвейерах.

**What-if**  
Функция Azure, показывающая, какие изменения будут сделаны в ходе развертывания без фактического выполнения.

## Y

**YAML**  
YAML Ain't Markup Language. Читаемый человеком стандарт сериализации данных, используемый для конфигурационных файлов, например, azure.yaml.

## Z

**Zone**  
Физически отдельные локации в регионе Azure, обеспечивающие избыточность и высокую доступность.

## Соответствие названий служб Azure

| Распространённое имя | Официальное название службы Azure | Тип хоста azd |
|-------------|------------------------------|---------------|
| Web App | Azure App Service | `appservice` |
| API App | Azure App Service | `appservice` |
| Container App | Azure Container Apps | `containerapp` |
| Function | Azure Functions | `function` |
| Static Site | Azure Static Web Apps | `staticwebapp` |
| Database | Azure Database for PostgreSQL | Ресурс инфраструктуры, не приложение `host` |
| NoSQL DB | Azure Cosmos DB | Ресурс инфраструктуры, не приложение `host` |
| Storage | Azure Storage Account | Ресурс инфраструктуры, не встроенное приложение `host` |
| Cache | Azure Managed Redis | Ресурс инфраструктуры, не приложение `host` |
| Search | Azure AI Search | Ресурс инфраструктуры, не приложение `host` |
| Messaging | Azure Service Bus | Ресурс инфраструктуры, не приложение `host` |

`services.<name>.host` выбирает целевую среду развертывания приложения; это не сокращение для какого-либо типа ресурса Azure. Базы данных, кэши, службы поиска и очереди обычно создаются через провайдера инфраструктуры и соединяются с приложением через outputs/конфигурацию.

## Термины в конкретных контекстах

### Термины разработки
- **Hot Reload**: Автоматическое обновление приложений во время разработки без перезапуска
- **Build Pipeline**: Автоматизированный процесс сборки и тестирования кода
- **Deployment Slot**: Промежуточная среда внутри App Service
- **Environment Parity**: Поддержание сходства между средами разработки, тестирования и продакшн

### Термины безопасности
- **Managed Identity**: Функция Azure для автоматического управления учётными данными
- **Key Vault**: Безопасное хранилище для секретов, ключей и сертификатов
- **RBAC**: Контроль доступа на основе ролей для ресурсов Azure
- **Network Security Group**: Виртуальный файрвол для контроля сетевого трафика

### Термины мониторинга
- **Telemetry**: Автоматический сбор измерений и данных
- **Application Performance Monitoring (APM)**: Мониторинг производительности ПО
- **Log Analytics**: Сервис для сбора и анализа логов
- **Alert Rules**: Автоматические уведомления на основе метрик или условий

### Термины развертывания
- **Blue-Green Deployment**: Стратегия развертывания с нулевым временем простоя
- **Canary Deployment**: Постепенное развертывание на подмножество пользователей
- **Rolling Update**: Поочередная замена экземпляров приложения
- **Rollback**: Откат к предыдущей версии приложения
