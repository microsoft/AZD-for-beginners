## 🚀 Быстрый старт

Запускайте из корня **уже инициализированного приложения azd**, а не из репозитория курса. Используйте свободные имена сред, если они уже существуют.

```bash
# Create multiple environments
azd env new dev
azd env new staging
azd env new prod

# Switch environments
azd env select prod

# Set environment variables
azd env set AZURE_LOCATION eastus
azd env set SKU_NAME P1v3

# View configuration
azd env get-values
```

`SKU_NAME` служит для иллюстрации: он влияет на инфраструктуру только если ваш шаблон явно его использует. Обычные значения `azd env set` сохраняются локально в открытом виде и не являются безопасным хранилищем секретов.

---

## 🔧 Иерархия конфигурации

Разделяйте три различные поверхности конфигурации: глобальные предпочтения (`azd config`), структуру проекта (`azure.yaml`) и значения для каждой среды (`azd env`). Флаги переопределяют только те настройки, которые они фактически поддерживают; нет универсального наложения произвольных переменных среды на `azure.yaml` или Bicep.

## 🔐 Лучшие практики безопасности

```bash
# Runtime managed identity must be enabled in infrastructure and granted RBAC.
# To authenticate azd itself on an Azure host with an assigned identity:
# azd auth login --managed-identity

# Check AZD authentication status
azd auth login --check-status

# Optional: verify Azure CLI context if you plan to run az commands
az account show

# Re-authenticate if needed
azd auth login

# Optional: refresh Azure CLI authentication for az commands
az login
```
