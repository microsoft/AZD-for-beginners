## Модуль 1: Понимание структуры AZD для AI приложений

### Анатомия AI шаблона AZD

Ознакомьтесь с ключевыми файлами AI-готового AZD шаблона:

```
azure-search-openai-demo/
├── azure.yaml              # AZD configuration
├── infra/                   # Infrastructure as Code
│   ├── main.bicep          # Main infrastructure template
│   ├── main.parameters.json # Environment parameters
│   ├── core/               # Shared infrastructure modules
│   └── app/                # Application-specific infrastructure
├── app/                    # Backend, frontend, and optional ingestion functions
├── scripts/               # Deployment scripts
└── .azure/               # AZD environment files
```

Полученный пример может изменяться; `.azure/` появляется после инициализации окружения, а не обязательно в свежем клоне. Изучайте фактическую копию, а не создавайте отсутствующие директории для соответствия этой схеме.

- Конфигурации хостов

2. **Рассмотрите инфраструктуру main.bicep:**

**Ключевые AI паттерны для выявления:**

### **Обсуждение:** Почему эти паттерны важны для AI

- **Зависимости сервисов**: AI приложения часто требуют нескольких скоординированных сервисов
- **Безопасность**: API ключи и конечные точки требуют безопасного управления
- **Масштабируемость**: AI рабочие нагрузки имеют уникальные требования к масштабированию
- **Управление затратами**: AI сервисы могут быть дорогими при неправильной конфигурации

## Модуль 2: Развертывание вашего первого AI приложения

### Шаг 2.1: Инициализация окружения

1. **Создайте новое окружение AZD:**
```bash
azd env new myai-workshop
```

2. **Установите необходимые параметры:**
```bash

```

### Шаг 2.2: Разверните инфраструктуру и приложение

1. **Разверните с помощью AZD:**
```bash

```

**Что происходит во время `azd up`:**
- ✅ Провиженинг сервиса Microsoft Foundry Models
- ✅ Создание сервиса Azure AI Search

- ✅ Конфигурация сетей и безопасности
- ✅ Развертывание кода приложения
- ✅ Настройка мониторинга и логирования

2. **Отслеживайте ход развертывания** и отмечайте создаваемые ресурсы.

### Шаг 2.3: Проверьте развертывание

1. **Проверьте развернутые ресурсы:**
```bash

```

2. **Откройте развернутое приложение:**
```bash

```

Откройте веб-адрес, показанный в выводе `azd show`.

3. **Проверьте работу AI-функционала:**
   - Перейдите в веб-приложение
   - Попробуйте примерные запросы
   - Убедитесь, что AI отвечает корректно

### **Лабораторное задание 3.1: Оптимизация затрат**

**Задача**: Настроить шаблон для экономически эффективной разработки.

**Задания:**
1. Выберите disposable workshop environment: `azd env select myai-workshop`.
2. Зафиксируйте текущие параметры Search SKU и ёмкости модели из `infra/main.parameters.json` и выбранной среды.
3. Используйте поддерживаемые входные параметры ниже, после подтверждения квоты модели/региона:
   ```bash
   azd env set AZURE_SEARCH_SERVICE_SKU basic
   azd env set AZURE_OPENAI_CHATGPT_DEPLOYMENT_CAPACITY 10
   azd up
   ```
4. Проверьте Search SKU и ёмкость развертывания в портале и оцените разницу с помощью калькулятора стоимости. Не ожидайте немедленного обновления данных о выставлении счетов.

**Критерии успеха:** Search использует Basic, развертывание чата имеет запрошенную поддерживаемую ёмкость, и приложение по-прежнему отвечает на примерный вопрос. Ёмкость `10` — это выделение по ограничению скорости, а не скидка на цену токенов. Изменения уровня Search могут быть ограничены или требовать пересоздания; не экспериментируйте с рабочими ресурсами. F0 специфичен для сервиса и не является SKU модели Azure OpenAI.

## Модуль 4: Безопасность и лучшие практики для продакшена

### Шаг 4.1: Безопасное управление учетными данными

**Текущая проблема**: Многие AI-приложения хранят API-ключи в коде или используют небезопасное хранилище.

**Решение AZD**: Интеграция управляемой идентичности с Key Vault.

1. **Проверьте конфигурацию безопасности в вашем шаблоне:**
```bash
# Look for Key Vault and Managed Identity configuration
grep -r "keyVault\|managedIdentity" infra/
```

2. **Проверьте работу управляемой идентичности:**
```bash
# For the sample's default Container Apps host
az containerapp identity show --name YOUR_CONTAINER_APP_NAME --resource-group YOUR_RG
```

### Шаг 4.2: Сетевая безопасность

1. **Включите приватные конечные точки** с использованием поддерживаемой конфигурации сети образца (если еще не настроено).

Для вашего собственного шаблона этот иллюстративный фрагмент показывает подключение к конечной точке OpenAI. Он также требует VNet, настройки приватного DNS и подключения приложения; не вставляйте его без изменений в образец, который уже содержит модули приватных конечных точек:
```bicep
// Private endpoint for OpenAI
resource openAIPrivateEndpoint 'Microsoft.Network/privateEndpoints@2023-04-01' = {
  name: 'pe-openai-${uniqueString(resourceGroup().id)}'
  location: location
  properties: {
    subnet: {
      id: vnet.properties.subnets[0].id
    }
    privateLinkServiceConnections: [
      {
        name: 'openai-connection'
        properties: {
          privateLinkServiceId: openAIAccount.id
          groupIds: ['account']
        }
      }
    ]
  }
}
```

### Шаг 4.3: Мониторинг и наблюдаемость

1. **Настройте Application Insights:**
```bash
# Application Insights should be automatically configured
# Check the configuration:
az monitor app-insights component show --app YOUR_APP_INSIGHTS_NAME --resource-group YOUR_RG
```

2. **Включите интеграцию Application Insights образца:**
```bash
azd env set AZURE_USE_APPLICATION_INSIGHTS true
azd up
azd monitor --overview
```

Инструментация образца отправляет телеметрию; произвольная настройка `OPENAI_MONITOR_ENABLED` не включает метрики AI. Проверьте трассы вызовов модели, задержки, ошибки и использование токенов, избегайте записи конфиденциальных подсказок или ответов.

### Шаг 5.2: Создайте ваш AZD-шаблон

**Следуйте этому шаблону для конвертации вашего приложения:**

**Только каркас:** Этот раздел не предоставляет исходный код API/веб-приложения, инфраструктуру хоста, развертывания моделей, идентичность/RBAC или готовый `main.parameters.json`. Шаблон Bicep на уровне ресурсной группы иллюстрирует состав модулей; типичная точка входа AZD на уровне подписки должна создавать ресурсную группу и вызывать его в этом контексте. Не ожидайте, что `azd up` развернет полное приложение, если копировать только эти фрагменты. Для рабочей базовой версии продолжайте использовать шаблон RAG из Модуля 1.

1. **Создайте базовую структуру:**
```bash
mkdir my-ai-app-azd
cd my-ai-app-azd

# Initialize AZD template
azd init --template minimal .
```

2. **Создайте azure.yaml:**
```yaml
# Metadata
name: my-ai-app
metadata:
  template: my-ai-app-template@0.0.1-beta

# Services definition
services:
  api:
    project: ./api
    host: containerapp
  web:
    project: ./web
    host: staticwebapp
    
# Hooks for custom deployment logic  
hooks:
  predeploy:
    shell: sh
    run: echo "Preparing AI models..."
```

3. **Создайте инфраструктурные шаблоны:**

**infra/main.bicep** — основной шаблон:
```bicep
@description('Primary location for all resources')
param location string = resourceGroup().location

@description('Name of the OpenAI service')
param openAIServiceName string = 'openai-${uniqueString(resourceGroup().id)}'

// Your AI services here
module openAI 'modules/openai.bicep' = {
  name: 'openai'
  params: {
    name: openAIServiceName
    location: location
  }
}
```

**infra/modules/openai.bicep** — модуль OpenAI:
```bicep
@description('Name of the OpenAI service')
param name string

@description('Location for the OpenAI service')
param location string

resource openAIAccount 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: name
  location: location
  kind: 'OpenAI'
  sku: {
    name: 'S0'
  }
  properties: {
    customSubDomainName: name
    disableLocalAuth: true
  }
}

output endpoint string = openAIAccount.properties.endpoint
output name string = openAIAccount.name
```

## Модуль 6: Устранение распространенных проблем

### Распространённые проблемы при развертывании

#### Проблема 1: Превышена квота сервиса OpenAI
**Симптомы:** Развертывание неудачно из-за ошибки квоты
**Решения:**
```bash
# Check current quotas
az cognitiveservices usage list --location eastus

# Request quota increase, OR try a new disposable environment in another region.
# Azure resources cannot be relocated merely by changing AZURE_LOCATION.
azd env new myai-quota-test
azd env set AZURE_LOCATION westus2
azd up
```

#### Проблема 2: Модель недоступна в регионе
**Симптомы:** Неудачные отклики ИИ или ошибки развертывания модели
**Решения:**
```bash
# Check model availability by region
az cognitiveservices model list --location eastus

# Update to available model
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
azd up
```

#### Проблема 3: Проблемы с разрешениями
**Симптомы:** Ошибки 403 Forbidden при вызове сервисов ИИ
**Решения:**
```bash
# Check role assignments
az role assignment list --scope /subscriptions/YOUR_SUB/resourceGroups/YOUR_RG

# Add missing roles
az role assignment create \
  --assignee YOUR_PRINCIPAL_ID \
```

## Модуль 7: Мониторинг и оптимизация

### Шаг 7.1: Настройка всестороннего мониторинга

1. **Создайте пользовательские панели мониторинга:**

Перейдите в портал Azure и создайте панель мониторинга с:
- Количеством запросов и задержкой OpenAI
- Уровнем ошибок приложения
- Использованием ресурсов
- Отслеживанием затрат

2. **Настройте оповещения:**
```bash
# Failed-request count on the Application Insights component (not a percentage)
az monitor metrics alert create \
  --name "AI-App-Failed-Requests" \
  --resource-group YOUR_RG \
  --scopes YOUR_APPLICATION_INSIGHTS_RESOURCE_ID \
  --condition "count requests/failed > 10" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --description "More than 10 failed requests in five minutes"
```

Проверьте, что компонент передает телеметрию запросов, и добавьте группу действий, если нужны уведомления. Метрика — это количество, а не процент ошибок; для оповещений по скорости требуется соответствующий запрос и знаменатель.
