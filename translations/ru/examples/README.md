## Что реально существует локально

Существует **четыре примера приложений** и **один каркас инфраструктуры**:

| Пример | Локальная реализация | Область обучения | Уровень |
|---|---|---|---|
| [Простой Flask API](../../../examples/container-app/simple-flask-api) | Flask CRUD API, Dockerfile, Bicep, `azure.yaml` | Развёртывание контейнера, проверочные запросы, логи | Начинающий |
| [Микросервисы из двух сервисов](../../../examples/container-app/microservices) | Node.js шлюз и read-only Python сервис продукта, Dockerfiles, Bicep, `azure.yaml` | Внутреннее HTTPS взаимодействие, независимое масштабирование | Средний |
| [Приложение с базой данных](../../../examples/database-app) | Flask read API, Azure SQL, App Service, Bicep, `azure.yaml` | Подключение к SQL, инициализация, логи | Средний |
| [Чат Azure OpenAI](../../../examples/azure-openai-chat) | Локальный Python CLI, Azure OpenAI и Key Vault Bicep, только инфраструктура `azure.yaml` | Развёртывание модели, история чата, оценка токенов | Средний |
| [Инфраструктура розничной торговли](../../../examples/retail-multiagent-arm-template) | ARM-шаблон, параметры, скрипт развертывания на Bash; **только контейнеры hello-world** | Инфраструктура для будущего многокомпонентного приложения | Продвинутый |

Сценарий [розничной торговли](retail-scenario.md) — это **архитектурный план**, а не
полноценная реализация многокомпонентного приложения. Код агента розничной торговли, фронтенд чата, API маршрутизатора,
конвейер поиска данных, интерфейс командной строки для оценки, автоматическое переключение при сбоях или производственная
устойчивость не включены. Все это должно быть разработано, построено и протестировано отдельно.

Обзор [микросервисов](microservices/README.md) указывает на пример с двумя запускаемыми сервисами; это не другая директория развертывания.


## Рекомендуемый маршрут обучения

1. Разверните Flask API и проверьте `/health` и операции CRUD.
2. Разверните приложение базы данных и проверьте его пять предварительно загруженных продуктов.
3. Разверните пример с двумя сервисами и проверьте запросы от шлюза к продукту.
4. Обеспечьте ресурсы чата и запустите интерактивный CLI **локально**.
5. Изучите архитектуру розничной торговли после выполнения рабочих примеров.

Заложите примерно 30–60 минут на каждый образец приложения, включая предварительные требования и
проверку. Реализация розничной торговли — это отдельный проект разработки, а не
30-минутный мастер-класс. Ознакомление с его архитектурой занимает около 2–3 часов; реализация
и готовность к производству могут занять значительно больше времени, чем показанные в руководстве
80–120 часов разработки.

## Быстрый старт

Из корня репозитория для первого образца контейнера:

```bash
cd examples/container-app/simple-flask-api
azd auth login
azd env new flask-demo
azd up
API_URL=$(azd env get-value API_ENDPOINT)
curl --fail-with-body "${API_URL}/health"
```

Ожидается: HTTP 200 и JSON, содержащий `"status": "healthy"`.
Для локальной сборки контейнера необходим запущенный Docker.

Для чата следуйте инструкции в [chat README](azure-openai-chat/README.md): используйте
`azd provision`, загрузите API-ключ из Key Vault в текущую оболочку, установите
`src/requirements.txt` и запустите `python src/chat.py`. Хостингового чат-сервиса нет.

Для розничной торговли используйте [ARM руководство](retail-multiagent-arm-template/README.md).
В нем нет `azure.yaml`, и оно **не** разворачивается и не удаляется с помощью `azd up`/`azd down`.

## Затраты и ограничения

- Все развертывания создают тарифицируемые ресурсы Azure. Масштабирование до нуля применимо только к
  вычислительным функциям приложения; оно не устраняет затраты на реестр, базу данных, хранилище, поиск или логи.
- Точные цены зависят от региона, валюты, трафика, модели/SKU и хранения.
  Используйте [калькулятор цен Azure](https://azure.microsoft.com/pricing/calculator/)
  перед развертыванием и настройте бюджет в Azure Cost Management.
- Данные Flask CRUD хранятся в памяти, ограничены одним воркером и максимум одной репликой по
  умолчанию. Они исчезают при перезапуске или масштабировании до нуля. Это не устойчивое хранилище.
- Микросервис продукта предоставляет только GET эндпоинты. Сервис заказов, сервис пользователей,
  база данных, Service Bus, реализации на C# или Go не включены.
- Ресурсы Application Insights не автоматически инструментируют каждое приложение.
  Обратитесь к каждому примеру для сведения о фактически собираемой телеметрии.
- Образцы не реализуют аутентификацию приложения. Добавьте идентификацию, авторизацию,
  устойчивое хранение, сетевые контролы, тесты и операционные процедуры перед запуском в продакшен.

## Структура репозитория

```text
examples/
├── azure-openai-chat/               # Local CLI + model infrastructure
├── container-app/
│   ├── simple-flask-api/            # Single Flask API
│   └── microservices/               # Gateway + read-only product service
├── database-app/                    # Flask + Azure SQL on App Service
├── microservices/README.md          # Navigation to the canonical example
├── retail-multiagent-arm-template/  # Infrastructure scaffold only
```

Нет общего `configurations/`, `scripts/` или директории с тестами, обещанной этим индексом.
Фактические файлы и идеи для необязательных расширений описаны в каждом руководстве.

## Очистка

Для четырех образцов AZD выполните это **из каталога выбранного образца**:

```bash
azd down
```

Проверьте запрос на удаление. Для розничной торговли удаляйте только выделенную группу ресурсов,
которую вы создали, используя инструкции в соответствующем ARM руководстве. Проверьте Azure Cost Management
после очистки; расчетные данные могут поступить позже.
