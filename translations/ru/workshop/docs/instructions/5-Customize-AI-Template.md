## 5.1 Установите базовый уровень

Используйте инициализированный репозиторий [Get Started with AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) из предыдущих модулей. Запишите ревизию шаблона, версию AZD, выбранную среду, развертывание модели и рабочие примерные вопросы перед внесением изменений.

Пример реализует приложение для чата с поддержкой агента. Оно **не превращается** в розничную систему с двумя агентами лишь путем установки переменных окружения или сохранения дополнительных файлов с инструкциями. Дополнительные агенты, обработчики инструментов, маршрутизация, авторизация и доступ к данным требуют кода приложения.

Проверьте инструкции и инструменты текущего развернутого агента в Foundry. Протестируйте один фактологический вопрос, один вопрос извлечения и один вопрос, на который образец данных не может ответить. Подтвердите цитаты с реальными исходными документами, а не полагайтесь на плавный ответ.

## 5.2 Настройка извлечения знаний

Шаблон поддерживает извлечение на основе файлов и опциональную интеграцию с Azure AI Search. Следуйте [текущему руководству по AI Search](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) для индексирования и настройки инструментов.

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

Включение сервиса — это только часть извлечения. Перед загрузкой собственных данных:

1. Убедитесь, что у вас есть разрешение на использование документов и удалите конфиденциальную информацию.
2. Выберите модель встраивания, поддерживаемую в вашем регионе, и задайте ее совместимую версию, тип развертывания и размеры векторов.
3. Создайте/заполните индекс согласно документированному процессу из примера.
4. Настройте инструмент извлечения агента для использования этого индекса.
5. Проверьте извлечение, цитаты, авторизацию и поведение при отсутствии релевантных документов.

Не переключайтесь с `text-embedding-3-small` на другую модель встраивания без проверки размеров и при необходимости перестроения/переиндексации векторов. Имя вроде `retail-products` не является реализованным каталогом или политикой контроля доступа.

## 5.3 Трассировка и мониторинг

Следуйте [руководству по наблюдаемости из примера](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring). Убедитесь, что требуемый ресурс Application Insights и подключение уже существуют; при изменении настроек инфраструктуры используйте `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

Отправьте тестовый запрос, затем проверьте логи приложения Container App и просмотр трассировки агента в Foundry. Проверьте задержки, вызовы инструментов, ошибки и корреляцию между запросом и трассировкой. Не считайте, что телеметрия подключена только потому, что развертывание прошло успешно.

Оставьте `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` отключенным, если вы явно не проверили согласие, редактирование, хранение и контроль доступа. Трассировки могут содержать конфиденциальные аргументы инструментов или содержание документов, даже если обычные логи приложения выглядят безобидно.

## 5.4 Оценка агента

Точка входа оценки примера теперь [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py), а не каталог `evals/`. Из корня примера используйте Python-среду, соответствующую задокументированным требованиям:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

Перед запуском выполните [предварительные требования к оценке](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md). Тесты загружают конфигурацию из выбранного `.azure/<environment>/.env`; подтвердите, что выбрана нужная среда. Важные входные данные включают:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, в формате, требуемом текущим примером (рецензируемая версия использует `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, используемый как развертывание модели судьи

Изучите тесты, чтобы понять выбор оценщика, пороги, требуемые роли и стоимость моделей. Завершение запуска не означает автоматическое прохождение контрольного качества; проверьте баллы, неудачные/с ошибками случаи и результаты, связанные с Foundry.

### Отдельное расширение оценок AZD

Приведенный выше тест Python — это **специфичный для примера рабочий процесс**. Необязательное расширение `azure.ai.evaluations` — это другой рабочий процесс со своей конфигурацией `evals/azure.eval.yaml`. Оно устанавливается отдельно и не входит в общедоступный пакет `microsoft.foundry` 1.0:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

Для полного развертывания расширения см. [рабочие процессы оценки и миграция](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md). С версии beta.22 расширения агентов не используйте удаленные команды `azd ai agent eval`. Установка расширения оценок не преобразует тесты Python примера и автоматически не создает конфигурацию оценки.

Для отдельного **упражнения с размещенным агентом GA** используйте пустую папку вне примера этого мастер-класса и следуйте [пошаговому руководству Foundry "с локального до облака"](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga). Используются AZD 1.37.0+, пакет `microsoft.foundry`, Python 3.13+ и текущий uv. Вы изучите `azure.yaml`, протестируете локально с Agent Inspector, развернете исходники для удаленной сборки Foundry, создадите/просмотрите набор данных и рубрику перед конфигурацией `azd ai eval init --name quality`. Не заменяйте тесты этого примера и не думайте, что установка пакета изменит его модель хостинга.

## 5.5 Красная команда ИИ и непрерывная оценка

Текущий пример предоставляет [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py). Выполните его предварительные требования и изучите предназначенную цель и затраты перед запуском:

```bash
pytest tests/test_red_teaming.py -s
```

Используйте авторизованное тестовое развертывание и синтетические данные. Просмотрите сгенерированные атаки и результаты; это сканирование не подтверждает безопасность или соответствие приложения.

В [руководстве по наблюдаемости](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) также описана непрерывная оценка, настраиваемая при запуске контейнера. Она оценивает реальные взаимодействия пользователей, а не сгенерированный тестовый трафик, и поддержка оценщика варьируется в зависимости от региона. Отсутствие взаимодействий означает отсутствие записей оценки. Проверьте установленную образцовую версию и конфигурацию оценщика, а не предполагайте, что каждое развертывание использует одни и те же значения по умолчанию.

Аутентификация отделена от оценки. Следуйте задокументированной настройке идентификации/доступа в образце. Нет задокументированного «резервного базового аутентификатора», на который можно было бы опереться для защиты публичной конечной точки.

## 5.6 Практическое задание по проектированию: настройка розничной торговли

!!! warning "Практическое задание, а не завершённое развертывание"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

Напишите краткий план, охватывающий:

| Область | Решение и собираемые доказательства |
|------|----------------------------------|
| Обязанности агента | Начните с одного агента или обоснуйте отдельных агентов Shopper и Loyalty и логику маршрутизации |
| Данные | Определите синтетический каталог/набор данных с наградами и ответственность за обновления |
| Инструменты | Сначала реализуйте обработчики только для чтения; укажите авторизацию и проверку для любых записей |
| Модели | Выберите доступные комбинации модели/версии/SKU и проверьте квоту; избегайте выделения ресурсов для неиспользуемых моделей |
| Извлечение | Определите индексацию, размерность вложений, цитирования и контроль доступа на уровне документов |
| Оценка | Добавьте случаи с ожидаемым ответом, неподдерживаемыми вопросами, использованием инструментов и безопасностью с явными порогами |
| Операции | Определите телеметрию, бюджеты задержки/ошибок, лимиты затрат и ответственность за очистку |

Сохранение `custom-agents/shopper-agent-instructions.md` не заставляет образец его загружать. Найдите код приложения, который создаёт/обновляет агента, подключите туда ваши проверенные инструкции и убедитесь в версии агента перед тестированием. Инструкции не могут предоставлять доступ к данным или инструментам, которые вы не реализовали.

Вносите по одному изменению за раз, повторно развертывайте затронутые компоненты и повторно запускайте ваши исходные вопросы и оценки. Сохраняйте рабочую версию для сравнения. Для вдохновения по архитектуре смотрите [шаблон розничной торговли](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md), который также не является полным розничным приложением.
