## 5.1 Установите базовую конфигурацию

Используйте инициализированный репозиторий [Get Started with AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) из предыдущих модулей. Запишите версию шаблона, версию AZD, выбранную среду, развертывание модели и рабочие примеры вопросов перед внесением изменений.

Пример реализует чат-приложение с поддержкой агента. Оно **не становится** двухагентной розничной системой просто при установке переменных окружения или сохранении дополнительных файлов с инструкциями. Дополнительные агенты, обработчики инструментов, маршрутизация, авторизация и доступ к данным требуют кода приложения.

Проверьте инструкции и инструменты текущего развернутого агента в Foundry. Протестируйте один фактический вопрос, один вопрос на поиск и один вопрос, на который образец данных не может ответить. Проверьте ссылки на источники на соответствие с реальными исходными документами, а не полагайтесь на плавный ответ.

## 5.2 Настройка поиска знаний

Шаблон поддерживает поиск на основе файлов и опциональную интеграцию Azure AI Search. Следуйте [текущему руководству по AI Search](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) для индексации и настройки инструментов.

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

Включение сервиса — только часть задачи поиска. Перед загрузкой собственных данных:

1. Подтвердите, что у вас есть разрешение на использование документов и удалите конфиденциальную информацию.
2. Выберите модель эмбеддингов, поддерживаемую в вашем регионе, и установите ее совместимую версию, тип развертывания и размерность векторов.
3. Создайте/заполните индекс, используя задокументированный процесс из примера.
4. Настройте инструмент поиска агента для использования этого индекса.
5. Проверьте поиск, ссылки на источники, авторизацию и поведение при отсутствии соответствующих документов.

Не переходите с `text-embedding-3-small` на другую модель эмбеддингов без проверки размерностей и необходимости перестроить/переиндексировать векторы. Имя, такое как `retail-products`, не является реализованным каталогом или политикой контроля доступа.

## 5.3 Трассировка и мониторинг

Следуйте [руководству по наблюдаемости примера](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring). Убедитесь, что необходимый ресурс Application Insights и подключение уже созданы; при изменении настроек инфраструктуры используйте `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

Отправьте тестовый запрос, затем проверьте журналы приложения Container App и представление трассировки агента в Foundry. Проверьте задержки, вызовы инструментов, ошибки и корреляцию между запросом и трассировкой. Не предполагая, что телеметрия подключена лишь потому, что развертывание прошло успешно.

Оставьте `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` отключенным, если вы явно не проверили согласие, редактирование, хранение и контроль доступа. Трассировки могут содержать конфиденциальные аргументы инструментов или содержимое документов, даже если обычные журналы приложения кажутся безопасными.

## 5.4 Оценка агента

Точка входа для оценки текущего примера теперь [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py), а не каталог `evals/`. Из корня примера используйте среду Python, соответствующую задокументированным требованиям:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

Перед запуском выполните [требования для оценки](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md). Тесты загружают конфигурацию из выбранного `.azure/<environment>/.env`; подтвердите, что выбрана нужная среда. Важные входные данные включают:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, используя формат, требуемый текущим примером (просмотренная версия использует `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, используемая как развертывание модели-судьи

Изучите тесты, чтобы понять выбор оценщика, пороги, необходимые роли и затраты на модели. Завершённый запуск не гарантирует прохождение контрольного качества; проверьте баллы, сбои/ошибки и связанные результаты Foundry.

### Отдельное расширение оценок AZD

Указанный выше Python-тест — это **специфичный для примера рабочий процесс**. Опциональное расширение `azure.ai.evaluations` — это другой рабочий процесс с собственной конфигурацией `evals/azure.eval.yaml`:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

Для полного развертывания расширения см. [рабочие процессы оценки и миграцию](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md). С версии beta.22 расширения агентов не используйте удалённые команды `azd ai agent eval`. Установка расширения оценок не конвертирует Python-тесты примера и не создаёт автоматически конфигурацию оценки.

## 5.5 AI red teaming и непрерывная оценка

Текущий пример предоставляет [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py). Выполните его требования и ознакомьтесь с предполагаемыми целями и затратами перед запуском:

```bash
pytest tests/test_red_teaming.py -s
```

Используйте авторизованное тестовое развертывание и синтетические данные. Проверьте сгенерированные атаки и результаты; это сканирование не гарантирует, что приложение безопасно или соответствует требованиям.

В [руководстве по наблюдаемости](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) также описывается непрерывная оценка, настроенная при запуске контейнера. Она оценивает реальные взаимодействия пользователей, а не сгенерированный тестовый трафик, и поддержка оценщика варьируется в зависимости от региона. Отсутствие взаимодействий означает отсутствие записей оценки. Проверьте установленную версию образца и конфигурацию оценщика вместо того, чтобы предполагать, что у каждого развертывания одни и те же настройки по умолчанию.

Аутентификация отделена от оценки. Следуйте документированной настройке идентификации/доступа из образца. Нет документированного «резервного базового аутентификатора», на который можно было бы опереться для защиты публичной конечной точки.

## 5.6 Упражнение по дизайну: настройка розничной торговли

!!! warning "Упражнение по дизайну, а не завершённое развертывание"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

Напишите короткий план по следующим пунктам:

| Область | Решение и данные для сбора |
|------|----------------------------------|
| Ответственность агента | Начните с одного агента или обоснуйте наличие отдельных агентов Shopper и Loyalty и логику маршрутизации |
| Данные | Определите синтетический каталог/набор данных по наградам и ответственного за обновления |
| Инструменты | Сначала реализуйте обработчики только для чтения; укажите авторизацию и проверку для любых записей |
| Модели | Выберите доступные комбинации модели/версии/SKU и проверьте квоты; избегайте выделения ресурсов на неиспользуемые модели |
| Извлечение | Определите индексацию, размерность эмбеддингов, цитаты и контроль доступа на уровне документов |
| Оценка | Добавьте случаи с ожидаемым ответом, неподдерживаемыми вопросами, использованием инструментов и безопасностью с явными порогами |
| Операции | Определите телеметрию, бюджеты задержек/ошибок, лимиты стоимости и ответственность за очистку |

Сохранение `custom-agents/shopper-agent-instructions.md` не приводит к его загрузке образцом. Найдите код приложения, который создаёт/обновляет агента, подключите туда свои проверенные инструкции и проверьте итоговую версию агента перед тестированием. Инструкции не могут предоставлять доступ к данным или инструментам, которые вы не реализовали.

Вносите по одному изменению за раз, заново развертывайте затронутые компоненты и повторно выполняйте исходные вопросы и оценки. Имейте рабочую версию для сравнения. Для вдохновения по архитектуре смотрите [шаблон розничной торговли](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md), который также не является полноценным розничным приложением.
