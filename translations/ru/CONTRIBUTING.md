# Содействие проекту AZD For Beginners

Спасибо за ваш интерес к участию в курсе AZD For Beginners! Этот документ содержит рекомендации и информацию для участников.

## Как внести вклад

### Сообщение о проблемах

Если вы обнаружили ошибки, баги или у вас есть предложения по улучшению:

1. **Проверьте существующие проблемы**: Поиск [существующих проблем](https://github.com/microsoft/azd-for-beginners/issues), чтобы избежать дубликатов
2. **Создайте новую проблему**: Используйте соответствующий шаблон для issue
3. **Предоставьте детали**: Включите шаги для воспроизведения, ожидаемое поведение и скриншоты, если применимо

### Предложение изменений

1. **Форкните репозиторий**: Создайте собственный форк проекта
2. **Создайте ветку**: Создайте ветку для вашей функциональности
3. **Внесите изменения**: Следуйте стандартам кодирования и документации
4. **Протестируйте ваши изменения**: Убедитесь, что все ссылки работают и контент отображается корректно
5. **Отправьте pull-запрос**: Предоставьте четкое описание ваших изменений

### Виды вкладов

Мы приветствуем следующие виды вкладов:

#### Улучшения контента
- Исправление опечаток, грамматики и форматирования

- Сообщение о сломанных ссылках или неправильных примерах кода

## Руководство по внесению вклада

### Стандарты документации

- Используйте ясный, понятный язык, подходящий для начинающих
- Включайте цели обучения и результаты
- Предоставляйте пошаговые инструкции с ожидаемыми результатами
- Добавляйте навигационные ссылки на связанный контент
- Используйте согласованное форматирование и стиль markdown

### Примеры кода

- Убедитесь, что все примеры кода протестированы и работают
- Включайте комментарии с объяснением ключевых концепций
- Следуйте лучшим практикам Azure и AZD
- При необходимости предоставляйте ожидаемый вывод

### Проверка английской документации

Из корня репозитория установите существующие требования для разработки и запустите:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

Проверка ссылок офлайн проверяет пути Markdown/HTML на английском, заголовки, явные якоря и пустые ссылки. Она исключает сгенерированные `translations/` и `translated_images/`, включая ссылки на эти директории. Она не загружает внешние сайты и не проверяет развертывания Azure. Используйте `--json <report-path>` для экспорта ошибок и списка внешних URL для отдельной сетевой проверки. При изменении технических инструкций проверяйте текущие команды из upstream и требования к примерам; различайте протестированные приложения и проектные схемы.

### Сообщения коммитов

Используйте ясные, описательные сообщения коммитов:
- `docs: fix typo in installation guide`
- `feat: add new container app example`
- `fix: correct broken link in chapter 2`
