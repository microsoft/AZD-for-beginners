## ਝਲਕ

**ਲਕੜੀ:** ਇੱਕ ਕਸਟਮਰ ਸਹਾਇਤਾ ਪ੍ਰਣਾਲੀ ਡਿਜ਼ਾਇਨ ਕਰਨੀ ਜਿਸ ਵਿੱਚ ਇੱਕ ਕਸਟਮਰ ਏਜੰਟ ਅਤੇ ਇੱਕ ਇਨਵੈਟਰੀ
ਏਜੰਟ ਹੋਵੇ, ਇਹ ਪਛਾਣਣਾ ਕਿ ਢਾਂਚਾ ਕੀ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਅਤੇ ਗੁੰਮ ਐਪਲੀਕੇਸ਼ਨ
ਠੇਕਿਆਂ ਅਤੇ ਸੱਚਾਈ ਤਪਾਸੀ ਦੀ ਯੋਜਨਾ ਬਣਾਉਣਾ।

**ਦਰਸ਼ਕ:** ਵਿਕਾਸਕਾਰ ਜਿਨ੍ਹਾਂ ਨੇ ਸਥਾਨਕ
[ਚੈਟ ਸੈਂਪਲ](../../../examples/azure-openai-chat) ਅਤੇ [ਦੋ-ਸੇਵਾ ਕੰਟੇਨਰ ਸੈਂਪਲ](../../../examples/container-app/microservices)।
ਆਰਕੀਟੈਕਚਰ ਅਧਿਐਨ ਲਈ 2–3 ਘੰਟੇ ਦਿਓ। ਐਪਲੀਕੇਸ਼ਨ ਬਣਾਉਣਾ ਇੱਕ ਵੱਖਰਾ
ਪ੍ਰੋਜੈਕਟ ਹੈ: 80–120 ਵਿਕਾਸ ਘੰਟੇ ਅਨੁਭਵੀ ਡਿਵੈਲਪਰਾਂ ਲਈ ਇੱਕ ਦਿੱਖੀ ਯੋਜਨਾ ਅੰਦਾਜ਼ਾ ਹੈ,
**ਡਿਲੀਵਰੀ ਦਾ ਵਾਅਦਾ ਨਹੀਂ**; ਉਤਪਾਦਨ ਸਖਤੀ, ਟੈਸਟ,
ਸੁਰੱਖਿਆ ਸਮੀਖਿਆ, ਅਤੇ ਓਪਰੇਸ਼ਨ ਵਾਧੂ ਕੰਮ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

### ਸਿੱਖਣ ਦੇ ਨਤੀਜੇ

- ਰੂਟਿੰਗ, ਗ੍ਰਾਉਂਡਿੰਗ, ਟੂਲ ਅਧਿਕਾਰ, ਅਤੇ ਗੱਲਬਾਤ ਦੀ ਮਾਲਕੀ ਬਾਰੇ ਸਮਝਾਓ।
- ਮਾਡਲ ਪਛਾਣ, ਡਿਪਲੋਏਮੈਂਟ ਨਾਂ, API ਵਰਜਨ ਅਤੇ ARM ਵਰਜਨਾਂ ਨੂੰ ਵੱਖਰਾ ਕਰੋ।
- ਮਿਲਦੇ-ਜੁਲਦੇ ਵੇਕਟਰ ਮਾਪਦੰਡਾਂ ਦੇ ਨਾਲ ਦਸਤਾਵੇਜ਼ ਖਪਤ ਅਤੇ ਪ੍ਰਾਪਤੀ ਡਿਜ਼ਾਈਨ ਕਰੋ।
- ਪਰਖਣਯੋਗ ਕਾਰਗੁਜ਼ਾਰੀ, ਮੁੱਲਾਂਕਣ ਅਤੇ ਨਾਕਾਮੀ-ਪੁਨਰ ਪ੍ਰਾਪਤੀ ਦੀਆਂ ਲੋੜਾਂ ਨੂੰ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ।
- ਆਪਣੇ-ਆਪ्शन ਅਰਕੀਟੈਕਚਰ ਲਕੜਾਂ ਨੂੰ ਅਸਲ ਵਿੱਚ ਪ੍ਰਦਾਨ ਕੀਤੀਆਂ ਸਰੋਤਾਂ ਤੋਂ ਵੱਖਰਾ ਕਰੋ।

## ਸਮਾਧਾਨ ਅਰਕੀਟੈਕਚਰ

```mermaid
flowchart TB
    User[Customer] --> Frontend[Frontend — must build]
    Frontend --> Router[Authenticated router — must build]
    Router --> Customer[Customer agent — must build]
    Router --> Inventory[Inventory agent — must build]
    Customer --> Chat[Primary chat deployment]
    Inventory --> Mini[Optional mini deployment]
    Customer --> Search[AI Search — empty service]
    Inventory --> Stock[Inventory source + tool — must build]
    Search --> Index[Index + ingestion — must build]
    Blob[Blob documents] --> Processor[Document pipeline — must build]
    Processor --> DocAI[Document Intelligence]
    Processor --> Embeddings[Optional embeddings deployment]
    Processor --> Index
    Router --> Cosmos[Cosmos DB chat-history container]
    Router -. instrument .-> Insights[Optional Application Insights]
    Customer -. instrument .-> Insights
    Eval[Evaluation runner — must build] --> Grader[Grader deployment]
```

ਇਹ ਇੱਕ **ਲਕੜੀਐਂਡੀ ਐਪਲੀਕੇਸ਼ਨ ਅਰਕੀਟੈਕਚਰ** ਹੈ, ਚੱਲਦੇ ਏਜੰਟ
ਸੇਵਾਵਾਂ ਦਾ ਚਿੱਤਰ ਨਹੀਂ। ARM ਸਕੈਫੋਲਡ ਅਧਾਰਭੂਤ ਸੇਵਾਵਾਂ ਅਤੇ ਦੋ ਪਲੇਸਹੋਲਡਰ
ਕੰਟੇਨਰ ਹੀ ਬਣਾਉਂਦਾ ਹੈ। ਫਰੰਟ ਡੋਰ, ਰਜਿਸਟਰੀ, ਪ੍ਰਬੰਧਿਤ ਪਹਿਚਾਣਾਂ, ਭੂਮਿਕਾ ਅਸਾਈਨਮੈਂਟ,
ਪ੍ਰਾਈਵੇਟ ਐਂਡਪੌਇੰਟ, ਫੇਲਓਵਰ, ਐਪਲੀਕੇਸ਼ਨ ਇੰਸਟ੍ਰੂਮੈਂਟੇਸ਼ਨ, ਅਤੇ ਚੇਤਾਵਨੀਆਂ ਸ਼ਾਮਲ ਨਹੀਂ ਹਨ।

ਇੱਕ Azure OpenAI ਬੇਨਤੀ ਦਾ `model` ਦਲੀਲ **ਡਿਪਲੋਇਮੈਂਟ ਨਾਮ** ਹੁੰਦਾ ਹੈ, ਜਰੂਰੀ ਨਹੀਂ ਕਿ
ਕੈਟਾਲੌਗ ਮਾਡਲ ਪਹਚਾਣਕਾਰ ਹੈ। ਡਾਟਾ-ਪਲੇਨ API ਵਰਜਨ `2024-10-21`

ਕੋਈ ਮਾਡਲ ਜੋ ਉਪਲੱਬਧ ਨਹੀਂ ਹੈ, ਉਸਨੂੰ ਸਿਰਫ਼ ਡਾਟਾ-ਪਲੇਨ API ਵਰਜਨ ਬਦਲ ਕੇ ਠੀਕ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ।

`--no-multi-region` ਸੈਕੰਡਰੀ ਅਤੇ ਐਂਬੈਡਿੰਗਸ ਖਾਤਿਆਂ ਨੂੰ ਛੱਡ ਦਿੰਦਾ ਹੈ। ਇੱਕ ਪ੍ਰਾਥਮਿਕ ਚੈਟ ਅਤੇ
ਸੁਤੰਤਰ ਗਰੇਡਰ ਖਾਤਾ ਬਚਦਾ ਹੈ। ਵੱਖਰੇ ਮਾਡਲ ਖਾਤੇ ਆਪਣੇ ਆਪ ਫੇਲਓਵਰ ਨਹੀਂ ਦਿੰਦੇ;
ਇਸ ਲਈ ਐਪਲੀਕੇਸ਼ਨ ਰਾਊਟਿੰਗ, ਮਿਲਦੇ ਜੁਲਦੇ ਡਿਪਲੋਇਮੈਂਟ, ਹੈਲਥ ਚੈਕ,
ਰਿਟ੍ਰਾਈ ਹੱਦਾਂ ਅਤੇ ਡਾਟਾ-ਰਿਹਾਇਸ਼ੀ ਸਮੀਖਿਆ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

## ਲਾਗੂ ਕਰਨ ਦਾ ਰੋਡਮੇਪ

### 1. ਇੱਕ ਟੈਸਟ ਕੀਤੀ ਗਈ ਇੰਟਰੈਕਸ਼ਨ ਨਾਲ ਸ਼ੁਰੂ ਕਰੋ

ਵੱਡੇ ਸਕੈਫੋਲਡ ਦੀ ਪ੍ਰੋਵੀਜ਼ਨਿੰਗ ਤੋਂ ਪਹਿਲਾਂ, ਸਥਾਨਕ ਚੈਟ ਨਮੂਨੇ ਦਾ ਇਸਤੇਮਾਲ ਕਰਕੇ
ਅਨੁਮਾਨ ਕਨੈਕਟਿਵਿਟੀ ਸਥਾਪਿਤ ਕਰੋ। ਇੱਕ ਪ੍ਰਤੀਨਿਧੀ ਗ੍ਰਾਹਕ ਸਵਾਲ, ਮੰਨਿਆ ਗਿਆ
ਉੱਤਰੀ ਸਰੋਤ, ਉਮੀਦਵਾਰ ਹਵਾਲਾ, ਅਤੇ ਜਦੋਂ ਉਹ ਸਰੋਤ ਗਾਇਬ ਹੋਵੇ ਤਾਂ ਅਸਫਲਤਾ ਦੇ ਵਰਤਾਵ ਨੂੰ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ।

### 2. ਰਾਊਟਿੰਗ ਅਤੇ ਟੂਲ ਦੀਆਂ ਸੀਮਾਵਾਂ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ

ਆਪਣੇ ਰਾਊਟਰ ਸਰੋਤ, ਡਿਪੈਂਡেন্সੀ ਮੈਨਿਫੈਸਟ, ਡਾਕਰਫਾਇਲ, ਅਤੇ ਟੈਸਟ ਬਣਾਓ। ਇੱਕ
illustrative contract could be `POST /chat` with `{"message":"...","conversation_id":"..."}`.
**ਉਹ ਐਂਡਪੌਇੰਟ ਇੱਕ ਡਿਜ਼ਾਈਨ ਪ੍ਰস্তਾਵ ਹੈ; ਇਹ ARM ਟੈਂਪਲੇਟ ਦੁਆਰਾ ਲਾਗੂ ਨਹੀਂ ਕੀਤਾ ਗਿਆ ਹੈ।**

Validate body types/limits, derive user identity from authentication, enforce
conversation ownership, apply request timeouts, and return meaningful error codes.
Do not treat HTTP failures or empty replies as successful agent results.

### 3. Implement grounding and ingestion

The ARM template does not create a search index. This is a **reference JSON
fragment to adapt in your own index definition**, not a file already in the repo:

```json
{
  "name": "retail-product-index",
  "fields": [
    {"name": "id", "type": "Edm.String", "key": true},
    {"name": "title", "type": "Edm.String", "searchable": true},
    {"name": "content", "type": "Edm.String", "searchable": true},
    {"name": "category", "type": "Edm.String", "filterable": true},
    {
      "name": "content_vector",
      "type": "Collection(Edm.Single)",
      "searchable": true,
      "dimensions": 1536,
      "vectorSearchProfile": "retail-profile"
    }
  ],
  "vectorSearch": {
    "algorithms": [{"name": "retail-hnsw", "kind": "hnsw"}],
    "profiles": [{"name": "retail-profile", "algorithm": "retail-hnsw"}]
  }
}
```

ਪ੍ਰੋਫਾਈਲ ਵੈਕਟਰ ਫੀਲਡ ਨੂੰ ਇਸ ਦੇ ਐਲਗੋਰਿਦਮ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਮਾਪਦੰਡਾਂ ਨੂੰ ਮਿਲਣਾ ਜਰੂਰੀ ਹੈ
ਅਸਲ ਐਮਬੈਡਿੰਗ ਆਉਟਪੁੱਟ (ਇਸ `ada-002` ਡਿਪਲੋਇਮੈਂਟ ਲਈ 1536). Python ਰੀਟਰੀਵਲ ਲਈ,
ਅਧੂਰੇ ਡਿਕਸ਼ਨਰੀ ਦੀ ਬਜਾਏ `azure.search.documents.models.VectorizedQuery` ਦੀ ਵਰਤੋਂ ਕਰੋ
ਜਿਸ ਵਿੱਚ ਇਸਦਾ ਵੇਕਟਰ ਕ్వੈਰੀ ਕਿਸਮ ਨਹੀਂ ਹੈ:

```python
# Reference function only: supply an authenticated async SearchClient and an embedding.
from azure.search.documents.models import VectorizedQuery

async def retrieve(search_client, embedding):
    results = await search_client.search(
        search_text=None,
        vector_queries=[VectorizedQuery(
            vector=embedding,
            k_nearest_neighbors=5,
            fields="content_vector"
        )],
        select=["id", "title", "content"]
    )
    return [document async for document in results]
```

ਇੱਕ ਵੱਖਰੀ ਇੰਜੈਸ਼ਨ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਬਣਾਓ ਜੋ:

1. ਅਪਲੋਡ ਐਕਸੈਸ ਲਈ ਅਧਿਕਾਰ ਦਿੰਦਾ ਹੈ ਅਤੇ ਸਮੱਗਰੀ ਦੀ ਕਿਸਮ ਅਤੇ ਆਕਾਰ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ।
2. ਪ੍ਰਮਾਣਿਤ SDK ਕਾਲਾਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਾਈਵੇਟ ਬਲੌਬ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ। ਇੱਕ ਪ੍ਰਾਈਵੇਟ ਬਲੌਬ URL ਆਪਣੇ ਆਪ ਵਿੱਚ
   ਇੱਕ ਪੜ੍ਹਨ ਯੋਗ ਡੌਕਯੂਮੈਂਟ ਇੰਟੈਲੀਜੈਂਸ ਇਨਪੁੱਟ **ਨਹੀਂ** ਹੈ; ਡਾਊਨਲੋਡ ਕੀਤੇ ਬਾਈਟਾਂ ਨੂੰ ਭੇਜੋ
   `AnalyzeDocumentRequest(bytes_source=...)` ਨਾਲ ਜਾਂ ਕਿਸੇ ਉਚਿਤ ਸਕੋਪ ਵਾਲੇ,
   ਛੋਟੀ ਮਿਆਦ ਵਾਲੇ SAS ਦੀ ਵਰਤੋਂ ਕਰੋ, ਪਹੁੰਚ ਦੀਆਂ ਲੋੜਾਂ ਦੀ ਸਮੀਖਿਆ ਕਰਨ ਤੋਂ ਬਾਅਦ।
3. ਟੈਕਸਟ ਨਿਕਾਲਦਾ ਹੈ, ਇਸਨੂੰ ਏਮਬੈਡਿੰਗ ਸੀਮਾਵਾਂ ਵਿੱਚ ਫਿੱਟ ਕਰਨ ਲਈ ਚੰਕ ਕਰਦਾ ਹੈ, ਅਤੇ ਏਮਬੈਡਿੰਗ ਤਿਆਰ ਕਰਦਾ ਹੈ।
4. ਸਥਿਰ ਵੈਧ ਦਸਤਾਵੇਜ਼ ਕੁੰਜੀਆਂ ਬਣਾਂਦਾ ਹੈ ਅਤੇ ਮੇਲ ਖਾਂਦੇ ਵੈਕਟਰਾਂ ਨਾਲ ਚੰਕ ਅੱਪਲੋਡ ਕਰਦਾ ਹੈ।
5. ਪ੍ਰਤੀ ਦਸਤਾਵੇਜ਼ ਇੰਡੈਕਸਿੰਗ ਨਤੀਜਿਆਂ ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ, ਮੁੜ ਕੋਸ਼ਿਸ਼ਾਂ ਨੂੰ ਸੰਭਾਲਦਾ ਹੈ, ਅਤੇ ਪੁਰਾਣਾ ਡਾਟਾ ਅਪਡੇਟ/ਹਟਾਉਂਦਾ ਹੈ।

OData ਫਿਲਟਰਾਂ ਵਿੱਚ ਮਨਮਾਨੇ ਯੂਜ਼ਰ ਕੁੰਜੀਆਂ/ਮੁੱਲ ਨਹੀਂ ਜੋੜੋ। ਖੇਤਰਾਂ ਦੀ ਅਨੁਮਤੀ ਸੂਚੀ ਬਨਾਓ,
ਮੁੱਲਾਂ ਦੀ ਕਿਸਮਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ, ਅਤੇ ਸਤਰਿੰਗ ਦਾ ਕੋਟ ਛੁਟਕਾਰਾ ਦਿਓ। ਬੂਲੀਅਨ ਅਤੇ ਨੰਬਰ ਫਿਲਟਰਾਂ ਨੂੰ ਲੋੜ ਹੈ
ਟਾਈਪ ਕੀਤੇ ਹੋਏ ਲਿਟਰਲਾਂ ਦੀ, ਨਾ ਕਿ ਕੋਟ ਕੀਤੇ ਸਤਰਿੰਗਾਂ ਦੀ।

### 5. ਟੈਲੀਮੀਟਰੀ ਅਤੇ ਮੁਲਾਂਕਣ ਜੋੜੋ

ਐਪਲੀਕੇਸ਼ਨ ਇਨਸਾਈਟਸ ਬਣਾਉਣਾ ਕੋਡ ਨੂੰ ਸਾਜੋ-ਸਮਭਾਲ ਨਹੀਂ ਕਰਦਾ। ਨਵੀਂ ਐਪਲੀਕੇਸ਼ਨ ਬਣਾਉਂਦੇ ਸਮੇਂ ਸਮਰਥਿਤ Azure Monitor
OpenTelemetry ਸਾਜੋ-ਸਮਭਾਲ ਦੀ ਵਰਤੋਂ ਕਰੋ, ਸੇਵਾਵਾਂ ਵਿੱਚ ਟਰੇਸ ਸੰਦਰਭ ਨੂੰ ਪ੍ਰਸਾਰਿਤ ਕਰੋ,
ਅਤੇ ਗਾਹਕ ਦੇ ਪ੍ਰਾਂਪਟਸ, ਦਸਤਾਵੇਜ਼, ਜਾਂ ਰਾਜ਼ ਨਾ ਲੌਗ ਕਰੋ।
ਇੱਕ ਕੈਵਰੀ ਨੂੰ ਕੱਟਨਾ ਇਸਨੂੰ **ਗੁਪਤ** ਨਹੀਂ ਬਨਾਉਂਦਾ।

ਬੇਨਤੀ ਸਮਾਂਬੱਧਤਾ, ਰੂਟਿੰਗ/ਟੂਲ ਨਾਕਾਮੀਆਂ, ਪ੍ਰਾਪਤੀ ਪ੍ਰਸੰਗਿਕਤਾ, ਹਵਾਲਾ ਸਹੀਤਾ, ਟੋਕਨ ਵਰਤੋਂ,
ਅਤੇ ਪਰਹੇਜ਼ ਨੂੰ ਮਾਪੋ। ਮੁਲਾਂਕਣ ਮਾਮਲਿਆਂ ਨਾਲ ਨਾਲ ਸੱਚਾਈ ਦੀ ਸੂਚੀ/ਨੀਤੀ ਤੱਥ ਸੰਭਾਲੋ:
ਇਕ ਗਰੇਡਰ ਕੇਵਲ ਇੱਕ ਸਵਾਲ ਅਤੇ ਜਵਾਬ ਤੋਂ ਤੱਥਮੂਲ ਨਿਰਧਾਰਿਤ ਨਹੀਂ ਕਰ ਸਕਦਾ।


ਸੰਰਚਿਤ ਆਊਟਪੁੱਟ/ਸਕੀਮਾ ਪੁਸ਼ਟੀ, ਸਕੋਰ-ਰੇਂਜ ਚੈੱਕ, ਟ੍ਰਾਂਸਪੋਰਟ ਨਾਕਾਮੀ ਗਿਣਤੀ,
ਅਤੇ ਮਨੁੱਖੀ ਸਮੀਖਿਆ ਕੀਤੀਆਂ ਮਾਮਲਿਆਂ ਨੂੰ। ਅਧੂਰੇ/ਤ੍ਰੁੱਟੀ ਵਾਲੇ ਮਾਮਲਿਆਂ ਦੀ ਵੱਖਰੇ ਰਿਪੋਰਟ ਕਰੋ; ਇਨ੍ਹਾਂ ਨੂੰ ਸਫਲ ਗਰੇਡਾਂ ਵਿੱਚ ਨਾ ਬਦਲੋ
ਜਾਂ ਖ਼ਾਮੋਸ਼ੀ ਨਾਲ ਜ਼ੀਰੋ-ਗੁਣਵੱਤਾ ਵਾਲੇ ਮਾਡਲ ਜਵਾਬਾਂ ਵਿੱਚ ਸਮੇਲਿਤ ਨਾ ਕਰੋ।


ਬੇਨਤੀ, ਗੁੰਮਸ਼ੁਦਾ ਟੈਸਟ ਰਣਨੀਤੀ, ਜਾਂ ਖਾਲੀ ਜਵਾਬ ਇੱਕ ਟੈਸਟ ਨੂੰ **ਅਨਿਰਣਾ ਜਾਂ
ਅਸਫਲ** ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ, ਨਾ ਕਿ "100% ਸੁਰੱਖਿਅਤ" ਸਕੋਰ ਦੇਣਾ। ਢੰਗ ਨਾਲ ਅਧਿਕ੍ਰਿਤ ਟੈਸਟਿੰਗ ਕਰੋ
ਫੇਲ੍ਹ**, "100% ਸੁਰੱਖਿਅਤ" ਸਕੋਰ ਨਾ ਦੇਣ। ਯੋਗ ਅਧਿਕ੍ਰਿਤ ਟੈਸਟਿੰਗ ਕਰੋ
ਉਤਪਾਦਨ-ਤਿਆਰੀ ਦੇ ਕਿਸੇ ਵੀ ਦਾਅਵੇ ਤੋਂ ਪਹਿਲਾਂ ਸੰਦਕਾਰੀ ਅਤੇ ਮਨੁੱਖੀ ਸਮੀਖਿਆ।

### 6. ਆਪਣੀ ਐਪਲੀਕੇਸ਼ਨ ਡਿਪਲੋਏ ਕਰੋ

ਆਪਣੀਆਂ ਸੋਰਸ ਡਾਇਰੈਕਟਰੀਜ਼, ਮੇਨੀਫੈਸਟ, ਟੈਸਟ, ਰਜਿਸਟਰੀ, ਅਤੇ ਇਮੇਜ-ਪੁੱਲ ਅਧਿਕਾਰ ਬਣਾਓ।

ਬਿਲਕੁਲ ਕੋਈ ਸਾਹਮਣੇ ਵਾਲਾ `config` ਡਕਸ਼ਨਰੀ ਆਜ਼ਦ ਸਰਵਿਸ ਹੇਠ ਨਹੀਂ ਹੈ ਜੋ ਆਪਣੇ ਆਪ ਰਨਟਾਈਮ ਵਾਤਾਵਰਣ ਚਲਾਉਂਦਾ ਹੈ।
`azd env set` ਸਿਰਫ ਉਹਨਾਂ ਸਰੋਤਾਂ ਵਿੱਚ ਬਦਲਾਅ ਕਰਦਾ ਹੈ ਜੋ ਉਨ੍ਹਾਂ ਮੁੱਲਾਂ ਨੂੰ ਖਪਤ ਕਰਦੇ ਹਨ।
ਇਸ ਸਕੈਫੋਲਡ ਵਿੱਚ ਕੋਈ ਕੈਨਰੀ, ਖੇਤਰਾਂ ਦੀ ਸੂਚੀ, ਜਾਂ ਬਰੀਕੀ ਨਾਲ ਸੁਧਾਰਨ ਵਾਲਾ ਹੂਕ ਲਾਗੂ ਨਹੀਂ ਕੀਤਾ ਗਿਆ ਹੈ।


## ਪ੍ਰාਯੋਗਿਕ ਡਿਜ਼ਾਈਨ ਅਭਿਆਸ

ਇਹ **ਆਰਕੀਟੈਕਚਰ ਅਭਿਆਸ** ਹਨ, ਨਾ ਕਿ ਚਲਾਉਣਯੋਗ ਰੀਟੇਲ ਸਟਾਰਟਰ ਕੋਡ ਦੇ ਦਾਅਵੇ।

### ਅਭਿਆਸ 1: ਸਰਹੱਦ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ

**ਸ਼ੁਰੂਆਤੀ ਬਿੰਦੂ:** ਤਿੰਨ ਫਾਇਲਾਂ `retail-multiagent-arm-template/` ਵਿੱਚ।
**ਲਕੜੀ:** ਪ੍ਰੋਵੀਜ਼ਨਿੰਗ ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਕਾਰਜਸ਼ੀਲਤਾ ਨੂੰ ਵੱਖਰਾ ਕਰੋ।
`azuredeploy.json` ਖੋਲ੍ਹੋ, ਦੋਹਾਂ ਕੰਟੇਨਰ ਚਿੱਤਰਾਂ ਅਤੇ `targetPort` ਮੁੱਲਾਂ ਨੂੰ ਲੱਭੋ,
ਫਿਰ ਭੰਡਾਰ ਵਿਚੋਂ ਲਾਪਤਾ ਐਪਲੀਕੇਸ਼ਨ ਹਿੱਸੇ ਦੀ ਸੂਚੀ ਬਣਾਓ।

**ਸਫਲਤਾ ਮਾਪਦੰਡ / ਉੱਤਰ:** ਦੋਹਾਂ ਚਿੱਤਰ hello-world ਪਲੇਸਹੋਲਡਰ ਹਨ ਜੋ ਸੁਣ ਰਹੇ ਹਨ
ਪੋਰਟ 80 ਤੇ; ਏਜੰਟ, ਚੈਟ UI, ਰਾਊਟਰ ਹੈਂਡਲਰ, ਇੰਡੈਕਸ/ਇੰਜੈਸਟਨ, ਮੁਲਾਂਕਣਕਾਰ, ਅਤੇ ਸਕੈਨਰ
ਮੌਜੂਦ ਨਹੀਂ ਹਨ। ਇੱਕ ਸਫਲ ਪਲੇਸਹੋਲਡਰ ਰੂਟ ਬੇਨਤੀ `/chat` ਨੂੰ ਵੈਧ ਨਹੀਂ ਕਰਦੀ।
**ਆਮ ਸਮੱਸਿਆ:** ਸਾਧਨ ਨਾਮਾਂ ਨੂੰ `retail-router` ਵਜੋਂ ਕੰਮ ਕਰਨ ਵਾਲੇ ਕੋਡ ਦੇ ਤੌਰ 'ਤੇ ਸਮਝਣਾ।

### ਅਭਿਆਸ 2: ਵੇਕਟਰ ਕੰਫਿਗਰੇਸ਼ਨ ਦਾ ਟਰੇਸ ਕਰੋ

**ਸ਼ੁਰੂਆਤੀ ਬਿੰਦੂ:** ਉਪਰ ਦਿੱਤਾ ਗਿਆ ਇੰਡੈਕਸ JSON।
**ਉਦੇਸ਼:** ਖੇਤਰ → ਪ੍ਰੋਫਾਈਲ → ਅਲਗੋਰਿਦਮ ਸੰਬੰਧ ਨੂੰ ਸਮਝਣਾ।
ਇਹ ਪਛਾਣੋ ਕਿ ਕਿਹੜੀਆਂ ਕੀਮਤਾਂ ਨੂੰ ਵੱਖਰੇ ਆਉਟਪੁੱਟ ਡਾਇਮੈਨਸ਼ਨ ਵਾਲੇ ਐੰਬੈਡਿੰਗ ਮਾਡਲ ਵਿੱਚ ਬਦਲਦੇ ਸਮੇਂ ਬਦਲਣਾ ਲਾਜ਼ਮੀ ਹੈ,
ਫਿਰ `retrieve` ਫੰਕਸ਼ਨ ਦੀ ਜਾਂਚ ਕਰੋ।

**ਸਫਲਤਾ ਦੇ ਮਾਪਦੰਡ / ਜਵਾਬ:** ਫੀਲਡ `dimensions` ਨੂੰ ਅਸਲ ਵੈਕਟਰ ਲੰਬਾਈ ਵਿੱਚ ਬਦਲੋ;
`vectorSearchProfile` ਨੂੰ ਘੋਸ਼ਿਤ ਪ੍ਰੋਫਾਈਲ ਅਤੇ ਇਸਦੇ ਐਲਗੋਰਿਦਮ ਨਾਲ ਸੰਗਤ ਬਨਾਓ;
ਕਵੇਰੀ `fields` ਨੂੰ ਵੈਕਟਰ ਫੀਲਡ ਦਾ ਨਾਮ ਦੇਣਾ ਚਾਹੀਦਾ ਹੈ। ਮੌਜੂਦਾ ਦਸਤਾਵੇਜ਼ ਵੈਕਟਰਾਂ ਨੂੰ ਦੁਬਾਰਾ ਬਣਾਓ
ਜਦੋਂ ਐਂਬੈਡਿੰਗ ਮਾਡਲ ਬਦਲਦਾ ਹੈ।
**ਆਮ ਸਮੱਸਿਆ:** ਸਿਰਫ ਮਾਡਲ ਦਾ ਨਾਮ ਬਦਲਣਾ ਜਦਕਿ ਅਣਮਿਲਦਿਆਂ ਵਾਲੇ ਵੈਕਟਰਾਂ ਨੂੰ ਜਾਰੀ ਰੱਖਣਾ।

### ਕਸਰਤ 3: ਇੱਕ ਅਸਫਲਤਾ ਟੈਸਟ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ

**ਸ਼ੁਰੂਆਤੀ ਬਿੰਦੂ:** ਜ਼ਿੰਮੇਵਾਰੀਆਂ ਦੀ ਸਾਰਣੀ।
**ਲਕੜੀ:** ਗਲਤ ਸਫਲਤਾ ਨੂੰ ਰੋਕਣਾ।
ਉਪਲਬਧ inventory API, ਕੋਈ ਮਿਲਦੇ ਦਸਤਾਵੇਜ਼ ਨਾ ਹੋਣ ਵਾਲੇ ਖੋਜ ਇੰਡੈਕਸ, ਅਤੇ HTTP 503 ਵਾਪਸ ਕਰਨ ਵਾਲੀ ਮੁਲਾਂਕਣ ਬੇਨਤੀ ਲਈ ਉਮੀਦ ਕੀਤੀ ਵਿਹਵਾਰ ਲਿਖੋ।


**ਆਮ ਸਮੱਸਿਆ:** ਹਰ ਇੱਕ exception ਫੜ ਕੇ ਖਾਲੀ ਜਵਾਬ ਨਾਲ ਜਾਰੀ ਰੱਖਣਾ।

## ਖਰਚੇ, ਸਮੱਸਿਆ ਸਮਾਧਾਨ ਅਤੇ ਸਫਾਈ


## ਲਾਗਤਾਂ, ਸਮੱਸਿਆ ਸुलਝਾਉਣ ਅਤੇ ਸਾਫ਼ ਸੁਥਰਾ ਕਰਨਾ

- ਇੰਫਰਾਸਟਰੱਕਚਰ ਦੇ ਨਿਰੰਤਰ ਖਰਚ ਹੁੰਦੇ ਹਨ ਭਾਵੇਂ ਖਾਲੀ ਖੋਜ ਸੂਚੀਕਰਣ ਅਤੇ ਪਲੇਸਹੋਲਡਰ ਹੋਣ
  ਐਪਸ। ਮੌਜੂਦਾ ਖੇਤੀ ਦੇ ਮੁੱਲ ਵਰਤੋ; ਨਾ “ਛੋਟਾ” ਨਾ ਹੀ ਬਹੁ-ਖੇਤਰ ਮਤਲਬ ਮੁਫ਼ਤ ਹੈ।
- ਟੋਕਨ ਖ਼ਰਚ ਮਾਡਲ, ਕੈਸ਼ਡ/ਅਣਕੈਸ਼ਡ ਇਨਪੁੱਟ, ਆਉਟਪੁੱਟ, ਅਤੇ ਡਿਪਲੋਯਮੈਂਟ SKU 'ਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।
  ਰਾਊਟਿੰਗ ਸਿਰਫ਼ ਤਦ ਹੀ ਪੈਸਾ ਬਚਾ ਸਕਦੀ ਹੈ ਜਦੋਂ ਮਾਪੀ ਗਈ ਵਰਕਲੋਡ ਅਤੇ ਗੁਣਵੱਤਾ ਦੇ ਨਤੀਜੇ ਇਸਦੀ ਵਜ੍ਹਾ ਸਾਬਤ ਹੁੰਦੇ ਹਨ;
  ਇੱਕ ਨਿਸ਼ਚਿਤ 60-80% ਬਚਤ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਹੈ।
- ਪ੍ਰੋਵਿਜ਼ਨਿੰਗ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਮਾਡਲ ਉਪਲਬਧਤਾ ਅਤੇ ਕੋਟਾ ਦੀ ਜਾਂਚ ਕਰੋ; ਅਨੁਮਤੀ,
  ਡਿਪਲੋਇਮੈਂਟ ਨਾਮ, ਖੇਤਰ, ਮਾਡਲ ਸੰਸਕਰਣ, ਅਤੇ ਏਪੀਆਈ ਸੰਸਕਰਣ ਦੀਆਂ ਗਲਤੀਆਂ ਵਿੱਚ ਫਰਕ ਕਰੋ।
- ਗੁੰਮ ਹੋਏ `setup-data.sh`, evaluator CLI, ਜਾਂ `pytest tests/` ਕਮਾਂਡ ਨਾ ਚਲਾਓ।
  ਉਹਨਾਂ ਦੀਆਂ ਕਾਰਗੁਜ਼ਾਰੀਆਂ ਤੁਹਾਡੇ ਵਿਕਾਸ ਬੈਕਲੌਗ ਦਾ ਹਿੱਸਾ ਹਨ।
- ਸਪਾਫੋਲਡ ਸਿਰਫ਼ ARM ਲਈ ਹੈ: ਉਸ ਦੇ
  [ਤਸਦੀਕ ਅਤੇ ਸਾਫ਼-ਸਫਾਈ ਦੇ ਨਿਰਦੇਸ਼](retail-multiagent-arm-template/README.md) ਦੀ ਪਾਲਣਾ ਕਰੋ।
  `azd down` ਉਹਨਾਂ ਸਰੋਤਾਂ ਦਾ ਪ੍ਰਬੰਧ ਨਹੀਂ ਕਰਦਾ।
