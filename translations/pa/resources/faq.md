## ਸ਼ੁਰੂਆਤ

### ਪ੍ਰ: Azure Developer CLI (azd) ਕੀ ਹੈ?
**ਉੱਤਰ**: Azure Developer CLI (azd) ਇੱਕ ਵਿਕਾਸਕਾਰ-ਕੇਂਦਰਿਤ ਕਮਾਂਡ-ਲਾਈਨ ਟੂਲ ਹੈ ਜੋ ਤੁਹਾਡੇ ਲਈ ਤੁਹਾਡੇ ਐਪਲੀਕੇਸ਼ਨ ਨੂੰ ਸਥਾਨਕ ਵਿਕਾਸ ਵਾਤਾਵਰਣ ਤੋਂ Azure ਵਿੱਚ ਲਿਜਾਣ ਦਾ ਸਮਾਂ ਤੇਜ਼ ਕਰਦਾ ਹੈ। ਇਹ ਟੈਂਪਲੇਟਾਂ ਰਾਹੀਂ ਸਰਵੋਤਮ ਅਭਿਆਸ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ ਅਤੇ ਪੂਰੇ ਡਿਪਲੋਇਮੈਂਟ ਲਾਈਫਸਾਈਕਲ ਵਿੱਚ ਮਦਦ ਕਰਦਾ ਹੈ।

### ਪ੍ਰ: azd Azure CLI ਤੋਂ ਕਿਵੇਂ ਵੱਖਰਾ ਹੈ?
**ਉੱਤਰ**: 
- **Azure CLI**: Azure ਸਰੋਤਾਂ ਦੇ ਪ੍ਰਬੰਧਨ ਲਈ ਸਾਰਵਜਨਿਕ ਉਦੇਸ਼ ਵਾਲਾ ਟੂਲ
- **azd**: ਐਪਲੀਕੇਸ਼ਨ ਡਿਪਲੋਇਮੈਂਟ ਵਰਕਫਲੋ ਲਈ ਵਿਕਾਸਕਾਰ-ਕੇਂਦਰਿਤ ਟੂਲ
- azd ਦੀ ਆਪਣੀ ਪ੍ਰਮਾਣਿਕਤਾ ਅਤੇ ਡਿਪਲੋਇਮੈਂਟ ਵਰਕਫਲੋ ਹੈ; Azure CLI ਇੱਕ ਵੱਖਰਾ, ਪੂਰਕ ਟੂਲ ਹੈ
- azd ਵਿੱਚ ਟੈਂਪਲੇਟ, ਵਾਤਾਵਰਣ ਪ੍ਰਬੰਧਨ, ਅਤੇ ਡਿਪਲੋਇਮੈਂਟ ਆਟੋਮੇਸ਼ਨ ਸ਼ਾਮਲ ਹੈ

### ਪ੍ਰ: ਕੀ ਮੈਂ azd ਵਰਤਣ ਲਈ Azure CLI ਨੂੰ ਇੰਸਟਾਲ ਕਰਨਾ ਜਰੂਰੀ ਹੈ?
**ਉੱਤਰ**: AZD ਦੇ ਮੁੱਖ ਵਰਕਫਲੋ ਲਈ ਨਿਰਦੇਸ਼ਤ ਨਹੀਂ। ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ `azd auth login` ਦੀ ਵਰਤੋਂ ਕਰੋ। ਜਦੋਂ ਕਿਸੇ ਟੈਂਪਲੇਟ ਹੂਕ ਜਾਂ ਅਭਿਆਸ ਵਿੱਚ ਖਾਸ ਤੌਰ 'ਤੇ `az` ਕਮਾਂਡ ਚਲਾਈ ਜਾਵੇ, ਤਦੋਂ Azure CLI ਨੂੰ ਅਲੱਗ ਇੰਸਟਾਲ ਕਰੋ।

### ਪ੍ਰ: azd ਕਿਹੜੀਆਂ ਪ੍ਰੋਗ੍ਰਾਮਿੰਗ ਭਾਸ਼ਾਵਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ?
**ਉੱਤਰ**: azd ਭਾਸ਼ਾ-ਨਿਰਪੱਖ ਹੈ। ਇਹ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- ਸਥਿਰ ਵੈਬਸਾਈਟਾਂ
- ਕੰਟੇਨਰ ਸ਼ੁਦ ਹਾਲਾਤ ਵਾਲੀਆਂ ਐਪਲੀਕੇਸ਼ਨਾਂ

### ਪ੍ਰ: ਕੀ ਮੈਂ ਅਸਲ ਪ੍ਰੋਜੈਕਟਾਂ ਨਾਲ azd ਵਰਤ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ! ਤੁਸੀਂ:
1. ਆਪਣੇ ਮੌਜੂਦਾ ਪ੍ਰੋਜੈਕਟਾਂ ਵਿੱਚ azd ਸੰਰਚਨਾ ਸ਼ਾਮਲ ਕਰਨ ਲਈ `azd init` ਦੀ ਵਰਤੋਂ ਕਰੋ
2. ਮੌਜੂਦਾ ਪ੍ਰੋਜੈਕਟਾਂ ਨੂੰ azd ਟੈਂਪਲੇਟ ਢਾਂਚੇ ਦੇ ਅਨੁਕੂਲ ਬਣਾ ਦਿਓ
3. ਆਪਣੇ ਮੌਜੂਦਾ ਢਾਂਚੇ ਦੇ ਆਧਾਰ 'ਤੇ ਕਸਟਮ ਟੈਂਪਲੇਟ ਬਣਾਓ

## ਪ੍ਰਮਾਣਿਕਤਾ ਅਤੇ ਪਹੁੰਚ

### ਪ੍ਰ: ਮੈਂ azd ਨਾਲ Azure ਨਾਲ ਕਿਵੇਂ ਪ੍ਰਮਾਣਿਕਤਾ ਕਰਾਂ?
**ਉੱਤਰ**: `azd auth login` ਦੀ ਵਰਤੋਂ ਕਰੋ ਜੋ Azure ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ ਬਰਾਊਜ਼ਰ ਵਿੰਡੋ ਖੋਲ੍ਹੇਗਾ। CI/CD ਸਥਿਤੀਆਂ ਲਈ ਸੇਵਾ ਪ੍ਰਿੰਸਿਪਲਾਂ ਜਾਂ ਮੈਨੇਜਡ ਪਛਾਣਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ।

### ਪ੍ਰ: ਕੀ ਮੈਂ azd ਨਾਲ ਕਈ Azure سبسਕ੍ਰਿਪਸ਼ਨਾਂ ਦੀ ਵਰਤੋਂ ਕਰ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ। ਹਰ ਵਾਤਾਵਰਣ ਲਈ ਕਿਹੜੀ سبਸਕ੍ਰਿਪਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਨੀ ਹੈ, ਇਹ ਦੱਸਣ ਲਈ `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` ਦੀ ਵਰਤੋਂ ਕਰੋ।

### ਪ੍ਰ: azd ਨਾਲ ਡਿਪਲੋਇਮੈਂਟ ਲਈ ਮੈਨੂੰ ਕਿਹੜੀਆਂ ਅਨੁਮਤੀਆਂ ਦੀ ਜ਼ਰੂਰਤ ਹੈ?
**ਉੱਤਰ**: ਆਮ ਤੌਰ ਤੇ ਤੁਹਾਨੂੰ ਲੋੜ ਹੈ:
- ਸਰੋਤ ਸਮੂਹ ਜਾਂ سبਸک੍ਰਿਪਸ਼ਨ ਉੱਤੇ **Contributor** ਭੂਮਿਕਾ
- ਰੋਲੇ ਅਸਾਈਨਮੈਂਟ ਦੀ ਲੋੜ ਵਾਲੀਆਂ ਸੇਵਾਵਾਂ ਲਈ **User Access Administrator**
- ਵਿਸ਼ੇਸ਼ ਅਨੁਮਤੀਆਂ ਟੈਂਪਲੇਟ ਅਤੇ ਡਿਪਲੋਇਮੈਂਟ ਸਰੋਤਾਂ ਤੇ ਨਿਰਭਰ ਕਰਦੀਆਂ ਹਨ

### ਪ੍ਰ: ਕੀ ਮੈਂ azd ਨੂੰ CI/CD ਪਾਈਪਲਾਈਨਜ਼ ਵਿੱਚ ਵਰਤ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਬਿਲਕੁਲ! azd CI/CD ਇন্টੇਗ੍ਰੇਸ਼ਨ ਲਈ ਤਿਆਰ ਕੀਤਾ ਗਇਆ ਹੈ। ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ ਸੇਵਾ ਪ੍ਰਿੰਸਿਪਲ ਦੀ ਵਰਤੋਂ ਕਰੋ ਅਤੇ ਸੰਰਚਨਾ ਲਈ ਵਾਤਾਵਰਣ ਚਰਪ ਰਾਖੋ।

### ਪ੍ਰ: GitHub Actions ਵਿੱਚ ਪ੍ਰਮਾਣਿਕਤਾ ਕਿਵੇਂ ਸੰਭਾਲੀ ਜਾਵੇ?
**ਉੱਤਰ**: ਵਰਕਲੋਡ ਪਹਚਾਣ ਫੈਡਰੇਸ਼ਨ (OIDC), ਜੋ ਕਿ `azd pipeline config` ਨਾਲ ਸੰਰਚਿਤ ਹੈ, ਦੀ ਸ਼ਿਫਾਰਸ਼ ਕਰੋ। ਜਨਰੇਟ ਕੀਤਾ ਗਿਆ ਵਰਕਫਲੋ AZD ਨੂੰ ਸਿੱਧਾ ਫੈਡਰੇਟਿਡ ਪਹਚਾਣ ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ। ਸਿਰਫ਼ `azure/login` ਕਦਮ AZD ਲੌਗਇਨ ਸਥਾਪਿਤ ਨਹੀਂ ਕਰਦਾ। ਮੌਜੂਦ ਜੌਬ ਵਿੱਚ ਲੌਗਇਨ ਕਦਮ ਹੈ:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

ਲੌਗਇਨ ਬਾਅਦ ਪ੍ਰੋਵਿਜ਼ਨ ਜਾਂ ਡਿਪਲੋਇਮੈਂਟ ਕਰੋ, ਜਿਸ ਵਿੱਚ ਮਨੋਰਥਿਤ AZD ਵਾਤਾਵਰਣ, سبسک੍ਰਿਪਸ਼ਨ ਅਤੇ ਸਥਾਨ ਸੰਰਚਿਤ ਹਨ। ਪਹਚਾਣ ਦਾ ਫੈਡਰੇਟਿਡ ਪ੍ਰਮਾਣ ਪੱਤਰ ਵਰਕਫਲੋ ਦੇ ਰਿਪੋਜ਼ਿਟਰੀ/ਰੇਫ਼ ਜਾਂ GitHub ਵਾਤਾਵਰਣ 'ਤੇ ਭਰੋਸਾ ਕਰਦਾ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ, ਅਤੇ ਇਸ ਦੇ Azure ਰੋਲਾਂ ਨੂੰ ਮੰਗੇ ਗਏ ਆਪਰੇਸ਼ਨਾਂ ਦੀ ਆਗਿਆ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ।

## ਟੈਂਪਲੇਟ ਅਤੇ ਪ੍ਰੋਜੈਕਟ

### ਪ੍ਰ: ਮੈਂ azd ਟੈਂਪਲੇਟ ਕਿੱਥੇ ਲੱਭ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: 
- ਅਧਿਕਾਰਤ ਅਤੇ ਕਮਿਊਨਿਟੀ ਟੈਂਪਲੇਟ: [Awesome AZD](https://azure.github.io/awesome-azd/)
- ਕਮਿਊਨਿਟੀ ਟੈਂਪਲੇਟ: GitHub 'ਚ "azd-template" ਖੋਜੋ
- ਮੌਜੂਦਾ ਟੈਂਪਲੇਟ ਦਿਖਾਉਣ ਲਈ `azd template list` ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: ਮੈਂ ਕਿਵੇਂ ਕਸਟਮ ਟੈਂਪਲੇਟ ਬਣਾਵਾਂ?
**ਉੱਤਰ**: 
1. ਮੌਜੂਦਾ ਟੈਂਪਲੇਟ ਢਾਂਚੇ ਨਾਲ ਸ਼ੁਰੂ ਕਰੋ
2. `azure.yaml`, ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਫਾਇਲਾਂ ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਕੋਡ ਵਿੱਚ ਸੋਧ ਕਰੋ
3. `azd up` ਨਾਲ ਪੂਰੀ ਤਰ੍ਹਾਂ ਟੈਸਟ ਕਰੋ
4. ਯੋਗ ਟੈਗਾਂ ਦੇ ਨਾਲ GitHub ਤੇ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ

### ਪ੍ਰ: ਕੀ ਮੈਂ ਬਿਨਾਂ ਕਿਸੇ ਟੈਂਪਲੇਟ ਦੇ azd ਵਰਤ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ, ਮੌਜੂਦਾ ਪ੍ਰੋਜੈਕਟ ਵਿੱਚ ਜ਼ਰੂਰੀ ਸੰਰਚਨਾ ਫਾਈਲਾਂ ਬਣਾਉਣ ਲਈ `azd init` ਦੀ ਵਰਤੋਂ ਕਰੋ। ਤੁਹਾਨੂੰ ਹੱਥੋਂ `azure.yaml` ਅਤੇ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਫਾਈਲਾਂ ਸੰਰਚਿਤ ਕਰਣੀਆਂ ਪੈਣਗੀਆਂ।

### ਪ੍ਰ: ਅਧਿਕਾਰਤ ਅਤੇ ਕਮਿਊਨਿਟੀ ਟੈਂਪਲੇਟ ਵਿੱਚ ਕੀ ਫਰਕ ਹੈ?
**ਉੱਤਰ**: 
- **ਅਧਿਕਾਰਤ ਟੈਂਪਲੇਟ**: ਮਾਈਕਰੋਸੌਫਟ ਦੁਆਰਾ ਸੰਭਾਲੇ ਜਾਂਦੇ, ਨਿਯਮਤ ਤੌਰ 'ਤੇ ਅੱਪਡੇਟ, ਵਿਸਤ੍ਰਿਤ ਦਸਤਾਵੇਜ਼ੀਕਰਨ
- **ਕਮਿਊਨਿਟੀ ਟੈਂਪਲੇਟ**: ਵਿਕਾਸਕਾਰਾਂ ਦੁਆਰਾ ਬਣਾਏ, ਸੰਭਵ ਹੈ ਕਿ ਖਾਸ ਉਪਯੋਗ ਮਾਮਲੇ ਹੋਣ, ਗੁਣਵੱਤਾ ਅਤੇ ਸੰਭਾਲ ਵਿੱਚ ਵੱਖਰੇ

### ਪ੍ਰ: ਮੈਂ ਆਪਣੇ ਪ੍ਰੋਜੈਕਟ ਵਿੱਚ ਟੈਂਪਲੇਟ ਕਿਵੇਂ ਅਪਡੇਟ ਕਰਾਂ?
**ਉੱਤਰ**: ਟੈਂਪਲੇਟ ਆਪੋ-ਆਪਣੇ ਅਪਡੇਟ ਨਹੀਂ ਹੁੰਦੇ। ਤੁਸੀਂ:
1. ਸਰੋਤ ਟੈਂਪਲੇਟ ਨਾਲ ਬਦਲਾਅ ਮਿਲਾ ਕੇ ਮੈਨੁਅਲ ਤੌਰ 'ਤੇ
2. ਅਪਡੇਟ ਕੀਤੇ ਟੈਂਪਲੇਟ ਨਾਲ `azd init` ਨਾਲ ਨਵਾਂ ਸ਼ੁਰੂ ਕਰੋ
3. ਅਪਡੇਟ ਕੀਤੇ ਟੈਂਪਲੇਟਾਂ ਵਿਚੋਂ ਖਾਸ ਸੁਧਾਰ ਚੁਣੋ

## ਡਿਪਲੋਇਮੈਂਟ ਅਤੇ ਬੁਨਿਆਦੀ ਢਾਂਚਾ

### ਪ੍ਰ: azd ਕਿਹੜੀਆਂ Azure ਸੇਵਾਵਾਂ ਨੂੰ ਡਿਪਲੋਇ ਕਰ ਸਕਦਾ ਹੈ?
**ਉੱਤਰ**: azd ਕਿਸੇ ਵੀ Azure ਸੇਵਾ ਨੂੰ Bicep/ARM ਟੈਂਪਲੇਟਾਂ ਰਾਹੀਂ ਡਿਪਲੋਇ ਕਰ ਸਕਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਸ਼ਾਮਲ ਹਨ:
- ਐਪ ਸੇਵਾਵਾਂ, ਕੰਟੇਨਰ ਐਪਸ, ਫੰਕਸ਼ਨਜ਼
- ਡੇਟਾਬੇਸ (SQL, PostgreSQL, Cosmos DB)
- ਸਟੋਰੇਜ, ਕੀ ਵਾਲਟ, ਐਪਲੀਕੇਸ਼ਨ ਇਨਸਾਈਟਸ
- ਨੈੱਟਵਰਕਿੰਗ, ਸੁਰੱਖਿਆ, ਅਤੇ ਮਾਨੀਟਰਿੰਗ ਸਰੋਤ

### ਪ੍ਰ: ਕੀ ਮੈਂ ਕਈ ਖੇਤਰਾਂ ਵਿੱਚ ਡਿਪਲੋਇ ਕਰ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ, ਆਪਣੇ Bicep ਟੈਂਪਲੇਟ ਵਿੱਚ ਕਈ ਖੇਤਰਾਂ ਨੂੰ ਸੰਰਚਿਤ ਕਰੋ ਅਤੇ ਹਰ ਵਾਤਾਵਰਣ ਲਈ ਢੰਗ ਨਾਲ ਸਥਾਨ ਪੈਰਾਮੀਟਰ ਸੈੱਟ ਕਰੋ।

### ਪ੍ਰ: ਮੈਨੂੰ ਡੇਟਾਬੇਸ ਸਕੀਮਾ ਮਾਈਗ੍ਰੇਸ਼ਨ ਕਿਵੇਂ ਸੰਭਾਲਣੇ ਚਾਹੀਦੇ ਹਨ?
**ਉੱਤਰ**: `azure.yaml` ਦੇ ਡਿਪਲੋਇਮੈਂਟ ਹੂਕਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### ਪ੍ਰ: ਕੀ ਮੈਂ ਸਿਰਫ਼ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਬਿਨਾਂ ਐਪਲੀਕੇਸ਼ਨਾਂ ਦੇ ਡਿਪਲੋਇ ਕਰ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ, ਆਪਣੇ ਟੈਂਪਲੇਟਾਂ ਵਿੱਚ ਪਰਿਭਾਸ਼ਿਤ ਸਿਰਫ਼ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਹਿੱਸੇ ਡਿਪਲੋਇ ਕਰਨ ਲਈ `azd provision` ਦੀ ਵਰਤੋਂ ਕਰੋ।

### ਪ੍ਰ: ਮੈਂ ਮੌਜੂਦਾ Azure ਸਰੋਤਾਂ ਤੇ ਕਿਵੇਂ ਡਿਪਲੋਇ ਕਰਾਂ?
**ਉੱਤਰ**: ਹਾਂ, ਜਦੋਂ ਟੈਂਪਲੇਟ ਇਸ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। ਬਾਇਸਪ ਦੀਆਂ `existing` ਘੋਸ਼ਣਾਵਾਂ ਜਾਂ ਟੈਂਪਲੇਟ ਦੇ ਦਸਤਾਵੇਜ਼ ਕੀਤੇ ਮੌਜੂਦਾ-ਸਰੋਤ ਪੈਰਾਮੀਟਰਾਂ ਨਾਲ ਮੌਜੂਦਾ ਸਰੋਤਾਂ ਦਾ ਹਵਾਲਾ ਦਿਓ, ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਸੇਵਾਵਾਂ ਨੂੰ ਉਨ੍ਹਾਂ ਦੇ ਮਨੋਰਥਿਤ ਟਾਰਗੇਟਾਂ ਨਾਲ ਨਕਸ਼ਾ ਕਰੋ। ਇਸ ਨਾਲ ਮਲਕੀਅਤ ਆਯਾਤ ਨਹੀਂ ਹੁੰਦਾ ਅਤੇ ਸਵੈਚਾਲਿਤ ਤੌਰ 'ਤੇ ਲੋੜੀਂਦੇ ਅਨੁਮਤੀਆਂ ਬਣਦੀਆਂ ਨਹੀਂ। ਡਿਪਲੋਇਮੈਂਟ ਤੋਂ ਪਹਿਲਾਂ ਟੈਂਪਲੇਟ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।

### ਪ੍ਰ: ਕੀ ਮੈਂ Bicep ਦੀ ਥਾਂ Terraform ਵਰਤ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਹਾਂ। AZD Terraform ਅਤੇ Bicep ਦੋਹਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। Terraform-ਆਧਾਰਿਤ ਟੈਂਪਲੇਟ ਚੁਣੋ ਜਾਂ `infra.provider: terraform` ਨੂੰ `azure.yaml` ਵਿੱਚ ਸੰਰਚਿਤ ਕਰੋ, ਜਿੱਥੇ ਲਾਗੂ Terraform ਫਾਈਲਾਂ ਅਤੇ ਸਟੇਟ/ਬੈਕਐਂਡ ਸੰਰਚਨਾ ਸ਼ਾਮਲ ਹੈ। [Terraform ਵਰਕਫਲੋ](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd) ਵੇਖੋ।

## ਸੰਰਚਨਾ ਅਤੇ ਵਾਤਾਵਰਣ

### ਪ੍ਰ: ਮੈਂ ਵੱਖ-ਵੱਖ ਵਾਤਾਵਰਣ (dev, staging, prod) ਕਿਵੇਂ ਪ੍ਰਬੰਧਤ ਕਰਾਂ?
**ਉੱਤਰ**: `azd env new <environment-name>` ਨਾਲ ਵੱਖਰੇ ਵਾਤਾਵਰਣ ਬਣਾਓ ਅਤੇ ਹਰ ਇੱਕ ਲਈ ਵੱਖਰੇ ਸੈਟਿੰਗਸ ਸੰਰਚਿਤ ਕਰੋ:
```bash
azd env new development
azd env new staging  
azd env new production
```

### ਪ੍ਰ: ਵਾਤਾਵਰਣ ਸੰਰਚਨਾਵਾਂ ਕਿੱਥੇ ਸਟੋਰ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ?
**ਉੱਤਰ**: ਪ੍ਰੋਜੈਕਟ ਡਾਇਰੈਕਟਰੀ ਦੇ ਅੰਦਰ `.azure` ਫੋਲਡਰ ਵਿੱਚ। ਹਰ ਵਾਤਾਵਰਣ ਲਈ ਇੱਕ ਆਪਣੇ-ਆਪਣੇ ਫੋਲਡਰ ਵਿੱਚ ਸੰਰਚਨਾ ਫਾਈਲਾਂ ਹੁੰਦੀਆਂ ਹਨ।

### ਪ੍ਰ: ਮੈਂ ਵਾਤਾਵਰਣ-ਵਿਸ਼ੇਸ਼ ਸੰਰਚਨਾ ਕਿਵੇਂ ਸੈੱਟ ਕਰਾਂ?
**ਉੱਤਰ**: ਵਾਤਾਵਰਣ ਚਰਪ ਰਾਖਣ ਲਈ `azd env set` ਦੀ ਵਰਤੋਂ ਕਰੋ:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### ਪ੍ਰ: ਕੀ ਮੈਂ ਟੀਮ ਮੈਂਬਰਾਂ ਵਿਚਕਾਰ ਵਾਤਾਵਰਣ ਸੰਰਚਨਾਵਾਂ ਸਾਂਝੀਆਂ ਕਰ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: `.azure` ਫੋਲਡਰ ਸਮਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਰੱਖਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ ਵਰਜਨ ਕੰਟਰੋਲ ਵਿੱਚ ਕਮੇਟ ਨਹੀਂ ਕਰਨਾ ਚਾਹੀਦਾ। ਇਸ ਤੋਂ ਇਲਾਵਾ:
1. ਲੋੜੀਂਦੇ ਵਾਤਾਵਰਣ ਚਰਪ ਦਸਤਾਵੇਜ਼ ਕਰੋ
2. ਵਾਤਾਵਰਣ ਸੈੱਟਅਪ ਲਈ ਡਿਪਲੋਇਮੈਂਟ ਸਕ੍ਰਿਪਟ ਦੀ ਵਰਤੋਂ ਕਰੋ
3. ਸੰਵੇਦਨਸ਼ੀਲ ਸੰਰਚਨਾ ਲਈ Azure Key Vault ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: ਮੈਂ ਟੈਂਪਲੇਟ ਡਿਫੌਲਟ ਕਿਵੇਂ ਬਦਲ ਸਕਦਾ ਹਾਂ?
**ਉੱਤਰ**: ਟੈਂਪਲੇਟ ਪੈਰਾਮੀਟਰਾਂ ਦੇ ਅਨੁਕੂਲ ਵਾਤਾਵਰਣ ਚਰਪ ਰਾਖੋ:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

ਕੇਵਲ ਉਹ ਚਰਪ ਟੈਂਪਲੇਟ ਦੁਆਰਾ ਖਪਤ ਹੁੰਦੇ ਹਨ ਜੋ ਡਿਪਲੋਇਮੈਂਟ 'ਤੇ ਪ੍ਰਭਾਵ ਪਾਉਂਦੇ ਹਨ। ਉੱਪਰ ਦਿੱਤਾ ਗਿਆ `SKU_NAME` ਇਕ ਉਦਾਹਰਨ ਕੱਸਟਮ ਇਨਪੁੱਟ ਹੈ, ਇੱਕ ਸਰਵਜਨਕ AZD ਸੈਟਿੰਗ ਨਹੀਂ।

## ਟ੍ਰਬਲਸ਼ੂਟਿੰਗ

### ਪ੍ਰ: `azd up` ਕਿਉਂ ਫੇਲ ਹੋ ਰਿਹਾ ਹੈ?
**ਉੱਤਰ**: ਆਮ ਕਾਰਨ:
1. **ਪ੍ਰਮਾਣਿਕਤਾ ਦੀਆਂ ਸਮੱਸਿਆਵਾਂ**: `azd auth login` ਚਲਾਓ
2. **ਪਰਯਾਪਤ ਅਨੁਮਤੀਆਂ ਨਹੀਂ**: ਆਪਣੇ Azure ਰੋਲ ਅਸਾਈਨਮੈਂਟ ਚੈੱਕ ਕਰੋ
3. **ਸਰੋਤ ਨਾਮ-ਟਕਰਾਅ**: ਟਕਰਾਅ ਵਾਲੇ ਸਰੋਤ ਅਤੇ ਟੈਂਪਲੇਟ ਦੇ ਨਾਮਕਰਨ ਇਨਪੁੱਟ ਦੀ ਸਮੀਖਿਆ ਕਰੋ; ਜਦੋਂ ਅਲੱਗ ਜਗ੍ਹਾ ਦੀ ਲੋੜ ਹੋਵੇ ਤਾਂ `azd env new` ਨਾਲ ਵੱਖਰਾ ਵਾਤਾਵਰਣ ਬਣਾਓ
4. **ਕੋਟਾ/ਖਪਤ ਸਮੱਸਿਆਵਾਂ**: ਖੇਤਰੀ ਉਪਲਬਧਤਾ ਦੀ ਜਾਂਚ ਕਰੋ
5. **ਟੈਂਪਲੇਟ ਤਰੁੱਟੀਆਂ**: Bicep ਟੈਂਪਲੇਟ ਵੈਰੀਫਾਈ ਕਰੋ

### ਪ੍ਰ: ਮੈਂ ਡਿਪਲੋਇਮੈਂਟ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਕਿਵੇਂ ਡੀਬੱਗ ਕਰਾਂ?
**ਉੱਤਰ**: 
1. ਵਿਸਤ੍ਰਿਤ ਆਉਟਪੁੱਟ ਲਈ `azd deploy --debug` ਦੀ ਵਰਤੋਂ ਕਰੋ
2. Azure ਪੋਰਟਲ ਡਿਪਲੋਇਮੈਂਟ ਇਤਿਹਾਸ ਦੀ ਜਾਂਚ ਕਰੋ
3. Azure ਪੋਰਟਲ ਵਿੱਚ ਐਕਟਿਵਿਟੀ ਲੌਗ ਦੀ ਸਮੀਖਿਆ ਕਰੋ
4. ਮੌਜੂਦਾ ਵਾਤਾਵਰਣ ਸਥਿਤੀ ਦਿਖਾਉਣ ਲਈ `azd show` ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: ਮੇਰੇ ਵਾਤਾਵਰਣ ਚਰਪ ਕਿਉਂ ਕੰਮ ਨਹੀਂ ਕਰ ਰਹੇ?
**ਉੱਤਰ**: ਚੈੱਕ ਕਰੋ:
1. ਟੈਂਪਲੇਟ ਪੈਰਾਮੀਟਰਾਂ ਨਾਲ ਸਹੀ ਚਰਪ ਨਾਮ
2. ਜੇ ਵੈਲਯੂਜ਼ ਵਿੱਚ ਖਾਲੀ ਥਾਵਾਂ ਹਨ ਤਾਂ ਉਹ ਠੀਕ ਤਰੀਕੇ ਨਾਲ ਕੌਟ ਕੀਤੇ ਗਏ ਹਨ
3. ਵਾਤਾਵਰਣ ਚੁਣਿਆ ਗਿਆ ਹੈ: `azd env select <environment>`
4. ਚਰਪ ਸਹੀ ਵਾਤਾਵਰਣ ਵਿੱਚ ਸੈੱਟ ਕੀਤੇ ਗਏ ਹਨ

### ਪ੍ਰ: ਮੈਂ ਅਸਫਲ ਡਿਪਲੋਇਮੈਂਟਾਂ ਨੂੰ ਕਿਵੇਂ ਸਾਫ ਕਰਾਂ?
**ਉੱਤਰ**: 
```bash
azd down
```
ਪਹਿਲਾਂ ਚੁਣੇ ਗਏ ਵਾਤਾਵਰਣ ਅਤੇ ਮਿਟਾਉਣ ਦੀ ਪੁਸ਼ਟੀ ਸਮੀਖਿਆ ਕਰੋ। ਇਹ ਡਿਪਲੋਇਡ Azure ਸਰੋਤਾਂ ਨੂੰ ਮਿਟਾਉਂਦਾ ਹੈ, ਨਾ ਕਿ ਸਥਾਨਕ `.azure` ਵਾਤਾਵਰਣ ਸੰਰਚਨਾ। `--purge` ਕੁਝ ਸਮਰਥਤ ਸਾਫ-ਮਿਟਾਏ ਗਏ ਸਰੋਤਾਂ ਦੀ ਸਥਾਈ ਮਿਟਾਈ ਵੀ ਮੰਗਦਾ ਹੈ ਅਤੇ ਰਿਟੇਨਸ਼ਨ/ਪੁਰਜ ਪ੍ਰੋਟੈਕਸ਼ਨ ਦੁਆਰਾ ਰੋਕਿਆ ਜਾ ਸਕਦਾ ਹੈ; ਇਹ ਇੱਕ ਰੁਟੀਨੀ ਰੀਕਵਰੀ ਕਦਮ ਨਹੀਂ ਹੈ।

### ਪ੍ਰ: ਡਿਪਲੋਇਮੈਂਟ ਤੋਂ ਬਾਅਦ ਮੇਰੀ ਐਪਲੀਕੇਸ਼ਨ ਕਿਉਂ ਸਹਾਇਕ ਨਹੀਂ ਹੈ?
**ਉੱਤਰ**: ਚੈੱਕ ਕਰੋ:
1. ਡਿਪਲੋਇਮੈਂਟ ਸਫਲਤਾਪੂਰਵਕ ਪੂਰਾ ਹੋਇਆ
2. ਐਪਲੀਕੇਸ਼ਨ ਚੱਲ ਰਹੀ ਹੈ (Azure ਪੋਰਟਲ ਵਿਚ ਲਾਗ ਚੈੱਕ ਕਰੋ)
3. ਨੈੱਟਵਰਕ ਸੁਰੱਖਿਆ ਸਮੂਹ ਟ੍ਰੈਫਿਕ ਦੀ ਆਗਿਆ ਦਿੰਦੇ ਹਨ
4. DNS/ਕਸਟਮ ਡੋਮੇਨ ਸਹੀ ਤਰੀਕੇ ਨਾਲ ਸੰਰਚਿਤ ਹਨ

## ਲਾਗਤ ਅਤੇ ਬਿੱਲਿੰਗ

### ਪ੍ਰ: azd ਡਿਪਲੋਇਮੈਂਟ ਦੀ ਕੀ ਲਾਗਤ ਹੋਵੇਗੀ?
**ਉੱਤਰ**: ਲਾਗਤਾਂ ਵਿੱਚ ਫਰਕ ਹੁੰਦਾ ਹੈ:
- ਡਿਪਲੋਇ ਕੀਤੀਆਂ Azure ਸੇਵਾਵਾਂ
- ਚੁਣੇ ਗਏ ਸਰਵਿਸ ਟੀਅਰ/ਜ਼ਟੂ
- ਖੇਤਰੀ ਕੀਮਤਾਂ ਦੇ ਅੰਤਰ
- ਵਰਤੋਂ ਦੇ ਤਰੀਕਿਆਂ

ਅਨੁਮਾਨ ਲਗਾਉਣ ਲਈ [Azure ਕੀਮਤ ਕੈਲਕੂਲੇਟਰ](https://azure.microsoft.com/pricing/calculator/) ਦੀ ਵਰਤੋਂ ਕਰੋ।

### ਪ੍ਰ: ਮੈਂ azd ਡਿਪਲੋਇਮੈਂਟ ਵਿੱਚ ਲਾਗਤਾਂ ਨੂੰ ਕਿਵੇਂ ਕੰਟਰੋਲ ਕਰਾਂ?
**ਉੱਤਰ**: 
1. ਵਿਕਾਸ ਵਾਤਾਵਰਣਾਂ ਲਈ ਘੱਟ ਟੀਅਰ ਵਾਲੇ SKU ਦੀ ਵਰਤੋਂ ਕਰੋ
2. Azure ਬਜਟ ਅਤੇ ਸਕੱਤਰ ਸੈੱਟ ਕਰੋ
3. ਜਦੋਂ ਲੋੜ ਨਾ ਹੋਵੇ ਤਾਂ ਸਰੋਤਾਂ ਨੂੰ ਹਟਾਉਣ ਲਈ `azd down` ਦੀ ਵਰਤੋਂ ਕਰੋ
4. موزوں ਖੇਤਰ ਚੁਣੋ (ਲਾਗਤ ਸਥਾਨ ਦੇ ਅਨੁਸਾਰ ਵੱਖਰਾ ਹੁੰਦੀ ਹੈ)
5. Azure ਲਾਗਤ ਪ੍ਰਬੰਧਨ ਉਪਕਰਣਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: ਕੀ azd ਟੈਂਪਲੇਟਾਂ ਲਈ ਮੁਫ਼ਤ ਟੀਅਰ ਵਿਕਲਪ ਹਨ?
**ਉੱਤਰ**: ਕੁਝ ਸੇਵਾਵਾਂ ਕੋਲ ਮੁਫ਼ਤ SKU ਜਾਂ ਮਹੀਨਾਵਾਰ ਅਨੁਦਾਨ ਹਨ, ਜੋ ਯੋਗਤਾ, ਹੋਸਟਿੰਗ ਯੋਜਨਾ, ਖੇਤਰ ਅਤੇ سبਸک੍ਰਿਪਸ਼ਨ ਸੀਮਾਵਾਂ ਦੇ ਅਧੀਨ ਹਨ। ਇਹ ਸਮੂਹ ਟੈਂਪਲੇਟ ਨੂੰ ਮੁਫ਼ਤ ਨਹੀਂ ਬਣਾਉਂਦੇ: ਡੇਟਾਬੇਸ, ਖੋਜ, ਨੈੱਟਵਰਕਿੰਗ, ਰਜਿਸਟਰੀ, ਟੈਲੀਮੇਟਰੀ ਅਤੇ ਮਾਡਲ ਇਨਫਰੰਸਿਂਗ ਸੁਤੰਤਰ ਰੂਪ ਵਿੱਚ ਖਰਚੇ ਪੈਦਾ ਕਰ ਸਕਦੇ ਹਨ। ਡਿਪਲੋਇਮੈਂਟ ਤੋਂ ਪਹਿਲਾਂ [Azure ਮੁਫ਼ਤ ਸੇਵਾਵਾਂ ਸੂਚੀ](https://azure.microsoft.com/free/) ਅਤੇ ਹਰ ਸਰੋਤ ਦੀ ਵਰਤਮਾਨ ਕੀਮਤ ਜਾਂਚੋ।

### ਪ੍ਰ: ਮੈਂ ਡਿਪਲੋਇਮੈਂਟ ਤੋਂ ਪਹਿਲਾਂ ਲਾਗਤਾਂ ਦਾ ਅਨੁਮਾਨ ਕਿਵੇਂ ਲਗਾਵਾਂ?
**ਉੱਤਰ**: 
1. ਟੈਂਪਲੇਟ ਦੇ `main.bicep` ਨੂੰ ਸਮੀਖਿਆ ਕਰੋ ਕਿ ਕਿਹੜੇ ਸਰੋਤ ਬਣਾਏ ਜਾਣਗੇ
2. ਖਾਸ SKU ਦੇ ਨਾਲ Azure ਕੀਮਤ ਕੈਲਕੂਲੇਟਰ ਦੀ ਵਰਤੋਂ ਕਰੋ
3. ਅਸਲੀ ਲਾਗਤਾਂ ਦੇ ਨਿਗਰਾਨੀ ਲਈ ਪਹਿਲਾਂ ਵਿਕਾਸ ਵਾਤਾਵਰਣ ਵਿੱਚ ਡਿਪਲੋਇ ਕਰੋ
4. ਵਿਸਤ੍ਰਿਤ ਲਾਗਤ ਵਿਸ਼ਲੇਸ਼ਣ ਲਈ Azure ਲਾਗਤ ਪ੍ਰਬੰਧਨ ਦੀ ਵਰਤੋਂ ਕਰੋ

## ਸਰਵੋਤਮ ਪ੍ਰਵਣਤਾਵਾਂ

### ਪ੍ਰ: azd ਪ੍ਰੋਜੈਕਟ ਢਾਂਚੇ ਲਈ ਸਰੇਸ਼ਠ ਅਭਿਆਸ ਕੀ ਹਨ?
**ਉੱਤਰ**: 
1. ਐਪਲੀਕੇਸ਼ਨ ਕੋਡ ਨੂੰ ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਤੋਂ ਵੱਖਰਾ ਰੱਖੋ
2. `azure.yaml` ਵਿੱਚ ਅਰਥਪੂਰਨ ਸੇਵਾ ਨਾਮ ਵਰਤੋ
3. ਬਿਲਡ ਸਕ੍ਰਿਪਟਾਂ ਵਿੱਚ ਢੰਗ ਨਾਲ ਗਲਤੀ ਸੰਭਾਲ ਲਾਗੂ ਕਰੋ
4. ਵਾਤਾਵਰਣ-ਵਿਸ਼ੇਸ਼ ਸੰਰਚਨਾ ਦੀ ਵਰਤੋਂ ਕਰੋ
5. ਸਮਗ੍ਰ ਦਸਤਾਵੇਜ਼ ਸ਼ਾਮਲ ਕਰੋ

### ਪ੍ਰ: ਮੈਂ azd ਵਿੱਚ ਕਈ ਸੇਵਾਵਾਂ ਕਿਵੇਂ ਵਿਵਸਥਿਤ ਕਰਾਂ?
**ਉੱਤਰ**: ਸੁਧਾਰਿਤ ਢਾਂਚਾ ਵਰਤੋ:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### ਪ੍ਰ: ਕੀ ਮੈਂ `.azure` ਫੋਲਡਰ ਨੂੰ ਵਰਜਨ ਕੰਟਰੋਲ ਵਿੱਚ ਕਮੇਟ ਕਰਾਂ?
**ਉੱਤਰ**: **ਨਹੀਂ!** `.azure` ਫੋਲਡਰ ਵਿੱਚ ਸੰਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ। ਇਸਨੂੰ `.gitignore` ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ:
```gitignore
.azure/
```

### ਪ੍ਰ: ਮੈਂ ਸਿਕ੍ਰੇਟਸ ਅਤੇ ਸੰਵੇਦਨਸ਼ੀਲ ਸੰਰਚਨਾ ਨੂੰ ਕਿਵੇਂ ਸੰਭਾਲ ਸਕਦਾ ਹਾਂ?
**ਜਵਾਬ**: 
1. ਸਿਕ੍ਰੇਟਸ ਲਈ Azure ਕੀ ਵੌਲਟ ਦੀ ਵਰਤੋਂ ਕਰੋ
2. ਐਪਲੀਕੇਸ਼ਨ ਸੰਰਚਨਾ ਵਿੱਚ ਕੀ ਵੌਲਟ ਸਿਕ੍ਰੇਟਸ ਦਾ ਹਵਾਲਾ ਦਿਓ
3. ਸਿਕ੍ਰੇਟਸ ਨੂੰ ਕਦੇ ਵੀ ਵਰਜ਼ਨ ਕੰਟਰੋਲ ਵਿੱਚ ਨਹੀਂ ਜਮ੍ਹਾਂ ਕਰੋ
4. ਸਰਵਿਸ-ਟੂ-ਸਰਵਿਸ ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ ਪ੍ਰਬੰਧਿਤ ਪਹਿਚਾਣਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: azd ਨਾਲ CI/CD ਲਈ ਸਿਫਾਰਸ਼ੀ ਤਰੀਕਾ ਕੀ ਹੈ?
**ਜਵਾਬ**: 
1. ਹਰ ਸਟੇਜ਼ (ਡੈਵ/ਸਟੇਜਿੰਗ/ਪ੍ਰੋਡ) ਲਈ ਵੱਖਰੇ ਮਾਹੌਲ ਵਰਤੋਂ
2. ਤਾਇਨਾਤੀ ਤੋਂ ਪਹਿਲਾਂ ਆਟੋਮੇਟਿਡ ਟੈਸਟਿੰਗ ਲਾਗੂ ਕਰੋ
3. ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ ਸਰਵਿਸ ਪ੍ਰਿੰਸੀਪਲ ਦੀ ਵਰਤੋਂ ਕਰੋ
4. ਸੰਵੇਦਨਸ਼ੀਲ ਸੰਰਚਨਾ ਨੂੰ ਪਾਈਪਲਾਈਨ ਸਿਕ੍ਰੇਟਸ/ਵੈਰੀਏਬਲਜ਼ ਵਿੱਚ ਸਟੋਰ ਕਰੋ
5. ਪ੍ਰੋਡਕਸ਼ਨ ਤਾਇਨਾਤੀ ਲਈ ਮਨਜ਼ੂਰੀ ਗੇਟ ਲਾਗੂ ਕਰੋ

## ਅਗੇਮੀ ਵਿਸ਼ੇ

### ਪ੍ਰ: ਕੀ ਮੈਂ azd ਨੂੰ ਕਸਟਮ ਫੰਕਸ਼ਨੈਲਟੀ ਨਾਲ ਵੱਧਾ ਸਕਦਾ ਹਾਂ?
**ਜਵਾਬ**: ਹਾਂ, `azure.yaml` ਵਿੱਚ ਡਿਪਲੋਇਮੈਂਟ ਹੂਕਾਂ ਰਾਹੀਂ:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### ਪ੍ਰ: ਮੈਂ azd ਨੂੰ ਮੌਜੂਦਾ DevOps ਪ੍ਰਕਿਰਿਆਵਾਂ ਨਾਲ ਕਿਵੇਂ ਏਕੀਕ੍ਰਿਤ ਕਰਾਂ?
**ਜਵਾਬ**: 
1. ਮੌਜੂਦਾ ਪਾਈਪਲਾਈਨ ਸਕ੍ਰਿਪਟਾਂ ਵਿੱਚ azd ਕਮਾਂਡਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ
2. ਟੀਮਾਂ ਵਿੱਚ azd ਟੈਮਪਲੇਟਾਂ ਨੂੰ ਮਿਆਰੀਕਰਨ ਕਰੋ
3. ਮੌਜੂਦਾ ਮਾਨੀਟਰਿੰਗ ਅਤੇ ਅਲਾਰਟਿੰਗ ਨਾਲ ਏਕੀਕ੍ਰਿਤ ਕਰੋ
4. ਪਾਈਪਲਾਈਨ ਏਕੀਕ੍ਰਿਤੀ ਲਈ azd ਦੇ JSON ਆਉਟਪੁੱਟ ਦੀ ਵਰਤੋਂ ਕਰੋ

### ਪ੍ਰ: ਕੀ ਮੈਂ azd ਨੂੰ Azure DevOps ਨਾਲ ਵਰਤ ਸਕਦਾ ਹਾਂ?
**ਜਵਾਬ**: ਹਾਂ, azd ਕਿਸੇ ਵੀ CI/CD ਸਿਸਟਮ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ। Azure DevOps ਪਾਈਪਲਾਈਨਾਂ ਬਣਾਓ ਜੋ azd ਕਮਾਂਡਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦੀਆਂ ਹਨ।

### ਪ੍ਰ: ਮੈਂ azd ਵਿੱਚ ਕਿਵੇਂ ਯੋਗਦਾਨ ਪਾ ਸਕਦਾ ਹਾਂ ਜਾਂ ਕਮਿਊਨਿਟੀ ਟੈਮਪਲੇਟਾਂ ਬਣਾਉਂਦਾ ਹਾਂ?
**ਜਵਾਬ**: 
1. **azd ਟੂਲ**: ਯੋਗਦਾਨ ਪਾਓ [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **ਟੈਂਪਲੇਟਸ**: ਪਾਲਣਾ ਕਰੋ [Awesome AZD gallery contribution instructions](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **ਦਸਤਾਵੇਜ਼ੀकरण**: ਯੋਗਦਾਨ ਪਾਓ ਡੌਕਸ ਵਿੱਚ [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### ਪ੍ਰ: azd ਲਈ ਰੋਡਮੈਪ ਕੀ ਹੈ?
**ਉੱਤਰ**: ਪ੍ਰਯੋਜਿਤ ਫੀਚਰਾਂ ਅਤੇ ਸੁਧਾਰਾਂ ਲਈ [ਅਧਿਕਾਰਿਕ ਰੋਡਮੈਪ](https://github.com/Azure/azure-dev/projects) ਵੇਖੋ।

### ਪ੍ਰ: ਮੈਂ ਹੋਰ ਤਾਇਨਾਤੀ ਟੂਲਾਂ ਤੋਂ azd ਵੱਲ ਕਿਵੇਂ ਮਾਈਗ੍ਰੇਟ ਕਰਾਂ?
**ਜਵਾਬ**: 
1. ਮੌਜੂਦਾ ਤਾਇਨਾਤੀ ਸਟ੍ਰਕਚਰ ਦਾ ਵਿਸ਼ਲੇਸ਼ਣ ਕਰੋ
2. ਬਰਾਬਰ ਦੇ Bicep ਟੈਂਪਲੇਟ ਬਣਾਓ
3. ਮੌਜੂਦਾ ਸੇਵਾਵਾਂ ਨਾਲ ਮੇਲ ਖਾਣ ਲਈ `azure.yaml` ਸੈੱਟ ਕਰੋ
4. ਵਿਕਾਸ ਵਾਤਾਵਰਣ ਵਿੱਚ ਸੰਪੂਰਣ ਪਰਖ ਕਰੋ
5. ਹੌਲੇ-ਹੌਲੇ ਵਾਤਾਵਰਣ ਮਾਈਗ੍ਰੇਟ ਕਰੋ
