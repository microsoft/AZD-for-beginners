## Έναρξη Χρήσης

### Ε: Τι είναι το Azure Developer CLI (azd);
**Α**: Το Azure Developer CLI (azd) είναι ένα εργαλείο γραμμής εντολών προσανατολισμένο στον προγραμματιστή που επιταχύνει τον χρόνο από το τοπικό περιβάλλον ανάπτυξης έως το Azure. Παρέχει βέλτιστες πρακτικές μέσω προτύπων και βοηθά σε ολόκληρο τον κύκλο ζωής της ανάπτυξης.

### Ε: Πώς διαφέρει το azd από το Azure CLI;
**Α**: 
- **Azure CLI**: Γενικής χρήσης εργαλείο διαχείρισης πόρων Azure
- **azd**: Εργαλείο προσανατολισμένο στην ανάπτυξη εφαρμογών
- Το azd έχει δικό του σύστημα πιστοποίησης και ροή εργασίας ανάπτυξης· το Azure CLI είναι ξεχωριστό, συμπληρωματικό εργαλείο
- Το azd περιλαμβάνει πρότυπα, διαχείριση περιβάλλοντος και αυτοματοποίηση ανάπτυξης

### Ε: Χρειάζεται να εγκαταστήσω το Azure CLI για να χρησιμοποιήσω το azd;
**Α**: Όχι για την βασική ροή εργασίας του AZD. Αυθεντικοποιηθείτε με `azd auth login`. Εγκαταστήστε το Azure CLI ξεχωριστά όταν κάποιο hook προτύπου ή άσκηση εκτελεί ρητά εντολές `az`.

### Ε: Ποιες γλώσσες προγραμματισμού υποστηρίζει το azd;
**Α**: Το azd είναι ανεξάρτητο γλωσσών. Υποστηρίζει:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- Στατικές ιστοσελίδες
- Εφαρμογές σε κοντέινερ

### Ε: Μπορώ να χρησιμοποιήσω το azd με υπάρχοντα έργα;
**Α**: Ναι! Μπορείτε είτε:
1. Να χρησιμοποιήσετε `azd init` για να προσθέσετε ρυθμίσεις azd σε υπάρχοντα έργα
2. Να προσαρμόσετε τα υπάρχοντα έργα ώστε να ταιριάζουν στη δομή προτύπου azd
3. Να δημιουργήσετε προσαρμοσμένα πρότυπα βασισμένα στην υπάρχουσα αρχιτεκτονική σας

### Ε: Τι άλλαξε με τη γενική διαθεσιμότητα του Foundry extension;
**Α**: Το πακέτο `microsoft.foundry` έφτασε στην έκδοση 1.0 και τη GA στις 5 Νοεμβρίου 2026. Με AZD 1.37.0+, χρησιμοποιήστε `azd ext install microsoft.foundry` για εγκατάσταση επτά βασικών επεκτάσεων για agents, συνδέσεις, inspector, έργα, ρουτίνες, δεξιότητες και εργαλεία. Δεν πρόκειται για νέο namespace εντολών και τα στοιχεία του εκδόνονται ανεξάρτητα. Αξιολογήσεις, σύνολα δεδομένων, fine-tuning και προσαρμοσμένα μοντέλα εγκαθίστανται ξεχωριστά· προαιρετικά χαρακτηριστικά προεπισκόπησης δεν γίνονται GA επειδή το πακέτο έγινε GA.

Το [παράδειγμα hosted-agent](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) χρησιμοποιεί Python 3.13+ και τρέχον uv. Το `azd ai agent run` ανοίγει τον Agent Inspector τοπικά, αλλά οι κλήσεις μοντέλου εξακολουθούν να χρησιμοποιούν Azure και επιβαρύνονται οικονομικά. Η λειτουργία κώδικα `azd deploy` ανεβάζει πηγαίο κώδικα για απομακρυσμένο build χωρίς να απαιτεί τοπικό build κοντέινερ.

### Ε: Αφαιρεί το `azd down` έναν hosted agent από υπάρχον έργο Foundry;
**Α**: Όχι για τη διαδρομή με επαναχρησιμοποιούμενο έργο που περιγράφεται στο quickstart hosted-agent: αφήνει το έργο, τον hosted agent και τους υπόλοιπους πόρους στη θέση τους. Αφαιρέστε ανεπιθύμητους πόρους ξεχωριστά χωρίς να διαγράψετε κοινόχρηστους πόρους. Αν το περιβάλλον δημιούργησε νέο έργο Foundry, το `azd down` διαγράφει το resource group και όλα τα περιεχόμενά του. Αξιολογήστε τις [οδηγίες καθαρισμού](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#7-clean-up-deliberately) και τα προτροπές διαγραφής πριν επιβεβαιώσετε.

## Πιστοποίηση & Πρόσβαση

### Ε: Πώς αυθεντικοποιούμαι με το Azure χρησιμοποιώντας azd;
**Α**: Χρησιμοποιήστε `azd auth login` που θα ανοίξει παράθυρο browser για αυθεντικοποίηση Azure. Για σενάρια CI/CD, χρησιμοποιήστε service principals ή managed identities.

### Ε: Μπορώ να χρησιμοποιήσω azd με πολλούς συνδρομητές Azure;
**Α**: Ναι. Χρησιμοποιήστε `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` για να ορίσετε ποιον συνδρομητή να χρησιμοποιήσετε για κάθε περιβάλλον.

### Ε: Τι δικαιώματα χρειάζομαι για ανάπτυξη με azd;
**Α**: Συνήθως χρειάζεστε:
- Το ρόλο **Συνεισφέροντος** στο resource group ή συνδρομή
- Το ρόλο **Διαχειριστή Πρόσβασης Χρηστών** αν αναπτύσσετε πόρους που απαιτούν αναθέσεις ρόλων
- Τα συγκεκριμένα δικαιώματα διαφέρουν ανάλογα με τα πρότυπα και τους πόρους που αναπτύσσονται

### Ε: Μπορώ να χρησιμοποιήσω azd σε pipelines CI/CD;
**Α**: Απολύτως! Το azd είναι σχεδιασμένο για ενσωμάτωση CI/CD. Χρησιμοποιήστε service principals για πιστοποίηση και ορίστε μεταβλητές περιβάλλοντος για ρυθμίσεις.

### Ε: Πώς διαχειρίζομαι την πιστοποίηση σε GitHub Actions;
**Α**: Προτιμήστε workload identity federation (OIDC), διαμορφωμένο με `azd pipeline config`. Η δημιουργούμενη ροή εργασίας εγκαθιστά το AZD και αυθεντικοποιεί το AZD απευθείας με ενοποιημένη ταυτότητα. Μια μόνο εντολή `azure/login` δεν καθιερώνει σύνδεση AZD. Μια εντολή σύνδεσης εντός υπάρχοντος job είναι:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

Παρέχετε ή αναπτύξτε μετά από σύνδεση, με το προοριζόμενο περιβάλλον AZD, συνδρομή και τοποθεσία ρυθμισμένα. Η διαπιστευτήρια της ταυτότητας πρέπει να εμπιστεύεται το αποθετήριο/ref της ροής εργασίας ή το περιβάλλον GitHub, και οι ρόλοι Azure να επιτρέπουν τις επιθυμητές ενέργειες.

## Πρότυπα & Έργα

### Ε: Πού μπορώ να βρω πρότυπα azd;
**Α**: 
- Επίσημα και κοινοτικά πρότυπα: [Awesome AZD](https://azure.github.io/awesome-azd/)
- Κοινοτικά πρότυπα: Αναζήτηση στο GitHub για "azd-template"
- Χρησιμοποιήστε `azd template list` για να περιηγηθείτε σε διαθέσιμα πρότυπα

### Ε: Πώς δημιουργώ προσαρμοσμένο πρότυπο;
**Α**: 
1. Ξεκινήστε με υπάρχουσα δομή προτύπου
2. Τροποποιήστε `azure.yaml`, αρχεία υποδομής και κώδικα εφαρμογής
3. Δοκιμάστε σχολαστικά με `azd up`
4. Δημοσιεύστε στο GitHub με κατάλληλες ετικέτες

### Ε: Μπορώ να χρησιμοποιήσω azd χωρίς πρότυπο;
**Α**: Ναι, χρησιμοποιήστε `azd init` σε υπάρχον έργο για να δημιουργήσετε τα απαραίτητα αρχεία ρυθμίσεων. Θα χρειαστεί να ρυθμίσετε χειροκίνητα `azure.yaml` και αρχεία υποδομής.

### Ε: Ποια η διαφορά μεταξύ επίσημων και κοινοτικών προτύπων;
**Α**: 
- **Επίσημα πρότυπα**: Συντηρούνται από τη Microsoft, ενημερώνονται τακτικά, πλήρης τεκμηρίωση
- **Κοινοτικά πρότυπα**: Δημιουργούνται από προγραμματιστές, μπορεί να έχουν εξειδικευμένες χρήσεις, ποικίλη ποιότητα και συντήρηση

### Ε: Πώς ενημερώνω ένα πρότυπο στο έργο μου;
**Α**: Τα πρότυπα δεν ενημερώνονται αυτόματα. Μπορείτε:
1. Να συγκρίνετε και να συγχωνεύσετε αλλαγές από το αρχικό πρότυπο χειροκίνητα
2. Να ξεκινήσετε από την αρχή με `azd init` χρησιμοποιώντας το ενημερωμένο πρότυπο
3. Να επιλέξετε συγκεκριμένες βελτιώσεις από ενημερωμένα πρότυπα

## Ανάπτυξη & Υποδομή

### Ε: Ποιες υπηρεσίες Azure μπορεί να αναπτύξει το azd;
**Α**: Το azd μπορεί να αναπτύξει οποιαδήποτε υπηρεσία Azure μέσω προτύπων Bicep/ARM, συμπεριλαμβανομένων:
- Υπηρεσίες Εφαρμογών, Container Apps, Functions
- Βάσεις δεδομένων (SQL, PostgreSQL, Cosmos DB)
- Αποθήκευση, Key Vault, Application Insights
- Πόροι δικτύωσης, ασφάλειας και παρακολούθησης

### Ε: Μπορώ να αναπτύξω σε πολλαπλές περιοχές;
**Α**: Ναι, ρυθμίστε πολλαπλές περιοχές στα πρότυπα Bicep και ορίστε το παράμετρο τοποθεσίας ανάλογα για κάθε περιβάλλον.

### Ε: Πώς διαχειρίζομαι μεταφορές σχήματος βάσης δεδομένων;
**Α**: Χρησιμοποιήστε hooks ανάπτυξης στο `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### Ε: Μπορώ να αναπτύξω μόνο υποδομή χωρίς εφαρμογές;
**Α**: Ναι, χρησιμοποιήστε `azd provision` για να αναπτύξετε μόνο τα στοιχεία υποδομής που ορίζονται στα πρότυπα σας.

### Ε: Πώς αναπτύσσω σε υπάρχοντες πόρους Azure;
**Α**: Ναι, εφόσον το πρότυπο το υποστηρίζει. Αναφερθείτε σε υπάρχοντες πόρους με δηλώσεις `existing` του Bicep ή χρησιμοποιώντας παραμέτρους για υπάρχοντες πόρους τεκμηριωμένες στο πρότυπο, και χαρτογραφήστε τις υπηρεσίες εφαρμογών στα προοριζόμενα σημεία. Δεν μεταφέρει ιδιοκτησία ή δημιουργεί αυτόματα δικαιώματα. Εξετάστε το πρότυπο πριν την ανάπτυξη.

### Ε: Μπορώ να χρησιμοποιήσω Terraform αντί για Bicep;
**Α**: Ναι. Το AZD υποστηρίζει Terraform και Bicep. Επιλέξτε πρότυπο βάσει Terraform ή ρυθμίστε `infra.provider: terraform` σε `azure.yaml`, με τα κατάλληλα αρχεία Terraform και ρυθμίσεις κατάστασης/backend. Δείτε το [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## Ρυθμίσεις & Περιβάλλοντα

### Ε: Πώς διαχειρίζομαι διαφορετικά περιβάλλοντα (dev, staging, prod);
**Α**: Δημιουργήστε ξεχωριστά περιβάλλοντα με `azd env new <environment-name>` και ρυθμίστε διαφορετικές ρυθμίσεις για κάθε ένα:
```bash
azd env new development
azd env new staging  
azd env new production
```

### Ε: Πού αποθηκεύονται οι ρυθμίσεις περιβάλλοντος;
**Α**: Στον φάκελο `.azure` μέσα στον κατάλογο του έργου σας. Κάθε περιβάλλον έχει ξεχωριστό φάκελο με αρχεία ρυθμίσεων.

### Ε: Πώς ορίζω ρυθμίσεις συγκεκριμένες για το περιβάλλον;
**Α**: Χρησιμοποιήστε `azd env set` για να ρυθμίσετε μεταβλητές περιβάλλοντος:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### Ε: Μπορώ να μοιράζομαι ρυθμίσεις περιβάλλοντος μεταξύ μελών ομάδας;
**Α**: Ο φάκελος `.azure` περιέχει ευαίσθητες πληροφορίες και δεν πρέπει να προστεθεί σε σύστημα ελέγχου εκδόσεων. Αντ’ αυτού:
1. Τεκμηριώστε τις απαιτούμενες μεταβλητές περιβάλλοντος
2. Χρησιμοποιήστε σενάρια ανάπτυξης για τη ρύθμιση περιβαλλόντων
3. Χρησιμοποιήστε Azure Key Vault για ευαίσθητες ρυθμίσεις

### Ε: Πώς παρακάμπτω τις προεπιλογές των προτύπων;
**Α**: Ορίστε μεταβλητές περιβάλλοντος που αντιστοιχούν σε παραμέτρους προτύπου:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

Μόνο οι μεταβλητές που καταναλώνονται από το πρότυπο επηρεάζουν την ανάπτυξη. Το `SKU_NAME` παραπάνω είναι παράδειγμα προσαρμοσμένης εισόδου, όχι οικουμενική ρύθμιση AZD.

## Επίλυση Προβλημάτων

### Ε: Γιατί αποτυγχάνει το `azd up`;
**Α**: Κοινές αιτίες:
1. **Προβλήματα πιστοποίησης**: Τρέξτε `azd auth login`
2. **Ελλιπή δικαιώματα**: Ελέγξτε τις αναθέσεις ρόλων Azure
3. **Σύγκρουση ονομάτων πόρων**: Εξετάστε τον συγκρουόμενο πόρο και τις εισόδους ονομάτων του προτύπου; δημιουργήστε ξεχωριστό περιβάλλον με `azd env new` όταν απαιτείται απομόνωση
4. **Προβλήματα ορίων/δυναμικότητας**: Ελέγξτε τη διαθεσιμότητα ανά περιοχή
5. **Σφάλματα προτύπου**: Επικυρώστε πρότυπα Bicep

### Ε: Πώς αποσφαλματώνω αποτυχίες ανάπτυξης;
**Α**: 
1. Χρησιμοποιήστε `azd deploy --debug` για λεπτομερή έξοδο
2. Ελέγξτε το ιστορικό ανάπτυξης στο portal Azure
3. Εξετάστε το Activity Log στο portal Azure
4. Χρησιμοποιήστε `azd show` για εμφάνιση τρέχουσας κατάστασης περιβάλλοντος

### Ε: Γιατί δεν λειτουργούν οι μεταβλητές περιβάλλοντος μου;
**Α**: Ελέγξτε:
1. Τα ονόματα μεταβλητών ταιριάζουν ακριβώς με τις παραμέτρους προτύπου
2. Οι τιμές είναι σωστά σε εισαγωγικά αν περιέχουν κενά
3. Το περιβάλλον είναι επιλεγμένο: `azd env select <environment>`
4. Οι μεταβλητές έχουν οριστεί στο σωστό περιβάλλον

### Ε: Πώς καθαρίζω αποτυχημένες αναπτύξεις;
**Α**: 
```bash
azd down
```
Εξετάστε πρώτα το επιλεγμένο περιβάλλον και την επιβεβαίωση διαγραφής. Αυτό διαγράφει τους προμηθευμένους πόρους Azure, όχι τη τοπική ρύθμιση περιβάλλοντος `.azure`. Το `--purge` ζητά επίσης οριστική διαγραφή υποστηριζόμενων πόρων που έχουν απαλώς διαγραφεί και μπορεί να εμποδιστεί από προστασία διατήρησης/εκκαθάρισης· δεν είναι ρουτίνα ανάκτησης.

### Ε: Γιατί η εφαρμογή μου δεν είναι προσβάσιμη μετά την ανάπτυξη;
**Α**: Ελέγξτε:
1. Η ανάπτυξη ολοκληρώθηκε επιτυχώς
2. Η εφαρμογή λειτουργεί (ελέγξτε τα αρχεία καταγραφής στο portal Azure)
3. Οι ομάδες ασφαλείας δικτύου επιτρέπουν την κίνηση
4. DNS/προσαρμοσμένα domains έχουν διαμορφωθεί σωστά

1. Χρησιμοποιήστε SKUs πιο χαμηλού επιπέδου για περιβάλλοντα ανάπτυξης
2. Ορίστε προϋπολογισμούς και ειδοποιήσεις Azure
3. Χρησιμοποιήστε `azd down` για να αφαιρείτε πόρους όταν δεν χρειάζονται
4. Επιλέξτε κατάλληλες περιοχές (το κόστος διαφέρει ανά τοποθεσία)
5. Χρησιμοποιήστε τα εργαλεία Azure Cost Management

### Ε: Υπάρχουν δωρεάν επιλογές επιπέδου για τα πρότυπα azd;
**Α**: Μερικές υπηρεσίες διαθέτουν δωρεάν SKU ή μηνιαίες χορηγίες, υπόκεινται σε επιλεξιμότητα, σχέδιο φιλοξενίας, περιοχή και όρια συνδρομής. Αυτά δεν καθιστούν ολόκληρο το πρότυπο δωρεάν: οι βάσεις δεδομένων, η αναζήτηση, οι δικτυακές υπηρεσίες, το μητρώο, η τηλεμετρία και η εκτέλεση μοντέλων μπορεί να επιφέρουν ξεχωριστά χρεώσεις. Ελέγξτε τη [λίστα δωρεάν υπηρεσιών Azure](https://azure.microsoft.com/free/) και τις τρέχουσες τιμές για κάθε πόρο πριν την ανάπτυξη.

### Ε: Πώς εκτιμώ το κόστος πριν από την ανάπτυξη;
**Α**: 
1. Ελέγξτε το `main.bicep` του προτύπου για να δείτε ποιους πόρους δημιουργεί
2. Χρησιμοποιήστε τον Υπολογιστή Τιμολόγησης Azure με συγκεκριμένα SKU
3. Αναπτύξτε πρώτα σε περιβάλλον ανάπτυξης για να παρακολουθήσετε τα πραγματικά κόστη
4. Χρησιμοποιήστε το Azure Cost Management για λεπτομερή ανάλυση κόστους

## Καλύτερες Πρακτικές

### Ε: Ποιες είναι οι καλύτερες πρακτικές για τη δομή έργου azd;
**Α**: 
1. Κρατήστε τον κώδικα της εφαρμογής ξεχωριστά από την υποδομή
2. Χρησιμοποιήστε ουσιαστικά ονόματα υπηρεσιών στο `azure.yaml`
3. Εφαρμόστε σωστή διαχείριση σφαλμάτων στα scripts κατασκευής
4. Χρησιμοποιήστε ρυθμίσεις συγκεκριμένες για το περιβάλλον
5. Συμπεριλάβετε εκτενή τεκμηρίωση

### Ε: Πώς οργανώνω πολλαπλές υπηρεσίες στο azd;
**Α**: Χρησιμοποιήστε τη συνιστώμενη δομή:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### Ε: Πρέπει να δεσμεύσω τον φάκελο `.azure` στο σύστημα ελέγχου εκδόσεων;
**Α**: **Όχι!** Ο φάκελος `.azure` περιέχει ευαίσθητες πληροφορίες. Προσθέστε τον στο `.gitignore`:
```gitignore
.azure/
```

### Ε: Πώς διαχειρίζομαι μυστικά και ευαίσθητες ρυθμίσεις;
**Α**: 
1. Χρησιμοποιήστε το Azure Key Vault για μυστικά
2. Αναφερθείτε σε μυστικά του Key Vault στις ρυθμίσεις της εφαρμογής
3. Ποτέ μην δεσμεύετε μυστικά στο σύστημα ελέγχου εκδόσεων
4. Χρησιμοποιήστε διαχειριζόμενες ταυτότητες για αυθεντικοποίηση υπηρεσίας προς υπηρεσία

### Ε: Ποια είναι η συνιστώμενη προσέγγιση για CI/CD με το azd;
**Α**: 
1. Χρησιμοποιήστε ξεχωριστά περιβάλλοντα για κάθε στάδιο (ανάπτυξη/δοκιμή/παραγωγή)
2. Εφαρμόστε αυτοματοποιημένα τεστ πριν την ανάπτυξη
3. Χρησιμοποιήστε πρακτικά διαπιστευτήρια υπηρεσίας για αυθεντικοποίηση
4. Αποθηκεύστε τις ευαίσθητες ρυθμίσεις στα μυστικά/μεταβλητές του αγωγού εργασίας
5. Εφαρμόστε σημεία έγκρισης για τις αναπτύξεις σε παραγωγή

## Προχωρημένα Θέματα

### Ε: Μπορώ να επεκτείνω το azd με προσαρμοσμένη λειτουργικότητα;
**Α**: Ναι, μέσω γάντζων ανάπτυξης στο `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### Ε: Πώς ενσωματώνω το azd με υπάρχουσες διαδικασίες DevOps;
**Α**: 
1. Χρησιμοποιήστε εντολές azd σε υπάρχοντα σενάρια αγωγών εργασίας
2. Τυποποιήστε τα πρότυπα azd σε όλες τις ομάδες
3. Ενσωματώστε με υπάρχοντα συστήματα παρακολούθησης και ειδοποιήσεων
4. Χρησιμοποιήστε την έξοδο JSON του azd για ενσωμάτωση στην αγωγό εργασία

### Ε: Μπορώ να χρησιμοποιήσω το azd με το Azure DevOps;
**Α**: Ναι, το azd λειτουργεί με κάθε σύστημα CI/CD. Δημιουργήστε αγωγούς εργασίας Azure DevOps που χρησιμοποιούν εντολές azd.

### Ε: Πώς συμβάλλω στο azd ή δημιουργώ πρότυπα κοινότητας;
**Α**: 
1. **Εργαλείο azd**: Συνεισφέρετε στο [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **Πρότυπα**: Ακολουθήστε τις [οδηγίες συνεισφοράς συλλογής Awesome AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **Τεκμηρίωση**: Συνεισφέρετε στα docs στο [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### Ε: Ποια είναι η οδικός χάρτης για το azd;
**Α**: Ελέγξτε τον [επίσημο οδικό χάρτη](https://github.com/Azure/azure-dev/projects) για προγραμματισμένες λειτουργίες και βελτιώσεις.

### Ε: Πώς μεταβαίνω από άλλα εργαλεία ανάπτυξης στο azd;
**Α**: 
1. Αναλύστε την τρέχουσα αρχιτεκτονική ανάπτυξης
2. Δημιουργήστε ισότιμα πρότυπα Bicep
3. Ρυθμίστε το `azure.yaml` ώστε να ταιριάζει στις τρέχουσες υπηρεσίες
4. Δοκιμάστε σχολαστικά σε περιβάλλον ανάπτυξης
5. Μεταβείτε σταδιακά τα περιβάλλοντα
