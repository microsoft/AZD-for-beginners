## Εκκίνηση

### Ε: Τι είναι το Azure Developer CLI (azd);
**Α**: Το Azure Developer CLI (azd) είναι ένα εργαλείο γραμμής εντολών επικεντρωμένο στον προγραμματιστή που επιταχύνει το χρόνο από το τοπικό περιβάλλον ανάπτυξης μέχρι το Azure. Παρέχει βέλτιστες πρακτικές μέσω προτύπων και υποστηρίζει ολόκληρο τον κύκλο ζωής της ανάπτυξης.

### Ε: Πώς διαφέρει το azd από το Azure CLI;
**Α**: 
- **Azure CLI**: Γενικού σκοπού εργαλείο διαχείρισης πόρων Azure
- **azd**: Εργαλείο εστιασμένο στην ανάπτυξη εφαρμογών
- Το azd έχει τη δική του ροή πιστοποίησης και ανάπτυξης. Το Azure CLI είναι ξεχωριστό, συμπληρωματικό εργαλείο
- Το azd περιλαμβάνει πρότυπα, διαχείριση περιβάλλοντων και αυτοματοποίηση ανάπτυξης

### Ε: Χρειάζεται να έχω εγκατεστημένο το Azure CLI για να χρησιμοποιήσω το azd;
**Α**: Όχι για την κύρια ροή εργασίας AZD. Πιστοποιηθείτε με `azd auth login`. Εγκαταστήστε το Azure CLI χωριστά όταν ένα πρότυπο ή άσκηση εκτελεί ρητά `az` εντολές.

### Ε: Ποιες γλώσσες προγραμματισμού υποστηρίζει το azd;
**Α**: Το azd είναι ανεξάρτητο από γλώσσα. Λειτουργεί με:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- Στατικές ιστοσελίδες
- Εφαρμογές σε κοντέινερ

### Ε: Μπορώ να χρησιμοποιήσω το azd με υπάρχοντα έργα;
**Α**: Ναι! Μπορείτε είτε:
1. Να χρησιμοποιήσετε `azd init` για να προσθέσετε διαμόρφωση azd σε υπάρχοντα έργα
2. Να προσαρμόσετε τα υπάρχοντα έργα ώστε να ταιριάζουν με τη δομή προτύπου azd
3. Να δημιουργήσετε προσαρμοσμένα πρότυπα βάσει της υπάρχουσας αρχιτεκτονικής σας

## Πιστοποίηση & Πρόσβαση

### Ε: Πώς πιστοποιούμαι στο Azure χρησιμοποιώντας το azd;
**Α**: Χρησιμοποιήστε `azd auth login` που θα ανοίξει ένα παράθυρο περιηγητή για πιστοποίηση Azure. Για σενάρια CI/CD, χρησιμοποιήστε service principals ή managed identities.

### Ε: Μπορώ να χρησιμοποιήσω το azd με πολλαπλούς συνδρομητές Azure;
**Α**: Ναι. Χρησιμοποιήστε `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` για να καθορίσετε ποια συνδρομή να χρησιμοποιηθεί για κάθε περιβάλλον.

### Ε: Ποιες άδειες χρειάζομαι για ανάπτυξη με azd;
**Α**: Τυπικά χρειάζεστε:
- Ρόλο **Συνεισφέροντος** στο resource group ή τη συνδρομή
- Ρόλο **Διαχειριστή Πρόσβασης Χρηστών** αν αναπτύσσετε πόρους που απαιτούν εκχώρηση ρόλων
- Οι συγκεκριμένες άδειες ποικίλλουν ανά πρότυπο και πόρους που αναπτύσσονται

### Ε: Μπορώ να χρησιμοποιήσω το azd σε pipelines CI/CD;
**Α**: Απόλυτα! Το azd έχει σχεδιαστεί για ενσωμάτωση σε CI/CD. Χρησιμοποιήστε service principals για πιστοποίηση και ρυθμίστε μεταβλητές περιβάλλοντος για διαμόρφωση.

### Ε: Πώς χειρίζομαι την πιστοποίηση σε GitHub Actions;
**Α**: Προτιμήστε το workload identity federation (OIDC), διαμορφωμένο με `azd pipeline config`. Το παραγόμενο workflow εγκαθιστά το AZD και πιστοποιεί απευθείας μέσω federated identity. Μια βήμα μόνο με `azure/login` δεν δημιουργεί σύνδεση AZD. Ένα βήμα σύνδεσης εντός υπάρχουσας εργασίας είναι:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

Κάντε προμήθεια ή ανάπτυξη μετά τη σύνδεση, με το επιθυμητό AZD περιβάλλον, συνδρομή και τοποθεσία ρυθμισμένα. Τα federated credentials πρέπει να εμπιστεύονται το αποθετήριο/ref ή περιβάλλον GitHub του workflow, και οι ρόλοι Azure να επιτρέπουν τις ζητούμενες λειτουργίες.

## Πρότυπα & Έργα

### Ε: Πού μπορώ να βρω πρότυπα azd;
**Α**: 
- Επίσημα και κοινότητας πρότυπα: [Awesome AZD](https://azure.github.io/awesome-azd/)
- Πρότυπα κοινότητας: Αναζήτηση GitHub για "azd-template"
- Χρησιμοποιήστε `azd template list` για να περιηγηθείτε στα διαθέσιμα πρότυπα

### Ε: Πώς δημιουργώ προσαρμοσμένο πρότυπο;
**Α**: 
1. Ξεκινήστε με υπάρχουσα δομή προτύπου
2. Τροποποιήστε `azure.yaml`, αρχεία υποδομής και κώδικα εφαρμογής
3. Δοκιμάστε σχολαστικά με `azd up`
4. Δημοσιεύστε στο GitHub με κατάλληλες ετικέτες

### Ε: Μπορώ να χρησιμοποιήσω το azd χωρίς πρότυπο;
**Α**: Ναι, χρησιμοποιήστε `azd init` σε υπάρχον έργο για να δημιουργήσετε τα απαραίτητα αρχεία διαμόρφωσης. Θα χρειαστεί να ρυθμίσετε χειροκίνητα `azure.yaml` και τα αρχεία υποδομής.

### Ε: Ποια είναι η διαφορά ανάμεσα σε επίσημα και κοινότητας πρότυπα;
**Α**: 
- **Επίσημα πρότυπα**: Συντηρούνται από τη Microsoft, ενημερώνονται τακτικά, πλήρης τεκμηρίωση
- **Πρότυπα κοινότητας**: Δημιουργήθηκαν από προγραμματιστές, μπορεί να έχουν εξειδικευμένες χρήσεις, ποικίλη ποιότητα και συντήρηση

### Ε: Πώς ενημερώνω ένα πρότυπο στο έργο μου;
**Α**: Τα πρότυπα δεν ενημερώνονται αυτόματα. Μπορείτε:
1. Να συγκρίνετε και να συγχωνεύσετε χειροκίνητα αλλαγές από το πρότυπο πηγής
2. Να ξεκινήσετε από την αρχή με `azd init` χρησιμοποιώντας το ενημερωμένο πρότυπο
3. Να επιλέξετε συγκεκριμένες βελτιώσεις από ενημερωμένα πρότυπα

## Ανάπτυξη & Υποδομή

### Ε: Ποιες υπηρεσίες Azure μπορεί να αναπτύξει το azd;
**Α**: Το azd μπορεί να αναπτύξει οποιαδήποτε υπηρεσία Azure μέσω προτύπων Bicep/ARM, όπως:
- App Services, Container Apps, Functions
- Βάσεις Δεδομένων (SQL, PostgreSQL, Cosmos DB)
- Storage, Key Vault, Application Insights
- Πόροι δικτύωσης, ασφάλειας και παρακολούθησης

### Ε: Μπορώ να αναπτύξω σε πολλαπλές περιοχές;
**Α**: Ναι, ρυθμίστε πολλαπλές περιοχές στα Bicep πρότυπά σας και ορίστε κατάλληλα την παράμετρο τοποθεσίας για κάθε περιβάλλον.

### Ε: Πώς διαχειρίζομαι μεταναστεύσεις διαμόρφωσης βάσεων δεδομένων;
**Α**: Χρησιμοποιήστε hooks ανάπτυξης σε `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### Ε: Μπορώ να αναπτύξω μόνο την υποδομή χωρίς εφαρμογές;
**Α**: Ναι, χρησιμοποιήστε `azd provision` για ανάπτυξη μόνο των στοιχείων υποδομής που ορίζονται στα πρότυπά σας.

### Ε: Πώς αναπτύσσω σε υπάρχοντες πόρους Azure;
**Α**: Ναι, όταν το πρότυπο το υποστηρίζει. Αναφερθείτε σε υπάρχοντες πόρους με δηλώσεις `existing` Bicep ή παραμέτρους προτύπου για υπάρχοντες πόρους και αντιστοιχίστε τις υπηρεσίες εφαρμογής στους κατάλληλους στόχους. Αυτό δεν εισάγει κατοχή ή δημιουργεί αυτόματα άδειες. Ελέγξτε το πρότυπο πριν από την ανάπτυξη.

### Ε: Μπορώ να χρησιμοποιήσω Terraform αντί για Bicep;
**Α**: Ναι. Το AZD υποστηρίζει και Terraform και Bicep. Επιλέξτε πρότυπο με βάση Terraform ή ρυθμίστε `infra.provider: terraform` σε `azure.yaml`, με κατάλληλα αρχεία και ρυθμίσεις backend Terraform. Δείτε το [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## Ρύθμιση & Περιβάλλοντα

### Ε: Πώς διαχειρίζομαι διαφορετικά περιβάλλοντα (dev, staging, prod);
**Α**: Δημιουργήστε ξεχωριστά περιβάλλοντα με `azd env new <environment-name>` και ρυθμίστε διαφορετικές ρυθμίσεις για κάθε ένα:
```bash
azd env new development
azd env new staging  
azd env new production
```

### Ε: Πού αποθηκεύονται οι ρυθμίσεις περιβάλλοντος;
**Α**: Στον φάκελο `.azure` μέσα στον κατάλογο του έργου σας. Κάθε περιβάλλον έχει το δικό του φάκελο με αρχεία ρύθμισης.

### Ε: Πώς ρυθμίζω ρύθμιση ειδική για το περιβάλλον;
**Α**: Χρησιμοποιήστε `azd env set` για να ρυθμίσετε μεταβλητές περιβάλλοντος:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### Ε: Μπορώ να μοιραστώ ρυθμίσεις περιβάλλοντος με άλλα μέλη της ομάδας;
**Α**: Ο φάκελος `.azure` περιέχει ευαίσθητες πληροφορίες και δεν πρέπει να καταχωρείται σε έλεγχο έκδοσης. Αντίθετα:
1. Τεκμηριώστε τις απαιτούμενες μεταβλητές περιβάλλοντος
2. Χρησιμοποιήστε scripts ανάπτυξης για να ρυθμίσετε περιβάλλοντα
3. Χρησιμοποιήστε Azure Key Vault για ευαίσθητες ρυθμίσεις

### Ε: Πώς παρακάμπτω τις προεπιλογές προτύπου;
**Α**: Ορίστε μεταβλητές περιβάλλοντος που αντιστοιχούν σε παραμέτρους προτύπου:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

Μόνο οι μεταβλητές που χρησιμοποιούνται από το πρότυπο επηρεάζουν την ανάπτυξη. Το `SKU_NAME` παραπάνω είναι παράδειγμα προσαρμοσμένης εισόδου, όχι καθολική ρύθμιση AZD.

## Αντιμετώπιση Προβλημάτων

### Ε: Γιατί αποτυγχάνει `azd up`;
**Α**: Συνηθισμένες αιτίες:
1. **Προβλήματα πιστοποίησης**: Εκτελέστε `azd auth login`
2. **Ανεπαρκείς άδειες**: Ελέγξτε τις εκχωρήσεις ρόλων στο Azure
3. **Σύγκρουση ονομάτων πόρων**: Ελέγξτε τον συγκρουόμενο πόρο και τις εισόδους ονομάτων προτύπου· δημιουργήστε ξεχωριστό περιβάλλον με `azd env new` όταν χρειάζεται απομόνωση
4. **Προβλήματα ποσόστωσης/χωρητικότητας**: Ελέγξτε τη διαθεσιμότητα ανά περιοχή
5. **Σφάλματα προτύπων**: Επαληθεύστε τα πρότυπα Bicep

### Ε: Πώς εντοπίζω σφάλματα αποτυχίας ανάπτυξης;
**Α**: 
1. Χρησιμοποιήστε `azd deploy --debug` για λεπτομερή έξοδο
2. Ελέγξτε το ιστορικό ανάπτυξης στο Azure portal
3. Ανασκοπήστε το Activity Log στο Azure portal
4. Χρησιμοποιήστε `azd show` για εμφάνιση τρέχουσας κατάστασης περιβάλλοντος

### Ε: Γιατί δεν λειτουργούν οι μεταβλητές περιβάλλοντός μου;
**Α**: Ελέγξτε:
1. Τα ονόματα μεταβλητών να ταιριάζουν ακριβώς με παραμέτρους προτύπου
2. Οι τιμές να είναι σωστά εγκλωβισμένες σε εισαγωγικά αν περιέχουν κενά
3. Έχετε επιλέξει το περιβάλλον: `azd env select <environment>`
4. Οι μεταβλητές είναι ορισμένες στο σωστό περιβάλλον

### Ε: Πώς καθαρίζω αποτυχημένες αναπτύξεις;
**Α**: 
```bash
azd down
```
 Ελέγξτε πρώτα το επιλεγμένο περιβάλλον και επιβεβαιώστε τη διαγραφή. Αυτό διαγράφει τους παρεχόμενους πόρους Azure, όχι τη τοπική διαμόρφωση περιβάλλοντος `.azure`. Το `--purge` ζητά επιπλέον μόνιμη διαγραφή υποστηριζόμενων πόρων με μαλακή διαγραφή και μπορεί να μπλοκαριστεί από προστασία διατήρησης/εκκαθάρισης· δεν είναι ρουτίνα ανάκτησης.

### Ε: Γιατί δεν είναι προσβάσιμη η εφαρμογή μου μετά την ανάπτυξη;
**Α**: Ελέγξτε:
1. Η ανάπτυξη ολοκληρώθηκε με επιτυχία
2. Η εφαρμογή τρέχει (ελέγξτε τα logs στο Azure portal)
3. Οι ομάδες ασφαλείας δικτύου επιτρέπουν την κίνηση
4. Τα DNS/προσαρμοσμένα domains είναι σωστά ρυθμισμένα

## Κόστος & Χρέωση

### Ε: Πόσο θα κοστίσουν οι αναπτύξεις azd;
**Α**: Τα κόστη εξαρτώνται από:
- Υπηρεσίες Azure που αναπτύσσονται
- Τιμές υπηρεσιών/πακέτων που επιλέγονται
- Διαφορές τιμολόγησης ανά περιοχή
- Πρότυπα χρήσης

Χρησιμοποιήστε τον [Υπολογιστή Τιμών Azure](https://azure.microsoft.com/pricing/calculator/) για εκτιμήσεις.

### Ε: Πώς ελέγχω τα κόστη στις αναπτύξεις azd;
**Α**: 
1. Χρησιμοποιήστε πακέτα χαμηλότερου επιπέδου για περιβάλλοντα ανάπτυξης
2. Ορίστε προϋπολογισμούς και ειδοποιήσεις Azure
3. Χρησιμοποιήστε `azd down` για αφαίρεση πόρων όταν δεν χρειάζονται
4. Επιλέξτε κατάλληλες περιοχές (τα κόστη διαφέρουν ανά τοποθεσία)
5. Χρησιμοποιήστε τα εργαλεία Azure Cost Management

### Ε: Υπάρχουν δωρεάν επιλογές για πρότυπα azd;
**Α**: Κάποιες υπηρεσίες έχουν δωρεάν πακέτα ή μηνιαίες χορηγήσεις, υπό όρους επιλεξιμότητας, σχεδίου φιλοξενίας, περιοχής και ορίων συνδρομής. Δεν καθιστούν ολόκληρο το πρότυπο δωρεάν: βάσεις δεδομένων, αναζήτηση, δικτύωση, μητρώο, τηλεμετρία και εισηγήσεις μοντέλων μπορεί να χρεωθούν ξεχωριστά. Ελέγξτε τη [λίστα δωρεάν υπηρεσιών Azure](https://azure.microsoft.com/free/) και την τρέχουσα τιμολόγηση για κάθε πόρο πριν από την ανάπτυξη.

### Ε: Πώς εκτιμώ τα κόστη πριν από την ανάπτυξη;
**Α**: 
1. Ελέγξτε το `main.bicep` προτύπου για τους πόρους που θα δημιουργηθούν
2. Χρησιμοποιήστε τον Υπολογιστή Τιμών Azure με συγκεκριμένα πακέτα
3. Αναπτύξτε πρώτα σε περιβάλλον ανάπτυξης για παρακολούθηση πραγματικών κόστους
4. Χρησιμοποιήστε το Azure Cost Management για λεπτομερή ανάλυση κόστους

## Βέλτιστες Πρακτικές

### Ε: Ποιες είναι οι βέλτιστες πρακτικές για τη δομή έργου azd;
**Α**: 
1. Κρατήστε τον κώδικα εφαρμογής ξεχωριστά από την υποδομή
2. Χρησιμοποιήστε σημασιολογικά ονόματα υπηρεσιών στο `azure.yaml`
3. Εφαρμόστε κατάλληλη διαχείριση σφαλμάτων στα scripts κατασκευής
4. Χρησιμοποιήστε ρυθμίσεις ειδικές για το περιβάλλον
5. Συμπεριλάβετε πλήρη τεκμηρίωση

### Ε: Πώς οργανώνω πολλαπλές υπηρεσίες στο azd;
**Α**: Χρησιμοποιήστε τη συνιστώμενη δομή:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### Ε: Πρέπει να καταχωρήσω τον φάκελο `.azure` στον έλεγχο έκδοσης;
**Α**: **Όχι!** Ο φάκελος `.azure` περιέχει ευαίσθητες πληροφορίες. Προσθέστε τον στο `.gitignore`:
```gitignore
.azure/
```

### Ε: Πώς διαχειρίζομαι μυστικά και ευαίσθητη διαμόρφωση;
**Α**: 
1. Χρησιμοποιήστε το Azure Key Vault για μυστικά
2. Αναφέρετε μυστικά του Key Vault στη διαμόρφωση της εφαρμογής
3. Μην δεσμεύετε ποτέ μυστικά σε σύστημα ελέγχου εκδόσεων
4. Χρησιμοποιήστε διαχειριζόμενες ταυτότητες για αυθεντικοποίηση μεταξύ υπηρεσιών

### Ε: Ποια είναι η προτεινόμενη προσέγγιση για CI/CD με το azd;
**Α**: 
1. Χρησιμοποιήστε ξεχωριστά περιβάλλοντα για κάθε στάδιο (ανάπτυξη/δοκιμαστικό/παραγωγή)
2. Εφαρμόστε αυτοματοποιημένες δοκιμές πριν από την ανάπτυξη
3. Χρησιμοποιήστε υπηρεσιακούς λογαριασμούς για αυθεντικοποίηση
4. Αποθηκεύστε ευαίσθητη διαμόρφωση σε μυστικά/μεταβλητές της ροής εργασίας
5. Υλοποιήστε πύλες έγκρισης για αναπτύξεις παραγωγής

## Προχωρημένα Θέματα

### Ε: Μπορώ να επεκτείνω το azd με προσαρμοσμένη λειτουργικότητα;
**Α**: Ναι, μέσω των deployment hooks στο `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### Ε: Πώς ενσωματώνω το azd με υπάρχουσες διαδικασίες DevOps;
**Α**: 
1. Χρησιμοποιήστε τις εντολές azd σε υπάρχοντα σενάρια ροής εργασίας
2. Τυποποιήστε τα πρότυπα azd σε όλες τις ομάδες
3. Ενσωματωθείτε με υπάρχοντες μηχανισμούς παρακολούθησης και ειδοποιήσεων
4. Χρησιμοποιήστε την έξοδο JSON του azd για ενσωμάτωση στη ροή εργασίας

### Ε: Μπορώ να χρησιμοποιήσω το azd με το Azure DevOps;
**Α**: Ναι, το azd λειτουργεί με οποιοδήποτε σύστημα CI/CD. Δημιουργήστε Azure DevOps pipelines που χρησιμοποιούν εντολές azd.

### Ε: Πώς μπορώ να συμβάλω στο azd ή να δημιουργήσω πρότυπα κοινότητας;
**Α**: 
1. **εργαλείο azd**: Συμβάλετε στο [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **Πρότυπα**: Ακολουθήστε τις [Οδηγίες συμβολής στη συλλογή Awesome AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **Τεκμηρίωση**: Συμβάλετε σε έγγραφα στο [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### Ε: Ποιος είναι ο οδικός χάρτης για το azd;
**Α**: Ελέγξτε τον [επίσημο οδικό χάρτη](https://github.com/Azure/azure-dev/projects) για προγραμματισμένες δυνατότητες και βελτιώσεις.

### Ε: Πώς μεταπηδώ από άλλα εργαλεία ανάπτυξης στο azd;
**Α**: 
1. Αναλύστε την τρέχουσα αρχιτεκτονική ανάπτυξης
2. Δημιουργήστε ισοδύναμα πρότυπα Bicep
3. Διαμορφώστε `azure.yaml` για να ταιριάζει με τις τρέχουσες υπηρεσίες
4. Δοκιμάστε εκτενώς σε περιβάλλον ανάπτυξης
5. Μεταφέρετε σταδιακά τα περιβάλλοντα
