## 5.1 Καθιέρωση βάσης αναφοράς

Χρησιμοποιήστε το αρχικοποιημένο αποθετήριο [Get Started with AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) από τα προηγούμενα μοντούλα. Καταγράψτε την αναθεώρηση του προτύπου, την έκδοση AZD, το επιλεγμένο περιβάλλον, την ανάπτυξη μοντέλου και τα δείγματα ερωτήσεων πριν κάνετε οποιαδήποτε αλλαγή.

Το δείγμα υλοποιεί μια εφαρμογή συνομιλίας υποστηριζόμενη από πράκτορα. Δεν γίνεται **αυτόματα** ένα σύστημα λιανικής με δύο πράκτορες απλώς με τη ρύθμιση μεταβλητών περιβάλλοντος ή την αποθήκευση πρόσθετων αρχείων οδηγιών. Επιπλέον πράκτορες, χειριστές εργαλείων, δρομολόγηση, εξουσιοδότηση και πρόσβαση σε δεδομένα απαιτούν κώδικα εφαρμογής.

Εξετάστε τις οδηγίες και τα εργαλεία του τρέχοντος αναπτυγμένου πράκτορα στο Foundry. Δοκιμάστε μία ερώτηση γεγονότος, μία ερώτηση ανάκτησης και μία ερώτηση που τα δείγματα δεδομένων δεν μπορούν να απαντήσουν. Επαληθεύστε τις αναφορές έναντι των πραγματικών αρχείων πηγής αντί να υποθέσετε ότι η ομαλή απάντηση είναι σωστή.

## 5.2 Εξατομίκευση ανάκτησης γνώσης

Το πρότυπο υποστηρίζει ανάκτηση βάσει αρχείων και προαιρετική ενσωμάτωση Azure AI Search. Ακολουθήστε τον [τρέχοντα οδηγό AI Search](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) για ευρετηρίαση και διαμόρφωση εργαλείων.

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

Η ενεργοποίηση της υπηρεσίας είναι μόνο ένα μέρος της ανάκτησης. Πριν ανεβάσετε δικά σας δεδομένα:

1. Επιβεβαιώστε ότι έχετε άδεια χρήσης των εγγράφων και αφαιρέστε ευαίσθητες πληροφορίες.
2. Επιλέξτε ένα μοντέλο ενσωμάτωσης που υποστηρίζεται στην περιοχή σας και ορίστε την συμβατή έκδοση, τον τύπο ανάπτυξης και τις διαστάσεις διανύσματος.
3. Δημιουργήστε/γεμίστε τον δείκτη χρησιμοποιώντας τη διαδικασία τεκμηριωμένη στο δείγμα.
4. Διαμορφώστε το εργαλείο ανάκτησης του πράκτορα για χρήση αυτού του δείκτη.
5. Δοκιμάστε την ανάκτηση, τις αναφορές, την εξουσιοδότηση και τη συμπεριφορά όταν δεν υπάρχει σχετικό έγγραφο.

Μην αλλάξετε από `text-embedding-3-small` σε διαφορετικό μοντέλο ενσωμάτωσης χωρίς να ελέγξετε τις διαστάσεις και να αναδημιουργήσετε/επαναξιολογήσετε τα διανύσματα όπως χρειάζεται. Ένα όνομα όπως `retail-products` δεν είναι υλοποιημένος κατάλογος ή πολιτική ελέγχου πρόσβασης.

## 5.3 Παρακολούθηση και ιχνηλασία

Ακολουθήστε τον [οδηγό παρατηρησιμότητας του δείγματος](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring). Βεβαιωθείτε ότι η απαιτούμενη πόρος Application Insights και η σύνδεση υπάρχουν ήδη· αν αλλάζετε ρυθμίσεις υποδομής, χρησιμοποιήστε το `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

Στείλτε ένα δοκιμαστικό αίτημα, εξετάστε τα αρχεία καταγραφής εφαρμογής του Container App και την προβολή ιχνηλασίας του πράκτορα στο Foundry. Ελέγξτε καθυστέρηση, κλήσεις εργαλείων, σφάλματα και συσχέτιση ανάμεσα στο αίτημα και το ιχνηλάσιο. Μην υποθέτετε ότι η τηλεμετρία είναι συνδεδεμένη απλώς επειδή η ανάπτυξη πέτυχε.

Αφήστε το `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` απενεργοποιημένο εκτός αν έχετε εξετάσει ρητά τη συγκατάθεση, τη λογοκρισία, τη διατήρηση και τους ελέγχους πρόσβασης. Τα ιχνηλασια μπορούν να περιέχουν ευαίσθητα επιχειρήματα εργαλείων ή περιεχόμενο εγγράφων ακόμα και όταν τα συνηθισμένα αρχεία καταγραφής εφαρμογής φαίνονται ακίνδυνα.

## 5.4 Αξιολόγηση πράκτορα

Το σημείο εισόδου αξιολόγησης του δείγματος είναι τώρα [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py), όχι ένας κατάλογος `evals/`. Από τη ρίζα του δείγματος, χρησιμοποιήστε ένα περιβάλλον Python που πληροί τις τεκμηριωμένες απαιτήσεις του:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

Πριν την εκτέλεση, ολοκληρώστε τις [απαιτούμενες προϋποθέσεις αξιολόγησης](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md). Τα τεστ φορτώνουν διαμόρφωση από το επιλεγμένο `.azure/<environment>/.env`· επιβεβαιώστε ότι έχει επιλεγεί το επιθυμητό περιβάλλον. Σημαντικές είσοδοι περιλαμβάνουν:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, χρησιμοποιώντας τη μορφή που απαιτεί το τρέχον δείγμα (η αναθεωρημένη έκδοση χρησιμοποιεί `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, που χρησιμοποιείται ως η ανάπτυξη κριτηρίου μοντέλου

Εξετάστε τα τεστ για να κατανοήσετε την επιλογή αξιολογητή, τα όρια, τους απαιτούμενους ρόλους και το κόστος μοντέλου. Μια ολοκληρωμένη εκτέλεση δεν είναι αυτόματα πύλη επιτυχίας ποιότητας· εξετάστε τους βαθμούς, τις αποτυχίες/λάθη και τα συνδεδεμένα αποτελέσματα Foundry.

### Ξεχωριστή επέκταση αξιολογήσεων AZD

Το παραπάνω τεστ Python είναι μια **διαδικασία συγκεκριμένη για το δείγμα**. Η προαιρετική επέκταση `azure.ai.evaluations` είναι διαφορετική διαδικασία, με τη δική της διαμόρφωση `evals/azure.eval.yaml`. Εγκαθίσταται ξεχωριστά και δεν περιλαμβάνεται στο γενικά διαθέσιμο πακέτο `microsoft.foundry` 1.0:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

Για πλήρη ρύθμιση επέκτασης, δείτε τη [διαδικασία αξιολογήσεων και μετανάστευσης](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md). Από το beta.22 της επέκτασης πρακτόρων, μη χρησιμοποιείτε τις αφαιρεθείσες εντολές `azd ai agent eval`. Η εγκατάσταση της επέκτασης αξιολογήσεων δεν μετατρέπει αυτόματα τα τεστ Python του δείγματος ή δεν δημιουργεί αυτόματα διαμόρφωση αξιολόγησης.

Για ξεχωριστή **άσκηση με φιλοξενούμενο πράκτορα GA**, χρησιμοποιήστε έναν κενό φάκελο εκτός από το δείγμα αυτού του εργαστηρίου και ακολουθήστε τον [περιηγητή Foundry από τοπικά στο cloud](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga). Χρησιμοποιεί AZD 1.37.0+, το πακέτο `microsoft.foundry`, Python 3.13+ και τον τρέχοντα uv. Θα εξετάσετε το `azure.yaml`, θα δοκιμάσετε τοπικά με Agent Inspector, θα αναπτύξετε πηγαίο κώδικα για απομακρυσμένη κατασκευή Foundry, και θα δημιουργήσετε/αναθεωρήσετε σύνολο δεδομένων και ρουμπρίκα πριν διαμορφώσετε το `azd ai eval init --name quality`. Μην αντικαθιστάτε τα τεστ αυτού του δείγματος ή υποθέτετε ότι η εγκατάσταση του πακέτου αλλάζει το μοντέλο φιλοξενίας.

## 5.5 Κόκκινη ομάδα τεχνητής νοημοσύνης και συνεχής αξιολόγηση

Το τρέχον δείγμα παρέχει [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py). Ολοκληρώστε τις προϋποθέσεις του και αναθεωρήστε τον προοριζόμενο στόχο και τα κόστη πριν τρέξετε:

```bash
pytest tests/test_red_teaming.py -s
```

Χρησιμοποιήστε εξουσιοδοτημένη ανάπτυξη δοκιμών και συνθετικά δεδομένα. Εξετάστε τις δημιουργημένες επιθέσεις και τα αποτελέσματα· αυτή η σάρωση δεν αποδεικνύει ότι μια εφαρμογή είναι ασφαλής ή συμμορφούμενη.

Ο [οδηγός παρατηρησιμότητας](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) περιγράφει επίσης συνεχής αξιολόγηση διαμορφωμένη κατά την εκκίνηση κοντέινερ. Αξιολογεί τις πραγματικές αλληλεπιδράσεις χρηστών, όχι την παραγόμενη κίνηση δοκιμής, και η υποστήριξη αξιολογητή διαφέρει ανά περιοχή. Καμία αλληλεπίδραση σημαίνει κανένα καταχώρισμα αξιολόγησης. Επιβεβαιώστε την έκδοση δείγματος που έχει εγκατασταθεί και τη διαμόρφωση αξιολογητή αντί να υποθέσετε ότι κάθε ανάπτυξη έχει τις ίδιες προεπιλογές.

Η πιστοποίηση είναι ξεχωριστή από την αξιολόγηση. Ακολουθήστε την τεκμηριωμένη ρύθμιση ταυτότητας/πρόσβασης του δείγματος. Δεν υπάρχει τεκμηριωμένη “βασική εναλλακτική αυθεντικοποίηση” για να βασιστείτε για την προστασία ενός δημόσιου σημείου πρόσβασης.

## 5.6 Άσκηση σχεδίασης: εξατομίκευση λιανικής

!!! warning "Άσκηση σχεδίασης, όχι ολοκληρωμένη ανάπτυξη"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

Γράψτε ένα σύντομο σχέδιο που να απαντά:

| Περιοχή | Απόφαση και στοιχεία προς συλλογή |
|------|----------------------------------|
| Ευθύνες πράκτορα | Ξεκινήστε με έναν πράκτορα ή αιτιολογήστε ξεχωριστούς πράκτορες Αγορών και Πιστότητας και λογική δρομολόγησης |
| Δεδομένα | Ορίστε συνθετικό κατάλογο/σύνολο βραβείων και ιδιοκτησία ενημερώσεων |
| Εργαλεία | Υλοποιήστε πρώτα χειριστές μόνο για ανάγνωση· καθορίστε εξουσιοδότηση και επικύρωση για οποιεσδήποτε εγγραφές |
| Μοντέλα | Επιλέξτε διαθέσιμους συνδυασμούς μοντέλου/έκδοσης/SKU και επαληθεύστε το όριο· αποφύγετε την προμήθεια μη χρησιμοποιούμενων μοντέλων |
| Ανάκτηση | Ορίστε ευρετηρίαση, διαστάσεις ενσωμάτωσης, παραπομπές και ελέγχους πρόσβασης σε επίπεδο εγγράφου |
| Αξιολόγηση | Προσθέστε περιπτώσεις αναμενόμενης απάντησης, μη υποστηριζόμενων ερωτήσεων, χρήσης εργαλείων και ασφάλειας με ρητά όρια |
| Λειτουργίες | Ορίστε τηλεμετρία, προϋπολογισμούς καθυστέρησης/σφαλμάτων, όρια κόστους και ιδιοκτησία καθαρισμού |

Η αποθήκευση `custom-agents/shopper-agent-instructions.md` δεν προκαλεί τη φόρτωση του από το δείγμα. Βρείτε τον κώδικα εφαρμογής που δημιουργεί/ενημερώνει τον πράκτορα, συνδέστε εκεί τις αναθεωρημένες οδηγίες σας και επιβεβαιώστε την προκύπτουσα έκδοση πράκτορα πριν δοκιμάσετε. Οι οδηγίες δεν μπορούν να παραχωρήσουν πρόσβαση σε δεδομένα ή εργαλεία που δεν έχετε υλοποιήσει.

Εφαρμόστε μία αλλαγή τη φορά, αναπτύξτε ξανά τα επηρεαζόμενα στοιχεία και επαναλάβετε τις ερωτήσεις βάσης και τις αξιολογήσεις σας. Κρατήστε μια λειτουργική αναθεώρηση για σύγκριση. Για έμπνευση αρχιτεκτονικής, δείτε το [πρότυπο λιανικής](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md), που επίσης δεν είναι πλήρης εφαρμογή λιανικής.
