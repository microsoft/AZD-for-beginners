## 5.1 Καθιέρωση ενός βασικού σημείου αναφοράς

Χρησιμοποιήστε το αρχικοποιημένο αποθετήριο [Ξεκινήστε με τους AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) από τα προηγούμενα ενότητες. Καταγράψτε την αναθεώρηση του προτύπου, την έκδοση AZD, το επιλεγμένο περιβάλλον, την ανάπτυξη του μοντέλου και τις δείγματα ερωτήσεων πριν από οποιαδήποτε αλλαγή.

Το δείγμα υλοποιεί μια εφαρμογή συνομιλίας υποστηριζόμενη από πράκτορα. Δεν γίνεται **όχι** ένα σύστημα λιανικής με δύο πράκτορες απλά με τη ρύθμιση περιβαλλοντικών μεταβλητών ή την αποθήκευση επιπλέον αρχείων οδηγιών. Επιπλέον πράκτορες, χειριστές εργαλείων, δρομολόγηση, εξουσιοδότηση και πρόσβαση σε δεδομένα απαιτούν κώδικα εφαρμογής.

Εξετάστε τις οδηγίες και τα εργαλεία του πράκτορα που έχει αναπτυχθεί επί του παρόντος στο Foundry. Δοκιμάστε μια ερώτηση πραγματικών γεγονότων, μια ερώτηση ανάκτησης και μια ερώτηση που τα δείγματα δεδομένων δεν μπορούν να απαντήσουν. Επαληθεύστε τις αναφορές σε σύγκριση με τα πραγματικά πηγαία έγγραφα αντί να υποθέσετε ότι μια ρέουσα απάντηση είναι σωστή.

## 5.2 Προσαρμογή ανάκτησης γνώσης

Το πρότυπο υποστηρίζει ανάκτηση βασισμένη σε αρχεία και προαιρετική ενσωμάτωση Azure AI Search. Ακολουθήστε τον [τρέχοντα οδηγό AI Search](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) για ευρετηρίαση και ρύθμιση εργαλείων.

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

Η ενεργοποίηση της υπηρεσίας είναι μόνο ένα μέρος της ανάκτησης. Πριν ανεβάσετε τα δικά σας δεδομένα:

1. Επιβεβαιώστε ότι έχετε άδεια χρήσης των εγγράφων και αφαιρέστε ευαίσθητες πληροφορίες.
2. Επιλέξτε ένα μοντέλο ενσωμάτωσης που υποστηρίζεται στην περιοχή σας και ορίστε την συμβατή έκδοση, τον τύπο ανάπτυξης και τις διαστάσεις διάνυσματός του.
3. Δημιουργήστε/γεμίστε το ευρετήριο χρησιμοποιώντας τη διαδικασία που τεκμηριώνεται στο δείγμα.
4. Διαμορφώστε το εργαλείο ανάκτησης του πράκτορα ώστε να χρησιμοποιεί αυτό το ευρετήριο.
5. Δοκιμάστε την ανάκτηση, τις αναφορές, την εξουσιοδότηση και τη συμπεριφορά όταν δεν υπάρχει σχετικό έγγραφο.

Μην αλλάζετε από `text-embedding-3-small` σε διαφορετικό μοντέλο ενσωμάτωσης χωρίς να ελέγξετε τις διαστάσεις και να ανακατασκευάσετε/αναδείξετε τα διανύσματα όπως απαιτείται. Ένα όνομα όπως `retail-products` δεν είναι ένα υλοποιημένο κατάλογο ή πολιτική ελέγχου πρόσβασης.

## 5.3 Παρακολούθηση και εντοπισμός σφαλμάτων

Ακολουθήστε τον [οδηγό παρατηρησιμότητας του δείγματος](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring). Βεβαιωθείτε ότι ο απαραίτητος πόρος και η σύνδεση Application Insights υπάρχουν ήδη· εάν αλλάζετε ρυθμίσεις υποδομής, χρησιμοποιήστε το `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

Στείλτε ένα δοκιμαστικό αίτημα, στη συνέχεια ελέγξτε τα αρχεία καταγραφής εφαρμογής του Container App και την προβολή εντοπισμού σφαλμάτων του πράκτορα στο Foundry. Ελέγξτε τη λανθάνουσα κατάσταση, τις κλήσεις εργαλείων, τα σφάλματα και τη συσχέτιση μεταξύ του αιτήματος και του εντοπισμού. Μην υποθέτετε ότι η τηλεμετρία είναι συνδεδεμένη μόνο επειδή η ανάπτυξη πέτυχε.

Αφήστε το `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` απενεργοποιημένο εκτός αν έχετε ρητά ελέγξει τη συγκατάθεση, την απόρριψη, τη διακράτηση και τους ελέγχους πρόσβασης. Οι ιχνηλασίες μπορούν να περιέχουν ευαίσθητα επιχειρήματα εργαλείων ή περιεχόμενο εγγράφων ακόμη και όταν τα συνηθισμένα αρχεία καταγραφής εφαρμογών φαίνονται ακίνδυνα.

## 5.4 Αξιολόγηση πράκτορα

Το σημείο εισόδου αξιολόγησης του δείγματος είναι τώρα [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py), όχι ένας φάκελος `evals/`. Από τη ρίζα του δείγματος, χρησιμοποιήστε ένα περιβάλλον Python που πληροί τις τεκμηριωμένες απαιτήσεις του:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

Πριν την εκτέλεση, ολοκληρώστε τις [προαπαιτούμενες αξιολογήσεις](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md). Τα τεστ φορτώνουν ρυθμίσεις από το επιλεγμένο `.azure/<environment>/.env`· επιβεβαιώστε ότι έχει επιλεγεί το επιθυμητό περιβάλλον. Σημαντικές εισόδους περιλαμβάνουν:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, χρησιμοποιώντας τη μορφή που απαιτείται από το τρέχον δείγμα (η αναθεωρημένη έκδοση χρησιμοποιεί `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, που χρησιμοποιείται ως ανάπτυξη μοντέλου κριτή

Εξετάστε τα τεστ για να κατανοήσετε την επιλογή αξιολογητή, τα όρια, τους απαιτούμενους ρόλους και το κόστος μοντέλου. Μία ολοκληρωμένη εκτέλεση δεν είναι αυτόματα πύλη ποιότητας που περνάει· εξετάστε τα σκορ, τις αποτυχημένες/προβληματικές περιπτώσεις και τα συνδεδεμένα αποτελέσματα Foundry.

### Επέκταση ξεχωριστών αξιολογήσεων AZD

Το παραπάνω τεστ Python είναι μια **ροή εργασίας ειδική για το δείγμα**. Η προαιρετική επέκταση `azure.ai.evaluations` είναι διαφορετική ροή εργασίας, με τη δική της ρύθμιση `evals/azure.eval.yaml`:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

Για πλήρη ρύθμιση επέκτασης, δείτε τις [ροές αξιολόγησης και μετανάστευσης](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md). Από την έκδοση beta.22 της επέκτασης πράκτορα, μην χρησιμοποιείτε τις αφαιρεθείσες εντολές `azd ai agent eval`. Η εγκατάσταση της επέκτασης αξιολογήσεων δεν μετατρέπει τα τεστ Python του δείγματος ούτε δημιουργεί αυτόματα μια ρύθμιση αξιολόγησης.

## 5.5 Κόκκινη ομάδα AI και συνεχή αξιολόγηση

Το τρέχον δείγμα παρέχει [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py). Ολοκληρώστε τις προαπαιτήσεις του και εξετάστε τον προορισμό και το κόστος πριν εκτελέσετε:

```bash
pytest tests/test_red_teaming.py -s
```

Χρησιμοποιήστε μια εξουσιοδοτημένη ανάπτυξη δοκιμής και συνθετικά δεδομένα. Εξετάστε τις δημιουργημένες επιθέσεις και τα αποτελέσματα· αυτή η σάρωση δεν αποδεικνύει ότι μια εφαρμογή είναι ασφαλής ή συμμορφωμένη.

Ο [οδηγός παρατηρησιμότητας](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) περιγράφει επίσης συνεχή αξιολόγηση που ρυθμίζεται κατά την εκκίνηση του κοντέινερ. Αξιολογεί τις πραγματικές αλληλεπιδράσεις χρήστη, όχι την παραγόμενη δοκιμαστική κίνηση, και η υποστήριξη αξιολογητή διαφέρει ανά περιοχή. Μηδενικές αλληλεπιδράσεις σημαίνουν μηδενικές καταχωρήσεις αξιολόγησης. Επαληθεύστε την εγκατεστημένη έκδοση δείγματος και τη ρύθμιση αξιολογητή αντί να υποθέτετε ότι κάθε ανάπτυξη έχει τις ίδιες προεπιλογές.

Η ταυτοποίηση είναι ξεχωριστή από την αξιολόγηση. Ακολουθήστε τη τεκμηριωμένη ρύθμιση ταυτότητας/πρόσβασης του δείγματος. Δεν υπάρχει τεκμηριωμένη «εφεδρική βασική ταυτότητα» για προστασία δημόσιου τερματικού σημείου.

## 5.6 Άσκηση σχεδιασμού: προσαρμογή λιανικής

!!! warning "Άσκηση σχεδιασμού, όχι ολοκληρωμένη ανάπτυξη"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

Συντάξτε ένα σύντομο σχέδιο που να καλύπτει:

| Περιοχή | Απόφαση και στοιχεία για συλλογή |
|------|----------------------------------|
| Ευθύνες πρακτόρων | Ξεκινήστε με έναν πράκτορα, ή αιτιολογήστε ξεχωριστούς πράκτορες Αγορών και Πιστότητας και τη λογική δρομολόγησης |
| Δεδομένα | Ορίστε σύνθετα σύνολα κατάλογου/ανταμοιβών και ιδιοκτησία ενημερώσεων |
| Εργαλεία | Υλοποιήστε χειριστές μόνο ανάγνωσης πρώτα· προσδιορίστε την εξουσιοδότηση και την επαλήθευση για όποιες εγγραφές |
| Μοντέλα | Επιλέξτε διαθέσιμες συνδυασμούς μοντέλου/έκδοσης/SKU και επαληθεύστε το όριο· αποφύγετε την προμήθεια αχρησιμοποίητων μοντέλων |
| Ανάκτηση | Ορίστε ευρετηρίαση, διαστάσεις ενσωμάτωσης, αναφορές και ελέγχους πρόσβασης σε επίπεδο εγγράφου |
| Αξιολόγηση | Προσθέστε αναμενόμενες απαντήσεις, μη υποστηριζόμενες ερωτήσεις, περιπτώσεις χρήσης εργαλείων και ασφάλειας με ρητά όρια |
| Λειτουργίες | Ορίστε τηλεμετρία, προϋπολογισμούς λανθάνουσας κατάστασης/σφαλμάτων, όρια κόστους και ιδιοκτησία καθαρισμού |

Η αποθήκευση `custom-agents/shopper-agent-instructions.md` δεν προκαλεί τη φόρτωση του δείγματος. Εντοπίστε τον κώδικα εφαρμογής που δημιουργεί/ενημερώνει τον πράκτορα, συνδέστε εκεί τις αναθεωρημένες οδηγίες σας, και επαληθεύστε την προκύπτουσα έκδοση πράκτορα πριν τη δοκιμή. Οι οδηγίες δεν μπορούν να παραχωρήσουν πρόσβαση σε δεδομένα ή εργαλεία που δεν έχετε υλοποιήσει.

Εφαρμόστε μία αλλαγή κάθε φορά, αναπτύξτε ξανά τα επηρεαζόμενα συστατικά και τρέξτε ξανά τις βασικές σας ερωτήσεις και αξιολογήσεις. Κρατήστε μια λειτουργική αναθεώρηση για σύγκριση. Για έμπνευση αρχιτεκτονικής, δείτε το [σχέδιο λιανικής](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md), που επίσης δεν είναι ολοκληρωμένη εφαρμογή λιανικής.
