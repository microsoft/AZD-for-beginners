# Φέρε Τη Δική Σου Εφαρμογή - Πρόσθεσε azd σε Ένα Υφιστάμενο Έργο

**Πλοήγηση Κεφαλαίου:**
- **📚 Αρχική Μαθήματος**: [AZD Για Αρχάριους](../../README.md)
- **📖 Τρέχον Κεφάλαιο**: Κεφάλαιο 1 - Θεμέλια & Γρήγορη Εκκίνηση
- **⬅️ Προηγούμενο**: [Το Πρώτο Σου Έργο](first-project.md)
- **➡️ Επόμενο**: [Dev Containers & Codespaces](dev-containers.md)

> Στόχος ανασκόπησης εντολών και ρυθμίσεων: `azd 1.37.2` (Νοέμβριος 2026). Τα παραγόμενα αρχεία εξαρτώνται από την ανιχνευμένη εφαρμογή· η ανάπτυξη στο Azure δεν εκτελέστηκε σε αυτή την ανασκόπηση.

## Εισαγωγή

Στο [Το Πρώτο Σου Έργο](first-project.md) ανέπτυξες μια εφαρμογή ξεκινώντας από ένα πρότυπο. Αλλά τις περισσότερες φορές ήδη *έχεις* μια εφαρμογή—ένα Node.js API, μια υπηρεσία Python Flask, μια .NET web εφαρμογή—που βρίσκεται σε έναν φάκελο στον υπολογιστή σου. Αυτό το μάθημα δείχνει πώς να προσθέσεις azd σε αυτόν τον υπάρχοντα κώδικα ώστε να μπορείς να τον αναπτύξεις με `azd up`, χωρίς να χρειάζεται πρότυπο.

## Στόχοι Μάθησης

Στο τέλος αυτού του μαθήματος, θα:
- Κατανοήσεις τους τρεις τρόπους εκκίνησης ενός έργου azd
- Εκτελέσεις `azd init` μέσα σε έναν υπάρχοντα κώδικα
- Κατανοήσεις τι κάνει το `azure.yaml` και ο φάκελος `infra/` για την εφαρμογή σου
- Γνωρίζεις πότε να αφήσεις το azd να δημιουργήσει την υποδομή έναντι του να γράψεις τη δική σου
- Αναπτύξεις την υπάρχουσα εφαρμογή σου στο Azure με `azd up`

## Μαθησιακά Αποτελέσματα

Αφού ολοκληρώσεις αυτό το μάθημα, θα μπορείς να:
- Αρχικοποιήσεις το azd σε ένα έργο που ήδη έχεις
- Διαβάσεις και επεξεργαστείς ένα βασικό αρχείο `azure.yaml`
- Δημιουργήσεις υποδομή εκκίνησης με `azd infra generate`
- Επιλέξεις έναν κατάλληλο υποδοχέα Azure για την εφαρμογή σου
- Αναπτύξεις και καθαρίσεις τη δική σου εφαρμογή

---

## Τρεις Τρόποι Εκκίνησης Έργου azd

| Σημείο εκκίνησης | Εντολή | Πότε να χρησιμοποιήσεις |
|----------------|---------|-------------|
| **Από πρότυπο** | `azd init --template <name> .` (κενός κατάλογος) | Μάθηση, ή εκκίνηση νέας εφαρμογής από δοκιμασμένο δείγμα |
| **Από τον υπάρχοντα κώδικα σου** | `azd init` (στο φάκελο του έργου σου) | Ήδη έχεις μια εφαρμογή και θες να την αναπτύξεις |
| **Από αποθετήριο Git** | `azd init --from-code` (σε κλωνοποιημένο αποθετήριο) | Υιοθέτηση azd για ένα υπάρχον αποθετήριο |

Έχεις ήδη εξασκηθεί στην πρώτη επιλογή. Αυτό το μάθημα καλύπτει τη δεύτερη—τη συνηθέστερη κατάσταση στον πραγματικό κόσμο.

## Βήμα 1: Εκτέλεση `azd init` στο Έργο Σου

Άνοιξε ένα τερματικό **μέσα στο φάκελο του υπάρχοντος έργου σου** και τρέξε:

```bash
cd my-existing-app
azd init
```

Το azd θα ρωτήσει πώς θες να αρχικοποιήσεις. Επίλεξε:

```
? How do you want to initialize your app?
> Use code in the current directory
  Select a template
```

Διάλεξε **"Χρήση κώδικα στον τρέχοντα κατάλογο."** Το azd στη συνέχεια σαρώνει το φάκελο, ανιχνεύει τη γλώσσα και το πλαίσιο, και προτείνει έναν υποδοχέα.

### Τι ανιχνεύει το azd

Το azd αναζητά σήματα εφαρμογής όπως `package.json`, `requirements.txt`, `pom.xml`, `*.csproj`, ή ένα `Dockerfile`. Η ροή από-κώδικα δεν είναι ένας γενικός οδηγός επιλογής υποδοχέα για κάθε υποστηριζόμενο στόχο ανάπτυξης:

| Η εφαρμογή σου | Πιθανός ανιχνευμένος υποδοχέας |
|----------|----------------------|
| Υποστηριζόμενη Node.js / Python / .NET web εφαρμογή | Τυπικά Azure Container Apps· επιθεώρησε τον παραγόμενο ορισμό |
| Εφαρμογή με container (`Dockerfile`) | Azure Container Apps |
| Εφαρμογή Function ή έργο Static Web Apps | Χρησιμοποίησε αντίστοιχο πρότυπο ή δημιούργησε `azure.yaml` και υποδομή αν ο από-κώδικα τρόπος δεν υποστηρίζει τη διάταξή σου |

Επιβεβαίωσε τις ανιχνευμένες υπηρεσίες, και το azd σκελετώνει τα αρχεία που χρειάζεσαι.

---

## Βήμα 2: Κατανόησε Τι Δημιούργησε το azd

Μετά την αρχικοποίηση, επιθεώρησε το `azure.yaml`. Η ροή παραγόμενης υποδομής μπορεί να κρατήσει την υποδομή σε υπονοούμενη μορφή μέχρι να τρέξεις `azd infra generate`· μην υποθέτεις ότι το `infra/` υπάρχει ήδη:

```
my-existing-app/
├── azure.yaml          # ← NEW: tells azd what to deploy and where
├── infra/              # Materialized with azd infra generate when using implicit infrastructure
│   ├── main.bicep
│   └── main.parameters.json
├── src/ (your code)    # unchanged
└── ...                 # your existing files, untouched
```

### `azure.yaml` — ο ορισμός του έργου

Αυτή είναι η καρδιά ενός έργου azd. Ο ακόλουθος **δημοσιευτικός ορισμός App Service** απαιτεί αντίστοιχη υποδομή App Service· δεν είναι λόγος να αλλάξεις έναν παραγόμενο υποδοχέα Container Apps χωρίς να αλλάξεις την υποδομή:

```yaml
# azure.yaml
name: my-existing-app
services:
  web:
    project: ./src           # path to your app code
    language: js             # js | python | dotnet | java
    host: appservice         # appservice | containerapp | function | staticwebapp
```

Το μπλοκ `services` είναι το κεντρικό σημείο: κάθε εγγραφή αντιστοιχίζει έναν φάκελο του κώδικά σου σε έναν υποδοχέα Azure. Αν η εφαρμογή σου έχει και frontend και API, θα έχεις δύο υπηρεσίες.

### `infra/` — οι πόροι Azure σου ως κώδικας

Ο φάκελος `infra/` κρατά αρχεία Bicep που ορίζουν τους πόρους Azure που χρειάζεται η εφαρμογή σου (το App Service, η βάση δεδομένων, κλπ.). Δεν χρειάζεται να τα γράψεις χειροκίνητα—το azd παράγει ένα λειτουργικό σημείο εκκίνησης. Μπορείς *να* τα επεξεργαστείς αργότερα για να προσθέσεις πόρους ή να αυξήσεις την ασφάλεια (καλυμμένο στο [Κεφάλαιο 4](../chapter-04-infrastructure/README.md)).

> **Συμβουλή:** Θες να δεις ή να προσαρμόσεις την παραγόμενη υποδομή πριν την ανάπτυξη; Εκτέλεσε `azd infra generate` (διαθέσιμο και ως `azd infra synth`) για να γράψεις το IaC στο δίσκο ώστε να το ελέγξεις και να το ελέγχεις με σύστημα ελέγχου εκδόσεων.

## Βήμα 3: Ρύθμισε τις Απαιτούμενες Ρυθμίσεις

Αν η εφαρμογή σου χρειάζεται ρυθμίσεις ή μυστικά (ένα connection string, ένα κλειδί API), μην τα σκληροκωδικοποιείς. Χρησιμοποίησε τιμές περιβάλλοντος:

```bash
# Create an environment
azd env new dev

# Set a non-secret value
azd env set API_VERSION 1.0.0
```

Αυτό αποθηκεύει μόνο μια τοπική τιμή. Για να επηρεάσεις την εφαρμογή, κατανάλωσέ την ρητά σε παραμέτρους υποδομής, υποστηριζόμενη ρύθμιση υπηρεσίας ή hook· η ρύθμιση μιας αυθαίρετης μεταβλητής δεν ρυθμίζει το runtime που αναπτύχθηκε.

Για πραγματικά μυστικά, αποθήκευσέ τα στο Key Vault και αναφέρσου σε αυτά από την υποδομή σου—βλέπε [Κεφάλαιο 3: Ρύθμιση & Πιστοποίηση](../chapter-03-configuration/authsecurity.md).

## Βήμα 4: Ανάπτυξη

Τώρα χρησιμοποίησε την ίδια ροή εργασίας που ήδη γνωρίζεις:

```bash
# Authenticate (required for azd)
azd auth login

# Preview the resources that will be created
azd provision --preview

# Provision infrastructure and deploy your code
azd up
```

Όταν τελειώσει, το azd εμφανίζει το URL της εφαρμογής σου. Επαλήθευσέ το με τον ίδιο τρόπο όπως οποιαδήποτε εφαρμογή azd:

```bash
azd show           # show endpoints
azd monitor --logs # check logs if needed
```

## Συνήθη Προβλήματα Πρώτης Φοράς

| Σύμπτωμα | Πιθανή αιτία | Διόρθωση |
|---------|--------------|-----|
| το azd δεν ανίχνευσε την εφαρμογή μου | Λείπει manifest (π.χ., `package.json`) | Πρόσθεσε το manifest, ή διάλεξε χειροκίνητα τον υποδοχέα κατά την `azd init` |
| Η κατασκευή αποτυγχάνει κατά την `azd up` | Η εφαρμογή χρειάζεται βήμα κατασκευής | Ρύθμισε τα πακέτα scripts της εφαρμογής ή το hook υπηρεσίας `prepackage`· χρησιμοποίησε `dist` για έξοδο ανάπτυξης, όχι `buildCommand`/`outputPath` |
| Η εφαρμογή ξεκινά αλλά επιστρέφει σφάλματα | Λείπει ρύθμιση/μυστικό | Συνδέστε τιμές σε ρυθμίσεις χρόνου εκτέλεσης ή αναφορά Key Vault· μόνο `azd env set` δεν είναι αρκετό |
| Λάθος υποδοχέας επιλέχτηκε | Η αυτόματη ανίχνευση δεν ταιριάζει με τις ανάγκες σου | Αλλάξε και `host:` και τη σχετική υποδομή, ή διάλεξε αντίστοιχο πρότυπο |

Για περισσότερα, δες [Κεφάλαιο 7: Επίλυση Προβλημάτων](../chapter-07-troubleshooting/README.md).

## Καθαρισμός

```bash
azd down --force --purge
```

## Περίληψη

- `azd init` → **"Χρήση κώδικα στον τρέχοντα κατάλογο"** προσθέτει το azd σε μια εφαρμογή που ήδη έχεις.
- `azure.yaml` αντιστοιχίζει τους φακέλους κώδικά σου σε υποδοχείς Azure· `infra/` ορίζει τους πόρους ως Bicep.
- `azd infra generate` σου επιτρέπει να ελέγξεις ή να προσαρμόσεις την παραγόμενη υποδομή.
- Μόλις αρχικοποιηθεί, η υπάρχουσα εφαρμογή σου χρησιμοποιεί την ίδια ακριβώς ροή εργασίας `azd up` / `azd down` όπως μια εφαρμογή βασισμένη σε πρότυπο.
