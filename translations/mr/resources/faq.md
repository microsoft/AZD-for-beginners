हे सर्वसमावेशक FAQ Azure Developer CLI (azd) आणि Azure तैनातींबाबत सर्वसामान्य प्रश्नांची उत्तरे प्रदान करते. सामान्य समस्या लवकर सोडवण्यासाठी उपाय शोधा, सर्वोत्तम पद्धती समजून घ्या आणि azd संकल्पना व कार्यप्रवाहांवर स्पष्टता मिळवा.

## प्रारंभ करणे

### प्रश्न: Azure Developer CLI (azd) काय आहे?
**उत्तर**: Azure Developer CLI (azd) एक विकसक-केंद्रित कमांड-लाइन साधन आहे जे आपला अनुप्रयोग स्थानिक विकास वातावरणापासून Azure पर्यंत पोहोचण्यासाठी लागणारा वेळ जलद करते. हे टेम्पलेट्सद्वारे सर्वोत्तम पद्धती प्रदान करते आणि संपूर्ण तैनाती जीवनचक्रात मदत करते.

### प्रश्न: azd आणि Azure CLI मध्ये काय फरक आहे?
**उत्तर**: 
- **Azure CLI**: Azure साधने व्यवस्थापित करण्यासाठी सर्वसामान्य हेतूचे साधन
- **azd**: अनुप्रयोग तैनाती कार्यप्रवाहासाठी विकसक-केंद्रित साधन
- azd स्वतःचे प्रमाणीकरण आणि तैनाती कार्यप्रवाह असते; Azure CLI वेगळे, पूरक साधन आहे
- azd मध्ये टेम्पलेट्स, वातावरण व्यवस्थापन आणि तैनाती ऑटोमेशन असते

### प्रश्न: azd वापरण्यासाठी मला Azure CLI स्थापित करणे आवश्यक आहे का?
**उत्तर**: मुख्य AZD कार्यप्रवाहासाठी नाही. `azd auth login` सह प्रमाणीकरण करा. जेव्हा टेम्पलेट हुक किंवा व्यायाम स्पष्टपणे `az` आदेश चालवतात तेव्हा Azure CLI स्वतंत्रपणे स्थापित करा.

### प्रश्न: azd कोणत्या प्रोग्रामिंग भाषा समर्थन करते?
**उत्तर**: azd भाषा-स्वतंत्र आहे. ते कार्य करते:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- स्थिर वेबसाइट्स
- कंटेनरयुक्त अनुप्रयोग

### प्रश्न: azd मी विद्यमान प्रकल्पांसह वापरू शकतो का?
**उत्तर**: होय! आपण:
1. विद्यमान प्रकल्पांमध्ये azd संरचना जोडण्यासाठी `azd init` वापरू शकता
2. विद्यमान प्रकल्प azd टेम्पलेट संरचनेशी सुसंगत करा
3. आपल्या विद्यमान आर्किटेक्चरवर आधारित सानुकूल टेम्पलेट तयार करा

## प्रमाणीकरण आणि प्रवेश

### प्रश्न: azd वापरून Azure सह मी कसे प्रमाणीकरण करावे?
**उत्तर**: उपयोग करा `azd auth login` जे Azure प्रमाणीकरणासाठी ब्राउझर विंडो उघडेल. CI/CD परिस्थितींमध्ये, सेवा प्रिन्सिपल्स किंवा व्यवस्थापित ओळख वापरा.

### प्रश्न: मी azd बहु Azure सदस्यता वापरू शकतो का?
**उत्तर**: होय. प्रत्येक वातावरणासाठी कोणती सदस्यता वापरायची ते निर्दिष्ट करण्यासाठी `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` वापरा.

### प्रश्न: azd बरोबर तैनातीसाठी कोणत्या परवानग्या आवश्यक आहेत?
**उत्तर**: सामान्यतः आपणास:
- रिसोर्स ग्रुप किंवा सदस्यता वर **Contributor** भूमिका आवश्यक आहे
- भूमिका नेमणीसाठी संसाधने तैनात करताना **User Access Administrator** लागतो
- विशिष्ट परवानग्या टेम्पलेट आणि तैनात होणाऱ्या संसाधनांनुसार बदलतात

### प्रश्न: azd मी CI/CD पाईपलाईनमध्ये वापरू शकतो का?
**उत्तर**: नक्कीच! azd CI/CD एकत्रीकरणासाठी डिझाइन केलेले आहे. प्रमाणीकरणासाठी सेवा प्रिन्सिपल्स वापरा आणि संरचनेसाठी पर्यावरणीय चल सेट करा.

### प्रश्न: GitHub Actions मधील प्रमाणीकरण कसे हाताळावे?
**उत्तर**: कामाचा ओळख फेडरेशन (OIDC) प्राधान्य द्या, ज्याचे конфिगरेशन `azd pipeline config` सहाय्याने होते. तयार केलेल्या वर्कफ्लोने AZD स्थापित करते आणि थेट फेडरेटेड ओळखीने AZD प्रमाणीकरण करते. फक्त `azure/login` टप्पा AZD लॉगिन स्थापित करत नाही. विद्यमान जॉबसाठी लॉगिन टप्पा आहे:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

लॉगिननंतर तैनात करा किंवा प्राव्हिजन करा, इच्छित AZD वातावरण, सदस्यता, आणि स्थान कॉन्फिगर केलेले असावे. ओळखीच्या फेडरेटेड क्रेडेन्शियलनी वर्कफ्लोचा रेपॉसिटरी/रिफ किंवा GitHub वातावरण विश्वसनीय असणे आवश्यक आहे, आणि त्याच्या Azure भूमिका विनंती केलेल्या ऑपरेशन्ससाठी परवानगी असावी.

## टेम्पलेट्स आणि प्रकल्प

### प्रश्न: azd टेम्पलेट्स मला कुठे मिळतील?
**उत्तर**: 
- अधिकृत आणि समुदाय टेम्पलेट्स: [Awesome AZD](https://azure.github.io/awesome-azd/)
- समुदाय टेम्पलेट्स: GitHub वर "azd-template" शोधा
- उपलब्ध टेम्पलेट्स ब्राउझ करण्यासाठी `azd template list` वापरा

### प्रश्न: सानुकूल टेम्पलेट कसे तयार करावे?
**उत्तर**: 
1. विद्यमान टेम्पलेट संरचनेपासून प्रारंभ करा
2. `azure.yaml`, पायाभूत रचना फाइल्स व अनुप्रयोग कोड बदला
3. `azd up` ने सखोल परीक्षण करा
4. योग्य टॅगसह GitHub वर प्रकाशित करा

### प्रश्न: मी टेम्पलेटशिवाय azd वापरू शकतो का?
**उत्तर**: होय, विद्यमान प्रकल्पात आवश्यक संरचना फाइल्स तयार करण्यासाठी `azd init` वापरा. आपल्याला `azure.yaml` व पायाभूत रचना फाईल्स हाताने कॉन्फिगर कराव्या लागतील.

### प्रश्न: अधिकृत आणि समुदाय टेम्पलेट्समधील फरक काय आहे?
**उत्तर**: 
- **अधिकृत टेम्पलेट्स**: Microsoft द्वारे देखभाल, नियमित अद्यतने, सविस्तर दस्तऐवजीकरण
- **समुदाय टेम्पलेट्स**: विकसकांनी तयार केलेले, कदाचित खास वापरासाठी, दर्जा आणि देखभाल वेगवेगळा असू शकतो

### प्रश्न: माझ्या प्रकल्पात टेम्पलेट कसे अपडेट करायचे?
**उत्तर**: टेम्पलेट आपोआप अपडेट होत नाही. आपण:
1. स्रोत टेम्पलेटमधील बदल मनually तुलना करून मर्ज करा
2. अद्ययावत टेम्प्लेट वापरून `azd init` सोबत नवीन सुरुवात करा
3. अद्ययावत टेम्प्लेटमधून विशिष्ट सुधारणा निवडा

## तैनाती आणि पायाभूत सुविधा

### प्रश्न: azd कोणत्या Azure सेवा तैनात करू शकतो?
**उत्तर**: azd कोणत्याही Azure सेवेची तैनाती करू शकतो Bicep/ARM टेम्प्लेटद्वारे, ज्यात समाविष्ट आहे:
- अॅप सेवा, कंटेनर अॅप्स, फंक्शन्स
- डेटाबेस (SQL, PostgreSQL, Cosmos DB)
- संचयन, की वॉल्ट, अॅप्लिकेशन इनसाइट्स
- नेटवर्किंग, सुरक्षा, आणि निरीक्षण संसाधने

### प्रश्न: मी अनेक प्रदेशांमध्ये तैनात करू शकतो का?
**उत्तर**: हो, Bicep टेम्प्लेटमध्ये अनेक प्रदेश कॉन्फिगर करा आणि प्रत्येक पर्यावरणासाठी स्थान पॅरामीटर योग्यरित्या सेट करा.

### प्रश्न: डेटाबेस स्कीमा माइग्रेशन कसे हाताळू?
**उत्तर**: `azure.yaml` मध्ये तैनाती हुक्स वापरा:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### प्रश्न: मी फक्त पायाभूत सुविधा तैनात करू शकतो का, अॅप्लिकेशन्सशिवाय?
**उत्तर**: हो, फक्त तुमच्या टेम्प्लेटमध्ये परिभाषित पायाभूत सुविधा घटक तैनात करण्यासाठी `azd provision` वापरा.

### प्रश्न: विद्यमान Azure संसाधनांवर कसे तैनात करावे?
**उत्तर**: हो, टेम्प्लेट समर्थन देत असल्यास. विद्यमान संसाधने संदर्भित करण्यासाठी Bicep च्या `existing` घोषणांचा किंवा टेम्प्लेटच्या दस्तऐवजीकृत विद्यमान-संसाधन पॅरामीटरचा वापर करा आणि अॅप्लिकेशन सेवा त्यांच्या इच्छित लक्ष्यांशी मॅप करा. हे मालकी हक्क आयात करत नाही किंवा स्वयंचलीतपणे गायब परवानग्या तयार करत नाही. तैनातीपूर्वी टेम्प्लेट पुनरावलोकन करा.

### प्रश्न: मी Bicep ऐवजी Terraform वापरू शकतो का?
**उत्तर**: हो. AZD Terraform आणि Bicep दोन्हीला समर्थन देतो. Terraform-आधारित टेम्प्लेट निवडा किंवा `infra.provider: terraform` ला `azure.yaml` मध्ये योग्य Terraform फायली आणि स्टेट/बॅकएंड कॉन्फिगरेशनसह कॉन्फिगर करा. पहा [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## कॉन्फिगरेशन आणि पर्यावरणे

### प्रश्न: मी वेगवेगळ्या पर्यावरणांचे (dev, staging, prod) व्यवस्थापन कसे करणार?
**उत्तर**: `azd env new <environment-name>` वापरून स्वतंत्र पर्यावरण तयार करा आणि प्रत्येका साठी वेगवेगळ्या सेटिंग्ज कॉन्फिगर करा:
```bash
azd env new development
azd env new staging  
azd env new production
```

### प्रश्न: पर्यावरण कॉन्फिगरेशन कुठे संग्रहित आहेत?
**उत्तर**: आपल्या प्रोजेक्ट निर्देशिकेतील `.azure` फोल्डरमध्ये. प्रत्येक पर्यावरणासाठी स्वतंत्र फोल्डर त्याच्या कॉन्फिगरेशन फाइल्ससह आहे.

### प्रश्न: मी पर्यावरण-विशिष्ट कॉन्फिगरेशन कसे सेट करू?
**उत्तर**: पर्यावरण व्हेरिएबल्स कॉन्फिगर करण्यासाठी `azd env set` वापरा:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### प्रश्न: मी पर्यावरण कॉन्फिगरेशन टीम सदस्यांमध्ये शेअर करू शकतो का?
**उत्तर**: `.azure` फोल्डर संवेदनशील माहिती ठेवतो आणि कोणत्याही आवृत्ती नियंत्रणात कमिट करू नये. त्याऐवजी:
1. आवश्यक पर्यावरण व्हेरिएबल्स दस्तऐवजीकरण करा
2. पर्यावरण सेट करण्यासाठी तैनाती स्क्रिप्ट वापरा
3. संवेदनशील कॉन्फिगरेशनसाठी Azure Key Vault वापरा

### प्रश्न: मी टेम्प्लेट डिफॉल्ट्सवर कसे अधिलेखित करू?
**उत्तर**: टेम्प्लेट पॅरामीटरशी संबंधित पर्यावरण व्हेरिएबल्स सेट करा:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

फक्त टेम्प्लेटद्वारे वापरले जाणारे व्हेरिएबल्स तैनातीवर प्रभाव टाकतात. वरील `SKU_NAME` हा एक उदाहरण कस्टम इनपुट आहे, सर्वसाधारण AZD सेटिंग नाही.

## समस्या निवारण

### प्रश्न: `azd up` का अयशस्वी होत आहे?
**उत्तर**: सामान्य कारणे:
1. **प्राधिकरण समस्या**: `azd auth login` चालवा
2. **पर्याप्त परवानग्या नाहीत**: आपल्या Azure रोल नियुक्त्या तपासा
3. **संसाधन नावाच्या संघर्ष**: संघर्ष करणाऱ्या संसाधनाचा आणि टेम्प्लेटच्या नाव इनपुटचा आढावा घ्या; विलगीकरण आवश्यक असल्यास `azd env new` वापरून स्वतंत्र पर्यावरण तयार करा
4. **कोटा/क्षमता समस्या**: प्रादेशिक उपलब्धता तपासा
5. **टेम्प्लेट त्रुटी**: Bicep टेम्प्लेट व्हॅलिडेट करा

### प्रश्न: मी तैनात अयशस्वी का झाला तो कसा डिबग करू शकतो?
**उत्तर**: 
1. तपशीलवार आउटपुटसाठी `azd deploy --debug` वापरा
2. Azure पोर्टलमधील तैनाती इतिहास तपासा
3. Azure पोर्टलमधील क्रियाकलाप लॉग पहा
4. सध्याच्या पर्यावरण स्थिती दाखवण्यासाठी `azd show` वापरा

### प्रश्न: माझी पर्यावरण व्हेरिएबल्स काम का करत नाहीत?
**उत्तर**: तपासा:
1. व्हेरिएबल नावे टेम्प्लेट पॅरामीटरशी अगदी जुळतात का
2. जागा असल्यास किंमती योग्यरित्या कोट केल्या आहेत का
3. पर्यावरण निवडले आहे: `azd env select <environment>`
4. व्हेरिएबल्स योग्य पर्यावरणात सेट केले आहेत का

### प्रश्न: मी अयशस्वी तैनाती कशी साफ करू?
**उत्तर**: 
```bash
azd down
```
 प्रथम निवडलेले पर्यावरण आणि हटवण्याची पुष्टी तपासा. हे तैनात केलेले Azure संसाधने हटवते, स्थानिक `.azure` पर्यावरण कॉन्फिगरेशन नाही. `--purge` ही अतिरिक्तपणे समर्पित सॉफ्ट-डिलीटेड संसाधनांची कायमस्वरूपी हटवणीची विनंती करते आणि ते ठेवणूक/शुद्धीकरण संरक्षणामुळे अडवले जाऊ शकते; हे नियमित पुनर्प्राप्ती पाऊल नाही.

### प्रश्न: माझे अॅप्लिकेशन तैनाती नंतर प्रवेशयोग्य का नाही?
**उत्तर**: तपासा:
1. तैनाती यशस्वी झाली आहे
2. अॅप्लिकेशन चालू आहे (Azure पोर्टलमधील लॉग तपासा)
3. नेटवर्क सुरक्षा गट ट्रॅफिक परवानगी देतात
4. DNS/कस्टम डोमेन योग्य प्रकारे कॉन्फिगर केले आहेत

## खर्च आणि बिलिंग

### प्रश्न: azd तैनात करण्यात किती खर्च येईल?
**उत्तर**: खर्चावर अवलंबून आहे:
- तैनात Azure सेवा
- निवडलेले सेवा स्तर/SKU
- प्रादेशिक किंमतीतील फरक
- वापर नमुने

अंदाजासाठी [Azure किमती गणक](https://azure.microsoft.com/pricing/calculator/) वापरा.

### प्रश्न: azd तैनातीतील खर्च मी कसा नियंत्रित करू?
**उत्तर**: 
1. विकास पर्यावरणासाठी कमी स्तराच्या SKU वापरा
2. Azure बजेट आणि अलर्ट सेट करा
3. गरज नसल्यास संसाधने काढून टाकण्यासाठी `azd down` वापरा
4. योग्य प्रदेश निवडा (खर्च ठिकाणानुसार वेगळा असतो)
5. Azure खर्च व्यवस्थापन साधने वापरा

### प्रश्न: azd टेम्प्लेटसाठी मोफत स्तर पर्याय आहेत का?
**उत्तर**: काही सेवा मोफत SKU किंवा मासिक अनुदान देतात, पात्रता, होस्टिंग योजना, प्रदेश, आणि सदस्यत्व मर्यादांनुसार. हे टेम्प्लेट पूर्णपणे मोफत करत नाही: डेटाबेस, शोध, नेटवर्किंग, रजिस्ट्री, टेलिमेट्री, आणि मॉडेल इन्फरन्स स्वतंत्रपणे शुल्क आकारू शकतात. तैनातीपूर्वी [Azure मोफत सेवा यादी](https://azure.microsoft.com/free/) आणि प्रत्येक संसाधनाचे वर्तमान किंमत तपासा.

### प्रश्न: तैनातीपूर्वी खर्च कसा अंदाजित करावा?
**उत्तर**: 
1. टेम्प्लेटचा `main.bicep` तपासा, कोणती संसाधने तयार होणार आहेत ते पहाण्यासाठी
2. विशिष्ट SKU सह Azure किमती गणक वापरा
3. प्रथम विकास पर्यावरणात तैनात करून प्रत्यक्ष खर्च परीक्षण करा
4. तपशीलवार खर्च विश्लेषणासाठी Azure खर्च व्यवस्थापन वापरा

## सर्वोत्तम पद्धती

### प्रश्न: azd प्रोजेक्ट संरचनेसाठी सर्वोत्तम पद्धती काय आहेत?
**उत्तर**: 
1. अॅप्लिकेशन कोड पायाभूत सुविधांपासून वेगळे ठेवा
2. `azure.yaml` मध्ये अर्थपूर्ण सेवा नावे वापरा
3. बिल्ड स्क्रिप्टमध्ये योग्य त्रुटी हाताळणी वापरा
4. पर्यावरण-विशिष्ट कॉन्फिगरेशन वापरा
5. संपूर्ण दस्तऐवजीकरण समाविष्ट करा

### प्रश्न: azd मध्ये अनेक सेवा कशा आयोजित कराव्यात?
**उत्तर**: शिफारस केलेली संरचना वापरा:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### प्रश्न: `.azure` फोल्डर आवृत्ती नियंत्रणात कमिट करावा का?
**उत्तर**: **नाही!** `.azure` फोल्डर संवेदनशील माहिती ठेवतो. त्याला `.gitignore` मध्ये जोडा:
```gitignore
.azure/
```

### प्रश्न: मी गुपिते आणि संवेदनशील कॉन्फिगरेशन कसे हाताळू?
**उत्तर**: 
1. गुपितांसाठी Azure Key Vault वापरा
2. अनुप्रयोग कॉन्फिगरेशनमध्ये Key Vault गुपितांना संदर्भित करा
3. गुपिते कधीही आवृत्ती नियंत्रणात कमिट करू नका
4. सेवा-ते-सेवा प्रमाणीकरणासाठी व्यवस्थापित ओळख वापरा

### प्रश्न: azd सोबत CI/CD साठी शिफारस केलेली पद्धत काय आहे?
**उत्तर**: 
1. प्रत्येक टप्प्यासाठी स्वतंत्र वातावरण वापरा (dev/staging/prod)
2. तैनातीपूर्वी स्वयंचलित चाचणी अंमलात आणा
3. प्रमाणीकरणासाठी सेवा प्रमुख वापरा
4. संवेदनशील कॉन्फिगरेशन pipeline गुपिते/चरांमध्ये साठवा
5. उत्पादन तैनातीसाठी मंजुरीचे दरवाजे अंमलात आणा

## प्रगत विषय

### प्रश्न: मी azd कस्टम कार्यक्षमतेने विस्तृत करू शकतो का?
**उत्तर**: होय, `azure.yaml` मध्ये तैनाती हुकद्वारे:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### प्रश्न: मी azd विद्यमान DevOps प्रक्रियांशी कसे एकत्र करू?
**उत्तर**: 
1. विद्यमान pipeline स्क्रिप्टमध्ये azd कमांड वापरा
2. संघांमध्ये azd साच्याचे मानकीकरण करा
3. विद्यमान निरीक्षण आणि सूचना यांच्याशी एकत्र करा
4. pipeline एकत्रिकरणासाठी azd चे JSON आउटपुट वापरा

### प्रश्न: मी azd Azure DevOps सोबत वापरू शकतो का?
**उत्तर**: होय, azd कोणत्याही CI/CD प्रणालीसह कार्य करते. azd कमांड वापरणारे Azure DevOps पाईपलाइन तयार करा.

### प्रश्न: मी azd मध्ये कसे योगदान देऊ किंवा समुदाय साच्यांची निर्मिती कशी करू?
**उत्तर**: 
1. **azd टूल**: योगदान द्या [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **टेम्पलेट्स**: अनुसरण करा [Awesome AZD gallery contribution instructions](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **डॉक्युमेंटेशन**: दस्तऐवजांना योगदान द्या [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### प्रश्न: azd साठी रोडमॅप काय आहे?
**उत्तर**: नियोजित वैशिष्ट्ये आणि सुधारणा पाहण्यासाठी [अधिकृत रोडमॅप](https://github.com/Azure/azure-dev/projects) तपासा.

### प्रश्न: मी इतर डिप्लॉयमेंट टूल्समधून azd कडे कसे स्थलांतर करू?
**उत्तर**: 
1. सध्याच्या डिप्लॉयमेंट आर्किटेक्चरचे विश्लेषण करा
2. समान Bicep टेम्पलेट तयार करा
3. सध्याच्या सेवांशी जुळवून घेण्यासाठी `azure.yaml` कॉन्फिगर करा
4. विकास वातावरणात संपूर्णपणे चाचणी करा
5. हळूहळू वातावरणे स्थलांतरित करा
