## 5.1 สร้างฐานข้อมูลเริ่มต้น

ใช้รีโพสิทอรี [Get Started with AI Agents](https://github.com/Azure-Samples/get-started-with-ai-agents) ที่เริ่มต้นไว้จากโมดูลก่อนหน้านี้ บันทึกการแก้ไขเทมเพลต เวอร์ชัน AZD สภาพแวดล้อมที่เลือก การปรับใช้โมเดล และคำถามตัวอย่างที่ทำงานได้ก่อนเปลี่ยนแปลงใด ๆ

ตัวอย่างนี้เป็นแอปพลิเคชันแชทที่สนับสนุนโดยเอเย่นต์ ซึ่ง **จะไม่** กลายเป็นระบบค้าปลีกที่มีสองเอเย่นต์เพียงแค่ตั้งค่าตัวแปรสภาพแวดล้อมหรือบันทึกไฟล์คำสั่งเพิ่มเติม เอเย่นต์เสริม ตัวจัดการเครื่องมือ การกำหนดเส้นทาง การอนุญาต และการเข้าถึงข้อมูลต้องใช้โค้ดแอปพลิเคชัน

ตรวจสอบคำสั่งและเครื่องมือของเอเย่นต์ที่ปรับใช้ปัจจุบันใน Foundry ทดสอบคำถามข้อเท็จจริงหนึ่งข้อ คำถามการดึงข้อมูลหนึ่งข้อ และคำถามที่ข้อมูลตัวอย่างไม่สามารถตอบได้ ตรวจสอบการอ้างอิงกับเอกสารต้นฉบับจริงแทนที่จะสมมติว่าคำตอบที่ลื่นไหลถูกต้อง

## 5.2 ปรับแต่งการดึงความรู้

เทมเพลตรองรับการดึงข้อมูลจากไฟล์และการผสานรวม Azure AI Search แบบไม่บังคับ ทำตาม [คำแนะนำ AI Search ปัจจุบัน](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/ai_search.md) สำหรับการสร้างดัชนีและกำหนดค่าเครื่องมือ

```bash
# Infrastructure settings; these can add charges
azd env set USE_AZURE_AI_SEARCH_SERVICE true
azd provision --preview
azd up
```

การเปิดใช้งานบริการเป็นเพียงแค่ส่วนหนึ่งของการดึงข้อมูล ก่อนที่จะอัปโหลดข้อมูลของคุณเอง:

1. ยืนยันว่าคุณได้รับอนุญาตให้ใช้เอกสารและลบข้อมูลที่ละเอียดอ่อนออก
2. เลือกโมเดลฝังตัวที่รองรับในภูมิภาคของคุณและตั้งค่ารุ่นที่เข้ากันได้ ประเภทการปรับใช้ และมิติเวกเตอร์
3. สร้าง/เติมดัชนีโดยใช้กระบวนการตามที่ระบุในตัวอย่าง
4. กำหนดค่าเครื่องมือดึงข้อมูลของเอเย่นต์เพื่อใช้ดัชนีนั้น
5. ทดสอบการดึง การอ้างอิง การอนุญาต และพฤติกรรมเมื่อไม่มีเอกสารที่เกี่ยวข้อง

อย่าสลับจาก `text-embedding-3-small` ไปเป็นโมเดลฝังตัวอื่นโดยไม่ตรวจสอบมิติและสร้าง/สร้างดัชนีเวกเตอร์ใหม่ตามความจำเป็น ชื่อเช่น `retail-products` ไม่ใช่แคตตาล็อกที่มีการใช้งานหรือเป็นนโยบายควบคุมการเข้าถึง

## 5.3 การติดตามและตรวจสอบ

ปฏิบัติตาม [คู่มือการตรวจสอบของตัวอย่าง](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#tracing-and-monitoring) ให้แน่ใจว่ามีทรัพยากร Application Insights ที่ต้องการและการเชื่อมต่อมีอยู่แล้ว; หากเปลี่ยนการตั้งค่าโครงสร้างพื้นฐาน ให้ใช้ `azd up`.

```bash
azd env set ENABLE_AZURE_MONITOR_TRACING true
azd up
```

ส่งคำขอทดสอบ จากนั้นตรวจสอบบันทึกแอปพลิเคชันของ Container App และมุมมองการติดตามของเอเจนต์ใน Foundry ตรวจสอบความล่าช้า การเรียกเครื่องมือ ข้อผิดพลาด และความสัมพันธ์ระหว่างคำขอและการติดตาม อย่าสันนิษฐานว่าการเทเลเมทรีเชื่อมต่อเพียงเพราะการปรับใช้งานสำเร็จ

ปล่อย `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` ไว้ในสถานะปิดใช้งาน เว้นแต่ว่าคุณได้ตรวจสอบความยินยอม การแก้ไข การเก็บรักษา และการควบคุมการเข้าถึงอย่างชัดเจนแล้ว ร่องรอยอาจมีอาร์กิวเมนต์เครื่องมือที่ละเอียดอ่อนหรือเนื้อหาเอกสารแม้ว่าบันทึกแอปพลิเคชันทั่วไปจะดูไม่มีอันตรายก็ตาม

## 5.4 การประเมินตัวแทน

จุดเริ่มต้นของการประเมินตัวอย่างตอนนี้คือ [`tests/test_evaluation.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_evaluation.py) ไม่ใช่ไดเรกทอรี `evals/` จากโฟลเดอร์รากตัวอย่าง ให้ใช้สภาพแวดล้อม Python ที่ตรงตามข้อกำหนดที่ระบุไว้:

```bash
python -m pip install -r src/requirements.txt
pytest tests/test_evaluation.py -s
```

ก่อนที่จะรัน ให้ทำ [ข้อกำหนดเบื้องต้นสำหรับการประเมิน](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md) ให้เสร็จสิ้น การทดสอบจะโหลดการตั้งค่าจาก `.azure/<environment>/.env` ที่เลือกไว้; ยืนยันว่าสภาพแวดล้อมที่ต้องการถูกเลือกแล้ว ข้อมูลที่สำคัญมีดังนี้:

- `AZURE_EXISTING_AIPROJECT_ENDPOINT`
- `AZURE_EXISTING_AGENT_ID`, โดยใช้รูปแบบที่ตัวอย่างปัจจุบันต้องการ (เวอร์ชันที่ตรวจทานใช้ `agent_name:agent_version`)
- `AZURE_AI_AGENT_DEPLOYMENT_NAME`, ใช้เป็นการปรับใช้โมเดลผู้ตัดสิน

ตรวจสอบการทดสอบเพื่อตีความการเลือกผู้ประเมิน ค่าเกณฑ์ บทบาทที่จำเป็น และต้นทุนของโมเดล การรันที่สมบูรณ์ไม่ใช่การผ่านประตูคุณภาพโดยอัตโนมัติ; ตรวจสอบคะแนน กรณีที่ล้มเหลว/เกิดข้อผิดพลาด และผลลัพธ์ Foundry ที่ลิงก์ไว้

### ส่วนขยายการประเมิน AZD แยกต่างหาก

การทดสอบ Python ข้างต้นเป็น **เวิร์กโฟลว์เฉพาะตัวอย่าง** ส่วนขยาย `azure.ai.evaluations` ที่เป็นทางเลือกเป็นเวิร์กโฟลว์ที่แตกต่างกัน โดยมีการกำหนดค่า `evals/azure.eval.yaml` ของตัวเอง มันติดตั้งแยกต่างหาก ไม่ได้รวมอยู่ในชุด `microsoft.foundry` 1.0 ที่มีให้ใช้งานทั่วไป:

```bash
azd extension install azure.ai.evaluations
azd ai eval --help
```

สำหรับการตั้งค่าส่วนขยายที่สมบูรณ์ ดูที่ [evaluation workflows and migration](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-08-production/production-ai-practices.md) ตั้งแต่เบต้า 22 ของส่วนขยาย agents อย่าใช้คำสั่ง `azd ai agent eval` ที่ถูกลบไปแล้ว การติดตั้งส่วนขยาย evaluations จะไม่แปลงการทดสอบ Python ของตัวอย่างหรือสร้างการกำหนดค่าการประเมินโดยอัตโนมัติ

สำหรับ **แบบฝึกหัดโฮสต์ agent GA แยกต่างหาก** ให้ใช้โฟลเดอร์ว่างนอกตัวอย่างในเวิร์กช็อปนี้และปฏิบัติตาม [Foundry local-to-cloud walkthrough](https://github.com/microsoft/AZD-for-beginners/blob/main/docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) ซึ่งใช้ AZD 1.37.0+, ชุด `microsoft.foundry`, Python 3.13+ และ uv ปัจจุบัน คุณจะตรวจสอบ `azure.yaml` ทดสอบในเครื่องด้วย Agent Inspector ปล่อยซอร์สสำหรับการสร้าง Foundry ระยะไกล และสร้าง/ตรวจทานชุดข้อมูลและรูบริกก่อนกำหนดค่า `azd ai eval init --name quality` อย่าแทนที่การทดสอบของตัวอย่างนี้หรือสมมติว่าการติดตั้งชุดนี้เปลี่ยนแปลงโมเดลการโฮสต์

## 5.5 การทดสอบด้านความปลอดภัย AI แบบ red teaming และการประเมินอย่างต่อเนื่อง

ตัวอย่างปัจจุบันมี [`tests/test_red_teaming.py`](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/tests/test_red_teaming.py) ให้ใช้งาน จัดเตรียมข้อกำหนดเบื้องต้นให้ครบถ้วนและตรวจทานเป้าหมายและค่าใช้จ่ายที่ตั้งไว้ก่อนดำเนินการ:

```bash
pytest tests/test_red_teaming.py -s
```

ใช้งานการปล่อยทดสอบที่ได้รับอนุญาตและข้อมูลสังเคราะห์ ตรวจทานการโจมตีและผลลัพธ์ที่สร้างขึ้น สแกนนี้ไม่ได้ยืนยันว่าแอปพลิเคชันมีความปลอดภัยหรือเป็นไปตามข้อกำหนด

คู่มือ [observability guide](https://github.com/Azure-Samples/get-started-with-ai-agents/blob/main/docs/observability.md#continuous-evaluation) ยังอธิบายถึงการประเมินผลอย่างต่อเนื่องที่ตั้งค่าที่การเริ่มต้นคอนเทนเนอร์ ซึ่งจะประเมินปฏิสัมพันธ์ของผู้ใช้จริง ไม่ใช่การจราจรทดสอบที่ถูกสร้างขึ้น และการสนับสนุนของ evaluator จะแตกต่างกันไปตามแต่ละภูมิภาค หากไม่มีปฏิสัมพันธ์ก็จะไม่มีบันทึกการประเมิน ตรวจสอบเวอร์ชันตัวอย่างที่ติดตั้งและการกำหนดค่า evaluator แทนการสันนิษฐานว่าการปรับใช้แต่ละครั้งจะมีค่าเริ่มต้นเหมือนกันทั้งหมด

การตรวจสอบสิทธิ์แยกต่างหากจากการประเมินผลองค์ประกอบ ให้ทำตามการตั้งค่าบัญชีผู้ใช้/การเข้าถึงที่ได้ถูกบันทึกไว้ในตัวอย่าง ไม่มีการบันทึก “basic auth fallback” เพื่อใช้ในการปกป้องจุดปลายสาธารณะ

## 5.6 แบบฝึกหัดการออกแบบ: การปรับแต่งขายปลีก

!!! warning "แบบฝึกหัดการออกแบบ ไม่ใช่การปรับใช้งานที่เสร็จสมบูรณ์"

    The workshop does not provide a complete Shopper/Loyalty multi-agent implementation. Do not claim that additional agents, models, catalogs, or policies exist until you have implemented and verified them.

เขียนแผนสั้น ๆ ที่ครอบคลุมถึง:

| พื้นที่ | การตัดสินใจและหลักฐานที่ต้องรวบรวม |
|------|----------------------------------|
| ความรับผิดชอบของตัวแทน | เริ่มต้นด้วยตัวแทนหนึ่งคน หรืออธิบายเหตุผลสำหรับตัวแทน Shopper และ Loyalty แยกกันพร้อมกับตรรกะการกำหนดเส้นทาง |
| ข้อมูล | กำหนดชุดข้อมูลแค็ตตาล็อก/รางวัลสังเคราะห์และการเป็นเจ้าของการอัปเดต |
| เครื่องมือ | ดำเนินการตัวจัดการแบบอ่านอย่างเดียวก่อน; ระบุการอนุญาตและการตรวจสอบความถูกต้องสำหรับการเขียนใดๆ |
| แบบจำลอง | เลือกแบบจำลอง/เวอร์ชัน/SKU ที่มีอยู่และตรวจสอบโควต้า; หลีกเลี่ยงการจัดเตรียมแบบจำลองที่ไม่ได้ใช้ |
| การเรียกคืน | กำหนดการจัดทำดัชนี, มิติของการฝัง, การอ้างอิง และการควบคุมการเข้าถึงระดับเอกสาร |
| การประเมินผล | เพิ่มกรณีคำตอบที่คาดไว้, คำถามที่ไม่รองรับ, การใช้เครื่องมือ และความปลอดภัย พร้อมเกณฑ์ระดับชัดเจน |
| การปฏิบัติการ | กำหนดการใช้เทเลเมทรี, งบประมาณความล่าช้า/ข้อผิดพลาด, ขีดจำกัดค่าใช้จ่าย และการเป็นเจ้าของการล้างข้อมูล |

การบันทึก `custom-agents/shopper-agent-instructions.md` จะไม่ทำให้ตัวอย่างโหลดข้อมูลดังกล่าว ค้นหาโค้ดแอปพลิเคชันที่สร้าง/อัปเดตตัวแทน เชื่อมต่อคำแนะนำที่คุณตรวจสอบแล้วที่นั่น และยืนยันเวอร์ชันตัวแทนที่ได้ก่อนทดสอบ คำแนะนำไม่สามารถให้สิทธิ์เข้าถึงข้อมูลหรือเครื่องมือที่คุณยังไม่ได้ดำเนินการ

ใช้การเปลี่ยนแปลงทีละอย่าง ทำการปรับใช้ส่วนประกอบที่ได้รับผลกระทบใหม่ และเรียกใช้คำถามและการประเมินผลพื้นฐานของคุณอีกครั้ง เก็บรุ่นทำงานไว้สำหรับการเปรียบเทียบ สำหรับแรงบันดาลใจด้านสถาปัตยกรรม ให้ดูที่ [retail blueprint](https://github.com/microsoft/AZD-for-beginners/blob/main/examples/retail-scenario.md) ซึ่งก็ไม่ใช่แอปพลิเคชันค้าปลีกที่สมบูรณ์เช่นกัน

!!! quote "เมื่อจบแลปนี้คุณควรจะมี"

    - [ ] A documented customization scope and cost/region checks
    - [ ] Evidence that retrieval and tracing work for your selected environment
    - [ ] Reviewed evaluation/red-teaming results, or a clear explanation of unmet prerequisites
    - [ ] A list of missing implementation work rather than a claim of automatic production readiness

ดำเนินการต่อไปยัง [รื้อถอนโครงสร้างพื้นฐาน](6-Teardown-Infrastructure.md).
