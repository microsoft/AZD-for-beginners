# การมีส่วนร่วมใน AZD สำหรับผู้เริ่มต้น

ขอบคุณสำหรับความสนใจในการมีส่วนร่วมในหลักสูตร AZD สำหรับผู้เริ่มต้น! เอกสารนี้ให้แนวทางและข้อมูลสำหรับผู้มีส่วนร่วม

## วิธีการมีส่วนร่วม

### การรายงานปัญหา

หากคุณพบข้อบกพร่อง ข้อผิดพลาด หรือมีข้อเสนอแนะสำหรับการปรับปรุง:

1. **ตรวจสอบปัญหาที่มีอยู่**: ค้นหา [ปัญหาที่มีอยู่](https://github.com/microsoft/azd-for-beginners/issues) เพื่อลดการซ้ำซ้อน
2. **สร้างปัญหาใหม่**: ใช้เทมเพลตปัญหาที่เหมาะสม
3. **ให้รายละเอียด**: รวมขั้นตอนการทำซ้ำ พฤติกรรมที่คาดหวัง และภาพหน้าจอถ้ามี

### การเสนอการเปลี่ยนแปลง

1. **โฟร์กที่เก็บข้อมูล**: สร้างโฟร์กของโปรเจกต์นี้ในบัญชีของคุณ
2. **สร้างสาขา**: สร้างสาขาคุณลักษณะสำหรับการเปลี่ยนแปลงของคุณ
3. **ทำการเปลี่ยนแปลง**: ปฏิบัติตามมาตรฐานการเขียนโค้ดและเอกสารของเรา
4. **ทดสอบการเปลี่ยนแปลงของคุณ**: ตรวจสอบให้แน่ใจว่าลิงก์ทั้งหมดใช้งานได้และเนื้อหาถูกแสดงถูกต้อง
5. **ส่งคำขอดึง (Pull Request)**: ให้คำอธิบายที่ชัดเจนของการเปลี่ยนแปลงของคุณ

### ประเภทของการมีส่วนร่วม

เรายินดีต้อนรับประเภทของการมีส่วนร่วมดังต่อไปนี้:

#### การปรับปรุงเนื้อหา
- แก้ไขการพิมพ์ ไวยากรณ์ และปัญหาการจัดรูปแบบ
- ปรับปรุงความชัดเจนของเอกสารที่มีอยู่
- อัพเดตข้อมูลที่ล้าสมัย
- เพิ่มคำอธิบายหรือบริบทที่ขาดหายไป

#### ตัวอย่างใหม่
- เพิ่มสถานการณ์การใช้งานจริงของการปรับใช้
- สร้างเทมเพลต AZD ใหม่สำหรับกรณีใช้งานทั่วไป
- จัดเตรียมตัวอย่างโค้ดและแบบฝึกหัดเพิ่มเติม

#### การสนับสนุนการแปล
- ช่วยดูแลการแปลที่มีอยู่
- ปรับปรุงคุณภาพการแปล
- เพิ่มการแปลสำหรับเนื้อหาใหม่

#### รายงานข้อบกพร่อง
- รายงานลิงก์เสียหายหรือตัวอย่างโค้ดที่ไม่ถูกต้อง
- ระบุความไม่สอดคล้องของเอกสาร
- แจ้งปัญหาการเข้าถึง

## แนวทางการมีส่วนร่วม

### มาตรฐานเอกสาร

- ใช้ภาษาที่ชัดเจนและเหมาะสำหรับผู้เริ่มต้น
- รวมวัตถุประสงค์การเรียนรู้และผลลัพธ์
- ให้คำแนะนำทีละขั้นตอนพร้อมผลลัพธ์ที่คาดหวัง
- เพิ่มลิงก์นำทางไปยังเนื้อหาที่เกี่ยวข้อง
- ใช้รูปแบบและสไตล์มาร์กดาวน์ที่สม่ำเสมอ

### ตัวอย่างโค้ด

- ตรวจสอบให้แน่ใจว่าตัวอย่างโค้ดทั้งหมดถูกทดสอบและใช้งานได้
- รวมความคิดเห็นอธิบายแนวคิดสำคัญ
- ปฏิบัติตามแนวทางปฏิบัติที่ดีที่สุดของ Azure และ AZD
- ให้ผลลัพธ์ที่คาดหวังเมื่อเหมาะสม

### ตรวจสอบเอกสารภาษาอังกฤษ

จากโฟลเดอร์รากของที่เก็บข้อมูล ติดตั้งความต้องการด้านการพัฒนาและรัน:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

ตัวตรวจสอบลิงก์ออฟไลน์ตรวจสอบเส้นทาง Markdown/HTML ภาษาอังกฤษ หัวเรื่อง จุดยึดชัดเจน และช่องว่างลิงก์ที่ว่างเปล่า โดยไม่รวม `translations/` และ `translated_images/` ที่สร้างขึ้น รวมถึงลิงก์ไปยังไดเรกทอรีเหล่านั้น มันไม่ดึงข้อมูลเว็บไซต์ภายนอกหรือยืนยันการปรับใช้ Azure ใช้ `--json <report-path>` เพื่อส่งออกความล้มเหลวและรายการ URL ภายนอกสำหรับการตรวจสอบเครือข่ายแยกต่างหาก ตรวจสอบคำสั่งต้นทางปัจจุบันและข้อกำหนดตัวอย่างเมื่อเปลี่ยนแปลงคำแนะนำทางเทคนิค; แยกแยะแอปพลิเคชันทดสอบจากต้นแบบการออกแบบ
