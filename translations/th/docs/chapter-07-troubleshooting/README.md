## ภาพรวม

บทนี้ช่วยให้คุณวินิจฉัยและแก้ไขปัญหาที่พบบ่อยเมื่อต้องทำงานกับ Azure Developer CLI ตั้งแต่ความล้มเหลวในการปรับใช้งานไปจนถึงปัญหาเฉพาะของ AI

> คำแนะนำคำสั่งได้รับการตรวจสอบกับเอกสารอ้างอิง `azd 1.37.2` ที่เผยแพร่แล้ว ยังไม่มีการดำเนินการปรับใช้บนคลาวด์ กรุณาแทนที่ชื่อตัวอย่างของทรัพยากรและ ID ก่อนใช้คำสั่ง

## วัตถุประสงค์การเรียนรู้

เมื่อเรียนจบบทนี้คุณจะสามารถ:
- วินิจฉัยความล้มเหลวในการปรับใช้ AZD ที่พบบ่อย
- ดีบักปัญหาการตรวจสอบสิทธิ์และสิทธิ์การใช้งาน
- แก้ไขปัญหาการเชื่อมต่อบริการ AI
- ใช้ Azure Portal และ CLI ในการแก้ไขปัญหา

## 🚨 การแก้ไขด่วน

### ปัญหาการตรวจสอบสิทธิ์
```bash
# Required for AZD workflows
azd auth login

# Optional if you are also using Azure CLI commands directly
az login

azd auth login --check-status
```

### ความล้มเหลวในการจัดเตรียม
```bash
azd show
azd monitor --logs
az deployment sub list --query "[?properties.provisioningState!='Succeeded']"
```

### ความขัดแย้งของทรัพยากร
ตรวจสอบทรัพยากรที่มีอยู่และข้อผิดพลาดในการปรับใช้ก่อน ห้ามลบสภาพแวดล้อมที่ใช้ร่วมกันหรือสำหรับการผลิตเพื่อแก้ไขความขัดแย้งชื่อ สำหรับ **สภาพแวดล้อมที่ใช้แล้วทิ้งใหม่** ให้ใช้ชื่อที่ไม่ซ้ำกัน:

```bash
azd env new different-name
azd up
```

### โควต้าเกิน
```bash
az vm list-usage --location eastus --output table
# Check the affected service's own quotas, not just VM quotas.
# For a new environment only, choose a supported region with available quota.
```

การเปลี่ยน `AZURE_LOCATION` จะไม่ย้ายทรัพยากรที่มีอยู่และอาจทำให้เกิดความขัดแย้งในตำแหน่งที่ตั้งในการปรับใช้ใหม่

## 📋 อ้างอิงรหัสข้อผิดพลาด

| ข้อผิดพลาด | สาเหตุ | วิธีแก้ไข |
|-------|-------|----------|
| `AuthenticationError` | ยังไม่เข้าสู่ระบบ | `azd auth login` |
| `ResourceNotFound` | ไม่พบทรัพยากร | ตรวจสอบชื่อทรัพยากร |
| `QuotaExceeded` | ขีดจำกัดการสมัครสมาชิก | ขอเพิ่มโควต้า |
| `InvalidTemplate` | ข้อผิดพลาดไวยากรณ์ Bicep | `az bicep build` |
| `Conflict` | มีทรัพยากรอยู่แล้ว | ใช้ชื่อใหม่หรือลบออก |
| `Forbidden` | สิทธิ์ไม่เพียงพอ | ตรวจสอบบทบาท RBAC |

## 🔄 การรีเซ็ตและกู้คืน

```bash
# Soft reset (keep resources, redeploy code)
azd deploy

# Hard reset (delete everything, start fresh)
azd down
azd up
```

การรีเซ็ตอย่างหนักจะลบข้อมูลและอาจเปลี่ยนจุดเชื่อมต่อ สำรองข้อมูลก่อนและทบทวนคำเตือนการลบแบบโต้ตอบ `--force --purge` เหมาะสมเฉพาะสำหรับสภาพแวดล้อมแบบใช้แล้วทิ้งเมื่อมีเจตนาลบถาวร
