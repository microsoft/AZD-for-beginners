## บทนำ

FAQ ฉบับสมบูรณ์นี้ให้คำตอบสำหรับคำถามที่พบบ่อยที่สุดเกี่ยวกับ Azure Developer CLI (azd) และการปรับใช้ Azure ค้นหาวิธีแก้ไขปัญหาอย่างรวดเร็วสำหรับปัญหาทั่วไป เข้าใจแนวทางปฏิบัติที่ดีที่สุด และรับคำชี้แจงเกี่ยวกับแนวคิดและเวิร์กโฟลว์ของ azd

## เป้าหมายการเรียนรู้

โดยการทบทวน FAQ นี้ คุณจะ:
- ค้นหาคำตอบอย่างรวดเร็วสำหรับคำถามและปัญหาทั่วไปเกี่ยวกับ Azure Developer CLI
- เข้าใจแนวคิดหลักและคำศัพท์ผ่านรูปแบบถาม-ตอบที่ปฏิบัติได้จริง
- เข้าถึงวิธีแก้ไขปัญหาเกี่ยวกับปัญหาและสถานการณ์ข้อผิดพลาดที่พบบ่อย
- เรียนรู้แนวทางปฏิบัติที่ดีที่สุดผ่านคำถามที่พบบ่อยเกี่ยวกับการปรับแต่งประสิทธิภาพ
- ค้นพบฟีเจอร์และความสามารถขั้นสูงผ่านคำถามระดับผู้เชี่ยวชาญ
- อ้างอิงคำแนะนำด้านค่าใช้จ่าย ความปลอดภัย และกลยุทธ์การปรับใช้อย่างมีประสิทธิภาพ

## ผลลัพธ์การเรียนรู้

ด้วยการอ้างอิง FAQ นี้อย่างสม่ำเสมอ คุณจะสามารถ:
- แก้ไขปัญหา Azure Developer CLI ทั่วไปด้วยตนเองโดยใช้วิธีแก้ไขที่มีให้
- ตัดสินใจอย่างมีข้อมูลเกี่ยวกับกลยุทธ์และการกำหนดค่าการปรับใช้
- เข้าใจความสัมพันธ์ระหว่าง azd กับเครื่องมือและบริการ Azure อื่น ๆ
- ใช้แนวทางปฏิบัติที่ดีที่สุดตามประสบการณ์ของชุมชนและคำแนะนำของผู้เชี่ยวชาญ
- แก้ไขปัญหาการตรวจสอบสิทธิ์ การปรับใช้ และการกำหนดค่าอย่างมีประสิทธิภาพ
- ปรับค่าใช้จ่ายและประสิทธิภาพโดยใช้ข้อมูลเชิงลึกและคำแนะนำจาก FAQ

## เริ่มต้นใช้งาน

### Q: Azure Developer CLI (azd) คืออะไร?
**A**: Azure Developer CLI (azd) เป็นเครื่องมือบรรทัดคำสั่งที่มุ่งเน้นนักพัฒนา ที่ช่วยเร่งเวลาที่คุณใช้ในการย้ายแอปพลิเคชันจากสภาพแวดล้อมการพัฒนาในเครื่องไปยัง Azure มันให้แนวทางปฏิบัติที่ดีที่สุดผ่านเทมเพลตและช่วยจัดการวงจรการปรับใช้ทั้งหมด

### Q: azd แตกต่างจาก Azure CLI อย่างไร?
**A**: 
- **Azure CLI**: เครื่องมือทั่วไปสำหรับการจัดการทรัพยากร Azure
- **azd**: เครื่องมือที่มุ่งเน้นนักพัฒนาเพื่อเวิร์กโฟลว์การปรับใช้แอปพลิเคชัน
- azd มีเวิร์กโฟลว์การตรวจสอบสิทธิ์และการปรับใช้ของตัวเอง; Azure CLI เป็นเครื่องมือแยกต่างหากที่เสริมกัน
- azd รวมเทมเพลต การจัดการสภาพแวดล้อม และการอัตโนมัติการปรับใช้

### Q: ฉันจำเป็นต้องติดตั้ง Azure CLI เพื่อใช้ azd หรือไม่?
**A**: ไม่จำเป็นสำหรับเวิร์กโฟลว์หลักของ AZD ให้ตรวจสอบสิทธิ์ด้วย `azd auth login` ติดตั้ง Azure CLI แยกต่างหากเมื่อตัวเทมเพลตหรือแบบฝึกหัดใช้คำสั่ง `az` อย่างชัดเจน

### Q: azd รองรับภาษาโปรแกรมอะไรบ้าง?
**A**: azd รองรับทุกภาษา มันทำงานกับ:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- เว็บไซต์แบบสแตติก
- แอปพลิเคชันที่ใช้คอนเทนเนอร์

### Q: ฉันสามารถใช้ azd กับโปรเจกต์ที่มีอยู่แล้วได้ไหม?
**A**: ได้! คุณสามารถ:
1. ใช้ `azd init` เพื่อเพิ่มการกำหนดค่า azd ในโปรเจกต์ที่มีอยู่
2. ปรับโปรเจกต์ที่มีอยู่ให้ตรงกับโครงสร้างเทมเพลตของ azd
3. สร้างเทมเพลตที่กำหนดเองตามสถาปัตยกรรมที่มีของคุณ

### Q: มีอะไรเปลี่ยนแปลงกับการเปิดตัวทั่วไปของส่วนขยาย Foundry บ้าง?
**A**: ชุด `microsoft.foundry` ถึงเวอร์ชัน 1.0 และเปิดตัวทั่วไปเมื่อวันที่ 5 พฤศจิกายน 2026 โดยใช้ AZD 1.37.0+ ใช้ `azd ext install microsoft.foundry` เพื่อติดตั้งส่วนขยายหลักเจ็ดตัวสำหรับเอเจนต์ การเชื่อมต่อ ผู้ตรวจสอบ โปรเจกต์ รูทีน สกิล และกล่องเครื่องมือ มันไม่ใช่พื้นที่ชื่อคำสั่งใหม่ และส่วนประกอบของมันเวอร์ชันอิสระ การประเมิน ชุดข้อมูล การปรับแต่ง และโมเดลที่กำหนดเองติดตั้งแยกต่างหาก; ฟีเจอร์ตัวอย่างเสริมไม่กลายเป็นการเปิดตัวทั่วไปเพียงเพราะชุดนั้นเปิดตัวทั่วไป

การ [hosted-agent walkthrough](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) ใช้ Python 3.13+ และ uv เวอร์ชันปัจจุบัน `azd ai agent run` เปิด Agent Inspector ในเครื่อง แต่การเรียกใช้งานโมเดลยังคงใช้ Azure และมีค่าใช้จ่าย โหมดโค้ด `azd deploy` อัปโหลดซอร์สสำหรับการสร้างระยะไกลโดยไม่ต้องสร้างคอนเทนเนอร์ในเครื่อง

### Q: `azd down` จะลบ hosted agent ออกจากโครงการ Foundry ที่มีอยู่หรือไม่?
**A**: ไม่ใช่ สำหรับเส้นทางโครงการที่ใช้ซ้ำตามที่อธิบายไว้ใน hosted-agent quickstart: มันจะปล่อยให้โครงการ hosted agent และทรัพยากรอื่น ๆ อยู่ในที่เดิม ลบทรัพยากรที่ไม่ต้องการแยกกันโดยไม่ลบทรัพยากรที่ใช้ร่วมกัน หากสภาพแวดล้อมสร้างโครงการ Foundry ใหม่ `azd down` จะลบกลุ่มทรัพยากรและทุกอย่างในนั้น ตรวจสอบ [คำแนะนำการทำความสะอาด](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#7-clean-up-deliberately) และการยืนยันการลบก่อนกดยืนยัน

## การรับรองความถูกต้องและการเข้าถึง

### Q: ฉันจะรับรองตัวตนกับ Azure โดยใช้ azd ได้อย่างไร?
**A**: ใช้ `azd auth login` ซึ่งจะเปิดหน้าต่างเบราว์เซอร์สำหรับการรับรองความถูกต้องกับ Azure สำหรับสถานการณ์ CI/CD ให้ใช้ service principals หรือ managed identities

### Q: ฉันสามารถใช้ azd กับหลายการสมัครสมาชิก Azure ได้หรือไม่?
**A**: ได้ ใช้ `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` เพื่อระบุการสมัครสมาชิกที่จะใช้สำหรับแต่ละสภาพแวดล้อม

### Q: ฉันต้องการสิทธิ์อะไรบ้างเพื่อการปรับใช้ด้วย azd?
**A**: โดยทั่วไปคุณต้องการ:
- บทบาท **Contributor** บนกลุ่มทรัพยากรหรือการสมัครสมาชิก
- บทบาท **User Access Administrator** หากปรับใช้ทรัพยากรที่ต้องกำหนดบทบาท
- สิทธิ์เฉพาะจะแตกต่างกันไปตามเทมเพลตและทรัพยากรที่ปรับใช้

### Q: ฉันสามารถใช้ azd ใน pipeline CI/CD ได้หรือไม่?
**A**: แน่นอน! azd ออกแบบมาเพื่อการผนวกรวม CI/CD ใช้ service principals สำหรับการรับรองตัวตนและตั้งค่าตัวแปรสภาพแวดล้อมสำหรับการกำหนดค่า

### Q: ฉันจะจัดการการรับรองตัวตนใน GitHub Actions อย่างไร?
**A**: แนะนำให้ใช้ workload identity federation (OIDC) ซึ่งตั้งค่าด้วย `azd pipeline config` workflow ที่สร้างจะติดตั้ง AZD และรับรองตัวตน AZD โดยตรงด้วยตัวตนแบบ federated การใช้ `azure/login` ขั้นตอนอย่างเดียวไม่สร้างการเข้าสู่ระบบ AZD ขั้นตอนการเข้าสู่ระบบภายในงานที่มีอยู่คือ:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

ปรับใช้หรือ provision หลังเข้าสู่ระบบ ด้วยสภาพแวดล้อม AZD การสมัครสมาชิก และตำแหน่งที่ตั้งที่ต้องการ การรับรองตัวตน federated ต้องเชื่อถือ repository/ref หรือสภาพแวดล้อม GitHub ของ workflow และบทบาท Azure ต้องอนุญาตให้ทำงานตามคำขอ

## เทมเพลตและโครงการ

### Q: ฉันหาทีมเพลต azd ที่ไหนได้บ้าง?
**A**: 
- เทมเพลตอย่างเป็นทางการและจากชุมชน: [Awesome AZD](https://azure.github.io/awesome-azd/)
- เทมเพลตชุมชน: ค้นหาใน GitHub ด้วยคำว่า "azd-template"
- ใช้ `azd template list` เพื่อเรียกดูเทมเพลตที่มีอยู่

### Q: ฉันจะสร้างเทมเพลตที่กำหนดเองได้อย่างไร?
**A**: 
1. เริ่มต้นด้วยโครงสร้างเทมเพลตที่มีอยู่
2. แก้ไข `azure.yaml`, ไฟล์โครงสร้างพื้นฐาน และโค้ดแอปพลิเคชัน
3. ทดสอบอย่างละเอียดด้วย `azd up`
4. เผยแพร่บน GitHub พร้อมแท็กที่เหมาะสม

### Q: ฉันสามารถใช้ azd โดยไม่ใช้เทมเพลตได้ไหม?
**A**: ได้ ใช้ `azd init` ในโครงการที่มีอยู่เพื่อสร้างไฟล์กำหนดค่าจำเป็น คุณต้องกำหนดค่า `azure.yaml` และไฟล์โครงสร้างพื้นฐานด้วยตนเอง

### Q: ความแตกต่างระหว่างเทมเพลตอย่างเป็นทางการกับเทมเพลตชุมชนคืออะไร?
**A**: 
- **เทมเพลตอย่างเป็นทางการ**: ดูแลโดย Microsoft อัปเดตเป็นประจำ พร้อมเอกสารครบถ้วน
- **เทมเพลตชุมชน**: สร้างโดยนักพัฒนา อาจมีกรณีการใช้งานเฉพาะคุณภาพและการดูแลแตกต่างกันไป

### Q: ฉันจะอัปเดตเทมเพลตในโครงการของฉันได้อย่างไร?
**A**: เทมเพลตจะไม่อัปเดตโดยอัตโนมัติ คุณสามารถ:
1. เปรียบเทียบและผสานการเปลี่ยนแปลงจากเทมเพลตต้นทางด้วยตนเอง
2. เริ่มใหม่ด้วย `azd init` โดยใช้เทมเพลตที่อัปเดต
3. เลือกดึงการปรับปรุงเฉพาะจากเทมเพลตที่อัปเดต

## การปรับใช้และโครงสร้างพื้นฐาน

### Q: บริการ Azure ใดบ้างที่ azd สามารถปรับใช้ได้?
**A**: azd สามารถปรับใช้บริการ Azure ใดก็ได้ผ่านเทมเพลต Bicep/ARM รวมถึง:
- App Services, Container Apps, Functions
- ฐานข้อมูล (SQL, PostgreSQL, Cosmos DB)
- Storage, Key Vault, Application Insights
- ทรัพยากรเครือข่าย ความปลอดภัย และการตรวจสอบ

### Q: ฉันสามารถปรับใช้ไปยังหลายภูมิภาคได้หรือไม่?
**A**: ได้ กำหนดค่าหลายภูมิภาคในเทมเพลต Bicep ของคุณและตั้งค่าพารามิเตอร์ location ให้เหมาะสมกับแต่ละสภาพแวดล้อม

### Q: ฉันจะจัดการการโยกย้ายโครงสร้างฐานข้อมูลอย่างไร?
**A**: ใช้ deployment hooks ใน `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### Q: ฉันสามารถปรับใช้เฉพาะโครงสร้างพื้นฐานโดยไม่รวมแอปพลิเคชันได้ไหม?
**A**: ได้ ใช้ `azd provision` เพื่อปรับใช้เฉพาะส่วนประกอบโครงสร้างพื้นฐานที่กำหนดไว้ในเทมเพลตของคุณ

### Q: ฉันจะปรับใช้ไปยังทรัพยากร Azure ที่มีอยู่แล้วได้อย่างไร?
**A**: ได้ เมื่อเทมเพลตรองรับ อ้างอิงทรัพยากรที่มีอยู่ด้วยการประกาศ `existing` ของ Bicep หรือพารามิเตอร์ existing-resource ที่ระบุในเทมเพลตและแมปบริการแอปพลิเคชันไปยังเป้าหมายที่ตั้งใจไว้ นี่ไม่ได้เป็นการนำความเป็นเจ้าของเข้ามาหรือสร้างสิทธิ์ที่ขาดหายโดยอัตโนมัติ ควรตรวจสอบเทมเพลตก่อนปรับใช้

### Q: ฉันสามารถใช้ Terraform แทน Bicep ได้ไหม?
**A**: ใช่ AZD รองรับ Terraform รวมถึง Bicep ด้วย เลือกเทมเพลตที่ใช้ Terraform หรือกำหนดค่า `infra.provider: terraform` ใน `azure.yaml` โดยใช้ไฟล์ Terraform และการกำหนดค่า state/backend ที่เหมาะสม ดูที่ [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## การกำหนดค่า & สิ่งแวดล้อม

### ถาม: ฉันจะจัดการกับสภาพแวดล้อมที่แตกต่างกัน (dev, staging, prod) อย่างไร?
**ตอบ**: สร้างสภาพแวดล้อมแยกต่างหากด้วย `azd env new <environment-name>` และกำหนดค่าการตั้งค่าที่แตกต่างกันสำหรับแต่ละสภาพแวดล้อม:
```bash
azd env new development
azd env new staging  
azd env new production
```

### ถาม: การตั้งค่าสภาพแวดล้อมถูกเก็บไว้ที่ไหน?
**ตอบ**: ในโฟลเดอร์ `.azure` ภายในไดเรกทอรีโปรเจกต์ของคุณ สภาพแวดล้อมแต่ละตัวจะมีโฟลเดอร์ของตัวเองพร้อมกับไฟล์การตั้งค่า

### Q: ฉันจะตั้งค่าการกำหนดค่าเฉพาะสภาพแวดล้อมอย่างไร?
**A**: ใช้ `azd env set` เพื่อกำหนดค่าตัวแปรสภาพแวดล้อม:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### Q: ฉันสามารถแชร์การกำหนดค่าสภาพแวดล้อมข้ามสมาชิกในทีมได้ไหม?
**A**: โฟลเดอร์ `.azure` มีข้อมูลที่ละเอียดอ่อนและไม่ควรถูกคอมมิตสู่ระบบควบคุมเวอร์ชัน แต่ควร:
1. บันทึกตัวแปรสภาพแวดล้อมที่จำเป็น
2. ใช้สคริปต์การปรับใช้เพื่อตั้งค่าสภาพแวดล้อม
3. ใช้ Azure Key Vault สำหรับการกำหนดค่าที่ละเอียดอ่อน

### Q: ฉันจะ override ค่าเริ่มต้นของเทมเพลตได้อย่างไร?
**A**: ตั้งค่าตัวแปรสภาพแวดล้อมที่สอดคล้องกับพารามิเตอร์ของเทมเพลต:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

ตัวแปรที่ถูกใช้โดยเทมเพลตเท่านั้นที่จะส่งผลต่อการปรับใช้ `SKU_NAME` ข้างต้นเป็นตัวอย่างอินพุตที่กำหนดเอง ไม่ใช่การตั้งค่า AZD ทั่วไป

## การแก้ไขปัญหา

### Q: ทำไม `azd up` ถึงล้มเหลว?
**A**: สาเหตุที่พบบ่อย:
1. **ปัญหาการยืนยันตัวตน**: รัน `azd auth login`
2. **สิทธิ์ไม่เพียงพอ**: ตรวจสอบการกำหนดบทบาท Azure ของคุณ
3. **ปัญหาการตั้งชื่อทรัพยากรชนกัน**: ตรวจสอบทรัพยากรที่ขัดแย้งและอินพุตการตั้งชื่อในเทมเพลต; สร้างสภาพแวดล้อมแยกต่างหากด้วย `azd env new` เมื่อจำเป็นต้องแยกออก
4. **ปัญหาควบคุมโควต้า/ความจุ**: ตรวจสอบความพร้อมใช้งานในภูมิภาค
5. **ข้อผิดพลาดของเทมเพลต**: ตรวจสอบความถูกต้องของเทมเพลต Bicep

### Q: ฉันจะแก้ไขข้อผิดพลาดการปรับใช้อย่างไร?
**ตอบ**:
1. ใช้ `azd deploy --debug` สำหรับผลลัพธ์แบบละเอียด
2. ตรวจสอบประวัติการปรับใช้ในพอร์ทัล Azure
3. ตรวจสอบบันทึกกิจกรรมในพอร์ทัล Azure
4. ใช้ `azd show` เพื่อแสดงสถานะสภาพแวดล้อมปัจจุบัน

### Q: ทำไมตัวแปรสภาพแวดล้อมของฉันถึงไม่ทำงาน?
**ตอบ**: ตรวจสอบ:
1. ชื่อตัวแปรตรงกับพารามิเตอร์ในเทมเพลตอย่างแม่นยำ
2. ค่าถูกใส่เครื่องหมายคำพูดอย่างถูกต้องหากมีช่องว่าง
3. เลือกสภาพแวดล้อมแล้ว: `azd env select <environment>`
4. ตั้งค่าตัวแปรในสภาพแวดล้อมที่ถูกต้อง

### Q: ฉันจะล้างข้อมูลการปรับใช้ที่ล้มเหลวได้อย่างไร?
**ตอบ**:
```bash
azd down
```
ตรวจสอบสภาพแวดล้อมที่เลือกและยืนยันการลบก่อน นี่จะลบทรัพยากร Azure ที่จัดเตรียมไว้ ไม่ใช่การกำหนดค่าสภาพแวดล้อม `.azure` ในเครื่อง `--purge` ยังร้องขอลบถาวรทรัพยากรที่ลบแบบนุ่มนวลที่รองรับและอาจถูกบล็อกโดยการเก็บรักษา/ป้องกันการล้างข้อมูล; ซึ่งไม่ใช่ขั้นตอนการกู้คืนปกติ

### Q: ทำไมแอปพลิเคชันของฉันถึงไม่สามารถเข้าถึงได้หลังจากการปรับใช้?
**ตอบ**: ตรวจสอบ:
1. การปรับใช้เสร็จสิ้นสำเร็จแล้ว
2. แอปพลิเคชันกำลังทำงาน (ตรวจสอบบันทึกในพอร์ทัล Azure)
3. กลุ่มความปลอดภัยเครือข่ายอนุญาตการรับส่งข้อมูล
4. การกำหนดค่า DNS/โดเมนที่กำหนดเองถูกต้อง

## ค่าใช้จ่าย & การเรียกเก็บเงิน

### Q: การปรับใช้ azd จะมีค่าใช้จ่ายเท่าไร?
**ก**: ค่าใช้จ่ายขึ้นอยู่กับ:
- บริการ Azure ที่นำไปใช้
- ระดับ/ประเภท SKU ที่เลือก
- ความแตกต่างของราคาตามภูมิภาค
- รูปแบบการใช้งาน

ใช้ [Azure Pricing Calculator](https://azure.microsoft.com/pricing/calculator/) เพื่อประเมินราคา

### ถาม: ฉันควบคุมค่าใช้จ่ายในการปรับใช้งาน azd อย่างไร?
**ตอบ**: 
1. ใช้ SKU ระดับต่ำกว่าในสภาพแวดล้อมการพัฒนา
2. ตั้งงบประมาณและการแจ้งเตือนบน Azure
3. ใช้ `azd down` เพื่อลบทรัพยากรเมื่อไม่จำเป็น
4. เลือกภูมิภาคที่เหมาะสม (ค่าใช้จ่ายจะแตกต่างกันตามสถานที่)
5. ใช้เครื่องมือจัดการค่าใช้จ่ายของ Azure

### Q: มีตัวเลือกฟรี tier สำหรับเทมเพลต azd ไหม?
**A**: บางบริการมี SKU ฟรีหรือสิทธิประโยชน์รายเดือน ขึ้นอยู่กับคุณสมบัติ แผนโฮสติ้ง ภูมิภาค และขีดจำกัดการสมัครใช้งาน ซึ่งไม่ได้หมายความว่าเทมเพลตทั้งหมดจะฟรี: ฐานข้อมูล การค้นหา เครือข่าย รีจิสทรี เทเลเมทรี และการอนุมานโมเดลอาจมีค่าใช้จ่ายแยกต่างหาก ตรวจสอบ [รายการบริการฟรีของ Azure](https://azure.microsoft.com/free/) และราคาปัจจุบันสำหรับแต่ละทรัพยากรก่อนการปรับใช้

### Q: ฉันจะประมาณค่าใช้จ่ายก่อนการปรับใช้อย่างไร?
**A**: 
1. ตรวจสอบ `main.bicep` ของเทมเพลตเพื่อดูทรัพยากรที่ถูกสร้าง
2. ใช้เครื่องมือคำนวณราคา Azure Pricing Calculator กับ SKU ที่เฉพาะเจาะจง
3. ปรับใช้ในสภาพแวดล้อมการพัฒนาก่อนเพื่อสังเกตค่าใช้จ่ายจริง
4. ใช้ Azure Cost Management เพื่อวิเคราะห์ค่าใช้จ่ายอย่างละเอียด

## แนวทางปฏิบัติที่ดีที่สุด

### Q: แนวทางปฏิบัติที่ดีที่สุดสำหรับโครงสร้างโครงการ azd คืออะไร?
**A**: 
1. แยกโค้ดแอปพลิเคชันออกจากโครงสร้างพื้นฐาน
2. ใช้ชื่อบริการที่มีความหมายใน `azure.yaml`
3. ใช้มาตรการจัดการข้อผิดพลาดอย่างเหมาะสมในสคริปต์บิลด์
4. ใช้การกำหนดค่าสภาพแวดล้อมเฉพาะ
5. รวมเอกสารที่ครอบคลุม

### Q: ฉันควรจัดระเบียบบริการหลายตัวใน azd อย่างไร?
**A**: ใช้โครงสร้างที่แนะนำ:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### Q: ฉันควรคอมมิตโฟลเดอร์ `.azure` ลงใน version control ไหม?
**A**: **ไม่!** โฟลเดอร์ `.azure` มีข้อมูลที่ละเอียดอ่อน ให้เพิ่มเข้าไปใน `.gitignore`:
```gitignore
.azure/
```

### Q: ฉันควรจัดการความลับและการกำหนดค่าที่ละเอียดอ่อนอย่างไร?
**A**: 
1. ใช้ Azure Key Vault สำหรับเก็บความลับ
2. อ้างอิงความลับ Key Vault ในการกำหนดค่าแอปพลิเคชัน
3. หลีกเลี่ยงการคอมมิตความลับลงใน version control
4. ใช้ managed identities สำหรับการรับรองความถูกต้องระหว่างบริการ

### Q: วิธีที่แนะนำสำหรับ CI/CD กับ azd คืออะไร?
**A**: 
1. ใช้สภาพแวดล้อมแยกสำหรับแต่ละขั้นตอน (dev/staging/prod)
2. ใช้การทดสอบอัตโนมัติก่อนการปรับใช้
3. ใช้ service principals สำหรับการรับรองความถูกต้อง
4. เก็บการกำหนดค่าที่ละเอียดอ่อนในความลับหรือ environment variables ของ pipeline
5. ใช้ approval gates สำหรับการปรับใช้ในสภาพแวดล้อม production

## หัวข้อขั้นสูง

### Q: ฉันสามารถขยาย azd ด้วยฟังก์ชันเฉพาะได้ไหม?
**A**: ได้ ผ่าน deployment hooks ใน `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### Q: ฉันจะผนวกรวม azd กับกระบวนการ DevOps ที่มีอยู่ได้อย่างไร?
**A**: 
1. ใช้คำสั่ง azd ในสคริปต์ pipeline ที่มีอยู่
2. มาตรฐานเทมเพลต azd ให้เหมือนกันในทุกทีม
3. ผนวกรวมกับการมอนิเตอร์และแจ้งเตือนที่มีอยู่
4. ใช้ JSON output ของ azd เพื่อผนวกรวมกับ pipeline

### Q: ฉันสามารถใช้ azd กับ Azure DevOps ได้ไหม?
**A**: ได้ azd ทำงานร่วมกับระบบ CI/CD ใดก็ได้ สร้าง Azure DevOps pipelines ที่ใช้คำสั่ง azd

### Q: ฉันจะช่วยพัฒนา azd หรือสร้างเทมเพลตชุมชนได้อย่างไร?
**A**: 
1. **เครื่องมือ azd**: ช่วยพัฒนาได้ที่ [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **เทมเพลต**: ทำตามคำแนะนำใน [Awesome AZD gallery contribution instructions](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **เอกสาร**: ช่วยพัฒนาเอกสารที่ [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### Q: แผนพัฒนา azd คืออะไร?
**A**: ตรวจสอบ [แผนงานอย่างเป็นทางการ](https://github.com/Azure/azure-dev/projects) สำหรับฟีเจอร์และการปรับปรุงที่วางแผนไว้

### Q: ฉันจะย้ายจากเครื่องมือปรับใช้อื่นมาใช้ azd อย่างไร?
**A**: 
1. วิเคราะห์สถาปัตยกรรมการปรับใช้ปัจจุบัน
2. สร้างเทมเพลต Bicep ที่เทียบเท่า
3. กำหนดค่า `azure.yaml` ให้ตรงกับบริการปัจจุบัน
4. ทดสอบอย่างละเอียดในสภาพแวดล้อมการพัฒนา
5. ค่อย ๆ ย้ายสภาพแวดล้อม
