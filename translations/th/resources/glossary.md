# อภิธานศัพท์ - คำศัพท์เกี่ยวกับ Azure และ AZD

- **📖 เรียนรู้พื้นฐาน**: [บทที่ 1: พื้นฐาน AZD](../docs/chapter-01-foundation/azd-basics.md)

## บทนำ

อภิธานศัพท์โดยละเอียดนี้ให้คำจำกัดความสำหรับคำศัพท์ แนวคิด และตัวย่อที่ใช้ใน Azure Developer CLI และการพัฒนา Azure บนคลาวด์ เป็นเอกสารอ้างอิงที่สำคัญสำหรับการทำความเข้าใจเอกสารทางเทคนิค การแก้ไขปัญหา และการสื่อสารเกี่ยวกับโครงการ azd และบริการ Azure อย่างมีประสิทธิผล

## เป้าหมายการเรียนรู้

โดยการใช้อภิธานศัพท์นี้ คุณจะสามารถ:
- เข้าใจคำศัพท์และแนวคิดพื้นฐานของ Azure Developer CLI
- เชี่ยวชาญคำศัพท์ด้านการพัฒนาบน Azure และคำเทคนิคต่าง ๆ
- อ้างอิงคำศัพท์เกี่ยวกับโครงสร้างพื้นฐานเป็นโค้ดและการปรับใช้ได้อย่างมีประสิทธิภาพ
- เข้าใจชื่อบริการ Azure ตัวย่อ และวัตถุประสงค์ของพวกเขา
- เข้าถึงคำจำกัดความสำหรับคำศัพท์เกี่ยวกับการแก้ไขปัญหาและการดีบัก
- เรียนรู้แนวคิดสถาปัตยกรรม Azure และการพัฒนาขั้นสูง

## ผลลัพธ์การเรียนรู้

ด้วยการอ้างอิงอภิธานศัพท์นี้อย่างสม่ำเสมอ คุณจะสามารถ:
- สื่อสารอย่างมีประสิทธิภาพโดยใช้คำศัพท์ที่ถูกต้องของ Azure Developer CLI
- เข้าใจเอกสารทางเทคนิคและข้อความแสดงข้อผิดพลาดได้ชัดเจนขึ้น
- ใช้บริการและแนวคิดของ Azure ได้อย่างมั่นใจ
- แก้ไขปัญหาโดยใช้คำศัพท์ทางเทคนิคที่เหมาะสม
- มีส่วนร่วมในการอภิปรายของทีมด้วยภาษาทางเทคนิคที่ถูกต้อง
- ขยายความรู้ด้านการพัฒนาบนคลาวด์ Azure อย่างเป็นระบบ

## A

**ARM Template**  
แบบฟอร์ม Azure Resource Manager ที่เป็นโครงสร้างโค้ดโครงสร้างพื้นฐานในรูปแบบ JSON ใช้สำหรับกำหนดและปรับใช้ทรัพยากร Azure อย่างระบุเจาะจง

**App Service**  
บริการแพลตฟอร์มเป็นบริการ (PaaS) ของ Azure สำหรับโฮสต์เว็บแอปพลิเคชัน REST API และแบ็กเอนด์มือถือโดยไม่ต้องจัดการโครงสร้างพื้นฐาน

**Application Insights**  
บริการตรวจสอบประสิทธิภาพแอปพลิเคชัน (APM) ของ Azure ที่ให้ข้อมูลเชิงลึกลึกเกี่ยวกับประสิทธิภาพ การพร้อมใช้งาน และการใช้งานของแอปพลิเคชัน

**Azure CLI**  
อินเทอร์เฟซบรรทัดคำสั่งสำหรับจัดการทรัพยากร Azure ซึ่งเสริม AZD แต่มีการเข้าสู่ระบบแยกต่างหาก; การพิสูจน์ตัวตนหลักของ AZD ใช้ `azd auth login`

**Azure Developer CLI (azd)**  
เครื่องมือบรรทัดคำสั่งสำหรับนักพัฒนาที่ช่วยเร่งกระบวนการสร้างและปรับใช้แอปพลิเคชันไปยัง Azure โดยใช้เทมเพลตและโครงสร้างพื้นฐานเป็นโค้ด

**azure.yaml**  
ไฟล์กำหนดค่าหลักของโครงการ azd ที่กำหนดบริการ โครงสร้างพื้นฐาน และฮุกการปรับใช้

**Azure Resource Manager (ARM)**  
บริการปรับใช้และจัดการของ Azure ที่ให้ชั้นการจัดการสำหรับการสร้าง อัปเดต และลบทรัพยากร

## B

**Bicep**  
ภาษาโดเมนเฉพาะ (DSL) ที่พัฒนาโดย Microsoft สำหรับปรับใช้ทรัพยากร Azure มีไวยากรณ์ที่ง่ายกว่าตัวแบบ ARM ในขณะที่คอมไพล์ไปเป็น ARM

**Build**  
กระบวนการคอมไพล์ซอร์สโค้ด ติดตั้ง Dependencies และเตรียมแอปพลิเคชันสำหรับการปรับใช้

**Blue-Green Deployment**  
กลยุทธ์การปรับใช้ที่ใช้สภาพแวดล้อมการผลิตสองตัวที่เหมือนกัน (สีน้ำเงินและสีเขียว) เพื่อลดเวลาหยุดทำงานและความเสี่ยง

## C

**Container Apps**  
บริการคอนเทนเนอร์แบบ serverless ของ Azure ที่ช่วยให้รันแอปพลิเคชันที่บรรจุในคอนเทนเนอร์ได้โดยไม่ต้องจัดการโครงสร้างพื้นฐานที่ซับซ้อน

**CI/CD**  
การผสานรวมและปรับใช้อย่างต่อเนื่อง เป็นแนวปฏิบัติอัตโนมัติสำหรับการรวมการเปลี่ยนแปลงโค้ดและปรับใช้แอปพลิเคชัน

**Cosmos DB**  
บริการฐานข้อมูลโมเดลหลากหลายที่กระจายทั่วโลกของ Azure ซึ่งให้ SLA ครอบคลุมสำหรับ throughput, latency, availability และ consistency

**Configuration**  
การตั้งค่าและพารามิเตอร์ที่ควบคุมพฤติกรรมของแอปพลิเคชันและตัวเลือกการปรับใช้

## D

**Deployment**  
กระบวนการติดตั้งและกำหนดค่าแอปพลิเคชันและ Dependencies ของพวกเขาบนโครงสร้างพื้นฐานเป้าหมาย

**Docker**  
แพลตฟอร์มสำหรับพัฒนา ส่ง และรันแอปพลิเคชันโดยใช้เทคโนโลยีคอนเทนเนอร์

**Dockerfile**  
ไฟล์ข้อความที่มีคำสั่งสำหรับการสร้างอิมเมจคอนเทนเนอร์ Docker

## E

**Environment**  
เป้าหมายการปรับใช้ที่แสดงถึงอินสแตนซ์เฉพาะของแอปพลิเคชันของคุณ (เช่น การพัฒนา การเตรียมการใช้งานจริง)

**Environment Variables**  
ค่าการกำหนดค่าที่จัดเก็บในรูปแบบคู่กุญแจ-ค่า ซึ่งแอปพลิเคชันสามารถเข้าถึงได้ในขณะรันไทม์

**Endpoint**  
URL หรือที่อยู่เครือข่ายที่สามารถเข้าถึงแอปพลิเคชันหรือบริการได้

## F

**Function App**  
บริการคอมพิวต์แบบ serverless ของ Azure ที่ช่วยให้รันโค้ดที่ถูกแจ้งเหตุการณ์ได้โดยไม่ต้องจัดการโครงสร้างพื้นฐาน

## G

**GitHub Actions**  
แพลตฟอร์ม CI/CD ที่ผสานรวมกับรีโพสิทอรีบน GitHub สำหรับทำงานอัตโนมัติกระบวนการทำงาน

**Git**  
ระบบควบคุมเวอร์ชันแบบกระจายที่ใช้ติดตามการเปลี่ยนแปลงในซอร์สโค้ด

## H

**Hooks**  
สคริปต์หรือคำสั่งที่กำหนดเองซึ่งรันในจุดเวลาที่กำหนดระหว่างวงจรชีวิตการปรับใช้ (เช่น preprovision, postprovision, predeploy, postdeploy)

**Host**  
ประเภทบริการ Azure ที่แอปพลิเคชันจะถูกปรับใช้ (เช่น appservice, containerapp, function)

## I

**Infrastructure as Code (IaC)**  
แนวปฏิบัติในการกำหนดและจัดการโครงสร้างพื้นฐานผ่านโค้ดแทนกระบวนการด้วยตนเอง

**Init**  
กระบวนการเริ่มต้นโครงการ azd ใหม่ โดยปกติมาจากเทมเพลต

## J

**JSON**  
JavaScript Object Notation รูปแบบแลกเปลี่ยนข้อมูลที่ใช้บ่อยสำหรับไฟล์กำหนดค่าและการตอบสนอง API

**JWT**  
JSON Web Token มาตรฐานสำหรับการส่งข้อมูลอย่างปลอดภัยระหว่างฝ่ายในรูปแบบ JSON

## K

**Key Vault**  
บริการของ Azure สำหรับการเก็บรักษาและจัดการความลับ กุญแจ และใบรับรองอย่างปลอดภัย

**Kusto Query Language (KQL)**  
ภาษาแบบสอบถามที่ใช้สำหรับวิเคราะห์ข้อมูลใน Azure Monitor, Application Insights และบริการ Azure อื่น ๆ

## L

**Load Balancer**  
บริการที่กระจายการรับส่งเครือข่ายเข้ามาไปยังเซิร์ฟเวอร์หรืออินสแตนซ์หลายตัว

**Log Analytics**  
บริการ Azure สำหรับการเก็บ รวบรวม วิเคราะห์ และดำเนินการกับข้อมูลเทเลเมทรีจากสภาพแวดล้อมบนคลาวด์และในสถานที่

## M

**Managed Identity**  
คุณสมบัติของ Azure ที่มอบตัวตนที่จัดการโดยอัตโนมัติให้บริการ Azure สำหรับการพิสูจน์ตัวตนกับบริการ Azure อื่น ๆ

**Microservices**  
แนวทางสถาปัตยกรรมที่แอปพลิเคชันถูกสร้างขึ้นเป็นชุดของบริการขนาดเล็กและอิสระ

**Monitor**  
โซลูชันการตรวจสอบแบบครบวงจรของ Azure ที่ให้การมองเห็นแบบเต็มสแต็กทั่วทั้งแอปพลิเคชันและโครงสร้างพื้นฐาน

## N

**Node.js**  
รันไทม์ JavaScript ที่สร้างโดยใช้เครื่องยนต์ JavaScript V8 ของ Chrome สำหรับการพัฒนาแอปพลิเคชันฝั่งเซิร์ฟเวอร์

**npm**  
ตัวจัดการแพ็กเกจสำหรับ Node.js ที่จัดการ Dependencies และแพ็กเกจ

## O

**Output**  
ค่าที่ส่งคืนจากการปรับใช้โครงสร้างพื้นฐานซึ่งสามารถใช้งานโดยแอปพลิเคชันหรือทรัพยากรอื่น ๆ

## P

**Package**  
กระบวนการเตรียมซอร์สโค้ดและ Dependencies ของแอปพลิเคชันสำหรับการปรับใช้

**Parameters**  
ค่าป้อนเข้าที่ส่งไปยังเทมเพลตโครงสร้างพื้นฐานเพื่อปรับแต่งการปรับใช้

**PostgreSQL**  
ระบบฐานข้อมูลเชิงสัมพันธ์แบบโอเพนซอร์สที่สนับสนุนในรูปแบบบริการที่มีการจัดการบน Azure

**Provisioning**  
กระบวนการสร้างและกำหนดค่าทรัพยากร Azure ที่กำหนดในเทมเพลตโครงสร้างพื้นฐาน

## Q

**Quota**  
ข้อจำกัดปริมาณทรัพยากรที่สามารถสร้างได้ในบัญชี Azure หรือภูมิภาค

## R

**Resource Group**  
ภาชนะตรรกะสำหรับทรัพยากร Azure ที่แบ่งปันวงจรชีวิต สิทธิ์ และนโยบายเดียวกัน

**Resource Token**  
สตริงที่ไม่ซ้ำที่สร้างโดย azd เพื่อให้แน่ใจว่าชื่อทรัพยากรไม่ซ้ำกันในการปรับใช้

**REST API**  
รูปแบบสถาปัตยกรรมสำหรับออกแบบแอปพลิเคชันเครือข่ายโดยใช้ HTTP Methods

**Rollback**  
กระบวนการย้อนกลับไปยังเวอร์ชันก่อนหน้าของแอปพลิเคชันหรือการกำหนดค่าโครงสร้างพื้นฐาน

## S

**Service**  
ส่วนประกอบของแอปพลิเคชันที่กำหนดใน azure.yaml (เช่น เว็บฟรอนต์เอนด์, API แบ็กเอนด์, ฐานข้อมูล)

**SKU**  
หน่วยเก็บสต็อก แทนระดับบริการหรือระดับประสิทธิภาพต่าง ๆ สำหรับทรัพยากร Azure

**SQL Database**  
บริการฐานข้อมูลเชิงสัมพันธ์ที่มีการจัดการบน Azure ซึ่งทำงานบน Microsoft SQL Server

**Static Web Apps**  
บริการ Azure สำหรับสร้างและปรับใช้เว็บแอปพลิเคชันแบบฟูลสแต็กจากรีโพสโค้ดต้นทาง

**Storage Account**  
บริการ Azure ที่ให้การเก็บข้อมูลบนคลาวด์สำหรับออบเจ็กต์ข้อมูล เช่น บล็อบ ไฟล์ คิว และตาราง

**Subscription**  
ภาชนะบัญชี Azure ที่เก็บกลุ่มทรัพยากรและทรัพยากร พร้อมกับการจัดการบิลและการเข้าถึงที่เกี่ยวข้อง

## T

**Template**  
โครงสร้างโครงการที่สร้างไว้ล่วงหน้าซึ่งประกอบด้วยซอร์สโค้ดแอปพลิเคชัน คำจำกัดความโครงสร้างพื้นฐาน และการกำหนดค่าสำหรับกรณีใช้งานทั่วไป

**Terraform**  
เครื่องมือ Infrastructure as Code แบบโอเพนซอร์สที่รองรับผู้ให้บริการคลาวด์หลายรายรวมถึง Azure

**Traffic Manager**  
ตัวจัดสมดุลโหลดทราฟฟิกของ Azure ที่ใช้ DNS สำหรับกระจายทราฟฟิกไปยังภูมิภาค Azure ทั่วโลก

## U

**URI**  
Uniform Resource Identifier สตริงที่ระบุตัวทรัพยากรเฉพาะ

**URL**  
Uniform Resource Locator ประเภทของ URI ที่ระบุที่ตั้งของทรัพยากรและวิธีการเข้าถึง

## V

**Virtual Network (VNet)**  
ออบเจ็กต์พื้นฐานสำหรับเครือข่ายส่วนตัวใน Azure ที่ให้การแบ่งแยกและแยกส่วน

**VS Code**  
Visual Studio Code โปรแกรมแก้ไขโค้ดยอดนิยมที่รวมการใช้งาน Azure และ azd ได้ดีเยี่ยม

## W

**Webhook**  
HTTP callback ที่จะเรียกใช้เมื่อเกิดเหตุการณ์เฉพาะ โดยปกติใช้ในท่อ CI/CD

**What-if**  
ฟีเจอร์ของ Azure ที่แสดงให้เห็นว่าการปรับใช้จะทำการเปลี่ยนแปลงอะไรบ้างโดยไม่ต้องดำเนินการจริง

## Y

**YAML**  
YAML Ain't Markup Language มาตรฐานการจัดเรียงข้อมูลที่อ่านง่ายสำหรับไฟล์กำหนดค่า เช่น azure.yaml

## Z

**Zone**  
ตำแหน่งที่แยกจากกันจริงภายในภูมิภาค Azure ที่ให้ความสามารถในการสำรองข้อมูลและความพร้อมใช้งานสูง

| Storage | Azure Storage Account | ทรัพยากรโครงสร้างพื้นฐาน ไม่ใช่แอปพลิเคชันในตัว `host` |
| Cache | Azure Managed Redis | ทรัพยากรโครงสร้างพื้นฐาน ไม่ใช่แอปพลิเคชัน `host` |

## คำศัพท์ตามบริบท

### คำศัพท์เกี่ยวกับการพัฒนา
- **Hot Reload**: การอัปเดตแอปพลิเคชันโดยอัตโนมัติในระหว่างการพัฒนาโดยไม่ต้องรีสตาร์ท
- **Build Pipeline**: กระบวนการอัตโนมัติสำหรับการสร้างและทดสอบโค้ด
- **Deployment Slot**: สภาพแวดล้อมเตรียมใช้งานภายใน App Service
- **Environment Parity**: รักษาความเหมือนของสภาพแวดล้อมการพัฒนา การเตรียมใช้งาน และการผลิต

### คำศัพท์เกี่ยวกับความปลอดภัย
- **Managed Identity**: คุณสมบัติของ Azure ที่จัดการข้อมูลรับรองโดยอัตโนมัติ
- **Key Vault**: ที่เก็บปลอดภัยสำหรับความลับ กุญแจ และใบรับรอง
- **RBAC**: การควบคุมการเข้าถึงตามบทบาทสำหรับทรัพยากร Azure
- **Network Security Group**: ไฟร์วอลล์เสมือนสำหรับควบคุมทราฟฟิกเครือข่าย

### คำศัพท์เกี่ยวกับการติดตามและตรวจสอบ
- **Telemetry**: การเก็บข้อมูลและวัดค่าโดยอัตโนมัติ
- **Application Performance Monitoring (APM)**: การตรวจสอบประสิทธิภาพซอฟต์แวร์
- **Log Analytics**: บริการสำหรับเก็บรวบรวมและวิเคราะห์ข้อมูลบันทึก
- **Alert Rules**: การแจ้งเตือนอัตโนมัติตามเมทริกซ์หรือเงื่อนไข

### คำศัพท์เกี่ยวกับการปรับใช้
- **Blue-Green Deployment**: กลยุทธ์การปรับใช้แบบไม่มีเวลาหยุดทำงาน
- **Canary Deployment**: การปล่อยฟีเจอร์เป็นช่วงกับผู้ใช้บางส่วน
- **Rolling Update**: การแทนที่อินสแตนซ์แอปพลิเคชันทีละชุด
- **Rollback**: การย้อนกลับไปยังเวอร์ชันก่อนหน้าของแอปพลิเคชัน
