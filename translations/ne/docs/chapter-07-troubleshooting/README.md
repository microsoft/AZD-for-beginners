# अध्याय ७: समस्याको समाधान र डिबगिङ

**📚 कोर्स**: [AZD लागि नयाँहरू](../../README.md) | **⏱️ अवधि**: १-१.५ घण्टा | **⭐ जटिलता**: मध्यम

---

## अवलोकन

यस अध्यायले Azure Developer CLI सँग काम गर्दा सामान्य समस्याहरू पहिचान गर्न र समाधान गर्न मद्दत गर्दछ। डिप्लोइमेन्ट असफलताबाट लिएर AI-विशिष्ट समस्याहरू सम्म।

> कमाण्ड मार्गदर्शन रिलिज गरिएको `azd 1.37.2` सन्दर्भसँग समीक्षित। क्लाउड डिप्लोइमेन्टहरू कार्यान्वयन गरिएको छैन। कमाण्डहरू प्रयोग गर्नुअघि उदाहरण स्रोत नामहरू र ID हरू प्रतिस्थापन गर्नुहोस्।

## सिकाइ उद्देश्यहरू

यस अध्याय पूरा गर्दा, तपाईं:
- सामान्य AZD डिप्लोइमेन्ट असफलताहरू पहिचान गर्नुहोस्
- प्रमाणीकरण र अनुमति समस्याहरू डिबग गर्नुहोस्
- AI सेवा कनेक्टिभिटी समस्याहरू समाधान गर्नुहोस्
- समस्याहरू समाधान गर्न Azure पोर्टल र CLI प्रयोग गर्नुहोस्

## 🚨 छिटो समाधानहरू

### प्रमाणीकरण समस्याहरू
```bash
# Required for AZD workflows
azd auth login

# Optional if you are also using Azure CLI commands directly
az login

azd auth login --check-status
```

### प्रावधान असफलता
```bash
azd show
azd monitor --logs
az deployment sub list --query "[?properties.provisioningState!='Succeeded']"
```

### स्रोत विवादहरू
पहिले अवस्थित स्रोत र डिप्लोइमेन्ट त्रुटिहरू निरीक्षण गर्नुहोस्। नाम विवाद समाधान गर्न साझेदार वा उत्पादन वातावरण मेट्नु हुँदैन। **नयाँ प्रयोग गर्न मिल्ने वातावरण** को लागि फरक नाम प्रयोग गर्नुहोस्:

```bash
azd env new different-name
azd up
```

### कोटा पुगेको
```bash
az vm list-usage --location eastus --output table
# Check the affected service's own quotas, not just VM quotas.
# For a new environment only, choose a supported region with available quota.
```

`AZURE_LOCATION` परिवर्तन गर्दा अवस्थित स्रोतहरू सारिँदैनन् र पुनःडिप्लोइमेन्टमा स्थान विवादहरू हुन सक्छन्।

## 📋 त्रुटि कोड सन्दर्भ

| त्रुटि | कारण | समाधान |
|-------|-------|----------|
| `AuthenticationError` | लगइन गरिएको छैन | `azd auth login` |
| `ResourceNotFound` | स्रोत छैन | स्रोत नामहरू जाँच गर्नुहोस् |
| `QuotaExceeded` | सदस्यता सीमा | कोटा वृद्धि अनुरोध गर्नुहोस् |
| `InvalidTemplate` | बाइसेप सिन्ट्याक्स त्रुटि | `az bicep build` |
| `Conflict` | स्रोत पहिले नै छ | नयाँ नाम प्रयोग गर्नुहोस् वा मेट्नुहोस् |
| `Forbidden` | पर्याप्त अनुमति छैन | RBAC भूमिकाहरू जाँच गर्नुहोस् |

## 🔄 रिसेट र पुन: प्राप्ति

```bash
# Soft reset (keep resources, redeploy code)
azd deploy

# Hard reset (delete everything, start fresh)
azd down
azd up
```

हार्ड रिसेटले डेटा मेटाउने छ र इन्डपोइन्टहरू परिवर्तन हुन सक्छ। पहिले ब्याकअप लिनुहोस् र अन्तरक्रियात्मक मेट्ने प्रम्प्टहरू समीक्षा गर्नुहोस्। `--force --purge` मात्र अस्थाई वातावरणहरूका लागि र अविनाशी मेट्ने उद्देश्यका लागि उपयुक्त छ।
