## Почетак рада

### П: Шта је Azure Developer CLI (azd)?
**О**: Azure Developer CLI (azd) је алат командне линије оријентисан на програмере који убрзава време потребно да ваша апликација пређе из локалног развојног окружења на Azure. Пружа најбоље праксе кроз шаблоне и помаже током целог животног циклуса деплојмента.

### П: По чему се azd разликује од Azure CLI?
**О**: 
- **Azure CLI**: Универзални алат за управљање Azure ресурсима
- **azd**: Алат фокусиран на програмере за радне токове распоређивања апликација
- azd има свој протокол аутентикације и деплојмента; Azure CLI је засебан, допунски алат
- azd укључује шаблоне, управљање окружењем и аутоматизацију деплојмента

### П: Да ли ми је потребан Azure CLI да бих користио azd?
**О**: Није за основни AZD радни ток. Аутентификовати се са `azd auth login`. Инсталирајте Azure CLI засебно када шаблонски хук или вежба експлицитно покрећу наредбе `az`.

### П: Које програмске језике azd подржава?
**О**: azd је независан од језика. Ради са:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- Статичким веб сајтовима
- Апликацијама у контејнерима

### П: Могу ли користити azd са постојећим пројектима?
**О**: Можете! Можете или:
1. Користити `azd init` да додате azd конфигурацију постојећим пројектима
2. Прилагодити постојеће пројекте да одговарају azd структури шаблона
3. Креирати прилагођене шаблоне на основу ваше постојеће архитектуре

### П: Шта се променило са општом доступношћу Foundry проширења?
**О**: `microsoft.foundry` пакет је достигао верзију 1.0 и GA 5. новембра 2026. Са AZD 1.37.0+ користите `azd ext install microsoft.foundry` да инсталирате седам основних проширења за агенте, везе, инспектор, пројекте, рутине, вештине и алатке. Није нови командни простор, а његове компоненте имају независне верзије. Процењивања, скупови података, прецизирање и прилагођени модели инсталирају се засебно; опционе функције у претпрегледу не постају GA само зато што је пакет GA.

Водич [hosted-agent walkthrough](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#hosted-agent-walkthrough-ga) користи Python 3.13+ и тренутни uv. `azd ai agent run` отвара Agent Inspector локално, али позиви модела и даље користе Azure и наплаћују трошкове. Режим кода `azd deploy` отпрема извор за даљинску изградњу без потребе за локалном изградњом контејнера.

### П: Да ли `azd down` уклања hosted agent са постојећег Foundry пројекта?
**О**: Не за reused-project пут описан у hosted-agent упутству за брзи почетак: он оставља пројекат, hosted agent и остале ресурсе на месту. Нежељене ресурсе уклоните појединачно без брисања заједничких ресурса. Ако је окружење направило нови Foundry пројекат, `azd down` брише његову групу ресурса и све у њој. Прегледајте [упутство за чишћење](../docs/chapter-02-ai-development/microsoft-foundry-integration.md#7-clean-up-deliberately) и упите за брисање пре потврде.

## Аутентификација и приступ

### П: Како да се аутентификујем на Azure користећи azd?
**О**: Користите `azd auth login` који ће отворити прозор прегледача за Azure аутентификацију. За CI/CD сценарије користите сервисне принципе или управљане идентитете.

### П: Могу ли да користим azd са више Azure претплата?
**О**: Да. Користите `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` да назначите коју претплату користити за свако окружење.

### П: Која ми овлашћења требају за деплоирање са azd?
**О**: Обично су вам потребна:
- улога **Contributor** на групи ресурса или претплати
- улога **User Access Administrator** ако деплојујете ресурсе који захтевају доделу улога
- Конкретна овлашћења варирају у зависности од шаблона и ресурса који се деплојују

### П: Могу ли да користим azd у CI/CD пипелинима?
**О**: Апсолутно! azd је дизајниран за CI/CD интеграцију. Користите сервисне принципе за аутентификацију и подесите променљиве окружења за конфигурацију.

### П: Како да поступам са аутентификацијом у GitHub Actions?
**О**: Преферирајте федерацију идентитета за радно оптерећење (OIDC), конфигурисану помоћу `azd pipeline config`. Генерисани workflow инсталира AZD и аутентификује AZD директно са федеративним идентитетом. Само `azure/login` корак не успоставља AZD пријаву. Корак пријаве у оквиру постојећег посла је:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

Извршите провизију или деплоирање након пријаве, са конфигурисаним жељеним AZD окружењем, претплатом и локацијом. Федеративни креденцијал идентитета мора да верује репозиторијуму/ref workflow-а или GitHub окружењу, а Azure улоге морају дозволити тражене операције.

## Шаблони и пројекти

### П: Где могу пронаћи azd шаблоне?
**О**: 
- Званични и заједнички шаблони: [Awesome AZD](https://azure.github.io/awesome-azd/)
- Заједнички шаблони: GitHub претрага за "azd-template"
- Користите `azd template list` да прегледате доступне шаблоне

### П: Како да креирам прилагођени шаблон?
**О**: 
1. Почните са постојећом структуром шаблона
2. Измените `azure.yaml`, инфраструктурне фајлове и апликациони код
3. Темелно тестирајте помоћу `azd up`
4. Објавите на GitHub-у са одговарајућим ознакама

### П: Могу ли користити azd без шаблона?
**О**: Да, користите `azd init` у постојећем пројекту да креирате потребне конфигурационе фајлове. Биће потребно ручно подешавање `azure.yaml` и инфраструктурних фајлова.

### П: Која је разлика између званичних и заједничких шаблона?
**О**: 
- **Службени шаблони**: Одржава Microsoft, редовно ажурирани, свеобухватна документација
- **Заједнички шаблони**: Креирани од стране програмера, могу имати специјализоване случајеве употребе, различит квалитет и одржавање

### П: Како ажурирам шаблон у свом пројекту?
**О**: Шаблони се не ажурирају аутоматски. Можете:
1. Ручно упоредити и спојити измене из изворног шаблона
2. Почети изнова са `azd init` користећи ажурирани шаблон
3. Изабрати одређена побољшања из ажурираних шаблона

## Деплојмент и инфраструктура

### П: Које Azure услуге може azd да деплојује?
**О**: azd може да деплојује било коју Azure услугу преко Bicep/ARM шаблона, укључујући:
- App Services, Container Apps, Functions
- Базе података (SQL, PostgreSQL, Cosmos DB)
- Сташење, Key Vault, Application Insights
- Мрежне, безбедносне и надзорне ресурсе

### П: Могу ли да деплојујем у више региона?
**О**: Да, конфигуришите више региона у вашим Bicep шаблонима и поставите параметар локације одговарајуће за свако окружење.

### П: Како да управљам миграцијама шеме базе података?
**О**: Користите ретке распореде у `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### П: Могу ли да деплојујем само инфраструктуру без апликација?
**О**: Да, користите `azd provision` да деплојујете само инфраструктурне компоненте дефинисане у вашим шаблонима.

### П: Како да деплојујем на постојеће Azure ресурсе?
**О**: Да, ако шаблон то подржава. Позовите постојеће ресурсе са Bicep-овим `existing` декларацијама или параметрима за постојеће ресурсе описаним у шаблону, и мапирајте сервисе апликације на њихове намењене циљеве. Ово не увози власништво нити аутоматски креира недостајуће дозволе. Прегледајте шаблон пре деплоја.

### П: Могу ли да користим Terraform уместо Bicep-а?
**О**: Да. AZD подржава Terraform као и Bicep. Изаберите шаблон заснован на Terraform-у или конфигуришите `infra.provider: terraform` у `azure.yaml`, са одговарајућим Terraform фајловима и конфигурацијом стања/backend-а. Погледајте [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## Конфигурација и окружења

### П: Како да управљам различитим окружењима (dev, staging, prod)?
**О**: Креирајте одвојена окружења са `azd env new <environment-name>` и конфигуришите различита подешавања за свако:
```bash
azd env new development
azd env new staging  
azd env new production
```

### П: Где се чувају конфигурације окружења?
**О**: У `.azure` фолдеру унутар вашег пројектног директоријума. Сваки окружен има свој фолдер са конфигурационим фајловима.

### П: Како подесити конфигурацију специфичну за окружење?
**О**: Користите `azd env set` за конфигурисање променљивих окружења:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### П: Могу ли делити конфигурације окружења међу члановима тима?
**О**: `.azure` фолдер садржи осетљиве информације и не би требало да се поставља у систем контроле верзија. Уместо тога:
1. Документујте потребне променљиве окружења
2. Користите скрипте за деплојмент да подесите окружења
3. Користите Azure Key Vault за осетљиву конфигурацију

### П: Како да преузмем контролу над подразумеваним вредностима шаблона?
**О**: Поставите променљиве окружења које одговарају параметрима шаблона:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

Само променљиве које шаблон користи утичу на деплојмент. `SKU_NAME` изнад је пример прилагођеног уноса, не општа AZD поставка.

## Решавање проблема

### П: Зашто `azd up` не успева?
**О**: Уобичајени узроци:
1. **Проблеми са аутентикацијом**: Покрените `azd auth login`
2. **Неприхватљива дозвола**: Проверите своје Azure доделе улога
3. **Сукоб именовања ресурса**: Прегледајте конфликтни ресурс и уносе именовања у шаблону; креирајте посебно окружење са `azd env new` када је изолација потребна
4. **Проблеми са квотом/капацитетом**: Проверите регионалну доступност
5. **Грешке у шаблону**: Верификујте Bicep шаблоне

### П: Како да отклоним грешке у имплементацији?
**О**: 
1. Користите `azd deploy --debug` за детаљан излаз
2. Проверите историјат имплементације у Azure порталу
3. Прегледајте Лог активности у Azure порталу
4. Користите `azd show` да бисте приказали тренутно стање окружења

### П: Зашто моје променљиве окружења не функционишу?
**О**: Проверите:
1. Да имена променљивих тачно одговарају параметрима у шаблону
2. Да су вредности правилно обухваћене ако садрже размаке
3. Да је одабрано окружење: `azd env select <environment>`
4. Да су променљиве постављене у исправно окружење

### П: Како да очистим неуспеле имплементације?
**О**: 
```bash
azd down
```
Прво прегледајте одабрано окружење и потврду брисања. Ово брише обезбеђене Azure ресурсе, а не локалну конфигурацију `.azure` окружења. `--purge` додатно тражи трајно брисање подржаних ресурса меког брисања и може бити блокиран заштитом задржавања/чишћења; није рутински корак за опоравак.

### П: Зашто моја апликација није доступна након имплементације?
**О**: Проверите:
1. Да је имплементација успешно завршена
2. Да апликација ради (проверите логове у Azure порталу)
3. Да мрежне безбедносне групе дозвољавају саобраћај
4. Да су DNS/прилагођени домени исправно конфигурисани

## Трошкови и наплата

### П: Колико ће коштати azd имплементације?
**О**: Трошкови зависе од:
- Azure услуга које се имплементирају
- Изабраних нивоа услуга/SKU-ова
- Регионалних разлика у ценама
- Обрасци коришћења

Користите [Azure Pricing Calculator](https://azure.microsoft.com/pricing/calculator/) за процене.

### П: Како да контролишем трошкове у azd имплементацијама?
**О**: 
1. Користите SKU-ове нижег нивоа за развојна окружења
2. Подесите Azure буџете и упозорења
3. Користите `azd down` за уклањање ресурса када нису потребни
4. Изаберите одговарајуће регионе (трошкови варирају у зависности од локације)
5. Користите алате за управљање трошковима у Azure-у

### П: Постоје ли бесплатне опције за azd шаблоне?
**О**: Неки сервиси имају бесплатне SKU-ове или месечне грантове, у зависности од подобности, плана хостинга, региона и ограничења претплате. Ово не чини цео шаблон бесплатним: базе података, претрага, мрежа, регистар, телеметрија и извођење модела могу независно изазвати трошкове. Проверите [Azure листу бесплатних сервиса](https://azure.microsoft.com/free/) и тренутне цене за сваки ресурс пре распоређивања.

### П: Како да проценим трошкове пре распоређивања?
**О**: 
1. Прегледајте `main.bicep` шаблона да видите који ресурси се креирају
2. Користите Azure Pricing Calculator са специфичним SKU-овима
3. Прво распоредите у развојно окружење да пратите стварне трошкове
4. Користите Azure Cost Management за детаљну анализу трошкова

## Најбоље праксе

### П: Које су најбоље праксе за структуру azd пројекта?
**О**: 
1. Чувајте код апликације одвојено од инфраструктуре
2. Користите смислена имена сервиса у `azure.yaml`
3. Имплементирајте правилну обраду грешака у build скриптама
4. Користите конфигурацију специфичну за окружење
5. Укључите свеобухватну документацију

### П: Како да организујем више сервиса у azd?
**О**: Користите препоручену структуру:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### П: Да ли треба да комитујем `.azure` фолдер у систем верзионисања?
**О**: **Не!** `.azure` фолдер садржи осетљиве информације. Додајте га у `.gitignore`:
```gitignore
.azure/
```

### П: Како да управљам тајнама и осетљивом конфигурацијом?
**О**: 
1. Користите Azure Key Vault за тајне
2. Реферишите тајне из Key Vault-а у конфигурацији апликације
3. Никада не комитујте тајне у систем верзионисања
4. Користите управљане идентитете за аутентификацију сервис-сервис

### П: Који је препоручени приступ за CI/CD са azd?
**О**: 
1. Користите одвојена окружења за сваки стадијум (развој/тестирање/производња)
2. Имплементирајте аутоматизовано тестирање пре распоређивања
3. Користите сервисне налоге за аутентификацију
4. Чувајте осетљиву конфигурацију у тајнама/променљивима pipeline-а
5. Имплементирајте одобрења за производне деплоје

## Напредне теме

### П: Могу ли проширити azd прилагођеном функционалношћу?
**О**: Да, кроз deployment hooks у `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### П: Како да интегришем azd са постојећим DevOps процесима?
**О**: 
1. Користите azd команде у постојећим pipeline скриптама
2. Стандардузирајте azd шаблоне кроз тимове
3. Интегришите са постојећим системима за надзор и алармирање
4. Користите azd JSON излаз за интеграцију pipeline-а

### П: Могу ли користити azd са Azure DevOps-ом?
**О**: Да, azd ради са било којим CI/CD системом. Направите Azure DevOps pipeline-ове који користе azd наредбе.

### П: Како могу да допринесем azd-у или креирам заједничке шаблоне?
**О**: 
1. **azd алат**: Доприносите на [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **Шаблони**: Пратите упутства за допринос у [Awesome AZD галерију](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **Документација**: Доприносите документацији на [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### П: Који је план развоја azd-а?
**О**: Погледајте [званични план развоја](https://github.com/Azure/azure-dev/projects) за планиране карактеристике и побољшања.

### П: Како да мигрирам са других алата за деплој на azd?
**О**: 
1. Анализирајте тренутну архитектуру деплоја
2. Креирајте еквивалентне Bicep шаблоне
3. Конфигуришите `azure.yaml` да одговара тренутним сервисима
4. Темелно тестирајте у развојном окружењу
5. Постепено мигрирајте окружења
