## Почетак

### П: Шта је Azure Developer CLI (azd)?
**О**: Azure Developer CLI (azd) је алат командне линије оријентисан на програмере који убрзава време потребно да вашу апликацију пребаците из локалног развојног окружења у Azure. Пружа најбоље праксе уз шаблоне и помаже у целом животном циклусу deployment-а.

### П: По чему се azd разликује од Azure CLI?
**О**: 
- **Azure CLI**: Општи алат за управљање Azure ресурсима
- **azd**: Алат фокусиран на програмере за workflow-је deployment апликација
- azd има свој ток аутентификације и deployment-а; Azure CLI је посебан, допунски алат
- azd укључује шаблоне, управљање окружењима и аутоматизацију deployment-а

### П: Да ли ми треба Azure CLI да бих користио azd?
**О**: За основни азд workflow није потребан. Аутентификујте се помоћу `azd auth login`. Инсталирајте Azure CLI посебно када шаблон или вежба јасно извршавају `az` команде.

### П: Које програмске језике azd подржава?
**О**: azd је језички неутралан. Ради са:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- Статичке веб странице
- Контейнеризоване апликације

### П: Могу ли користити azd са постојећим пројектима?
**О**: Да! Можете:
1. Користити `azd init` да додате azd конфигурацију постојећим пројектима
2. Прилагодити постојеће пројекте да одговарају структури azd шаблона
3. Креирати прилагођене шаблоне на основу ваше постојеће архитектуре

## Аутентификација и приступ

### П: Како да се аутентификујем на Azure користећи azd?
**О**: Користите `azd auth login` који ће отворити прегледач за Azure аутентификацију. За CI/CD сценарије, користите сервисне принципале или управљане идентитете.

### П: Могу ли користити azd са више Azure претплата?
**О**: Да. Користите `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` да одредите коју претплату користите за свако окружење.

### П: Које дозволе су ми потребне за deployment са azd?
**О**: Обично вам треба:
- Улога **Contributor** на ресурсу групе или претплати
- Улога **User Access Administrator** ако дејствујете на ресурсе који захтевају доделе улога
- Конкретне дозволе зависе од шаблона и ресурса који се deploy-ују

### П: Могу ли користити azd у CI/CD пипелинима?
**О**: Апсолутно! azd је дизајниран за интеграцију у CI/CD. Користите сервисне принципале за аутентификацију и подесите environment променљиве за конфигурацију.

### П: Како да управљам аутентификацијом у GitHub Actions?
**О**: Преферирајте workload identity federation (OIDC), конфигурисан помоћу `azd pipeline config`. Генерисани workflow инсталира AZD и аутентификује га директно са федералним идентитетом. Само `azure/login` корак не успоставља пријаву у AZD. Корак логина унутар постојећег job-а је:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

Проводите или deploy-ујте након пријаве, са намењеним AZD окружењем, претплатом и локацијом конфигурисаним. Федерални кредит идентитета мора да има поверење у репозиторијум/ref workflow-а или GitHub окружење, а његове Azure улоге морају дозволити тражене операције.

## Шаблони и пројекти

### П: Где могу пронаћи azd шаблоне?
**О**: 
- Званични и заједнички шаблони: [Awesome AZD](https://azure.github.io/awesome-azd/)
- Заједнички шаблони: претрага на GitHub-у за "azd-template"
- Користите `azd template list` да прегледате доступне шаблоне

### П: Како да креирам прилагођени шаблон?
**О**: 
1. Почните од постојеће структуре шаблона
2. Измените `azure.yaml`, инфраструктурне фајлове и код апликације
3. Тестирајте темељно помоћу `azd up`
4. Објавите на GitHub-у са одговарајућим ознакама

### П: Могу ли користити azd без шаблона?
**О**: Да, користите `azd init` у постојећем пројекту да бисте креирали неопходне конфигурационе фајлове. Биће потребно ручно конфигурисање `azure.yaml` и инфраструктурних фајлова.

### П: Која је разлика између званичних и заједничких шаблона?
**О**: 
- **Званични шаблони**: Одржава Microsoft, редовно ажурирани, свеобухватна документација
- **Заједнички шаблони**: Креирани од стране програмера, могу имати специјализовану примену, квалитет и одржавање варирају

### П: Како да ажурирам шаблон у свом пројекту?
**О**: Шаблони се не ажурирају аутоматски. Можете:
1. Ручно поредити и спојити промене са изворног шаблона
2. Почети изнова са `azd init` користећи ажурирани шаблон
3. Изабрати одређена побољшања из ажурираних шаблона

## Deployment и инфраструктура

### П: Које Azure услуге azd може deploy-овати?
**О**: azd може deploy-овати било коју Azure услугу преко Bicep/ARM шаблона, укључујући:
- App Services, Container Apps, Functions
- Базе података (SQL, PostgreSQL, Cosmos DB)
- Складиште, Key Vault, Application Insights
- Мрежне, безбедносне и мониторинг ресурсе

### П: Могу ли deploy-овати у више регија?
**О**: Да, конфигуришите више регија у вашим Bicep шаблонима и подесите локацију параметра за свако окружење.

### П: Како да управљам миграцијама шеме базе података?
**О**: Користите deployment hooks у `azure.yaml`:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### П: Могу ли deploy-овати само инфраструктуру без апликација?
**О**: Да, користите `azd provision` да deploy-ујете само инфраструктурне компоненте дефинисане у вашим шаблонима.

### П: Како да deploy-ујем постојеће Azure ресурсе?
**О**: Да, ако шаблон то подржава. Референтно користите постојеће ресурсе са Bicep-овим `existing` декларацијама или параметрима за постојеће ресурсе које шаблон докуметује, и мапирајте сервисе апликације на њихове намењене циљеве. Ово не увози власништво нити аутоматски креира недостајуће дозволе. Прегледајте шаблон пре deploy-а.

### П: Могу ли користити Terraform уместо Bicep-а?
**О**: Да. AZD подржава Terraform, као и Bicep. Изаберите шаблон заснован на Terraform-у или конфигуришите `infra.provider: terraform` у `azure.yaml`, са одговарајућим Terraform фајловима и конфигурацијом стања/backend-а. Погледајте [Terraform workflow](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd).

## Конфигурација и окружења

### П: Како да управљам различитим окружењима (dev, staging, prod)?
**О**: Креирајте одвојена окружења помоћу `azd env new <environment-name>` и конфигуришите различите поставке за сваки:
```bash
azd env new development
azd env new staging  
azd env new production
```

### П: Где се чувају конфигурације окружења?
**О**: У `.azure` фасцикли у оквиру вашег пројектног директоријума. Свака средина има своју фасциклу са конфигурационим фајловима.

### П: Како да подесим конфигурацију специфичну за окружење?
**О**: Користите `azd env set` за подешавање environment променљивих:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### П: Могу ли делити конфигурације окружења међу члановима тима?
**О**: `.azure` фасцикла садржи осетљиве информације и не треба је постићи у верзиони контролу. Уместо тога:
1. Документујте потребне environment променљиве
2. Користите deploy скрипте за постављање окружења
3. Користите Azure Key Vault за осетљиву конфигурацију

### П: Како да превазиђем подразумеване вредности шаблона?
**О**: Подесите environment променљиве које одговарају параметрима шаблона:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

Само променљиве које шаблон користи утичу на deployment. `SKU_NAME` изнад је пример прилагођеног уноса, не универзална AZD подешавања.

## Решавање проблема

### П: Зашто `azd up` не успева?
**О**: Чести узроци:
1. **Проблеми са аутентификацијом**: Покрените `azd auth login`
2. **Недовољне дозволе**: Проверавајте Azure доделе улога
3. **Конфликти у именовању ресурса**: Прегледајте конфликтни ресурс и унос у шаблону за именовање; када је потребна изолација, креирајте одвојено окружење са `azd env new`
4. **Проблеми са квотама/капацитетом**: Проверите регионалну доступност
5. **Грешке у шаблону**: Валидација Bicep шаблона

### П: Како да дебагујем неуспеле deploy-мене?
**О**: 
1. Користите `azd deploy --debug` за детаљан излаз
2. Проверавајте историју deploy-ова на Azure порталу
3. Прегледајте Activity Log на Azure порталу
4. Користите `azd show` за приказ тренутног стања окружења

### П: Зашто ми environment променљиве не функционишу?
**О**: Проверите:
1. Да имена променљивих тачно одговарају параметрима шаблона
2. Да су вредности исправно означене ако садрже размаке
3. Да је одабрано окружење: `azd env select <environment>`
4. Да су променљиве подешене у одговарајућем окружењу

### П: Како да очистим неуспеле deploy-мене?
**О**: 
```bash
azd down
```
 Прво прегледајте изабрано окружење и потврду брисања. Ово брише Azure ресурсе који су били provision-овани, не и локалну конфигурацију окружења `.azure`. `--purge` додатно захтева трајно брисање подржаних soft-deleted ресурса и може бити блокиран од стране заштите задржавања/пурге; није редовни корак опоравка.

### П: Зашто моја апликација није доступна након deploy-а?
**О**: Проверите:
1. Да је deploy успешно завршен
2. Да апликација ради (провера логова на Azure порталу)
3. Да мрежне безбедносне групе дозвољавају саобраћај
4. Да су DNS/прилагођени домени исправно конфигурисани

## Трошкови и фактурисање

### П: Колико ће ме коштати azd deploy-ови?
**О**: Трошкови зависе од:
- Услуга Azure које се deploy-ују
- Нивоа/СКУ услуга које изаберете
- Регионалних разлика у цени
- Обрасца коришћења

Користите [Azure Pricing Calculator](https://azure.microsoft.com/pricing/calculator/) за процене.

### П: Како контролисати трошкове у azd deploy-овима?
**О**: 
1. Користите ниже нивое СКУ-а за развојна окружења
2. Подесите Azure буџете и аларме
3. Користите `azd down` да уклоните ресурсе кад нису потребни
4. Изаберите одговарајуће регионе (трошкови варирају по локацији)
5. Користите Azure алате за управљање трошковима

### П: Постоје ли бесплатне опције за azd шаблоне?
**О**: Неки сервиси имају бесплатне СКУ-ове или месечне доделе, под условом подобности, хостинг плана, региона и ограничења претплате. Ово не чини цео шаблон бесплатним: базе података, претрага, мрежа, регистри, телеметрија и inference модела могу имати независне трошкове. Проверите листу [Azure бесплатних услуга](https://azure.microsoft.com/free/) и тренутне цене за сваки ресурс пре deploy-а.

### П: Како проценити трошкове пре deploy-а?
**О**: 
1. Прегледајте `main.bicep` шаблона да видите који ресурси ће бити креирани
2. Користите Azure Pricing Calculator са специфичним СКУ-овима
3. Прво deploy-ујте у развојно окружење да пратите стварне трошкове
4. Користите Azure Cost Management за детаљну анализу трошкова

## Најбоље праксе

### П: Које су најбоље праксе за структуру azd пројекта?
**О**: 
1. Одвојите код апликације од инфраструктуре
2. Користите смислене називе сервиса у `azure.yaml`
3. Имплементирајте правилно руковање грешкама у build скриптама
4. Користите конфигурацију специфичну за окружење
5. Укључите свеобухватну документацију

### П: Како да организујем више сервиса у azd-у?
**О**: Користите препоручену структуру:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### П: Да ли да укључим `.azure` фасциклу у систему контроле верзија?
**О**: **Не!** `.azure` фасцикла садржи осетљиве податке. Додајте је у `.gitignore`:
```gitignore
.azure/
```

### П: Како да управљам тајнама и осетљивом конфигурацијом?
**О**: 
1. Користите Azure Key Vault за чување тајни
2. Реферишите тајне из Key Vault у конфигурацији апликације
3. Никад не комитујте тајне у систем контроле верзија
4. Користите управљане идентитете за аутентификацију између сервиса

### П: Који је препоручени приступ за CI/CD са azd?
**О**: 
1. Користите одвојена окружења за сваки степен (dev/staging/prod)
2. Имплементирајте аутоматизовано тестирање пре постављања
3. Користите сервисне принципале за аутентификацију
4. Чувајте осетљиву конфигурацију у тајнама/променљивима pipeline-а
5. Имплементирајте одобрење пре производних деплоирања

## Напредне теме

### П: Могу ли проширити azd прилагођеним функционалностима?
**О**: Да, кроз hooks за деплоирање у `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### П: Како да интегришем azd са постојећим DevOps процесима?
**О**: 
1. Користите azd команде у постојећим скриптама pipeline-а
2. Стандардујте azd шаблоне у тимовима
3. Интегришите са постојећим системима за праћење и аларме
4. Користите JSON излаз azd-а за интеграцију у pipeline

### П: Могу ли користити azd са Azure DevOps-ом?
**О**: Да, azd ради са било којим CI/CD системом. Креирајте Azure DevOps pipeline-ове који користе azd команде.

### П: Како могу допринети azd-у или креирати шаблоне за заједницу?
**О**: 
1. **azd alat**: Доприносите на [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **Шаблони**: Пратите упутства за допринос у [Awesome AZD галерији](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **Документација**: Доприносите документацији на [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### П: Који је план рада (roadmap) за azd?
**О**: Погледајте [званични roadmap](https://github.com/Azure/azure-dev/projects) за планиране функције и унапређења.

### П: Како да мигрирам са других алата за деплоирање на azd?
**О**: 
1. Анализирајте тренутну архитектуру деплоирања
2. Креирајте еквивалентне Bicep шаблоне
3. Конфигуришите `azure.yaml` да одговара тренутним сервисима
4. Темљно тестирајте у развојном окружењу
5. Постепено мигрирајте окружења
