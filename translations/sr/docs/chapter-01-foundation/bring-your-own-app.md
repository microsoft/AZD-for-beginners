# Донесите своју апликацију - Додајте azd у постојећи пројекат

**Навигација кроз поглавље:**
- **📚 Почетна страница курса**: [AZD За почетнике](../../README.md)
- **📖 Тренутно поглавље**: Поглавље 1 - Оснивање и брзи почетак
- **⬅️ Претходно**: [Ваш први пројекат](first-project.md)
- **➡️ Следеће**: [Дев контејнери и Кодавски простори](dev-containers.md)

> Преглед команди и конфигурације циља: `azd 1.37.2` (новембар 2026). Генерисани фајлови зависе од детектоване апликације; Azure имплементација није извршена током овог прегледа.

## Увод

У [Ваш први пројекат](first-project.md) сте имплементирали апликацију почевши од шаблона. Али већином већ *имате* апликацију—Node.js API, Python Flask сервис, .NET веб апликацију—која се налази у фолдеру на вашем рачунару. Ова лекција показује како додати azd у тај постојећи код тако да га можете имплементирати уз помоћ `azd up`, без потребе за шаблоном.

## Циљеви учења

До краја ове лекције ћете:
- Разумети три начина за покретање azd пројекта
- Покренути `azd init` у оквиру постојеће базе кода
- Разумети шта `azure.yaml` и фолдер `infra/` значе за вашу апликацију
- Знати када треба дозволити azd-у да генерише инфраструктуру, а када да пишете своју
- Имплементирати вашу постојећу апликацију на Azure помоћу `azd up`

## Резултати учења

Након завршетка ове лекције, моћи ћете да:
- Иницијализујете azd у пројекту који већ поседујете
- Прочитате и уредите основни `azure.yaml` фајл
- Генеришете почетну инфраструктуру уз помоћ `azd infra generate`
- Изаберете одговарајућег Azure домаћина за вашу апликацију
- Имплементирате и очистите своју апликацију

---

## Три начина за покретање azd пројекта

| Појединачан почетак | Команда | Када користити |
|----------------|---------|-------------|
| **Пo шаблону** | `azd init --template <name> .` (празан директоријум) | За учење или покретање нове апликације на основу провереног узорка |
| **Из вашег постојећег кода** | `azd init` (у фолдеру вашег пројекта) | Када већ имате апликацију и желите да је имплементирате |
| **Из Git репозиторијума** | `azd init --from-code` (у клонираном репозиторијуму) | Прихватање azd за постојећи репозиторијум |

Већ сте вежбали прву опцију. Ова лекција покрива другу—најчешћи сценарио у стварном свету.

## Корак 1: Покрените `azd init` у вашем пројекту

Отворите терминал **унутар фолдера вашег постојећег пројекта** и покрените:

```bash
cd my-existing-app
azd init
```

azd ће питати како желите да инициализујете. Изаберите:

```
? How do you want to initialize your app?
> Use code in the current directory
  Select a template
```

Одаберите **"Користи код у тренутном директоријуму."** Затим azd скенира ваш фолдер, детектује језик и оквир, и предлаже домаћина.

### Шта azd детектује

azd тражи знаке апликације као што су `package.json`, `requirements.txt`, `pom.xml`, `*.csproj` или `Dockerfile`. Ток из кода није општи чаробњак за избор домаћина за сваки подржани циљ имплементације:

| Ваша апликација | Вероватно детектовани домаћин |
|----------|----------------------|
| Подржана Node.js / Python / .NET веб апликација | Обично Azure Container Apps; прегледајте генерисану дефиницију |
| Контейнеризована апликација (`Dockerfile`) | Azure Container Apps |
| Функцијска апликација или Static Web Apps пројекат | Користите одговарајући шаблон или ауторство `azure.yaml` и инфраструктуре ако из кода не подржава ваш распоред |

Потврдите детектовану услугу/услуге, и azd ће припремити потребне фајлове.

## Корак 2: Разумети шта је azd креирао

Након иницијализације, прегледајте `azure.yaml`. Ток са генерисаном инфраструктуром може задржати инфраструктуру имплицитном док не покренете `azd infra generate`; немојте претпостављати да `infra/` већ постоји:

```
my-existing-app/
├── azure.yaml          # ← NEW: tells azd what to deploy and where
├── infra/              # Materialized with azd infra generate when using implicit infrastructure
│   ├── main.bicep
│   └── main.parameters.json
├── src/ (your code)    # unchanged
└── ...                 # your existing files, untouched
```

### `azure.yaml` — дефиниција пројекта

Ово је срж azd пројекта. Следећа **илустративна дефиниција App Service** захтева усклађену App Service инфраструктуру; то није разлог за промену домаћина Container Apps без промене инфраструктуре:

```yaml
# azure.yaml
name: my-existing-app
services:
  web:
    project: ./src           # path to your app code
    language: js             # js | python | dotnet | java
    host: appservice         # appservice | containerapp | function | staticwebapp
```

Блок `services` је кључни део: сваки унос мапира фолдер вашег кода на Azure домаћина. Ако ваша апликација има и фронтенд и API, имаћете две услуге.

### `infra/` — ваши Azure ресурси као код

Фасцикла `infra/` садржи Bicep фајлове који дефинишу Azure ресурсе које ваша апликација треба (App Service, базу података итд.). Не морате их писањем ручно—azd генерише радну почетну тачку. Касније их *можете* уређивати да додате ресурсе или појачате безбедност (објашњено у [Поглављу 4](../chapter-04-infrastructure/README.md)).

> **Савет:** Желите да видите или прилагодите генерисану инфраструктуру пре распоређивања? Покрените `azd infra generate` (такође доступан као `azd infra synth`) да бисте записали IaC на диск ради прегледа и контроле верзија.

## Корак 3: Поставите Потребне Конфигурације

Ако ваша апликација треба подешавања или тајне (конекцијски низ, API кључ), немојте их у тврдом коду. Користите вредности окружења:

```bash
# Create an environment
azd env new dev

# Set a non-secret value
azd env set API_VERSION 1.0.0
```

Ово чува само локалну вредност. Да утиче на апликацију, експлицитно је користите у параметрима инфраструктуре, подешавању подржане услуге или као hook; подешавање произвољне променљиве не конфигурише распоређено време извршења.

За стварне тајне, чувате их у Key Vault-у и референцирате их из инфраструктуре—погледајте [Поглавље 3: Конфигурација и Аутентикација](../chapter-03-configuration/authsecurity.md).

---

## Корак 4: Распоређивање

Сада користите исти радни ток који већ познајете:

```bash
# Authenticate (required for azd)
azd auth login

# Preview the resources that will be created
azd provision --preview

# Provision infrastructure and deploy your code
azd up
```

Кад се заврши, azd приказује URL ваше апликације. Потврдите га на исти начин као и било коју azd апликацију:

```bash
azd show           # show endpoints
azd monitor --logs # check logs if needed
```

## Уобичајени Први Проблеми

| Симптом | Веројатни узрок | Решавање |
|---------|--------------|-----|
| azd није открио моју апликацију | Недостаје манифест (нпр., `package.json`) | Додајте манифест, или ручно изаберите хост током `azd init` |
| Собирање не успева током `azd up` | Апликацији је потребан корак собирања | Конфигуришите пакете скрипти за апликацију или сервисни `prepackage` hook; користите `dist` за излаз распоређивања, не `buildCommand`/`outputPath` |
| Апликација се покреће али враћа грешке | Недостају конфигурације/тајне | Повежите вредности у runtime подешавања апликације или Key Vault референцу; сам `azd env set` није довољан |
| Погрешан хост је изабран | Аутоматско откривање не одговара вашим потребама | Промените и `host:` и одговарајућу инфраструктуру, или изаберите одговарајући шаблон |

За више информација, погледајте [Поглавље 7: Решавање проблема](../chapter-07-troubleshooting/README.md).

## Чишћење

```bash
azd down --force --purge
```

---

## Резиме

- `azd init` → **"Употреби код у тренутном директоријуму"** додаје azd у апликацију коју већ имате.
- `azure.yaml` мапира ваше фолдере кода на Azure хостове; `infra/` дефинише ресурсе као Bicep.
- `azd infra generate` вам омогућава да прегледате или прилагодите генерисану инфраструктуру.
- Када је иницијализована, ваша постојећа апликација користи тачно исти `azd up` / `azd down` радни ток као шаблонска апликација.
