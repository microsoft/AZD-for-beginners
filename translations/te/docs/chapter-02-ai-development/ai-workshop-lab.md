## వర్క్‌షాప్ అవలోకనం

ఈ చేతితో చేయదగిన ల్యాబ్ డెవలపర్లను ఒక ఉన్న AI టెంప్లేట్ తీసుకొని దానిని Azure Developer CLI (AZD) ఉపయోగించి డిప్లాయ్ చేసే ప్రక్రియలో మార్గనిర్దేశం చేస్తుంది. మీరు Microsoft Foundry సేవలను ఉపయోగించి ప్రొడక్షన్ AI డిప్లాయ్‌మెంట్ కోసం అవసరమైన నమూనాలను నేర్చుకుంటారు.

> **విడుదల సమీక్ష (2026-11-04):** AZD కమాండ్ మార్గదర్శకత్వం మరియు ఉదాహరణ కాన్ఫిగరేషన్ పేర్లు `azd` `1.37.2` విడుదల మరియు లింకు ఇచ్చిన ఉదాహరణ యొక్క ప్రస్తుత కాన్ఫిగరేషన్‌పై తనిఖీ చేయబడ్డాయి. ఇది ఒక డాక్యుమెంటేషన్ సమీక్ష, ప్రత్యక్ష డిప్లాయ్‌మెంట్ ధృవీకరణ కాదు. RAG ల్యాబ్‌కు ఏజెంట్ ఎక్స్‌టెన్షన్ అవసరం లేదు; ఏజెంట్ మూర్త్యాంకనాలకు వేరు `azure.ai.evaluations` ఎక్స్‌టెన్షన్ మరియు [ప్రస్తుత మూర్త్యాంకన పనిమுறை](../chapter-08-production/production-ai-practices.md#evaluation-migration-and-quality-checks) ఉపయోగించండి, పాత ఏజెంట్ మూర్త్యాంకన కమాండ్లను కాదు.

**కాలవ్యవధి:** 2-3 గంటలు  
**స్థాయి:** మధ్యంతర  
**ముందస్తుగా కావలసినవి:** ప్రాథమిక Azure పరిజ్ఞానం, AI/ML కాన్సెప్ట్‌లపై పరిచయం

### Azure వనరులు

- Microsoft Foundry Models సేవలకు యాక్సెస్ (లేదా యాక్సెస్ అభ్యర్థించగలిగే సామర్ధ్యం)
- వనరు గ్రూప్ సృష్టి అనుమతులు

### జ్ఞాన సంబంధి అవసరాలు

## మాడ్యూల్ 1: AI అప్లికేషన్ల కోసం AZD నిర్మాణం అర్థం చేసుకోవడం

### AI AZD టెంప్లేట్ యొక్క నిర్మాణం

AI-సిద్ధ AZD టెంప్లేట్‌లో కీలకమైన ఫైళ్లను పరిశీలించండి:

```
azure-search-openai-demo/
├── azure.yaml              # AZD configuration
├── infra/                   # Infrastructure as Code
│   ├── main.bicep          # Main infrastructure template
│   ├── main.parameters.json # Environment parameters
│   ├── core/               # Shared infrastructure modules
│   └── app/                # Application-specific infrastructure
├── app/                    # Backend, frontend, and optional ingestion functions
├── scripts/               # Deployment scripts
└── .azure/               # AZD environment files
```

తనిఖీ చేసిన ఉదాహరణ మారవచ్చు; `.azure/` వాతావరణం ప్రారంభమైన తర్వాత వస్తుంది, తప్పనిసరిగా ఒక తాజా క్లోన్‌లో కాదు. ఈ ఆకృతీకరణకు సరిపోవడానికి లేపు డైరెక్టరీలను సృష్టించకుండా వాస్తవ తనిఖీ చేయండి.

### **ల్యాబ్ వ్యాయామం 1.1: కాన్ఫిగరేషన్‌ను పరిశీలించండి**

1. **azure.yaml ఫైల్‌ను పరిశీలించండి:**
```bash
cat azure.yaml
```

**పరిశీలించవలసిన అంశాలు:**
- AI భాగాల కోసం సేవ వివరణలు
- వాతావరణ చారాల మ్యాపింగ్లు
- హోస్ట్ కాన్ఫిగరేషన్స్

2. **main.bicep ఇన్‌ఫ్రాస్ట్రక్చర్‌ను పరిశీలించండి:**
```bash
cat infra/main.bicep
```

**ముఖ్య AI నమూనాలను గుర్తించండి:**
- Microsoft Foundry Models సేవ ప్రావిజనింగ్
- Azure AI Search ఇంటిగ్రేషన్
- సురక్షిత కీ నిర్వహణ
- నెట్‌వర్క్ సెక్యూరిటీ కాన్ఫిగరేషన్స్

### **చర్చ పాయింట్:** ఈ నమూనాలు AI కొరకు ఎందుకు అవసరం

- **సేవల ఆధారితాలు**: AI აპ్స్ తరచు అనేక సమన్వయ సేవలను కోరుకుంటాయి
- **సెక్యూరిటీ**: API కీలు మరియు ఎండ్పాయింట్లు సురక్షితంగా నిర్వహించాలి
- **స్కేలబిలిటీ**: AI వర్క్‌లోడ్లు ప్రత్యేకమైన స్కేలింగ్ అవసరాలు కలిగి ఉంటాయి
- **ఖర్చు నిర్వహణ**: AI సేవలు తగినట్లుగా కాన్ఫిగర్ చేయకపోతే ఖర్చు ఎక్కువవుతుంది

## మాడ్యూల్ 2: మీ మొదటి AI అప్లికేషన్‌ను డిప్లాయ్ చేయండి

### దశ 2.1: వాతావరణం ప్రారంభం

1. **కొత్త AZD వాతావరణాన్ని సృష్టించండి:**
```bash
azd env new myai-workshop
```

2. **అవసరమైన పరామితులను సెట్ చేయండి:**
```bash
# Set your preferred Azure region
azd env set AZURE_LOCATION eastus

# Optional: select a chat model supported by your region and quota
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
```

### దశ 2.2: ఇన్‌ఫ్రాస్ట్రక్చర్ మరియు అప్లికేషన్‌ను డిప్లాయ్ చేయండి

1. **AZD తో డిప్లాయ్ చేయండి:**
```bash
azd up
```

**`azd up` సమయంలో ఏమి జరుగుతుంది:**
- ✅ Microsoft Foundry Models సేవను ప్రావిజన్ చేస్తుంది
- ✅ Azure AI Search సేవను సృష్టిస్తుంది
- ✅ బ్యాకెండ్ మరియు బ్యండిల్ చేయబడిన ఫ్రంట్‌ఎండ్ కోసం Azure కంటైనర్ యాప్స్ సెట్ చేస్తుంది (ప్రస్తుత ఉదాహరణ డిఫాల్ట్)
- ✅ నెట్‌వర్కింగ్ మరియు సెక్యూరిటీని కాన్ఫిగర్ చేస్తుంది
- ✅ అప్లికేషన్ కోడ్‌ని డిప్లాయ్ చేస్తుంది
- ✅ మానిటరింగ్ మరియు లాగింగ్ సెట్ చేస్తుంది

2. **డిప్లాయ్‌మెంట్ పురోగతిని పర్యవేక్షించండి** మరియు సృష్టించబడుతున్న వనరులను గమనించండి.

### దశ 2.3: మీ డిప్లాయ్‌మెంట్‌ను ధృవీకరించండి

1. **డిప్లాయ్ అయిన వనరులను తనిఖీ చేయండి:**
```bash
azd show
```

2. **డిప్లాయ్ అయిన అప్లికేషన్‌ను తెరవండి:**
```bash
azd show
```

`azd show` అవుట్పుట్‌లో చూపించిన వెబ్ ఎండ్పాయింట్‌ను తెరవండి.

3. **AI ఫంక్షనాలిటీని పరీక్షించండి:**
   - వెబ్ అప్లికేషన్‌కు వెళ్ళండి
   - నమూనా క్వెరీలను ప్రయత్నించండి
   - AI ప్రతిస్పందనలు పనిచేస్తున్నాయా అని ధృవీకరించండి

### **ల్యాబ్ వ్యాయామం 2.1: సమస్య పరిష్కరణ ప్రాక్టీస్**

**సన్నివేశం**: మీ డిప్లాయ్‌మెంట్ విజయం సాధించింది కానీ AI స్పందించడం లేదు.

**సాధారణ సమస్యలు జాగ్రత్తగా తనిఖీ చేయాల్సినవి:**
1. **ప్రామాణీకరణ**: మేనేజ్డ్ ఐడెంటిటీ మరియు రోల్ నియామకాలను ధృవీకరించండి; మీరు ప్రత్యేకంగా కీ ఆధారిత ప్రామాణీకరణ ప్రారంభించినట్లయితే మాత్రమే API కీలు తనిఖీ చేయండి
2. **మోడల్ లభ్యత**: మీ ప్రాంతం మోడల్‌ను మద్దతు ఇస్తుందో లేదో తనిఖీ చేయండి

**ఉత్తమ ఆచారం**: అభివృద్ధి మరియు ఉత్పత్తికి వేరే వేరే కాన్ఫిగరేషన్లు.

1. **ఉత్పత్తి పర్యావరణాన్ని సృష్టించండి:**

```bash
azd env new myai-production
```

2. **ఉత్పత్తి-ప్రత్యేక పరామితులను సెటప్ చేయండి:**
```bash
# Use the sample's actual Search SKU parameter
azd env set AZURE_SEARCH_SERVICE_SKU standard

# Enable private endpoints using the sample's parameter
azd env set AZURE_USE_PRIVATE_ENDPOINT true
```

ఈ పేర్లు నమూనా యొక్క [main.parameters.json](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/infra/main.parameters.json) నుండి వస్తాయి. `azd env set` ఒక విలువను నిల్వ చేస్తుంది కానీ అయితే ఒక ఎరుపు వేరియబుల్‌ని ప్రభావితం చేయదు: టెంప్లేట్ దానిని ఉపయోగించాలి. ప్రజా ప్రవేశాన్ని నిలిపివేయకముందు నమూనా యొక్క [నెట్‌వర్క్ ఐసోలేషన్ గైడ్](https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/docs/deploy_private.md)ని సమీక్షించండి మరియు మౌలిక సదుపాయ మార్పులు చేయడానికి `azd up` ఉపయోగించండి. OpenAI SKU `S0` ఒక్కటే మోడల్ సామర్థ్యాన్ని నిర్ణయించదు; మోడల్ నిలపడం రకం మరియు సామర్థ్యం కూడా ముఖ్యం.

### **ల్యాబ్ వ్యాయామం 3.1: ఖర్చు ఆప్టిమైజేషన్**

**సవాలు**: ఖర్చు-ప్రభావవంతమైన అభివృద్ధి కోసం టెంప్లేట్‌ను కాన్ఫిగర్ చేయండి.

**పనులు:**
1. ఉపయోగించే వర్క్‌షాప్ పర్యావరణాన్ని ఎంచుకోండి: `azd env select myai-workshop`.
2. ప్రస్తుత Search SKU మరియు మోడల్ సామర్థ్యాన్ని `infra/main.parameters.json` మరియు ఎంపిక చేసిన పర్యావరణం నుండి రికార్డ్ చేయండి.
3. మోడల్/ప్రాంత క్వోటాను నిర్ధారించిన తరువాత క్రింది మద్దతు ఇచ్చిన ఇన్‌పుట్‌లను ఉపయోగించండి:
   ```bash
   azd env set AZURE_SEARCH_SERVICE_SKU basic
   azd env set AZURE_OPENAI_CHATGPT_DEPLOYMENT_CAPACITY 10
   azd up
   ```
4. పోర్టల్‌లో Search SKU మరియు వీటిని ఏర్పాటు చేసే సామర్థ్యాన్ని ధృవీకరించండి మరియు ధరల గణకంతో తేడాను అంచనా వేశారు. బిల్లింగ్ డేటా తక్షణమే నవీకరించబడుతుందని ఆశించవద్దు.

**విజయ ప్రమాణాలు:** Search Basic ఉపయోగిస్తుందని, చాట్ డిప్లాయ్‌మెంట్ అభ్యర్థించిన మద్దతు సామర్థ్యం కలిగి ఉందని, మరియు అప్లికేషన్ సాంపిల్ ప్రశ్నకు సమాధానం ఇస్తుందని నిర్ధారించాలి. సామర్థ్యం `10` ఒక రేట్-లిమిట్ కేటాయింపు, టోకెన్ ధర తగ్గింపు కాదు. Search స్థాయి మార్పులు పరిమితమవచ్చు లేదా తిరిగి సృష్టించాల్సి ఉంటుంది; ఉత్పత్తి వనరులపై పరీక్షించవద్దు. F0 సేవాధారితమైనదే మరియు Azure OpenAI మోడల్ SKU కాదు.

### దశ 4.2: నెట్‌వర్క్ భద్రత

1. నమూనా మద్దతు ఇచ్చిన నెట్‌వర్క్ కాన్ఫిగరేషన్ ఉపయోగించి ప్రైవేట్ ఎండ్పాయింట్లు ఎనేబుల్ చేయండి (ఇంకా కాన్ఫిగర్ చేయకపోతే).

మీ స్వంత టెంప్లేట్ కోసం, ఈ ఉదాహరణ భాగం OpenAI ఎండ్పాయింట్ కనెక్షన్ చూపిస్తుంది. ఇది VNet, ప్రైవేట్ DNS కాన్ఫిగరేషన్ మరియు అప్లికేషన్ కనెక్టివిటీ అవసరం; దానిని నమూనాలో చిక్క లేకుండా చేర్చవద్దు, అది ఇప్పటికే ప్రైవేట్-ఎండ్పాయింట్ మాడ్యూల్స్ కలిగి ఉంటుంది:
```bicep
// Private endpoint for OpenAI
resource openAIPrivateEndpoint 'Microsoft.Network/privateEndpoints@2023-04-01' = {
  name: 'pe-openai-${uniqueString(resourceGroup().id)}'
  location: location
  properties: {
    subnet: {
      id: vnet.properties.subnets[0].id
    }
    privateLinkServiceConnections: [
      {
        name: 'openai-connection'
        properties: {
          privateLinkServiceId: openAIAccount.id
          groupIds: ['account']
        }
      }
    ]
  }
}
```

### దశ 5.2: మీ AZD టెంప్లేట్ సృష్టించండి

**మీ అప్లికేషన్ మార్చడానికి ఈ నమూనాను అనుసరించండి:**

**కేవలం స్కాఫోల్డ్ చేయండి:** ఈ భాగం API/వెబ్ అప్లికేషన్ సోర్స్, హోస్ట్ మౌలిక సదుపాయాలు, మోడల్ డిప్లాయ్‌మెంట్‌లు, గుర్తింపు/RBAC లేదా పూర్తయిన `main.parameters.json` అందించడం లేదు. రీసోర్స్-గ్రూప్ పరిధిలో బైసెప్ మాడ్యూల్ కంకలనం చూపిస్తుంది; సాధారణ AZD సబ్‌స్క్రిప్షన్ పరిధి ప్రవేశ పాయింట్ రీసోర్స్ గ్రూప్ సృష్టించి దానిని ఆ పరిధిలో పిలవాలి. ఆ భాగాలు కాపీ చేసాక మాత్రమే పూర్తి అప్లికేషన్‌ని `azd up` ద్వారా రూపొందిస్తుందని ఆశించవద్దు. నడిపించగల ప్రాథమికముగా, మాడ్యూల్ 1 నుండి RAG టెంప్లేట్‌ను ఉపయోగించడం కొనసాగించండి.

1. **ప్రాథమిక నిర్మాణాన్ని సృష్టించండి:**
```bash
mkdir my-ai-app-azd
cd my-ai-app-azd

# Initialize AZD template
azd init --template minimal .
```

2. **azure.yaml సృష్టించండి:**
```yaml
# Metadata
name: my-ai-app
metadata:
  template: my-ai-app-template@0.0.1-beta

# Services definition
services:
  api:
    project: ./api
    host: containerapp
  web:
    project: ./web
    host: staticwebapp
    
# Hooks for custom deployment logic  
hooks:
  predeploy:
    shell: sh
    run: echo "Preparing AI models..."
```

3. **మౌలిక సదుపాయ టెంప్లేట్లను సృష్టించండి:**

**infra/main.bicep** - ప్రధాన టెంప్లేట్:
```bicep
@description('Primary location for all resources')
param location string = resourceGroup().location

@description('Name of the OpenAI service')
param openAIServiceName string = 'openai-${uniqueString(resourceGroup().id)}'

// Your AI services here
module openAI 'modules/openai.bicep' = {
  name: 'openai'
  params: {
    name: openAIServiceName
    location: location
  }
}
```

**infra/modules/openai.bicep** - OpenAI మాడ్యూల్:
```bicep
@description('Name of the OpenAI service')
param name string

@description('Location for the OpenAI service')
param location string

resource openAIAccount 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: name
  location: location
  kind: 'OpenAI'
  sku: {
    name: 'S0'
  }
  properties: {
    customSubDomainName: name
    disableLocalAuth: true
  }
}

output endpoint string = openAIAccount.properties.endpoint
output name string = openAIAccount.name
```

### **ల్యాబ్ వ్యాయామం 5.1: టెంప్లేట్ సృష్టి సవాలు**

**సవాలు**: డాక్యుమెంట్ ప్రాసెసింగ్ AI అప్లికేషన్ కోసం AZD టెంప్లేట్ సృష్టించండి.

**అవసరాలు:**
- Microsoft Foundry మోడల్స్ కంటెంట్ విశ్లేషణకు
- OCR కోసం డాక్యుమెంట్ ఇంటెలిజెన్స్
- డాక్యుమెంట్ అప్లోడ్స్ కోసం స్టోరేజ్ అకౌంట్
- ప్రాసెసింగ్ లాజిక్ కోసం ఫంక్షన్ అప్లికేషన్
- యూజర్ ఇంటర్‌ఫేస్ కోసం వెబ్ అప్లికేషన్

**బోనస్ పాయింట్లు:**
- సరియైన పొరపాటు నిర్వహణ జోడించండి
- ఖర్చు అంచనా చేర్చండి
- మానిటరింగ్ డాష్‌బోర్డ్లు ఏర్పాటు చేయండి

## మాడ్యూల్ 6: సైద్దాంతిక సాంకేతిక సమస్యల పరిష్కారం

### సాధారణ డిప్లాయ్‌మెంట్ సమస్యలు

#### సమస్య 1: OpenAI సేవా క్వోటా గరిష్టమైనది
**లక్షణాలు:** క్వోటా లోపం కారణంగా డిప్లాయ్‌మెంట్ విఫలమవుతుంది
**పరిష్కారాలు:**
```bash
# Check current quotas
az cognitiveservices usage list --location eastus

# Request quota increase, OR try a new disposable environment in another region.
# Azure resources cannot be relocated merely by changing AZURE_LOCATION.
azd env new myai-quota-test
azd env set AZURE_LOCATION westus2
azd up
```

#### సమస్య 2: మోడల్ ప్రాంతంలో అందుబాటులో లేదు
**లక్షణాలు:** AI స్పందనలు తప్పు ఇస్తున్నాయి లేదా మోడల్ డిప్లాయ్‌మెంట్ లోపాలు
**పరిష్కారాలు:**
```bash
# Check model availability by region
az cognitiveservices model list --location eastus

# Update to available model
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
azd up
```

#### సమస్య 3: అనుమతి సమస్యలు
**లక్షణాలు:** AI సేవలను పిలిచేటప్పుడు 403 నిషేధిత తప్పిదాలు వస్తున్నాయి
**పరిష్కారాలు:**
```bash

az role assignment list --scope /subscriptions/YOUR_SUB/resourceGroups/YOUR_RG

# Add missing roles
az role assignment create \
  --assignee YOUR_PRINCIPAL_ID \
  --role "Cognitive Services OpenAI User" \
  --scope /subscriptions/YOUR_SUB/resourceGroups/YOUR_RG
```

### పనితీరు సమస్యలు

#### సమస్య 4: నెమ్మదిగా AI స్పందనలు

3. నెట్‌వర్క్ కనెక్టివిటీ మరియు ఆలస్యం నిర్ధారించండి

**పరిష్కారాలు:**

- మీ వినియోగ కేసు కోసం సరైన OpenAI మోడల్‌ను ఉపయోగించండి
- మోడల్ RPM/TPM పరిమితులను తనిఖీ చేసిన తర్వాతే అప్లికేషన్ రిప్లికాలను స్కేలింగ్ చేయండి; Azure OpenAI డిప్లాయ్‌మెంట్స్ సాధారణ డేటాబేస్-స్టైల్ "రీడ్ రిప్లికా" సెట్టింగ్‌లను ఎగ్జిపోజ్ చేయవు

### **ప్రయోగశాల వ్యాయామం 6.1: డీబగ్గింగ్ సవాలు**

**సన్నివేశం**: మీ డిప్లాయ్‌మెంట్ విజయవంతమైంది, కానీ అప్లికేషన్ 500 దోషాలను తిరిగి ఇస్తోంది.

4. కాన్ఫిగరేషన్‌ను సమీక్షించండి

**ఉపయోగించవలసిన టూల్స్:**

## మాడ్యూల్ 7: మానిటరింగ్ మరియు ఆప్టిమైజేషన్

### దశ 7.1: సమగ్ర మానిటరింగ్‌ను సెటప్ చేయండి

1. **కస్టమ్ డాష్‌బోర్డులను సృష్టించండి:**

Azure పోర్టల్‌కు వెళ్లి ఈ అంశాలతో డాష్‌బోర్డ్ సృష్టించండి:
- OpenAI అభ్యర్థన లెక్కింపు మరియు లేటెన్సీ
- అప్లికేషన్ లోపాల రేట్లు
- వనరు వినియోగం
- ఖర్చు ట్రాకింగ్

2. **అలర్టులను సెటప్ చేయండి:**
```bash
# Failed-request count on the Application Insights component (not a percentage)
az monitor metrics alert create \
  --name "AI-App-Failed-Requests" \
  --resource-group YOUR_RG \
  --scopes YOUR_APPLICATION_INSIGHTS_RESOURCE_ID \
  --condition "count requests/failed > 10" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --description "More than 10 failed requests in five minutes"
```

కంపోన్‌మెంట్ అభ్యర్థన టెలిమెట్రీ పంపించిందో ధృవీకరించి, నోటిఫికేషన్లు అవసరమైతే చర్య గ్రూప్ జతచేయండి. మెట్రిక్ ఒక లెక్కింపు, విఫలత శాతం కాదు; రేటు అలర్ట్‌కు సరైన ప్రశ్న మరియు హేతుబద్ధం అవసరం.

### దశ 7.2: ఖర్చు ఆప్టిమైజేషన్

1. **ప్రస్తుత ఖర్చులను విశ్లేషించండి:**
```bash
# Set a recent reporting window supported by your billing account.
az consumption usage list --start-date YYYY-MM-DD --end-date YYYY-MM-DD
```

తేదీ ప్లేస్‌హోల్డర్లను మార్చండి. వినియోగ API మద్దతు బిల్లింగ్ ఒప్పందం ప్రకారం భిన్నంగా ఉంటుంది; వినియోగ వివరాలు అందుబాటులో లేవనట్లయితే పోర్టల్‌లో Cost Management ఉపయోగించండి. ఖర్చులు ఆలస్యంగా వస్తాయి, ఇది తక్షణ పరీక్ష oracle కాదు.

2. **ఖర్చు నియంత్రణలను అమలు చేయండి:**
- బడ్జెట్ అలర్టులను సెటప్ చేయండి
- ఆటోస్కేలింగ్ విధానాలు ఉపయోగించండి
- అభ్యర్థన క్యాషింగ్ అమలు చేయండి
- OpenAI కోసం టోకెన్ వినియోగం మానిటర్ చేయండి

### **ల్యాబ్ వ్యాయామం 7.1: పనితీరు ఆప్టిమైజేషన్**

**కార్యం**: మీ AI అప్లికేషన్ పనితీరు మరియు ఖర్చు రెండింటి కోసం ఆప్టిమైజ్ చేయండి.

**మెట్రిక్స్ మెరుగుపరచాల్సింది:**
- సగటు స్పందన సమయాన్ని 20% తగ్గించండి
- నెలవారీ ఖర్చులను 15% తగ్గించండి
- 99.9% అందుబాటుల SLO మరియు కొలమానం విండోని నిర్వచించండి (చిన్న ల్యాబ్ నెలవారీ అప్‌టైమ్ చూపించడం సాధ్యం కాదు)

**ప్రయత్నించాల్సిన వ్యూహాలు:**
- స్పందన క్యాషింగ్ అమలు చేయండి
- టోకెన్ సామర్థ్యానికి ప్రమ్ప్ట్‌లను ఆప్టిమైజ్ చేయండి
- సరైన కంప్యూట్ SKUలను ఉపయోగించండి
- సరైన ఆటోస్కేలింగ్ సెటప్ చేయండి

- నెలకు $500 లోపు ఖర్చు
- అనేక వాతావరణాల్లో (డెవ్, స్టేజింగ్, ప్రొడక్షన్) డిప్లాయ్ చేయడం

ఇవి ఊహా కంటే భాగస్వామి పరిమితులు, సమకాలీన వారితో ఒప్పందాలు కాదు. ఖర్చులను అంచనా వేయడానికి ముందు అభ్యర్థన రేటు, ప్రాంప్ట్/అవుట్‌పుట్ పరిమాణాలు మరియు సెషన్ వ్యవధిని నిర్వచించండి; 1000 సమకాలీన వినియోగదారులు పని భారాన్ని నిర్ణయించవు లేదా $500 బడ్జెట్ సాధ్యమేనని నిరూపించవు. SOC 2 సంస్థ ఆడిట్ ఫలితం, AZD టెంప్లేట్ ద్వారా సులభంగా మార్చగల విషయం కాదు. ట్రేడ్-ఆఫ్స్‌ను గుర్తించి, అసాధ్యమైన పరిమితులను సాక్ష్యాలతో తిరస్కరించండి.

### అమలు దశలు

1. **ఆర్కిటెక్చర్ రూపకల్పన చేయండి**
2. **AZD టెంప్లేట్ సృష్టించండి**
3. **భద్రతా చర్యలు అమలు చేయండి**
4. **మానిటరింగ్ మరియు అలర్టింగ్‌ను సెటప్ చేయండి**
5. **డిప్లాయ్‌మెంట్ పైప్‌లైన్లను సృష్టించండి**
6. **పరిష్కారాన్ని డాక్యుమెంట్ చేయండి**

### మూల్యాంకన ప్రమాణాలు

- ✅ **ఫంక్షనాలిటీ**: అమలుచేసిన సామర్థ్యాలు ప్రదర్శించబడినవా, మిగిలిన గ్యాప్తంగా స్పష్టంగా ఉన్నాయా?
- ✅ **భద్రత**: ఉత్తమ ప్రాక్టీసులను అమలు చేశారా?

- ✅ **ఖర్చు**: బడ్జెట్‌లో ఉండగలదా?

## 🎓 పూర్తిచేసినcheckpoint  

అభినందనలు! మీరు AI వర్క్‌షాప్ ల్యాబ్ పూర్తి చేసారు. ఇప్పుడు మీరు చేయగలుగుతారు:

- ✅ AZD టెంప్లేట్‌కు არსებული AI అప్లికేషన్‌ను ఎలా అనుకూలీకరించాలో వివరణ ఇవ్వండి
- ✅ AI సూచన అప్లికేషన్‌ను డిప్లాయ్ చేసి పరీక్షించండి
- ✅ AI వర్క్లోడ్‌ల కోసం భద్రత ఉత్తమ ప్రాక్టీసులు అమలు చేయండి
- ✅ AI అప్లికేషన్ పనితీరును మానిటర్ చేసి ఆప్టిమైజ్ చేయండి
- ✅ సాధారణ డిప్లాయ్‌మెంట్ సమస్యలను పరిష్కరించండి

**శుభ్రపరచడం:** `azd env list` ను రన్ చేసి, ఈ లాబ్‌లో సృష్టించబడిన ప్రతి పర్యావరణాన్ని అందులోంచి ఎంచుకోండి (`myai-workshop`, మరియు మీరు డిప్లాయ్ చేసినట్లయితే `myai-production`/`myai-quota-test` కూడా), ಮತ್ತು ప్రతి ఒక్కదానిలో `azd down` ను రన్ చేయండి. డిలీషన్ ప్లాన్‌ను సమీక్షించండి; పర్యావరణ స్థానిక కాన్ఫిగరేషన్ తీసివేత మాత్రమే Azure వనరులను తొలగించదు. మీరు తిరిగి రాబోలేని సోఫ్ట్-డిలీటెడ్ వనరు తొలగింపును అర్థం చేసుకోకపోతే `--purge` ను ఉపయోగించకుండా ఉండండి.
