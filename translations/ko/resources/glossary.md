## 소개

이 포괄적인 용어집은 Azure Developer CLI와 Azure 클라우드 개발에서 사용되는 용어, 개념 및 약어에 대한 정의를 제공합니다. 기술 문서 이해, 문제 해결 및 azd 프로젝트와 Azure 서비스에 대해 효과적으로 소통하는 데 필수적인 참고 자료입니다.

## 학습 목표

이 용어집을 사용하면 다음을 할 수 있습니다:
- 필수 Azure Developer CLI 용어 및 개념 이해
- Azure 클라우드 개발 어휘 및 기술 용어 숙달
- 인프라스트럭처 코드 및 배포 용어를 효율적으로 참고
- Azure 서비스 이름, 약어 및 용도 이해
- 문제 해결 및 디버깅 용어에 대한 정의 접근
- 고급 Azure 아키텍처 및 개발 개념 학습

## 학습 성과

이 용어집을 정기적으로 참고하면 다음을 할 수 있습니다:
- 적절한 Azure Developer CLI 용어를 사용해 효과적으로 소통
- 기술 문서와 오류 메시지를 더 명확히 이해
- Azure 서비스와 개념을 자신 있게 탐색
- 적절한 기술 용어를 사용해 문제 해결
- 정확한 기술 언어로 팀 토론에 기여
- 체계적으로 Azure 클라우드 개발 지식 확장

## A

**ARM 템플릿**  
Azure Resource Manager 템플릿. Azure 리소스를 선언적으로 정의하고 배포하는 JSON 기반 인프라스트럭처 코드 형식입니다.

**앱 서비스**  
인프라를 관리하지 않고 웹 애플리케이션, REST API 및 모바일 백엔드를 호스팅할 수 있는 Azure 플랫폼 서비스(PaaS)입니다.

**애플리케이션 인사이트**  
애플리케이션 성능, 가용성 및 사용 현황에 대한 심층 인사이트를 제공하는 Azure의 애플리케이션 성능 모니터링(APM) 서비스입니다.

**Azure CLI**  
Azure 리소스 관리를 위한 명령줄 인터페이스입니다. AZD를 보완하지만 별도의 로그인 필요; AZD 핵심 인증은 `azd auth login`을 사용합니다.

**Azure Developer CLI (azd)**  
템플릿과 인프라스트럭처 코드를 사용하여 Azure 애플리케이션 구축 및 배포를 가속화하는 개발자 중심 명령줄 도구입니다.

**azure.yaml**  
azd 프로젝트의 주요 구성 파일로서 서비스, 인프라 및 배포 후크를 정의합니다.

**Azure Resource Manager (ARM)**  
리소스 생성, 업데이트, 삭제를 위한 관리 계층을 제공하는 Azure의 배포 및 관리 서비스입니다.

## B

**Bicep**  
Microsoft가 개발한 Azure 리소스 배포용 도메인 특화 언어(DSL). ARM 템플릿보다 단순한 문법을 제공하며 ARM으로 컴파일됩니다.

<strong>빌드</strong>  
소스 코드 컴파일, 종속성 설치 및 애플리케이션 배포 준비 과정입니다.

**블루-그린 배포**  
두 개의 동일한 프로덕션 환경(블루와 그린)을 사용하여 다운타임과 위험을 최소화하는 배포 전략입니다.

## C

**컨테이너 앱**  
복잡한 인프라 관리를 하지 않고 컨테이너화된 애플리케이션을 실행할 수 있는 Azure 서버리스 컨테이너 서비스입니다.

**CI/CD**  
지속적 통합/지속적 배포. 코드 변경 통합 및 애플리케이션 배포를 자동화하는 관행입니다.

**Cosmos DB**  
처리량, 지연, 가용성, 일관성 등에 대해 포괄적인 SLA를 제공하는 Azure의 전 세계 분산 다중 모델 데이터베이스 서비스입니다.

<strong>구성</strong>  
애플리케이션 동작과 배포 옵션을 제어하는 설정 및 매개변수입니다.

## D

<strong>배포</strong>  
대상 인프라에 애플리케이션과 종속성을 설치 및 구성하는 과정입니다.

**Docker**  
컨테이너화 기술을 사용하여 애플리케이션을 개발, 배포 및 실행하는 플랫폼입니다.

**Dockerfile**  
도커 컨테이너 이미지를 빌드하는 명령이 포함된 텍스트 파일입니다.

## E

<strong>환경</strong>  
애플리케이션의 특정 인스턴스를 나타내는 배포 대상 (예: 개발, 스테이징, 프로덕션)입니다.

**환경 변수**  
애플리케이션이 런타임에 접근할 수 있는 키-값 쌍으로 저장된 구성 값입니다.

<strong>엔드포인트</strong>  
애플리케이션이나 서비스를 접근할 수 있는 URL 또는 네트워크 주소입니다.

## F

**Function App**  
인프라 관리를 하지 않고 이벤트 기반 코드를 실행할 수 있는 Azure 서버리스 컴퓨팅 서비스입니다.

## G

**GitHub Actions**  
GitHub 저장소와 통합된 CI/CD 플랫폼으로 워크플로우 자동화에 사용됩니다.

**Git**  
소스 코드 변경 추적을 위한 분산 버전 관리 시스템입니다.

## H

<strong>후크</strong>  
배포 수명 주기의 특정 시점(사전 준비, 사후 준비, 사전 배포, 사후 배포)에 실행되는 사용자 지정 스크립트나 명령입니다.

<strong>호스트</strong>  
애플리케이션이 배포될 Azure 서비스 유형(예: appservice, containerapp, function)입니다.

## I

**인프라스트럭처 코드화 (IaC)**  
수동 프로세스 대신 코드를 통해 인프라를 정의하고 관리하는 관행입니다.

<strong>초기화</strong>  
일반적으로 템플릿에서 새 azd 프로젝트를 초기화하는 과정입니다.

## J

**JSON**  
자바스크립트 객체 표기법. 구성 파일과 API 응답에서 일반적으로 사용되는 데이터 교환 형식입니다.

**JWT**  
JSON 웹 토큰. 당사자 간에 정보를 안전하게 전달하기 위한 JSON 객체 형식 표준입니다.

## K

**키 볼트**  
비밀, 키 및 인증서를 안전하게 저장하고 관리하는 Azure 서비스입니다.

**Kusto 쿼리 언어 (KQL)**  
Azure Monitor, Application Insights 및 기타 Azure 서비스 데이터 분석에 사용되는 쿼리 언어입니다.

## L

**로드 밸런서**  
들어오는 네트워크 트래픽을 여러 서버나 인스턴스에 분산하는 서비스입니다.

**로그 분석**  
클라우드 및 온프레미스 환경에서 원격 텔레메트리 데이터를 수집, 분석 및 대응하는 Azure 서비스입니다.

## M

**관리 ID**  
Azure 서비스가 다른 Azure 서비스 인증을 위해 자동으로 관리되는 ID를 제공하는 기능입니다.

<strong>마이크로서비스</strong>  
애플리케이션을 작고 독립적인 서비스들로 구성하는 아키텍처 접근법입니다.

<strong>모니터</strong>  
애플리케이션과 인프라 전반에 걸쳐 완전한 관찰성을 제공하는 Azure의 통합 모니터링 솔루션입니다.

## N

**Node.js**  
Chrome의 V8 자바스크립트 엔진 기반 서버사이드 애플리케이션 구축을 위한 자바스크립트 런타임입니다.

**npm**  
Node.js용 패키지 관리자이며, 종속성 및 패키지를 관리합니다.

## O

<strong>출력</strong>  
인프라 배포에서 반환되며 애플리케이션이나 다른 리소스에서 사용할 수 있는 값입니다.

## P

<strong>패키지</strong>  
애플리케이션 코드와 종속성을 배포 준비하는 과정입니다.

<strong>매개변수</strong>  
배포를 맞춤 설정하기 위해 인프라 템플릿에 전달되는 입력 값입니다.

**PostgreSQL**  
Azure에서 관리형 서비스로 지원하는 오픈소스 관계형 데이터베이스 시스템입니다.

<strong>프로비저닝</strong>  
인프라 템플릿에 정의된 Azure 리소스를 생성하고 구성하는 과정입니다.

## Q

<strong>쿼터</strong>  
Azure 구독 또는 지역에서 만들 수 있는 리소스 양에 대한 제한입니다.

## R

**리소스 그룹**  
동일한 수명 주기, 권한, 정책을 공유하는 Azure 리소스들의 논리적 컨테이너입니다.

**리소스 토큰**  
배포 전반에서 리소스 이름의 고유성을 보장하기 위해 azd가 생성하는 고유 문자열입니다.

**REST API**  
HTTP 메서드를 사용하여 네트워크 애플리케이션을 설계하는 아키텍처 스타일입니다.

<strong>롤백</strong>  
애플리케이션 또는 인프라 구성의 이전 버전으로 되돌리는 과정입니다.

## S

<strong>서비스</strong>  
azure.yaml에 정의된 애플리케이션 구성 요소(예: 웹 프런트엔드, API 백엔드, 데이터베이스)입니다.

**SKU**  
재고 관리 단위로서 Azure 리소스의 다양한 서비스 티어 또는 성능 수준을 나타냅니다.

**SQL 데이터베이스**  
Microsoft SQL Server 기반 Azure 관리형 관계형 데이터베이스 서비스입니다.

**정적 웹 앱**  
소스 코드 저장소에서 전체 스택 웹 애플리케이션을 빌드하고 배포하는 Azure 서비스입니다.

**스토리지 계정**  
Blob, 파일, 큐, 테이블 등의 데이터 객체를 위한 클라우드 스토리지 서비스를 제공하는 Azure 서비스입니다.

<strong>구독</strong>  
리소스 그룹과 리소스를 보유하고 청구 및 액세스 관리를 포함하는 Azure 계정 컨테이너입니다.

## T

<strong>템플릿</strong>  
애플리케이션 코드, 인프라 정의 및 일반 시나리오 구성을 포함한 미리 만들어진 프로젝트 구조입니다.

**Terraform**  
Azure를 비롯한 여러 클라우드 공급자를 지원하는 오픈소스 인프라스트럭처 코드 도구입니다.

**트래픽 매니저**  
전 세계 Azure 지역 간 트래픽을 분산하는 Azure의 DNS 기반 트래픽 부하 분산기입니다.

## U

**URI**  
통합 자원 식별자. 특정 리소스를 식별하는 문자열입니다.

**URL**  
통합 자원 위치자. 리소스 위치 및 검색 방법을 지정하는 URI 유형입니다.

## V

**가상 네트워크 (VNet)**  
Azure 내 사설 네트워크의 기본 단위로 격리 및 세분화를 제공합니다.

**VS Code**  
Visual Studio Code. Azure 및 azd 통합이 우수한 인기 코드 편집기입니다.

## W

<strong>웹후크</strong>  
특정 이벤트 발생 시 트리거되는 HTTP 콜백으로, 주로 CI/CD 파이프라인에서 사용됩니다.

**가상 실행 계획(What-if)**  
실제 실행하지 않고 배포 시 어떤 변경이 일어날지 보여주는 Azure 기능입니다.

## Y

**YAML**  
YAML은 마크업 언어가 아닙니다. azure.yaml 같은 구성 파일에 사용되는 사람이 읽기 쉬운 데이터 직렬화 표준입니다.

## Z

<strong>존</strong>  
Azure 지역 내 물리적으로 분리된 위치로 중복성과 고가용성을 제공합니다.

## 일반 약어

| 약어 | 전체 명칭 | 설명 |
|---------|-----------|-------------|
| AAD | Azure Active Directory (현 Microsoft Entra ID) | 신원 및 접근 관리 서비스 |
| ACR | Azure Container Registry | 컨테이너 이미지 저장소 서비스 |
| AKS | Azure Kubernetes Service | 관리형 쿠버네티스 서비스 |
| API | Application Programming Interface | 소프트웨어 구축 프로토콜 집합 |
| ARM | Azure Resource Manager | Azure 배포 및 관리 서비스 |
| CDN | Content Delivery Network | 분산 서버 네트워크 |
| CI/CD | 지속적 통합/지속적 배포 | 자동화된 개발 관행 |
| CLI | 명령줄 인터페이스 | 텍스트 기반 사용자 인터페이스 |
| DNS | Domain Name System | 도메인 이름을 IP 주소로 변환하는 시스템 |
| HTTPS | Hypertext Transfer Protocol Secure | HTTPS의 보안 버전 |
| IaC | 인프라스트럭처 코드화 | 코드를 통한 인프라 관리 |
| JSON | JavaScript Object Notation | 데이터 교환 형식 |
| JWT | JSON Web Token | 안전한 정보 전송을 위한 토큰 형식 |
| KQL | Kusto 쿼리 언어 | Azure 데이터 서비스용 쿼리 언어 |
| RBAC | 역할 기반 접근 제어 | 사용자 역할 기반 접근 제어 방식 |
| REST | Representational State Transfer | 웹 서비스 아키텍처 스타일 |
| SDK | 소프트웨어 개발 키트 | 개발 도구 모음 |
| SLA | 서비스 수준 계약 | 서비스 가용성과 성능 보장 약속 |
| SQL | 구조적 쿼리 언어 | 관계형 데이터베이스 관리 언어 |
| SSL/TLS | 보안 소켓 계층/전송 계층 보안 | 암호화 프로토콜 |
| URI | 통합 자원 식별자 | 리소스를 식별하는 문자열 |
| URL | 통합 자원 위치자 | 리소스 위치를 지정하는 URI 유형 |
| VM | 가상 머신 | 컴퓨터 시스템 에뮬레이션 |
| VNet | 가상 네트워크 | Azure 내 사설 네트워크 |
| YAML | YAML은 마크업 언어가 아님 | 데이터 직렬화 표준 |

## Azure 서비스 이름 매핑

| 일반 명칭 | 공식 Azure 서비스 이름 | azd 호스트 유형 |
|-------------|------------------------------|---------------|
| 웹 앱 | Azure App Service | `appservice` |
| API 앱 | Azure App Service | `appservice` |
| 컨테이너 앱 | Azure Container Apps | `containerapp` |
| 함수 | Azure Functions | `function` |
| 정적 사이트 | Azure Static Web Apps | `staticwebapp` |
| 데이터베이스 | Azure Database for PostgreSQL | 인프라 리소스, 애플리케이션 아님 `host` |
| NoSQL DB | Azure Cosmos DB | 인프라 리소스, 애플리케이션 아님 `host` |
| 스토리지 | Azure Storage Account | 인프라 리소스, 내장 애플리케이션 아님 `host` |
| 캐시 | Azure Managed Redis | 인프라 리소스, 애플리케이션 아님 `host` |
| 검색 | Azure AI Search | 인프라 리소스, 애플리케이션 아님 `host` |
| 메시징 | Azure Service Bus | 인프라 리소스, 애플리케이션 아님 `host` |

`services.<name>.host`는 애플리케이션 배포 대상을 선택하며 어떤 Azure 리소스 유형의 약칭이 아닙니다. 데이터베이스, 캐시, 검색 서비스 및 큐는 일반적으로 인프라 공급자를 통해 프로비저닝되고 출력/구성으로 애플리케이션에 연결됩니다.

## 상황별 용어

### 개발 용어
- **핫 리로드**: 재시작 없이 개발 중 애플리케이션 자동 업데이트
- **빌드 파이프라인**: 코드 빌드 및 테스트 자동화 과정
- **배포 슬롯**: 앱 서비스 내 스테이징 환경
- **환경 동등성**: 개발, 스테이징, 프로덕션 환경 유사성 유지

### 보안 용어
- **관리 ID**: 자동 자격 증명 관리를 제공하는 Azure 기능
- **키 볼트**: 비밀, 키, 인증서 안전 저장소
- **RBAC**: Azure 리소스에 대한 역할 기반 접근 제어
- **네트워크 보안 그룹**: 네트워크 트래픽 제어용 가상 방화벽

### 모니터링 용어
- <strong>텔레메트리</strong>: 자동 측정 및 데이터 수집
- **애플리케이션 성능 모니터링(APM)**: 소프트웨어 성능 모니터링
- **로그 분석**: 로그 데이터 수집 및 분석 서비스
- **경고 규칙**: 메트릭 또는 조건에 따른 자동 알림

### 배포 용어
- **블루-그린 배포**: 무중단 배포 전략
- **카나리아 배포**: 일부 사용자에 대한 점진적 롤아웃
- **롤링 업데이트**: 애플리케이션 인스턴스 순차 교체
- <strong>롤백</strong>: 이전 애플리케이션 버전으로 복귀
