- Microsoft Foundry Models சேவைகள் அணுகல் (அல்லது அணுகல் கோரிக்கையிடும் திறன்)

## தொகுதி 1: AI பயன்பாடுகளுக்கான AZD அமைப்பை அறிதல்

### AI AZD வார்ப்புருவின் அமைப்பு

AI-தயாரான AZD வார்ப்புருவின் முக்கிய கோப்புகளை ஆராய்க:

```
azure-search-openai-demo/
├── azure.yaml              # AZD configuration
├── infra/                   # Infrastructure as Code
│   ├── main.bicep          # Main infrastructure template
│   ├── main.parameters.json # Environment parameters
│   ├── core/               # Shared infrastructure modules
│   └── app/                # Application-specific infrastructure
├── app/                    # Backend, frontend, and optional ingestion functions
├── scripts/               # Deployment scripts
└── .azure/               # AZD environment files
```

சரிபார்க்கப்பட்ட மாதிரி மாற்றப்படலாம்; `.azure/` சுற்றுச்சூழல் துவக்கத்திற்கு பிறகு தோன்றும், புதிய கிளோனில் தேவையில்லை. இந்த படிமத்தை ஒப்பிட, கிடைக்கும் கிளோனின் நிறைவேற்றலை பரிசீலிக்கவும், குறைந்த சட்டப்படுத்தப்பட்ட கோப்புறைகளை உருவாக்க வேண்டாம்.

### **பயிற்சி 1.1: கட்டமைப்பை ஆராய்தல்**

1. **azure.yaml கோப்பை ஆய்வு செய்யவும்:**
```bash
cat azure.yaml
```

**காண வேண்டியது:**
- AI கூறுகளுக்கான சேவை வரைவுகள்
- சுற்றுச்சூழல் மாறிலி மாப்பிங்குகள்
- ஹோஸ்ட் அமைப்புகள்

2. **main.bicep சார்ந்த கட்டமைப்பை பார்வையிடவும்:**
```bash
cat infra/main.bicep
```

**முக்கிய AI முறைமைகள்:**
- Microsoft Foundry Models சேவை வழங்கல்
- அசூர் AI Search இன்டிக்ரேஷன்
- பாதுகாப்பான விசை நிர்வாகம்
- நெட்வொர்க் பாதுகாப்பு அமைப்புகள்

### **பேச்சுவார்த்தை புள்ளி:** AI க்கான இந்த முறைமைகள் முக்கியத்துவம் என்ன

- **சேவை சார்புகள்**: AI பயன்பாடுகள் பொதுவாக பல சேவைகள் இணைப்பை தேவைப்படுத்தும்
- **பாதுகாப்பு**: API விசைகள் மற்றும் முனையங்கள் பாதுகாப்பாக நிர்வகிக்கப்பட வேண்டும்
- **விரிவாக்கம்**: AI பணிகளுக்கு தனித்துவமான விரிவாக்க தேவைகள் இருக்கின்றன
- **காசோலை மேலாண்மை**: AI சேவைகள் சரியான அமைப்பில் இல்லாவிட்டால் பணம் அதிகமாக செலவுயும்

## தொகுதி 2: உங்கள் முதல் AI பயன்பாட்டை பங்கேற்க

### படி 2.1: சுற்றுச்சூழலை துவக்க விடுவி

1. **புதிய AZD சுற்றுச்சூழலை உருவாக்கவும்:**
```bash
azd env new myai-workshop
```

2. **தேவையான பண்புகளை நிலைநாட்டவும்:**
```bash
# Set your preferred Azure region
azd env set AZURE_LOCATION eastus

# Optional: select a chat model supported by your region and quota
azd env set AZURE_OPENAI_CHATGPT_MODEL gpt-4.1-mini
```

### படி 2.2: கட்டமைப்பு மற்றும் பயன்பாட்டை பங்கேற்பு செய்யவும்

1. **AZD மூலம் பங்கேற்பு செய்யவும்:**
```bash
azd up
```

**`azd up` செயல்படும்போது நிகழ்வுகள்:**
- ✅ Microsoft Foundry Models சேவை வழங்குகிறது
- ✅ அசூர் AI Search சேவை உருவாக்கப்படுகிறது
- ✅ பின்புறம் மற்றும் தொகுக்கப்பட்ட முன் முடிவிற்கு அசூர் கன்டெய்னர் ஆப்ஸ் அமைக்கப்படுகிறது (தற்போதைய மாதிரி இயல்பானது)
- ✅ நெட்வொர்கிங் மற்றும் பாதுகாப்பு அமைப்புக்கள் நிலைநாடு செய்யப்படுகிறது
- ✅ பயன்பாட்டு குறியீடு பங்கேற்பு செய்யப்படுகிறது
- ✅ கண்காணிப்பு மற்றும் பதிவு அமைக்கப்படுகிறது

2. **பங்கேற்பினை கண்காணிக்கவும்** மற்றும் உருவாக்கப்படும் வளங்களை கவனிக்கவும்.

### படி 2.3: உங்கள் பங்கேற்பை சரிபார்க்கவும்

1. **உருவாக்கப்பட்ட வளங்களை சரிபார்க்கவும்:**
```bash
azd show
```

2. **உருவாக்கப்பட்ட பயன்பாட்டை திறக்கவும்:**
```bash
azd show
```

`azd show` வெளியீட்டில் காட்டப்பட்ட வலை முனையத்தை திறக்கவும்.

3. **AI செயல்பாட்டை சோதிக்கவும்:**
   - வலை பயன்பாட்டை திறக்கவும்
   - மாதிரி வினாக்களை முயற்சி செய்யவும்
   - AI பதில்கள் வேலை செய்தே இருப்பது உறுதி செய்யவும்

### **பயிற்சி 2.1: பிரச்சனைத் தீர்க்கும் பயிற்சி**

**சூழல்:** உங்கள் பங்கேற்பு வெற்றிகரமாக முடிந்தது, ஆனால் AI பதிலளிக்கவில்லை.

**சாதாரண சிக்கல்களை சரிபார்க்க:**
1. **அங்கீகாரம்**: நிர்வகிக்கப்பட்ட அடையாளம் மற்றும் பங்கு ஒதுப்பீடுகளை சரிபார்; விசை அடிப்படையிலான அங்கீகரம் தெளிவாக இயலுமெனில் API விசைகளை மட்டுமே சரிபார்
2. **மாதிரி கிடைப்புத்தன்மை**: உங்கள் பிராந்தியத்தில் மாதிரி ஆதரவு உள்ளதா பார்க்கவும்
3. **நெட்வொர்க் தொடர்பு**: சேவைகள் தொடர்பு கொள்ள முடிகிறதா என உறுதிசெய்க
4. **RBAC அனுமதிகள்**: பயன்பாட்டுக்கு OpenAI அணுகல் உள்ளது என்பது உறுதி செய்யவும்

### **பயிற்சி 3.1: செலவு வேன்மை**

**சவால்**: செலவு பயனுள்ள மேம்பாடு வார்ப்புருவை அமைக்கவும்.


**வெற்றி அளவுகோல்:** Search Basic பயன்படுத்துகிறது, உரையாடல் பங்கேற்பு கோரிய திறன் பெற்றுள்ளது, பயன்பாடு இன்னும் மாதிரி கேள்விக்கு பதில் அளிக்கிறது. திறன் `10` என்பது வீத-வரம்பு ஒதுக்கீடு, டோக்கன் விலை தள்ளுபடி அல்ல. Search தர தொழிற்சாலை மாற்றங்கள் கட்டுப்படுத்தப்படலாம் அல்லது காப்புமாற்றத்தைக் கேட்கலாம்; உற்பத்தி வளங்களில் பரீட்சை செய்ய வேண்டாம். F0 என்பது சேவை குறிப்பிடப்பட்டவை மற்றும் அசூர் OpenAI மாதிரி SKU அல்ல.

### படி 4.2: நெட்வொர்க் பாதுகாப்பு

உங்கள் சொந்த வார்ப்புருவுக்கு, இந்த விளக்க துண்டு OpenAI முனைய இணைப்பை காண்பிக்கிறது. இதற்குப் பின்வரும் தேவை: VNet, தனியார் DNS கட்டமைப்பு மற்றும் பயன்பாட்டு இணைய இணைப்பு; மாதிரியில் ஏற்கனவே தனி-முனைய மாட்யூல்களும் உள்ளதால் இதை மாற்றாமல் நகலெடுக்க வேண்டாம்:
```bicep
// Private endpoint for OpenAI
resource openAIPrivateEndpoint 'Microsoft.Network/privateEndpoints@2023-04-01' = {
  name: 'pe-openai-${uniqueString(resourceGroup().id)}'
  location: location
  properties: {
    subnet: {
      id: vnet.properties.subnets[0].id
    }
    privateLinkServiceConnections: [
      {
        name: 'openai-connection'
        properties: {
          privateLinkServiceId: openAIAccount.id
          groupIds: ['account']
        }
      }
    ]
  }
}
```

## தொகுதி 5: உங்கள் சொந்த AI பயன்பாட்டை மாற்றுதல்

### படி 5.1: மதிப்பாய்வு வேலைपत्रம்

**உங்கள் பயன்பாட்டை மாற்றுவதற்கு முன்**, கீழ்காணும் கேள்விகளுக்கு பதில் அளிக்கவும்:

1. **பயன்பாட்டு கட்டமைப்பு:**
   - உங்கள் பயன்பாடு எந்த AI சேவைகளை பயன்படுத்துகிறது?
   - அது எத்தனை கணினி வளங்களை தேவைப்படுத்துகின்றது?
   - அதற்கு தரவுத்தளம் தேவைப்படுமா?
   - சேவைகளுக்கிடையேயான சார்புகள் என்ன?

2. **பாதுகாப்பு தேவைகள்:**
   - எந்த உணர்வூட்டும் தரவை உங்கள் பயன்பாடு கையாள்கிறது?
   - எவ்வித ஒத்துழைப்பு விதிமுறைகள் உண்டா?
   - தனிப்பட்ட வலய இணைப்பு தேவைப்படுமா?

3. **விரிவாக்க தேவைகள்:**
   - எதிர்பார்க்கப்படும் சுமை என்ன?
   - தானாக விரிவாக்கம் தேவைபடுமா?
   - பிராந்திய தேவைகள் உள்ளனவா?

### படி 5.2: உங்கள் AZD வார்ப்புருவை உருவாக்கவும்

**உங்கள் பயன்பாட்டை மாற்ற இதோ மாதிரி பின்பற்றவும்:**

**மட்டும் ஸ்காஃபோல்ட்:** இந்தப் பகுதி API/இணையப் பயன்பாட்டு மூலக் கோடு, ஹோஸ்ட் சமூகமைப்பு, மாதிரி விரிவாக்கங்கள், அடையாளம்/RBAC, அல்லது முடிக்கப்பட்ட `main.parameters.json` ஐ வழங்காது. வள-குழு-அளவிடப்பட்ட பைஸிப் கூறுப்பொருள் அமைப்பைக் காட்டுகிறது; ஒரு வழக்கமான AZD சந்தா-அளவிடப்பட்ட நுழைவாயில் ஒரு வளக் குழுவை உருவாக்கி அந்த அளவிடம் அதை அழைக்க வேண்டும். இந்த பகுதி துணுக்குகளை காப்பியிட்டு மட்டுமே முழுமையான பயன்பாட்டை `azd up` விரிவாக்கும் என்று எதிர்பார்க்க வேண்டாம். ஓடும் அடிப்படைக்கும், தொகுதி 1 இல் இருந்து RAG வார்ப்புருவைப் பயன்படுத்திக் கொண்டிருக்க வேண்டும்.

1. **அடிப்படை அமைப்பை உருவாக்கவும்:**
```bash
mkdir my-ai-app-azd
cd my-ai-app-azd

# Initialize AZD template
azd init --template minimal .
```

2. **azure.yaml ஐ உருவாக்கவும்:**
```yaml
# Metadata
name: my-ai-app
metadata:
  template: my-ai-app-template@0.0.1-beta

# Services definition
services:
  api:
    project: ./api
    host: containerapp
  web:
    project: ./web
    host: staticwebapp
    
# Hooks for custom deployment logic  
hooks:
```

## மொடியூல் 7: கண்காணிப்பு மற்றும் மேம்படுத்தல்

### படி 7.1: விரிவான கண்காணிப்பை அமைக்கு

1. **தனிப்பயன் டாஷ்போர்டுகளை உருவாக்குக:**

Azure போர்டல் செல்லவும் மற்றும் பின்வருமாறு டாஷ்போரை உருவாக்கவும்:
- OpenAI கோரிக்கை எண்ணிக்கை மற்றும் தாமதம்
- பயன்பாட்டு பிழை விகிதங்கள்
- வள பயன்பாடு
- செலவியல் கண்காணிப்பு

2. **அலைட்டுகளை அமைக்கவும்:**
```bash
# Failed-request count on the Application Insights component (not a percentage)
az monitor metrics alert create \
  --name "AI-App-Failed-Requests" \
  --resource-group YOUR_RG \
  --scopes YOUR_APPLICATION_INSIGHTS_RESOURCE_ID \
  --condition "count requests/failed > 10" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --description "More than 10 failed requests in five minutes"
```

கூறு கோரிக்கை தொலைநிலை அளவுரு வெளியிடுவதை சரிபார்க்கவும், அறிவிப்புகள் தேவைப்பட்டால் செயல் குழுவை சேர்க்கவும். அளவுபடம் ஒரு எண்ணிக்கை, தோல்வி சதவீதம் இல்லை; விகித அலைட்டு உரியக் கேள்வி மற்றும் காணொளி தேவை.

- பட்ஜெட் அறிவிப்புகளை அமைக்கவும்
- தானியங்கித் தூக்கியெடுக்கும் கொள்கைகளைப் பயன்படுத்தவும்
- கோரிக்கை கேஷிங் செயல்படுத்தவும்
- OpenAI டோக்கன் பயன்பாட்டைப் கண்காணிக்கவும்

இவை வழக்கமான பங்குதாரர் கட்டுப்பாடுகள், ஒரே நேரத்தில் உறுதி செய்யப்படும் முடிவுகள் அல்ல. கோரிக்கை வீதி, முன்மொழிவு/வெளியீடு அளவுகள், அமர்வு நேரத்தை வரையறுக்கவும் செலவுகளை மதிப்பீடு செய்வதற்கு முன்; 1000 இணைந்து பயனர்கள் வேலைப்பளுவை உறுதிப்படுத்தாது அல்லது $500 பட்ஜெட் சாத்தியமென நிரூபிக்காது. SOC 2 என்பது நிறுவன மதிப்பீடு முடிவு, AZD வடிவமைப்பால் இயக்கப்படக்கூடிய ஒரு மாற்றியல்ல. மாற்றுத்திறன்கள் மற்றும் சாத்தியமற்ற கட்டுப்பாடுகளை அடையாளம் காணவும் ஆதாரத்துடன் நிராகரிக்கவும்.

## 🎓 நிறைவு நிலை

வாழ்த்துக்கள்! நீங்கள் AI பணிமனை பயிற்சியை முடித்துவிட்டீர்கள். இப்போது நீங்கள் செய்யக்கூடியவை:

- ✅ உள்ளமைக்கப்பட்ட AI பயன்பாட்டை AZD வடிவமைப்பில் எவ்வாறு அமைப்பது என்பதை விளக்கவும்
- ✅ AI குறிப்புச் செயலியை மேய்ப்பு செய்து சோதிக்கவும்
- ✅ AI வேலைபளுக்கான சிறந்த பாதுகாப்பு நடைமுறைகளை செயல்படுத்தவும்
- ✅ AI பயன்பாட்டின் செயல்திறனை கண்காணித்து மேம்படுத்தவும்
- ✅ பொதுவான மேய்ப்பு பிரச்சினைகளை தீர்க்கவும்

**சுத்தம் செய்யவும்:** `azd env list` ஓட்டுக, இந்த பணிமனையில் உருவாக்கப்பட்ட ஒவ்வொரு பயன்பாட்டு சூழலைத் தேர்ந்தெடுக்கவும் (`myai-workshop`, மற்றும் நிலைத்திருந்தால் `myai-production`/`myai-quota-test`), மற்றும் ஒவ்வொன்றிலும் `azd down` ஓட்டவும். அழிக்கும் திட்டத்தை மதிப்பாய்வு செய்யவும்; ஒரு சூழலின் உள்ளக கட்டமைப்பை அழிப்பது Azure வளங்களை நீக்கவில்லை. மாற்றமுடியாத மென்மை நீக்கப்பட்ட வளங்களை நீக்கும் செயல்முறையைப் புரிந்துகொள்ளாதவர்களுக்கு `--purge` தவிர்க்கவும்.

### அடுத்து செய்யவுள்ளவை
1. இந்த மாதிரிகளை உங்கள் AI திட்டங்களில் பயன்படுத்து
2. மாதிரிகளை சமூகத்திற்கு திருப்பிச் செலுத்துக
3. தொடர்ந்து ஆதரவுக்கு Microsoft Foundry Discord அணி சேர்ந்துகொள்ளவும்
4. பல பிரதேச மேய்ப்பு போன்று மேம்பட்ட தலைப்புக்களை ஆராயவும்
