# Глава 6: Планиране и валидация преди разгръщане

**📚 Курс**: [AZD за начинаещи](../../README.md) | **⏱️ Продължителност**: 2-4 часа четене; допълнително време за адаптирани лаборатории | **⭐ Сложност**: Средно–напреднала

---

## Преглед

Тази глава обхваща основни стъпки за планиране и валидация преди да разположите вашето приложение. Научете как да избегнете скъпи грешки с правилно планиране на капацитета, избор на SKU и предварителни проверки.

> Ръководството за команди е проверено спрямо публикувания `azd 1.37.2` справочник. Разгръщанията в облака не са изпълнявани. По-дългите уроци включват илюстративни фрагменти, а не пълни локални проекти за разгръщане.

## Учебни цели

След завършване на тази глава ще можете:
- Да изпълнявате предварителни проверки преди разгръщане
- Да планирате капацитета и да оценявате изискванията за ресурси
- Да избирате подходящи SKU за оптимизация на разходите
- Да конфигурирате Application Insights за наблюдение
- Да разбирате модели на координация на множество агенти и техните изисквания за разгръщане

## 🚀 Бърз старт

```bash
# Check subscription quotas
az vm list-usage --location eastus --output table

# Preview infrastructure changes (inspect template hooks before running)
azd provision --preview

# Validate Bicep syntax
az bicep build --file infra/main.bicep

# Check environment configuration
azd env get-values
```

## ☑️ Контролен списък преди разгръщане

### Преди `azd provision`

- [ ] Проверен квотен лимит за региона
- [ ] Подбрани подходящи SKU
- [ ] Прегледана ценова оценка
- [ ] Консистентно именуване
- [ ] Конфигурирана сигурност/RBAC

### Преди `azd deploy`

- [ ] Зададени стойности на променливи на средата
- [ ] Тайни в Key Vault
- [ ] Проверени връзки за свързване
- [ ] Конфигурирани проверки за здраве

## 💰 Ръководство за избор на SKU

| Товар | Разработка | Производство |
|----------|-------------|------------|
| Container Apps | Потребление | Потребление или специален профил товар, базиран на измереното натоварване |
| App Service | B1/B2 | P1v3+ |
| Azure OpenAI модели | Поддържана pay-as-you-go схема за разгръщане | pay-as-you-go или осигурена пропускателна способност; зависи от модела/региона |
| AI Search | Безплатен/Основен в рамките на лимитите | Основен или стандартен план, съобразен с индекса, репликите и натоварването при заявки |
