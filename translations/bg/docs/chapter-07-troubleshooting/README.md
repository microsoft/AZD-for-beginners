## Преглед

Тази глава ви помага да диагностицирате и разрешавате често срещани проблеми при работа с Azure Developer CLI. От неуспехи при разгръщане до специфични проблеми с AI.

> Ръководството за команди е проверено спрямо пуснатия `azd 1.37.2` справочник. Облачните разгръщания не са изпълнявани. Заменете примерните имена и идентификатори на ресурси преди използване на командите.

## Учебни цели

Чрез завършването на тази глава ще:
- Диагностицирате често срещани грешки при разгръщане с AZD
- Дебъгнете проблеми с автентикация и разрешения
- Решите проблеми с връзката с AI услуги
- Използвате Azure Portal и CLI за отстраняване на проблеми

## 🚨 Бързи решения

### Проблеми с автентикация
```bash
# Required for AZD workflows
azd auth login

# Optional if you are also using Azure CLI commands directly
az login

azd auth login --check-status
```

### Провали при разгръщане
```bash
azd show
azd monitor --logs
az deployment sub list --query "[?properties.provisioningState!='Succeeded']"
```

### Конфликти на ресурси
Първо проверете съществуващите ресурси и грешки при разгръщане. Не изтривайте споделена или продукционна среда за разрешаване на конфликт с името. За **нова временна среда**, използвайте уникално име:

```bash
azd env new different-name
azd up
```

### Превишена квота
```bash
az vm list-usage --location eastus --output table
# Check the affected service's own quotas, not just VM quotas.
# For a new environment only, choose a supported region with available quota.
```

Смяната на `AZURE_LOCATION` не премества съществуващите ресурси и може да предизвика конфликти при локацията при повторно разгръщане.

## 📋 Справка с кодове за грешки

| Грешка | Причина | Решение |
|-------|-------|----------|
| `AuthenticationError` | Не сте влезли | `azd auth login` |
| `ResourceNotFound` | Липсващ ресурс | Проверете имената на ресурсите |
| `QuotaExceeded` | Ограничения на абонамента | Искане за увеличение на квотата |
| `InvalidTemplate` | Синтактична грешка в Bicep | `az bicep build` |
| `Conflict` | Ресурсът съществува | Използвайте ново име или изтрийте съществуващия |
| `Forbidden` | Недостатъчни разрешения | Проверете RBAC ролите |

## 🔄 Нулиране и възстановяване

```bash
# Soft reset (keep resources, redeploy code)
azd deploy

# Hard reset (delete everything, start fresh)
azd down
azd up
```

Твърдото нулиране изтрива данни и може да промени крайните точки. Направете архив първо и прегледайте интерактивните подкани за изтриване. `--force --purge` е подходящо само за временни среди, когато е необходима необратима изтриване.
