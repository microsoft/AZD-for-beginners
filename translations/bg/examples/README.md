Има **четири образци на приложения** и **една инфраструктурна основа**:

| Пример | Локална имплементация | Фокус на ученето | Ниво |
|---|---|---|---|
| [Simple Flask API](../../../examples/container-app/simple-flask-api) | Flask CRUD API, Dockerfile, Bicep, `azure.yaml` | Разполагане на контейнери, проверки, логове | Начинаещ |
| [Two-service microservices](../../../examples/container-app/microservices) | Node.js gateway и read-only Python услуга за продукт, Dockerfiles, Bicep, `azure.yaml` | Вътрешна HTTPS комуникация, независимо мащабиране | Средно ниво |
| [Database app](../../../examples/database-app) | Flask read API, Azure SQL, App Service, Bicep, `azure.yaml` | SQL свързаност, инициализация, логове | Средно ниво |
| [Azure OpenAI chat](../../../examples/azure-openai-chat) | Локален Python CLI, Azure OpenAI и Key Vault Bicep, само инфраструктура `azure.yaml` | Осигуряване на модели, чат история, оценки на токени | Средно ниво |
| [Retail infrastructure](../../../examples/retail-multiagent-arm-template) | ARM шаблон, параметри, Bash скрипт за разполагане; **само „hello-world“ контейнери** | Инфраструктура за бъдещо мултиагентно приложение | Напреднал |

Сценарият за [търговия на дребно](retail-scenario.md) е **архитектурен план**, а не
пълна реализация на множество агенти. Без код за търговски агент, чат интерфейс, маршрутизатор
Включени са API, тръбопровод за търсене на данни, CLI за оценка, автоматично превключване при повреда или затягане на продукцията.
Те трябва да бъдат проектирани, изградени и тествани поотделно.

Прегледът на [микросервизи](microservices/README.md) сочи към изпълнимия
пример с две услуги; това не е друга директория за разгръщане.

## Препоръчителен учебен път

1. Разположете Flask API и проверете `/health` и CRUD операциите.
2. Разположете приложението със база данни и проверете неговите пет попълнени продукта.
3. Разположете примера с две услуги и проверете заявките от шлюза към продукта.
4. Осигурете ресурсите за чат и стартирайте интерактивния CLI **локално**.
5. Изучете търговския план след като завършите работещите примери.

Отделете приблизително 30–60 минути на пример за приложение, включително предварителни изисквания и
проверка. Ритейл имплементацията е отделен проект за разработка, а не
30-минутен работен семинар. Четенето на неговата архитектура отнема около 2–3 часа; имплементацията
и готовността за продукция могат да отнемат значително повече от илюстративните
80–120 часа за разработка в ръководството.

## Бърз старт

От корена на хранилището, за първия контейнерен пример:

```bash
cd examples/container-app/simple-flask-api
azd auth login
azd env new flask-demo
azd up
API_URL=$(azd env get-value API_ENDPOINT)
curl --fail-with-body "${API_URL}/health"
```

Очаквано: HTTP 200 и JSON, съдържащ `"status": "healthy"`.
Трябва да имате стартиран Docker за локалното компилиране на контейнера.

За чат, следвайте [chat README](azure-openai-chat/README.md): използвайте
`azd provision`, заредете API ключа от Key Vault в текущия шел, инсталирайте
`src/requirements.txt`, и стартирайте `python src/chat.py`. Няма хоствана чат услуга.

За търговци, използвайте [ARM ръководството](retail-multiagent-arm-template/README.md).
То няма `azure.yaml` и **не** се разгръща или премахва от `azd up`/`azd down`.

## Разходи и ограничения

- Всички разгръщания създават таксувани Azure ресурси. Масштабиране до нула се прилага само за
  изчисления на приложението; то не премахва разходи за регистър, база данни, съхранение, търсене или логове.
- Точните цени зависят от региона, валутата, трафика, модела/SKU и съхранението.
  Използвайте [калькулатора на цените на Azure](https://azure.microsoft.com/pricing/calculator/)
  преди разгръщане и настройте бюджет в Azure Cost Management.
- Данните в Flask CRUD са в паметта, ограничени до един работник и най-много едно копие по
  подразбиране. Те изчезват при рестарт или при мащабиране до нула. Това не е трайно съхранение.
- Микросервисът за продукта предлага само GET крайни точки. Не е включена услуга за поръчки, потребителска
  услуга, база данни, Service Bus, C# или Go имплементация.
- Ресурсите на Application Insights не инструктират автоматично всяко приложение.
  Консултирайте се с всяко примерче за телеметрията, която реално се излъчва.
- Примерите не реализират удостоверяване на приложението. Добавете идентичност, авторизация,
  постоянно съхранение, мрежови контроли, тестове и оперативни процедури преди продукция.

```text

├── azure-openai-chat/               # Local CLI + model infrastructure
```

## Изчистване

За четирите примерa на AZD изпълнете това **от избраната директория на примера**:

```bash
azd down
```

Прегледайте съобщението за изтриване. За търговия на дребно изтрийте само специалната ресурсна група,
която сте създали, използвайки инструкциите в неговото ARM ръководство. Проверете Azure Cost Management
след почистването; данните за таксуване могат да пристигнат по-късно.
