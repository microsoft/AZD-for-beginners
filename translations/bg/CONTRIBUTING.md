# Принос към AZD за начинаещи

Благодарим ви за интереса към приноса в курса AZD за начинаещи! Този документ предоставя насоки и информация за сътрудници.

## Как да допринесете

### Докладване на проблеми

Ако откриете грешки, бъгове или имате предложения за подобрения:

1. **Проверете съществуващите проблеми**: Потърсете [съществуващи проблеми](https://github.com/microsoft/azd-for-beginners/issues), за да избегнете дублиране
2. **Създайте нов проблем**: Използвайте подходящия шаблон за проблем
3. **Дайте подробности**: Включете стъпки за възпроизвеждане, очаквано поведение и екрани, ако е приложимо

### Предлагане на промени

1. **Форкнете хранилището**: Създайте свой собствен форк на проекта
2. **Създайте клон**: Създайте клон за функции за вашите промени
3. **Направете промените**: Следвайте нашите стандарти за кодиране и документация
4. **Тествайте промените си**: Проверете, че всички връзки работят и съдържанието се визуализира правилно
5. **Изпратете Pull Request**: Осигурете ясно описание на вашите промени

### Видове приноси

Ние приветстваме следните видове приноси:

#### Подобрения на съдържанието
- Поправка на печатни грешки, граматика и форматиране
- Подобряване на яснотата на съществуващата документация
- Актуализиране на остаряло съдържание
- Добавяне на липсващи обяснения или контекст

#### Нови примери
- Добавяне на реални сценарии за внедряване
- Създаване на нови шаблони за AZD за общи случаи на използване
- Предоставяне на допълнителни образци код и упражнения

#### Поддръжка на превод
- Помощ при поддържане на съществуващи преводи
- Подобряване качеството на преводите
- Добавяне на преводи за ново съдържание

#### Докладване на бъгове
- Докладване на повредени връзки или неправилни примери на код
- Идентифициране на несъответствия в документацията
- Отбелязване на проблеми с достъпността

## Насоки за принос

### Стандарти за документация

- Използвайте ясен, приятелски език за начинаещи
- Включете учебни цели и резултати
- Осигурете стъпка по стъпка инструкции с очаквани резултати
- Добавете навигационни връзки към свързано съдържание
- Използвайте последователно форматиране и markdown стил

### Примери с код

- Уверете се, че всички примери с код са тествани и работят
- Включете коментари, обясняващи ключови концепции
- Следвайте най-добрите практики за Azure и AZD
- Осигурете очакван изход, където е приложимо

### Валидация на английската документация

От корена на хранилището инсталирайте съществуващите изисквания за разработка и изпълнете:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

Офлайн проверяващия връзките проверява пътищата на английски Markdown/HTML, заглавия, експлицитни котви и празни заместващи връзки. Изключва генерирани `translations/` и `translated_images/`, включително връзки към тези директории. Не зарежда външни уебсайтове и не валидира Azure внедрявания. Използвайте `--json <report-path>` за експортиране на неуспехи и инвентара на външни URL адреси за отделна проверка на мрежата. Потвърдете текущите upstream команди и примерни изисквания при промяна на технически инструкции; разграничете тествани приложения от проектни чертежи.
