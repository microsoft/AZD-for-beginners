# مشارکت در AZD برای مبتدیان

از علاقه‌مندی شما به مشارکت در دوره AZD برای مبتدیان سپاسگزاریم! این سند راهنمایی‌ها و اطلاعاتی برای مشارکت‌کنندگان فراهم می‌کند.

## چگونه مشارکت کنیم

### گزارش مشکلات

اگر باگ، خطا یا پیشنهاد برای بهبود پیدا کردید:

1. **بررسی مشکلات موجود**: برای جلوگیری از تکراری بودن، [مشکلات موجود](https://github.com/microsoft/azd-for-beginners/issues) را جستجو کنید
2. **ایجاد یک مشکل جدید**: از قالب مناسب مسئله استفاده کنید
3. **ارائه جزئیات**: مراحل بازتولید، رفتار مورد انتظار و اسکرین‌شات‌ها را در صورت لزوم درج کنید

### پیشنهاد تغییرات

1. **فورک کردن مخزن**: فورک خود را از پروژه ایجاد کنید
2. **ایجاد یک شاخه**: برای تغییرات خود یک شاخه ویژگی بسازید
3. **اعمال تغییرات**: استانداردهای کدنویسی و مستندسازی ما را دنبال کنید
4. **آزمون تغییرات**: بررسی کنید تمام لینک‌ها کار کنند و محتوا به درستی نمایش داده شود
5. **ارسال درخواست پول ریکوئست**: توضیح واضحی از تغییرات خود ارائه دهید

### انواع مشارکت‌ها

ما انواع مشارکت‌های زیر را استقبال می‌کنیم:

#### بهبود محتوایی
- اصلاح اشکالات تایپی، دستوری و قالب‌بندی
- بهبود وضوح مستندات موجود
- به‌روزرسانی اطلاعات منسوخ شده
- افزودن توضیحات یا زمینه‌های گمشده

#### نمونه‌های جدید
- افزودن سناریوهای استقرار واقعی
- ایجاد قالب‌های جدید AZD برای موارد استفاده رایج
- ارائه نمونه‌های کد و تمرین‌های اضافی

#### پشتیبانی ترجمه
- کمک به نگهداری ترجمه‌های موجود
- بهبود کیفیت ترجمه‌ها
- افزودن ترجمه برای محتوای جدید

#### گزارش باگ
- گزارش لینک‌های شکسته یا نمونه‌های کد نادرست
- شناسایی ناسازگاری‌های مستندات
- علامت‌گذاری مشکلات دسترسی

## دستورالعمل‌های مشارکت

### استانداردهای مستندسازی

- استفاده از زبان واضح و مناسب مبتدیان
- درج اهداف و نتایج یادگیری
- ارائه دستورالعمل‌های مرحله به مرحله با خروجی‌های مورد انتظار
- افزودن لینک‌های هدایت به محتوای مرتبط
- استفاده از قالب‌بندی و سبک مارک‌داون یکسان

### نمونه‌های کد

- اطمینان از تست و عملکرد صحیح تمام نمونه‌های کد
- درج توضیحات برای مفاهیم کلیدی
- پیروی از بهترین شیوه‌های Azure و AZD
- ارائه خروجی مورد انتظار در صورت امکان

### اعتبارسنجی مستندات انگلیسی

از ریشه مخزن، نیازمندی‌های توسعه موجود را نصب کنید و اجرا کنید:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s .github/scripts -p "test_*.py"
python .github/scripts/check_links.py
python -m mkdocs build --strict --config-file workshop/mkdocs.yml
```

بررسی کننده لینک آفلاین مسیرهای Markdown/HTML انگلیسی، سرفصل‌ها، لنگرهای صریح و جای‌خالی لینک را چک می‌کند. `translations/` و `translated_images/` تولید شده و لینک‌های به آن پوشه‌ها را مستثنی می‌کند. وب‌سایت‌های خارجی را بارگیری نمی‌کند و استقرارهای Azure را اعتبارسنجی نمی‌کند. از `--json <report-path>` برای خروجی گرفتن خطاها و فهرست URLهای خارجی برای بررسی شبکه جداگانه استفاده کنید. هنگام تغییر دستورالعمل‌های فنی، دستورات جاری upstream و پیش‌نیازهای نمونه را بررسی کنید؛ برنامه‌های آزمایش شده را از طرح‌های طراحی متمایز کنید.
