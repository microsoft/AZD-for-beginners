## شروع کار

### سوال: Azure Developer CLI (azd) چیست؟
**پاسخ**: Azure Developer CLI (azd) یک ابزار خط فرمان محور توسعه‌دهنده است که زمان لازم برای انتقال برنامه شما از محیط توسعه محلی به Azure را تسریع می‌کند. این ابزار بهترین روش‌ها را از طریق قالب‌ها ارائه می‌دهد و به کل چرخه عمر استقرار کمک می‌کند.

### سوال: azd چه تفاوتی با Azure CLI دارد؟
**پاسخ**: 
- **Azure CLI**: ابزار عمومی برای مدیریت منابع Azure
- **azd**: ابزار متمرکز بر توسعه‌دهنده برای جریان‌های کاری استقرار برنامه
- azd دارای روند مخصوص احراز هویت و استقرار است؛ Azure CLI ابزاری جداگانه و مکمل است
- azd شامل قالب‌ها، مدیریت محیط و اتوماسیون استقرار است

### سوال: آیا برای استفاده از azd باید Azure CLI نصب باشد؟
**پاسخ**: برای جریان کاری اصلی AZD نیازی نیست. با `azd auth login` احراز هویت کنید. زمانی که یک هوک قالب یا تمرین به طور صریح دستورات `az` را اجرا می‌کند، Azure CLI را جداگانه نصب کنید.

### سوال: azd از چه زبان‌های برنامه‌نویسی پشتیبانی می‌کند؟
**پاسخ**: azd مستقل از زبان است. با موارد زیر کار می‌کند:
- Node.js/JavaScript/TypeScript
- Python
- .NET/C#
- Java
- Go
- PHP
- وب‌سایت‌های استاتیک
- برنامه‌های کانتینرسازی‌شده

### سوال: آیا می‌توانم از azd با پروژه‌های موجود استفاده کنم؟
**پاسخ**: بله! شما می‌توانید:
1. از `azd init` برای افزودن پیکربندی azd به پروژه‌های موجود استفاده کنید
2. پروژه‌های موجود را با ساختار قالب azd تطبیق دهید
3. قالب‌های سفارشی بر اساس معماری موجود خود ایجاد کنید

## احراز هویت و دسترسی

### سوال: چگونه با استفاده از azd در Azure احراز هویت کنم؟
**پاسخ**: از `azd auth login` استفاده کنید که یک پنجره مرورگر برای احراز هویت Azure باز می‌کند. برای سناریوهای CI/CD، از service principal یا managed identity استفاده کنید.

### سوال: آیا می‌توانم از azd با چند اشتراک Azure استفاده کنم؟
**پاسخ**: بله. از `azd env set AZURE_SUBSCRIPTION_ID <subscription-id>` برای مشخص کردن اشتراکی که برای هر محیط استفاده می‌شود، بهره ببرید.

### سوال: چه دسترسی‌هایی برای استقرار با azd نیاز دارم؟
**پاسخ**: معمولاً شما نیاز دارید به:
- نقش **Contributor** بر روی گروه منابع یا اشتراک
- نقش **User Access Administrator** اگر در حال استقرار منابع نیازمند انتساب نقش هستید
- دسترسی‌های خاص بر اساس قالب و منابع مورد استقرار متفاوت است

### سوال: آیا می‌توانم از azd در خط لوله‌های CI/CD استفاده کنم؟
**پاسخ**: قطعاً! azd برای ادغام CI/CD طراحی شده است. از service principal برای احراز هویت و متغیرهای محیطی برای پیکربندی استفاده کنید.

### سوال: چگونه در GitHub Actions احراز هویت را مدیریت کنم؟
**پاسخ**: ترجیح دهید از workload identity federation (OIDC) استفاده کنید که با `azd pipeline config` پیکربندی می‌شود. گردش کاری تولید شده AZD را نصب و مستقیماً با هویت فدرال شده احراز هویت می‌کند. فقط یک مرحله `azure/login` به تنهایی لاگین AZD را ایجاد نمی‌کند. یک مرحله لاگین درون یک شغل موجود به شکل زیر است:
```yaml
permissions:
  contents: read
  id-token: write
steps:
  - uses: actions/checkout@v7
  - uses: Azure/setup-azd@v2
  - run: >-
      azd auth login
      --client-id "${{ vars.AZURE_CLIENT_ID }}"
      --tenant-id "${{ vars.AZURE_TENANT_ID }}"
      --federated-credential-provider github
```

پس از لاگین، با محیط، اشتراک و مکان AZD هدف برنامه‌ریزی شده، فراهم‌آوری یا استقرار انجام دهید. اعتبار هویت فدرال شده باید به مخزن/رف ارجاع گردش کار یا محیط GitHub اعتماد داشته باشد و نقش‌های آن در Azure باید عملیات درخواستی را مجاز کنند.

## قالب‌ها و پروژه‌ها

### سوال: قالب‌های azd را کجا می‌توانم پیدا کنم؟
**پاسخ**: 
- قالب‌های رسمی و جامعه: [Awesome AZD](https://azure.github.io/awesome-azd/)
- قالب‌های جامعه: جستجو در GitHub برای "azd-template"
- از `azd template list` برای مرور قالب‌های موجود استفاده کنید

### سوال: چگونه قالب سفارشی ایجاد کنم؟
**پاسخ**: 
1. از ساختار قالب موجود شروع کنید
2. `azure.yaml`، فایل‌های زیرساخت و کد برنامه را تغییر دهید
3. با `azd up` به طور جامع تست کنید
4. با برچسب‌های مناسب در GitHub منتشر کنید

### سوال: آیا می‌توانم بدون قالب از azd استفاده کنم؟
**پاسخ**: بله، از `azd init` در یک پروژه موجود برای ایجاد فایل‌های پیکربندی لازم استفاده کنید. باید `azure.yaml` و فایل‌های زیرساخت را به صورت دستی پیکربندی کنید.

### سوال: تفاوت بین قالب‌های رسمی و جامعه چیست؟
**پاسخ**: 
- **قالب‌های رسمی**: توسط مایکروسافت نگهداری می‌شوند، به طور منظم به‌روزرسانی می‌شوند، مستندات جامع دارند
- **قالب‌های جامعه**: توسط توسعه‌دهندگان ایجاد شده‌اند، ممکن است موارد استفاده تخصصی داشته باشند، کیفیت و نگهداری متغیر است

### سوال: چگونه قالب پروژه‌ام را به‌روزرسانی کنم؟
**پاسخ**: قالب‌ها به طور خودکار به‌روزرسانی نمی‌شوند. شما می‌توانید:
1. به‌صورت دستی تغییرات را با قالب منبع مقایسه و ادغام کنید
2. با `azd init` با قالب به‌روزشده کار را از نو شروع کنید
3. به‌طور انتخابی بهبودهای خاص را از قالب‌های به‌روزشده استخراج کنید

## استقرار و زیرساخت

### سوال: azd چه خدمات Azure را می‌تواند مستقر کند؟
**پاسخ**: azd می‌تواند هر سرویس Azure را از طریق قالب‌های Bicep/ARM مستقر کند، از جمله:
- App Services، Container Apps، Functions
- پایگاه‌های داده (SQL، PostgreSQL، Cosmos DB)
- Storage، Key Vault، Application Insights
- منابع شبکه، امنیت و مانیتورینگ

### سوال: آیا می‌توانم به چند منطقه مختلف مستقر کنم؟
**پاسخ**: بله، چند منطقه را در قالب‌های Bicep خود پیکربندی کنید و پارامتر مکان را به طور مناسب برای هر محیط تنظیم کنید.

### سوال: چگونه مهاجرت‌های طرح پایگاه داده را مدیریت کنم؟
**پاسخ**: از هوک‌های استقرار در `azure.yaml` استفاده کنید:
```yaml
hooks:
  postdeploy:
    posix:
      run: ./scripts/migrate-database.sh
    windows:
      run: ./scripts/migrate-database.ps1
```

### سوال: آیا می‌توانم تنها زیرساخت را بدون برنامه‌ها مستقر کنم؟
**پاسخ**: بله، از `azd provision` برای استقرار تنها اجزای زیرساخت تعریف‌شده در قالب‌های خود استفاده کنید.

### سوال: چگونه به منابع موجود Azure مستقر کنم؟
**پاسخ**: بله، هنگامی که قالب از آن پشتیبانی کند. منابع موجود را با اعلامیه‌های `existing` در Bicep یا پارامترهای منابع موجود مستند شده در قالب ارجاع دهید و خدمات برنامه را به مقصدهای هدف مربوطه نگاشت کنید. این کار مالکیت را وارد نمی‌کند یا به طور خودکار دسترسی‌های لازم را ایجاد نمی‌کند. قبل از استقرار قالب را بازبینی کنید.

### سوال: آیا می‌توانم به جای Bicep از Terraform استفاده کنم؟
**پاسخ**: بله. AZD از Terraform همچنین پشتیبانی می‌کند. یک قالب مبتنی بر Terraform انتخاب کنید یا `infra.provider: terraform` را در `azure.yaml` با فایل‌های مناسب Terraform و پیکربندی backend/state تنظیم کنید. به [گردش کار Terraform](https://learn.microsoft.com/azure/developer/azure-developer-cli/use-terraform-for-azd) مراجعه کنید.

## پیکربندی و محیط‌ها

### سوال: چگونه محیط‌های مختلف (dev، staging، prod) را مدیریت کنم؟
**پاسخ**: با استفاده از `azd env new <environment-name>` محیط‌های جداگانه ایجاد کنید و تنظیمات متفاوتی برای هر کدام پیکربندی کنید:
```bash
azd env new development
azd env new staging  
azd env new production
```

### سوال: پیکربندی محیط‌ها کجا ذخیره می‌شود؟
**پاسخ**: در پوشه `.azure` در دایرکتوری پروژه شما. هر محیط پوشه مخصوص به خود را با فایل‌های پیکربندی دارد.

### سوال: چگونه پیکربندی خاص محیط را تنظیم کنم؟
**پاسخ**: از `azd env set` برای تنظیم متغیرهای محیط استفاده کنید:
```bash
azd env set AZURE_LOCATION eastus
azd env set DATABASE_TIER Basic
```

### سوال: آیا می‌توانم پیکربندی محیط را بین اعضای تیم به اشتراک بگذارم؟
**پاسخ**: پوشه `.azure` شامل اطلاعات حساس است و نباید در کنترل نسخه تعهد شود. به جای آن:
1. متغیرهای محیط مورد نیاز را مستندسازی کنید
2. از اسکریپت‌های استقرار برای راه‌اندازی محیط‌ها استفاده کنید
3. از Azure Key Vault برای پیکربندی حساس بهره ببرید

### سوال: چگونه مقادیر پیش‌فرض قالب را بازنویسی کنم؟
**پاسخ**: متغیرهای محیطی که با پارامترهای قالب مطابقت دارند را تنظیم کنید:
```bash
azd env set AZURE_LOCATION westus2
azd env set SKU_NAME "B1"
```

تنها متغیرهایی که توسط قالب مصرف می‌شوند بر استقرار تأثیر می‌گذارند. `SKU_NAME` در بالا یک ورودی سفارشی نمونه است، نه تنظیم جهانی AZD.

## عیب‌یابی

### سوال: چرا `azd up` شکست می‌خورد؟
**پاسخ**: علل رایج:
1. **مشکلات احراز هویت**: اجرای `azd auth login`
2. **مجوزهای ناکافی**: انتساب‌های نقش Azure خود را بررسی کنید
3. **تداخل نام منابع**: منبع متداخل و ورودی‌های نام‌گذاری الگو را بازبینی کنید؛ زمانی که ایزوله‌سازی لازم است محیط جداگانه‌ای با `azd env new` بسازید
4. **مشکلات سقف/ظرفیت**: در دسترس بودن منطقه‌ای را بررسی کنید
5. **خطاهای الگو**: الگوهای Bicep را معتبرسازی کنید

### پرسش: چگونه خطاهای استقرار را رفع اشکال کنم؟
**پاسخ**: 
1. از `azd deploy --debug` برای خروجی مفصل استفاده کنید
2. سابقه استقرار در پرتال Azure را بررسی کنید
3. درگاه فعالیت (Activity Log) در پرتال Azure را مرور کنید
4. از `azd show` برای نمایش وضعیت فعلی محیط استفاده کنید

### پرسش: چرا متغیرهای محیطی من کار نمی‌کنند؟
**پاسخ**: بررسی کنید:
1. نام متغیرها دقیقاً با پارامترهای الگو مطابقت دارد
2. اگر شامل فاصله هستند، مقادیر به درستی در کوتیشن قرار گرفته‌اند
3. محیط انتخاب شده است: `azd env select <environment>`
4. متغیرها در محیط درست تنظیم شده‌اند

### پرسش: چگونه استقرارهای_failed را پاکسازی کنم؟
**پاسخ**: 
```bash
azd down
```
ابتدا محیط انتخاب‌شده و تأیید حذف را مرور کنید. این عمل منابع فراهم‌شده Azure را حذف می‌کند، نه پیکربندی محیط محلی `.azure`. علاوه بر این، `--purge` درخواست حذف دائمی منابع حذف‌شده نرم‌افزاری را می‌دهد که ممکن است توسط حفاظت حفظ/پاک‌سازی مسدود شود؛ این یک مرحله بازیابی عادی نیست.

### پرسش: چرا پس از استقرار برنامه من در دسترس نیست؟
**پاسخ**: بررسی کنید:
1. استقرار با موفقیت کامل شده است
2. برنامه در حال اجرا است (لاگ‌ها را در پرتال Azure بررسی کنید)
3. گروه‌های امنیت شبکه اجازه ترافیک می‌دهند
4. دامنه‌های DNS/سفارشی به درستی پیکربندی شده‌اند

## هزینه و صورتحساب

### پرسش: هزینه‌های استقرار azd چقدر خواهد بود؟
**پاسخ**: هزینه‌ها بستگی دارد به:
- خدمات Azure مستقر شده
- طبقات/ SKUهای سرویس انتخاب شده
- تفاوت‌های قیمت منطقه‌ای
- الگوهای مصرف

برای برآوردها از [ماشین‌حساب قیمت Azure](https://azure.microsoft.com/pricing/calculator/) استفاده کنید.

### پرسش: چگونه هزینه‌ها را در استقرار azd کنترل کنم؟
**پاسخ**: 
1. از SKUهای سطح پایین‌تر برای محیط‌های توسعه استفاده کنید
2. بودجه‌ها و هشدارهای Azure را تنظیم کنید
3. از `azd down` برای حذف منابع وقتی لازم نیست استفاده کنید
4. مناطق مناسب را انتخاب کنید (هزینه‌ها بسته به مکان متفاوتند)
5. از ابزارهای مدیریت هزینه Azure استفاده کنید

### پرسش: آیا گزینه‌های سطح رایگان برای الگوهای azd وجود دارد؟
**پاسخ**: برخی خدمات دارای SKUهای رایگان یا اعتبارهای ماهانه هستند که تابع شرایط صلاحیت، طرح میزبانی، منطقه و محدودیت‌های اشتراک هستند. این‌ها الگوی کامل را رایگان نمی‌کنند: پایگاه‌های داده، جستجو، شبکه، رجیستری، تله‌متری و استنتاج مدل ممکن است هزینه‌های جداگانه داشته باشند. قبل از استقرار، [فهرست خدمات رایگان Azure](https://azure.microsoft.com/free/) و قیمت‌های جاری هر منبع را بررسی کنید.

### پرسش: چگونه قبل از استقرار هزینه‌ها را برآورد کنم؟
**پاسخ**: 
1. `main.bicep` الگو را مرور کنید تا ببینید چه منابعی ایجاد می‌شوند
2. از ماشین‌حساب قیمت Azure با SKUهای خاص استفاده کنید
3. ابتدا در یک محیط توسعه مستقر کنید تا هزینه‌های واقعی را بررسی کنید
4. برای تحلیل دقیق هزینه‌ها از مدیریت هزینه Azure استفاده کنید

## بهترین شیوه‌ها

### پرسش: بهترین شیوه‌ها برای ساختار پروژه azd چیست؟
**پاسخ**: 
1. کد برنامه را جدا از زیرساخت نگه دارید
2. از نام‌های سرویس معنادار در `azure.yaml` استفاده کنید
3. در اسکریپت‌های ساخت مدیریت خطای مناسب پیاده‌سازی کنید
4. از پیکربندی اختصاصی برای هر محیط استفاده کنید
5. مستندسازی جامع را شامل کنید

### پرسش: چگونه باید چند سرویس را در azd سازماندهی کنم؟
**پاسخ**: از ساختار پیشنهادی استفاده کنید:
```
├── src/
│   ├── web/          # Frontend service
│   ├── api/          # Backend service  
│   └── worker/       # Background service
├── infra/            # Infrastructure templates
├── azure.yaml        # azd configuration
└── README.md         # Project documentation
```

### پرسش: آیا باید پوشه `.azure` را به کنترل نسخه ارسال کنم؟
**پاسخ**: **خیر!** پوشه `.azure` حاوی اطلاعات حساس است. آن را به `.gitignore` اضافه کنید:
```gitignore
.azure/
```

### سوال: چگونه باید با اسرار و پیکربندی حساس برخورد کنم؟
**پاسخ**: 
1. برای اسرار از Azure Key Vault استفاده کنید
2. مخازن اسرار Key Vault را در پیکربندی برنامه ارجاع دهید
3. هرگز اسرار را در کنترل نسخه ثبت نکنید
4. از هویت‌های مدیریت‌شده برای احراز هویت سرویس به سرویس استفاده کنید

### سوال: رویکرد توصیه‌شده برای CI/CD با azd چیست؟
**پاسخ**: 
1. برای هر مرحله (توسعه/آزمایشی/تولید) محیط‌های جداگانه استفاده کنید
2. قبل از استقرار، تست‌های خودکار را پیاده‌سازی کنید
3. برای احراز هویت از سرویس پرنسپل‌ها استفاده کنید
4. پیکربندی حساس را در اسرار/متغیرهای خط لوله ذخیره کنید
5. درگاه‌های تایید را برای استقرارهای تولید پیاده‌سازی کنید

## موضوعات پیشرفته

### سوال: آیا می‌توانم azd را با عملکرد سفارشی گسترش دهم؟
**پاسخ**: بله، از طریق hooks استقرار در `azure.yaml`:
```yaml
hooks:
  predeploy:
    run: ./scripts/custom-setup.sh
  postdeploy:
    run: ./scripts/custom-config.sh
```

### سوال: چگونه azd را با فرآیندهای DevOps موجود یکپارچه کنم؟
**پاسخ**: 
1. از دستورات azd در اسکریپت‌های خط لوله موجود استفاده کنید
2. در تیم‌ها از قالب‌های استاندارد azd استفاده کنید
3. آن را با مانیتورینگ و هشداردهی موجود یکپارچه کنید
4. از خروجی JSON azd برای یکپارچگی خط لوله استفاده کنید

### سوال: آیا می‌توانم از azd با Azure DevOps استفاده کنم؟
**پاسخ**: بله، azd با هر سیستم CI/CD کار می‌کند. خط لوله‌های Azure DevOps بسازید که از دستورات azd استفاده کنند.

### سوال: چگونه می‌توانم به azd کمک کنم یا قالب‌های جامعه ایجاد کنم؟
**پاسخ**: 
1. **ابزار azd**: مشارکت در [Azure/azure-dev](https://github.com/Azure/azure-dev)
2. **الگوها**: پیروی از [دستورالعمل‌های مشارکت در گالری عالی AZD](https://github.com/Azure/awesome-azd#3-contribute-to-gallery)
3. **مستندات**: مشارکت در مستندات در [MicrosoftDocs/azure-dev-docs](https://github.com/MicrosoftDocs/azure-dev-docs)

### پرسش: نقشه راه azd چیست؟
**پاسخ**: نقشه راه رسمی [official roadmap](https://github.com/Azure/azure-dev/projects) برای ویژگی‌ها و بهبودهای برنامه‌ریزی شده را بررسی کنید.

### پرسش: چگونه از ابزارهای استقرار دیگر به azd مهاجرت کنم؟
**پاسخ**:
1. تحلیل معماری استقرار فعلی
2. ایجاد قالب‌های Bicep معادل
3. پیکربندی `azure.yaml` به‌گونه‌ای که با سرویس‌های فعلی تطابق داشته باشد
4. آزمایش کامل در محیط توسعه
5. مهاجرت تدریجی محیط‌ها
